# 本地视觉与手机操作：当前边界和实施顺序

2026-10-15。用户要求更强模型与无 API App 操作。当前系统只有文本链路，没有视觉投影文件、截图入口或无障碍执行器；不能声称已能看图或发送微信。

## 模型选择

- 第一候选：现有 Qwen3.5-4B 配套视觉投影，先跑图像识别与控件定位基线。llama.cpp 的视觉链路要求匹配的 mmproj；语言 GGUF 单独存在不代表可看图。
- 第二候选：Qwen3.5-9B 的量化版，用相同截图任务比较准确率、端到端延迟、峰值内存与热稳态，再决定是否启用。当前手机约 15GB 可见总内存、采样时约 5.3GB 可用，不能从总内存推出 9B 视觉稳定可用。
- 默认本地处理，不把用户屏幕或画像自动交给云模型。更大模型不是已验证的更优手机交互方案。
- 当前模型源请求失败：本机 7897 代理拒绝连接，直接访问 Hugging Face 超时；未下载或验证视觉权重。

## 无 API App 的执行链路

用户选择任务与目标 App → 读取当前无障碍节点，必要时读取屏幕 → 本地视觉理解 → 输出受限动作提议 → 检查目标、画面版本和权限 → 用户确认敏感动作 → 执行一个动作 → 重新观察结果。

优先使用可访问节点的文字和边界，缺失时再使用截图；避免所有动作只依赖模型猜测坐标。系统安全页面和禁止截图的内容应返回不可操作，不绕过。

需实现：用户手动启用的 AccessibilityService、按应用/单次任务授权、实时停止、动作次数/时间上限、画面变化后重新定位；候选动作仅 click/scroll/input/back 等明确枚举；密码内容不采集；屏幕内容与模型输出不能授予权限。发送消息需确认收件人和完整正文，支付/删除等另行确认。

先在无真实账户和无真实外发的测试 App 中验证成功率、误点、弹窗、旋转、键盘、系统回收和取消；通过后才验证用户指定的真实 App。不能将任意 App 操作能力当成已经上线。
