# 机制推演：新人如何靠“认可”而不是“流量”获得高曝光

- 状态：提议（对应 SPEC REQ-CS-001 ~ 007，P1）
- 日期：2026-11-09

## 1. 目标

一个**零粉丝、零预算**的新创作者，发布一条真正高质量的视频，应当在可预期的时间内（目标 48h）
获得与其质量相称的曝光（例如 10 万级），而且整个过程中：

- 不需要买量；
- 不需要已有粉丝；
- 不依赖“认识谁”；
- 曝光每扩大一级，都有新的、独立的认可证据支撑。

## 2. 现状诊断：M1 设计做不到

用当前代码实测（3 人评审的新人 0.9 分作品 vs 12 人评审的头部 0.7 分作品）：

| 内容 | 共识分 | 置信度 | 排序分 | 名次 |
|---|---|---|---|---|
| 新人高质量 | 0.90 | 0.61 | 0.55 | 2 |
| 头部中等 | 0.70 | 0.98 | 0.68 | **1** |
| 新人、无人评审 | — | — | — | **不在推荐流** |

四个结构性缺陷：

1. **鸡生蛋**：只有已结算内容才进推荐流，而评审者没有任何途径发现新内容 → 新人作品永远无人评审。
2. **规模偏置（马太效应）**：`排序分 = 共识 × 置信度`，置信度随评审人数增长。评审人数本质上就是流量的函数，
   于是“流量多 → 评审多 → 置信度高 → 流量更多”。**质量输给了规模**，这和投流逻辑同构。
3. **一次性结算**：结算后评审窗口关闭，共识冻结，曝光不能随着认可增多而逐级放大。
4. **没有发现激励**：早期冒险认可冷门好内容的评审者，和后来跟风的人拿一样的回报 → 理性评审者会扎堆评审热门内容。

## 3. 机制设计：随机陪审 + 波次放量

把“流量池放量”这个大家熟悉的机制保留下来，但**晋级的依据从“付费买来的数据”换成“随机抽中的人的签名认可”**。

```
发布（质押少量声誉）
  │
  ▼
L0 探索池：每条新内容获得固定的初始曝光（与粉丝数无关）
  │   + 随机抽取 5 名该标签下有资质的陪审评审者（抽签，作者无法挑选）
  │
  ▼ 第 1 波结算：共识 ≥ 0.7 且 跨群体一致
L1 池（曝光上限 ×10）  + 追加 10 名陪审 + 读者信号（按读者声誉加权）
  │
  ▼ 第 2 波结算
L2 池（×10）  + 追加陪审，要求桥接共识（REQ-PS-008）
  │
  ▼ …… 每一级都需要新的、独立的证据
L4 全站推荐
```

### 3.1 探索池（REQ-CS-001）——解决“鸡生蛋”

- 每个推荐流固定拿出 **10%** 的位置给未结算的新内容。
- 分配单位是**内容**而不是作者：每条新内容获得相同的初始曝光，粉丝数不参与计算。
- 按标签匹配读者兴趣，但抽样是随机的。

### 3.2 随机陪审（REQ-CS-002）——认可不靠人脉

- 首轮评审者由系统从“该标签下声誉达标的评审者”中**随机抽签**（参考 Kleros 陪审团、Community Notes 的评审分配）。
- 首轮评审者**不能自选**内容 → 作者无法安排朋友刷分，合谋者也无法定点抢先。
- 完成陪审本身获得少量声誉奖励（参与费），抵消“评审冷门内容收益低”的问题。
- 评分采用 **commit-reveal**：先提交哈希、窗口结束后揭示，不能看别人的分数跟风。

### 3.3 波次放量（REQ-CS-003）——曝光与证据同步增长

| 级别 | 曝光上限（示例） | 晋级条件 | 新增证据 |
|---|---|---|---|
| L0 | ~100 | — | 5 名随机陪审 |
| L1 | ~1,000 | 共识 ≥ 0.7 | +10 陪审，读者“值得看”评分 |
| L2 | ~10,000 | 共识 ≥ 0.7，读者信号不显著低于陪审 | +20 陪审，跨 ≥2 个群体一致 |
| L3 | ~100,000 | 桥接共识成立 | 持续抽检 |
| L4 | 不设上限 | 持续保持 | 随机复审，可降级 |

关键性质：**每一级的放大倍数有上限（×10），而且每一级都需要新抽中的人独立认可。**
刷分者要把一条垃圾内容推到 L3，就必须连续多轮被随机抽中，成本呈指数增长。

### 3.4 排序去规模偏置（REQ-CS-004）

把 `共识 × 置信度` 改成**贝叶斯收缩 + 不确定性探索**：

```
后验均值 = (n × 共识 + n0 × 全站均值) / (n + n0)      # 评审少时向均值收缩，而不是直接打折
排序分   = 后验均值 + β × 不确定性                       # 同一池内用 UCB/Thompson 抽样
```

- 评审少的意思是“还不确定”，而不是“差”。不确定性会带来**更多**探索曝光，而不是更少。
- 不同级别之间的比较不靠排序分，靠池子的曝光上限 → 头部内容的评审数量优势无法挤占新人在本池内的位置。

### 3.5 发现者奖励（REQ-CS-005）——让“发现好内容”有利可图

- 广告收益里的策展人份额按波次加权：**L0 陪审 ×3、L1 ×2、L2 及以后 ×1**。
- 一条新人作品如果最终火了，最早认可它的 5 名随机陪审能分到它此后全部广告收益里最大的那份策展收益。
- 因为 L0 陪审是抽签决定的，这个奖励**无法被抢跑**（区别于 Steemit 的“早投票奖励”被机器人抢跑）。

### 3.6 防刷与防泛滥（REQ-CS-006 / 007）

AI 让发布成本趋近于零，探索池必然面临泛滥：

- **发布质押**：发布时锁定少量声誉（如 5 点），L0 共识 < 0.3 则罚没。零成本刷量变成“每次失败都掉声誉”。
- **每日配额**：每个 DID 每天进入探索池的条数有上限（如 3 条），新身份更少（结合 REQ-PS-009 女巫抵抗）。
- **读者信号**（REQ-CS-007）：完播、收藏、“值得看”评分，按读者声誉加权；读者信号与陪审结论显著背离时触发复审，而不是直接晋级。

## 4. 容量推演：这套机制跑得动吗

假设 100 万日活、每人每天刷 50 条：

| 量 | 计算 | 结果 |
|---|---|---|
| 每日推荐位 | 100 万 × 50 | 5,000 万 |
| 探索池（10%） | | 500 万 |
| 每日新内容（假设） | | 5 万条 |
| 每条 L0 曝光 | 500 万 ÷ 5 万 | **约 100 次** |
| L0 陪审需求 | 5 万 × 5 人 | 25 万次评审/天 |
| 陪审供给 | 5% 用户 × 每人 10 次 | 50 万次/天 ✅ |

如果每日新内容涨到 50 万条（AI 泛滥），每条 L0 曝光就会降到 10 次，陪审需求达到 250 万次/天，会超出供给。
这时候需要靠发布质押和每日配额把进入 L0 的数量压回容量以内。**探索池的容量是机制里最需要被治理的参数（REQ-GV-001）。**

## 5. 一个新人的 48 小时（示例）

| 时间 | 事件 | 曝光 |
|---|---|---|
| T+0 | 发布，质押 5 声誉；进入 L0，随机抽中 5 名“AI 教程”标签陪审 | 100 |
| T+6h | 陪审揭示，共识 0.86 → 晋级 L1，5 名陪审各 +声誉 | 1,000 |
| T+18h | 新增 10 陪审 + 600 名读者评分一致 → L2 | 10,000 |
| T+36h | 跨“技术/营销”两个群体一致（桥接成立）→ L3 | 100,000 |
| T+48h | 广告收益开始累积：创作者 60%，L0 陪审按 ×3 权重分策展份额 | — |

全程花费：**0 元投流 + 5 点声誉质押**。对比现有平台，同等曝光通常需要数千元量级的投流（具体价格待 M0 调研校准）。

> 补充：未能在首轮晋级的作品还有“二次机会”和“曝光欠账复兴”，见 [content-classes.md](content-classes.md) §2（REQ-EV-003/005）。

## 6. 风险与未决问题

1. **小众高质量内容**：小众内容的受众天然少，评“质量”时要用标签内的相对标准，晋级条件按标签规模归一化。
2. **陪审偷懒**：随机打分接近均值能“混”奖励 → 插入已知答案的抽检题（gold set），偏差过大则罚没。
3. **品味垄断**：如果某一群体的评审者占多数，会系统性压制其他风格 → 桥接共识 + 分品类维度（REQ-PS-011）。
4. **参数博弈**：阈值 0.7、×10、10% 都是初值，需要仿真（M2 加入多主体仿真器）和真实数据校准。
5. **与 M1 实现的冲突**：一次性结算（REQ-AT-003、PS-005）要改为“按波次结算”，SPEC 需在实现 CS-003 时同步修订。
