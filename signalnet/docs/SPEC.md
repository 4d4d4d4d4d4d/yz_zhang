> 本文件是**唯一的需求真相源**。代码与测试通过需求 ID（`REQ-XX-000`）追溯到这里。
> 需求表格式被 `harness/gate.py` 解析，请保持 `| ID | 优先级 | 描述 | 验收标准 |` 四列格式。

> 优先级：**P0** = 当前里程碑必须实现，且必须有测试引用（门禁强制）；

---

## 1. 范围

M1（当前）：**单进程可验证内核**——身份、内容、评审、PoS 共识、排序、广告分账、反垄断路由、日志重放，全部以纯 Python 库形式实现，可通过 `python -m signalnet demo` 端到端运行。

不在 M1 范围：网络通信、持久化、客户端、真实支付、媒体存储。

## 2. 术语

| 术语 | 定义 |
|---|---|
| DID | `did:sn:<ed25519 公钥 hex>`，自证明身份 |
| 内容（Content） | 作者签名的数据对象，ID 为规范化 JSON 的 SHA-256 |
| 评审（Attestation） | 评审者签名的三维评分 + 声誉质押 |
| 声誉（Reputation） | 绑定 DID 的整数积分，不可转让，不是代币 |
| 共识分（consensus） | 评审分数按 √质押 加权的中位数，∈[0,1] |
| 置信度（confidence） | 评审量饱和度 × (1 − 2 × 加权离散度)，∈[0,1] |
| 结算（Settlement） | 对一条内容的评审进行奖惩、并锁定共识分 |
| 枢纽节点（hub） | 提供加速能力的高性能节点，受份额上限约束 |
| micros | 金额单位，1 货币单位 = 1,000,000 micros |

## 3. 需求

### 3.1 身份（ID）

| ID | 优先级 | 描述 | 验收标准 |
|---|---|---|---|
| REQ-ID-001 | P0 | 身份为自证明 DID，基于 ed25519 | DID 格式校验；同种子同 DID；不同种子不同 DID |
| REQ-ID-002 | P0 | 所有签名基于规范化 JSON，篡改任一字段即校验失败 | 键序无关；改值/换签名者/非法签名均失败 |
| REQ-ID-003 | P1 | 密钥轮换与恢复（社交恢复 / 设备多签） | 轮换后旧内容仍可验证，新内容用新钥 |

### 3.2 内容（CT）

| ID | 优先级 | 描述 | 验收标准 |
|---|---|---|---|
| REQ-CT-001 | P0 | 内容哈希寻址 | 相同 payload 相同 ID；序列化往返 ID 不变 |
| REQ-CT-002 | P0 | 内容必须作者签名，校验失败拒绝 | 改正文、冒名作者均被拒 |
| REQ-CT-003 | P0 | AI 生成内容强制披露 `ai_generated` 字段 | 不声明无法创建；非 bool 被拒 |
| REQ-CT-004 | P1 | 内容版本/勘误：作者可发布引用原 ID 的修订 | 修订继承评审历史但单独结算 |

### 3.3 日志（LG）

| ID | 优先级 | 描述 | 验收标准 |
|---|---|---|---|
| REQ-LG-001 | P0 | 仅追加哈希链日志，篡改可检测 | 修改任一事件后 verify_chain 为 False |
| REQ-LG-002 | P0 | 事件数据入链时深拷贝冻结 | 调用方事后修改原对象不影响日志 |

### 3.4 评审（AT）

| ID | 优先级 | 描述 | 验收标准 |
|---|---|---|---|
| REQ-AT-001 | P0 | 评审含准确性/质量/有用性三维评分 ∈[0,1]，评审者签名；综合分权重 0.4/0.4/0.2 | 越界拒绝；签名可验 |
| REQ-AT-002 | P0 | 质押为正整数，且 ≤ 可用声誉 × 20%；声誉 < 10 不能评审 | 超限拒绝；锁定额正确 |
| REQ-AT-003 | P0 | 同一评审者对同一内容只能评审一次；结算后评审窗口关闭 | 重复/迟到评审被拒 |
| REQ-AT-004 | P0 | 作者不得评审自己的内容 | 节点拒绝；结算计算中剔除 |
| REQ-AT-005 | P1 | 评审窗口按时间关闭（如发布后 72h 自动结算） | 定时结算任务 |

### 3.5 PoS 共识（PS）

| ID | 优先级 | 描述 | 验收标准 |
|---|---|---|---|
| REQ-PS-001 | P0 | 声誉不可转让、不可铸造买卖 | ReputationBook 无 transfer/mint/sell/buy 类接口 |
| REQ-PS-002 | P0 | 共识分 = 评审综合分的加权中位数，权重 = √stake | 单元测试覆盖中位数与权重 |
| REQ-PS-003 | P0 | 评审者 ≥3 人时，单人权重占比 ≤ 34% | 极端质押下占比不超限 |
| REQ-PS-004 | P0 | \|分数−共识\| ≤ 0.15 奖励 stake×10%，否则罚没 stake×20%（至少 1）；声誉不为负；作者声誉变化 = round((共识−0.5)×2×20×置信度) | 余额精确匹配 |
| REQ-PS-005 | P0 | 结算是纯函数（与评审顺序无关、不改状态），且每条内容只结算一次 | 两次计算相等；重复结算被拒 |
| REQ-PS-006 | P0 | 结算计算剔除作者本人的评审 | 共识不受作者自评影响 |
| REQ-PS-007 | P0 | 权重少数（<50%）的合谋者无法把低质内容抬高，且会被罚没 | 5 诚实 vs 3 合谋（双倍质押）共识 < 0.3 |
| REQ-PS-008 | P1 | 桥接共识：评审者按互动图聚类，跨群体一致才给高置信度 | 单一群体刷分置信度显著降低 |
| REQ-PS-009 | P1 | 女巫抵抗：新身份评审权重随声誉/时长渐进解锁；邀请链连坐 | 批量新号无法左右共识 |
| REQ-PS-010 | P1 | 声誉按周期衰减（防躺赚），衰减部分注入新人扶持 | 不活跃账户声誉下降 |
| REQ-PS-011 | P1 | 分品类评分维度（资讯/教程/娱乐/艺术） | 不同品类使用不同权重 |

### 3.6 排序分发（RK）

| ID | 优先级 | 描述 | 验收标准 |
|---|---|---|---|
| REQ-RK-001 | P0 | 排序确定性：同输入同输出，同分按 content_id 升序 | 输入顺序打乱结果一致 |
| REQ-RK-002 | P0 | 广告预算在结构上无法影响自然排序：ranking 不依赖 ads，RankInput 无出价字段 | 分层门禁 + 投放前后自然流一致 |

| REQ-RK-005 | P0 | 共识分低于阈值（默认 0.3）的内容不进入推荐流（仍可被订阅/搜索） | demo 中的垃圾内容不再出现在 feed；阈值边界含等于 |
| REQ-RK-006 | P1 | 用户可选/可订阅第三方排序算法（自定义 Feed） | 至少两种算法可切换 |

### 3.6.1 冷启动与新人曝光（CS）

> 设计推演见 [design/cold-start.md](design/cold-start.md)。原 REQ-RK-007 并入 REQ-CS-001（ID 作废不复用）。

| ID | 优先级 | 描述 | 验收标准 |
|---|---|---|---|
| REQ-CS-001 | P1 | 探索池：推荐流固定比例（默认 10%）留给未结算新内容，按内容均分初始曝光，与粉丝数无关 | 零粉丝新内容必然获得 L0 曝光；比例可配置且公开 |
| REQ-CS-002 | P1 | 随机陪审：首轮评审者从标签内声誉达标者中确定性抽签（以内容 ID + 日志 head 为种子），作者与评审者不可自选 | 任意节点可复算抽签结果；非抽中者的首轮评审被拒 |
| REQ-CS-003 | P1 | 波次放量：多波次结算，达标晋级后曝光上限 ×10（L0~L4），每波追加独立陪审 | 未达标不晋级；单波放大倍数 ≤10 |
| REQ-CS-004 | P1 | 排序去规模偏置：同池内用贝叶斯收缩后验 + 不确定性探索替代 共识×置信度 | 3 人评审的 0.9 分新作在同池内排在 12 人评审的 0.7 分作品之前 |
| REQ-CS-005 | P1 | 发现者奖励：策展分成按波次加权（L0 ×3、L1 ×2、其后 ×1）；评分 commit-reveal | 早期一致陪审分成更高；揭示前无法读取他人分数 |
| REQ-CS-006 | P1 | 发布质押与配额：发布锁定少量声誉，L0 共识 < 0.3 罚没；每 DID 每日进入探索池条数有上限 | 超配额不进探索池；低质发布掉声誉 |
| REQ-CS-007 | P1 | 读者信号：完播/收藏/“值得看”按读者声誉加权，作为后续波次输入；与陪审显著背离时触发复审 | 背离场景进入复审而非晋级 |

### 3.6.2 原创性与反搬运（OR）

> 设计推演见 [design/originality.md](design/originality.md)。

| ID | 优先级 | 描述 | 验收标准 |

## 4. 不变量（任何改动都不得破坏）

1. **INV-1 无币**：系统中不存在可转让的价值单位；声誉不可转让。
2. **INV-2 买不到流量**：自然排序的输入中没有任何来自广告/支付的数据。
3. **INV-3 守恒**：广告扣费总额 == 各方收益总额。
4. **INV-4 可复算**：共识与排序是确定性纯函数；机制层不读取系统时间与随机数。
5. **INV-5 无垄断**：单节点流量份额有硬上限。
