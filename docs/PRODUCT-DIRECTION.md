# OPC 产品定位与设计前提 · 讨论稿

日期：2026-10-07。依据用户最新愿景整理；本文是设计提案，不表示功能已实现或商业模式已被验证。这是先于实现形成的定位讨论；后续已实现内容以 [实现核对表](IMPLEMENTATION-MATRIX.md) 和 [Spec 88](specs/88-individual-network-and-spaces.md) 为准。

## 定位

一个以独立个体为中心的开放协作网络：每个人拥有可经营的数字空间，借助 AI 延伸能力，通过可验证的约定与他人及机器形成合作，并把获授权的经验变成下一次合作的能力。

对用户的表达：让别人了解你，让想做的事找到一起完成的人。

平台承担发现、连接、组织、记录、复用等组织能力；每一次合作仍需明确决策权、履约责任和权益归属。公司、合伙、个人、工厂可以进入同一个网络，产品不预设所有业务必须脱离现有主体。扁平意味着信息和参与机会更开放，同时保留必要的项目负责人与决策机制。

## 产品的五个核心对象

1. 个体：公开身份、作品、观点、可提供的能力、经营内容、可合作时间、被验证的贡献。人是中心，组织有独立页面，Agent 和设备明确标注运营者及权限。
2. 关系：关注、交流、合作邀请、共同经历、经授权的推荐。社交可以独立成立，不强迫每次交流变成交易。
3. 意图：从“今晚帮忙遛狗”到“做一个机器人”，既可以是求助，也可以是探索、采购、共创和长期经营。
4. 合作空间：围绕意图建立共享上下文，逐步加入成员、计划、交付标准、预算、协议及成果；可临时组成，也可持续经营。
5. 经验资产：有来源、有适用条件、有验证结果、有使用权限的案例、流程和工具，供人和 Agent 复用。

## 个人空间：一个可经营的门面

公开空间回答“你是谁、做过什么、现在能一起做什么”。内容包括代表作、文章/视频、跨平台链接、服务、小店、直播入口及合作成果，可按个人身份和风格编排。访问者先看真实内容，再决定关注、交流、购买或邀请。

私人工作台回答“什么需要我处理”：邀请、进行中的合作、个人 Agent、收入、档案和设置。公开展示与私人管理分离。

外部内容先支持本人提交、授权同步和原平台嵌入，保留来源、更新时间、删除与撤回机制。全网自动抓取、直播转播和原生电商分别需要单独评估接入权限及运营成本，不应把链接聚合描述为已经打通交易。

## 从日常到复杂协作

| 场景 | 直接体验 | 按需展开的组织工具 |
|---|---|---|
| 邻里帮忙、遛狗、简单交付 | 找到附近合适的人，约定时间和结果 | 地点隐私、费用、完成确认、异常处理 |
| 设计、研究、咨询、内容制作 | 从作品认识人，说明想法，形成合作 | 交付范围、阶段、修改次数、专家复核 |
| 机器人、工业品共创 | 找架构师及各模块负责人，共同推进 | 依赖关系、接口/验收规范、物料与版本、工厂能力、集成验证、知识产权与收益约定 |
| 持续经营、复杂公司项目 | 在长期合作空间持续组织资源 | 角色授权、预算、财务、审计、决策记录和具名专业责任 |

轻量场景应能快速完成；复杂场景逐步显露结构。共用身份、协作与信任基础，匹配逻辑仍按领域区分：附近服务看距离和时段，工业合作看能力、接口、产能和交付证据。

## AI 的位置

- 个人 Agent：在本人授权内整理展示内容、回答基于公开资料的问题、筛选邀请、辅助准备工作。不能自行承诺价格、签约或转移权益。
- 协作助手：理解意图、指出缺失条件，生成可修改的计划，找到合适的人、Agent、设备或机构；在费用与权限预算内执行，遇到不确定性升级给人。
- 专业支持：针对法务、财务、政策等提供有来源和时效的信息、材料准备及问题梳理；需要专业判断的事项交给具名专家，并记录复核结果。
- 经验复用：检索历史案例、推荐适用流程、协助复盘。模型产物只有经过验收/评价才可能成为可信经验，不能把生成量当作能力增长。

每个 Agent 应展示代表谁、能访问什么、能花多少、哪些动作要确认，以及如何撤销权限。

## 信任和经验循环

信任分层：身份和能力证据 → 明确约定 → 实际交付记录 → 验收和争议处理 → 可校验的证据。链上合约支持适合程序执行的规则与摘要验证，线下事实、身份资格和质量判断仍需各自的验证机制。敏感原文与公开链上证据分开。

合作结果 → 获授权的结构化复盘 → 去标识与分级访问 → 专家/参与者验证 → 案例和流程检索 → 下一次使用 → 对照实际结果修正。

同时保存失败、返工、例外与过期条件。私人资料、项目共享资料、平台可复用经验分别授权；检索复用与模型训练分别管理。知识贡献需要署名，商业复用可试验按实际使用结算贡献收益。

## 首批受众与冷启动假设

长期面向所有有表达、经营、合作需求的人。首期建议围绕一个具体共创社群验证：独立专业人士、小工作室、发起产品的个人/小团队，以及有接口人的工厂与服务机构。

优先邀请能提出真实目标并组织验收的发起人，围绕真实合作补齐专家供给。首个可验证阶段可以是产品研究、设计和原型协作；工业量产、复杂重组和高频配送逐步引入对应行业能力。最终选择应根据用户已有社群和真实需求确认，不能仅靠理论市场规模。

单人加入即有价值：整理个人空间、汇总作品、让已有客户更容易联系、由 AI 辅助处理资料。然后邀请已有合作伙伴，完成真实合作，积累可公开成果，再吸引新关系。

## 商业模式假设

| 付费方 | 获得的价值 | 收费方式 |
|---|---|---|
| 独立经营者 | 个人站、授权同步、客户管理、个人 Agent | 免费基础空间 + 专业订阅；计算和存储设透明额度 |
| 合作发起人/参与者 | 撮合、签约、结算、履约支持 | 清楚列明的成交或服务费；自带伙伴与平台获客可以差异化 |
| 长期合作体/企业 | 私有知识、治理、授权、审计、连接器 | 空间订阅 + 适度使用量计费，测试是否更适合弹性团队 |
| 专家和 Agent 开发者 | 可销售的专业服务与可复用能力 | 按次/按使用量收费，平台分成 |

初期集中验证个人专业订阅与合作服务收费。观察实际续费、交付成本、支付及客服成本、纠纷率和 AI 成本后的贡献毛利，不虚构定价和收益预测。不出售个人隐私或付费信用排名；知识、模板、Agent 的分成在真实复用量出现后验证。

## UI 的设计约束

待验证的主导航：发现、合作、消息、我的空间；创建和 AI 作为可随时调用的动作。

发现优先展示人、作品、生活和正在发生的合作，支持目的明确的搜索。个人空间视觉可个性化，身份、权限和交易信息保持一致。访客可先看允许公开的内容，产生关注/交流/合作意图时再注册。

极简通过信息层级和渐进展开实现。合同的范围、金额、权限和后果必须清楚，不能为视觉简洁删掉决策信息。身份和案例证据要具体，避免把一个泛化信用分当成全领域能力判断。

动画用于解释空间关系：作品卡展开为个人空间、成员加入为合作关系、阶段完成为成果归档。保留滚动位置和阅读上下文。轻微视差可用于封面和作品，不劫持滚动，不拖慢输入、聊天和交易，尊重减少动态效果设置。Blender 只在具体作品或品牌场景确有需要时使用。

第一批概念稿应呈现：发现人与作品、一个人的公开空间、从想法到合作空间。用同一套原型分别走通日常帮忙和机器人原型合作，再据体验取舍导航与动效。暂不开展全站视觉重写。

## 验证标准与当前工程差距

主要结果指标建议为每月完成有价值合作且愿意再次合作的独立个体数，辅以首个有效联系耗时、复合作率、按约交付率、纠纷率、授权知识复用效果和贡献毛利。长期合作另看阶段结果，防止只优化短单数量。关注/交流本身的价值也需要独立用户访谈和留存验证。

当前代码已有任务、团队/合作体、内容、Agent、知识及链上记录等基础；导航与个人页仍以功能模块和账户管理为主。新方向仍需核验和补充公开个人空间、外部内容授权连接、以人为中心的发现、持续合作上下文、领域化能力证据、细粒度知识授权和贡献回报。本文不把既有测试数量视为上述体验已经成立。
