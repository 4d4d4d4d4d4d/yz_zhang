# 完成度与商用差距（2026-10-13 实查）

> 回答三个问题：**哪些真的做完了、哪些没做完、离商用还差多少。**
> 依据是真跑出来的结果，不是 spec 写了什么：真后端（uvicorn）+ 构建产物（`vite build`）+ 真浏览器（Chromium）
> 走完一单；全量测试；git 历史扫描。逐条的台账仍在 [72 号](specs/72-status-ledger.md)，远景对照在 [VISION](VISION.md)。

## 0. 一句话结论

**产品功能的主干是真的，能在真浏览器里走完一单**：注册、实名、发任务、报名、成交、双方签约、托管、交付、验收、
到账（360 元扣 8% 后到账 331.20）、互评，以及 AI 逐层拆解、推荐人选、私聊和法律问答，都打到了真服务端。
**但它现在收不了真钱，也不能公开商业运营**：支付、存管、实名、短信、内容安全、电子签名和司法存证都还是
沙箱或模拟实现，必须接入持牌机构。这不是「填个密钥」就能解决的事，详见第 4 节。

## 1. 真实运行演示（V140）

做法：以 `PLATFORM_ENV=sandbox` 起真后端，用构建产物加同源反代起网页，用 HTTP 造三个人和一整单数据，
再用 Chromium 登录点页面截图。全程 **0 个 5xx**。

| 走通的 | 说明 |
|---|---|
| 注册 / 实名 / 登录 | 实名走的是沙箱供应商 |
| 发任务 → 报名 → 选人 → 双签 → 托管 → 交付 → 验收放款 → 互评 | 钱的流转在平台内部账本里，账本是真的；对外打款是模拟的 |
| 执行方钱包 | 可用 ¥331.20，流水「任务收入 · 任务验收放款」 |
| 项目型任务 → AI 逐层拆解 → 确认发布子步骤 | 没有模型 Key，走的是通用三段式模板 |
| AI 推荐人选、报名列表、私聊、法律问答、个人空间 | 均为真实数据 |

**这次演示抓到一个测试一直没抓到的 bug**：V138 的事务守卫按线程计数。FastAPI 依赖的收尾可能落在别的线程上，
导致守卫偶发误报，「AI 拆解」在沙箱里偶发 500。已修复，改为按连接计数，并补了两条红验测试（113 号 spec 第 6 节）。
**这正是真实运行的价值：mock 掉网络的测试看不到线程调度。**

## 3. 有没有删过原有功能（用户要求：功能增补要兼容，不删除、不替换删除）

扫描全部 163 个提交，看接口、网页路由、SDK 方法和 App 页面「曾经有、现在没有」的情况：

| 曾有现无 | 何时 | 为什么 | 功能是否还在 |
|---|---|---|---|
| `POST /users/{id}/follow`（切换式关注） | V117 | 双击或弱网重试会把刚关注的人取消掉 | 在：换成了幂等的 `PUT`（关注）和 `DELETE`（取消），两端同批改 |
| SDK `addCertification` | V82 | 对服务端永远返回 422（字段对不上），是坏的 | 在：换成了 `submitCertification` 和 `myCertifications` |

除这两处之外，**没有删过任何页面、接口或 App 模块**。「代码变少」的感觉来自那几批加固工作，
代码量本身一直在增长（V133 → V139：78,415 → 84,622 行）。

**从现在起这一点由闸门守着**（FEAT-001）：
- [`docs/FEATURE-SURFACE.txt`](FEATURE-SURFACE.txt) 列出全部 717 项功能面：367 个接口、27 个网页路由、304 个 SDK 方法、19 个 App 模块。
- `tests/test_feature_surface.py` 检查清单里的每一项都还在。确需下线的，必须写进 `RETIRED` 并写明理由和替代品。
- 新加的功能也必须登记进清单。红验方法：改掉一个网页路由，闸门立刻报红。

值班与告警接收人、客服与争议处理时限、人工审核职责、法务对协议的审核、财税对分账和代扣的审核。

**可以给出的判断**：
- 「邀请制、不涉及真实资金的内测」现在就可以做。

- 不给凭空的上线日期：工期取决于选定的供应商和它们的接入节奏。
