
# 354 发单拦截类别登记一致性闸门

> 状态：本批实现（V381）。编号 SCN-248。
> 来源：BACKLOG V381（第四十一轮排期）。V369（年检包过）、V371（AI 声音克隆）、V378（篡改里程表）三次新加拦截类别，都靠手工同步四处。
> 只增不减：拦截行为、错误码、提示文案都不变；`errand.py` 多一张登记表 `KIND_CODES`，多一条测试，skill `spec-batch` 的登记清单多一行。

## 0. 要解决的问题

发单拦截现在有九类（八个错误码）。每加一类要同时改四处：

1. 服务端返回的错误码；
2. SDK 的 i18n 文案；
3. 复核列表里的类别名（`errand_reviews.KIND_LABEL`）；
4. SDK 的可复核清单（`ERRAND_REVIEW_CODES`）。

漏任何一处都没有测试会红，而后果是真实的：

- 漏了可复核清单：被拦下的人看不到「申请人工复核」，V363 那条路对这一类等于不存在；
- 漏了类别名：运营的复核列表和场景雷达里显示英文代码；
- 漏了 i18n：客户端提示退回成错误码。

## 1. 业界怎么做

把「散在几处、必须一致」的登记收拢成一张表，用测试双向核对。这与本仓库已有的调度表（JOB-001）、角色表、后台入口表做法相同。

## 2. 规则

- `errand.KIND_CODES`：拦截类别 → 错误码。代开处方药和倒卖号源共用 `errand_restricted`。
- `tests/test_errand_registry.py` 逐一核对：
  - `restricted_errand` 能返回的每一类（从源码里取 `return "…"`）都在 `KIND_CODES` 里，反之亦然；
  - 每一类 `_raise_for` 抛出的错误码就是登记的那个；
  - 每一类都有复核类别名；
  - 每个错误码都有 i18n 文案、都在 SDK 的可复核清单里；
  - SDK 清单里没有多出拦截不会抛的错误码。
- skill `spec-batch` 第 5 步登记清单写明这四处。
