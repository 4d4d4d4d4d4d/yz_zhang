# 418 App 补齐登录设备、通知已读与未读数、券

> 状态：本批实现（V445）。编号 APP-074c（APP-074「网页有而 App 没有的 SDK 方法」的又一批）。
> 来源：台账 APP-074。V444 之后清点：网页调用、App 没调用的 SDK 方法还有 203 个。大部分是后台运营用的，本来就只在网页。按「卡不卡住钱、卡不卡住账号安全、卡不卡住催办」挑出三件：
> - **登录设备**（`mySessions` / `revokeSession`）：手机丢了、借给别人登过，网页上能把那台设备踢下线；而执行方多半只有手机，App 上看不到也踢不掉；
> - **通知已读与未读数**（`markRead` / `markAllRead` / `unreadCount`）：App 的通知列表不分已读未读，顶栏「通知」也没有数字。V100 的催办、临期、预警全靠用户看见，看不出哪些是新的就等于没提醒；
> - **券**（`availableCoupons` / `claimCoupon` / `myCoupons`）：托管资金时能用券，App 用户却不知道自己有券，也领不了。
>
> 只增不减：服务端与 SDK 方法都不改，只在 App 上加入口。通知页原来的列表换成能标已读的列表，原有内容（标题、正文）照旧显示。

## 0. 要解决的问题

把这三件在 App 上做出来，规则仍在服务端：
- 下线就是服务端吊销那个会话；
- 已读按「从通知中心点开」记（NTF-073 的打开率分母）；
- 券的写法与网页一致，挪进 SDK 共用。

## 1. 业界怎么做（带来源链接）

- 账号安全页列出登录设备、可以逐个下线，是常见做法。
- 通知入口带未读数、超过 99 写 99+，是移动端的惯例。
- 本轮没有引用外部报道链接。

## 2. 数据

不涉及。

## 3. 接口

不改接口。SDK 新增 `packages/core/src/coupons.ts`：
- `couponValueText()`：「减 ¥20.00」或「8.5% 折，最高减 ¥30.00」；
- `couponTermsText()`：满多少可用、限哪个类目、仅新用户；
- `COUPON_STATUS_LABEL`；
- `unreadBadge()`：0 不显示，超过 99 写 99+，畸形当 0。

## 4. 两端

- **App**（新文件 `app/accountExtras.tsx`）：
  - `DeviceSessionsBlock`：放在「我的」里改密码下面，列出在登设备，点「下线」。
  - `CouponsBlock`：放在钱包里发票下面，可领的券点「领取」，下面是我的券和状态。领不了时原样说出服务端的理由。
  - `NoticesList`：通知页里未读的打「●」；点一条记成已读，`via=center`；点已读的不再发请求；可以「全部标为已读」。
  - 顶栏「通知」带未读数，关掉通知页、标完已读都会重新数。
- **Web**：早就有，不改。

## 5. 隐私、授权与边界

- 下线、领券、已读都只作用于自己的账号，服务端已有授权。
- 设备名最多显示 60 个字。
