
# 264 测试与迁移的未用导入清零并纳入静态检查

> 状态：本批实现（V291）。编号 LINT-006。
> 来源：262 号 spec「没做的」——「tests/ 与 migrations/ 里还有 107 处未用导入；检查范围扩到 tests/」；BACKLOG V291。
> 只增不减：只删了没人用的导入，一条测试都没删（收集到的测试数前后都是 2283）；ruff 检查范围只扩不缩。

## 0. 要解决的问题

V289 只清了 app/ 与 scripts/。tests/ 里还有 107 处未用导入，而且整个 tests/ 不在静态检查范围内：测试里写错一个名字（F821），那条断言可能根本没跑到，没人知道。

## 1. 业界怎么做

lint 一般覆盖测试代码；只对测试放宽风格类规则，不放宽「一定是错」的规则。（本批没有另找外部来源。）

## 2. 做了什么

- 删掉 tests/ 的 107 处未用导入（migrations/ 本来就是 0）。逐个查过：
  - 被删的名字没有一个是 pytest fixture（按名字注入的 fixture 在导入处看起来是「未用」，删了会出错）；
  - 没有 `test_` 开头的名字（导入别的文件的测试函数会让它多跑一次，删了会改变测试数）；
  - `from app.modules.x import y` 这类子模块导入没有副作用依赖（应用启动时已经导入）。
- 前后都跑了 `pytest --collect-only`，都是 2283 条；60 个被改的测试文件全部重跑通过（623 条）。
- `test_metrics_truthful.py` 的 ruff 检查范围加上 `tests` 与 `migrations`，规则与 app/ 一样（一定是错的几条加 F401）。
