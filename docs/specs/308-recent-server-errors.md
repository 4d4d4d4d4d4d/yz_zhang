
# 308 闭环脚本断言失败时打出服务端最近的错误

> 状态：本批实现（V335）。编号 DRILL-034。
> 来源：86 号 spec「没做的」与 72 号台账——「闭环脚本断言失败时不打印服务端最近的错误：V112 的 500 只能靠人去翻 uvicorn 日志才看得出病因」；BACKLOG V335。
> 只增不减：冒烟与真浏览器联调的步骤、判据、通过时的输出都不变；只在失败时多打几行。服务端多一个受令牌保护的 `/errorz`，日志照旧。

## 0. 要解决的问题

V112 那次，冒烟报的是 `None == 18400`——「钱包余额是空」，而真正的原因（首次读钱包并发建两行撞唯一约束）在 uvicorn 日志里。部署冒烟（`scripts.smoke`）对的是已经启动的实例，跑脚本的人手边往往没有那份日志；真浏览器联调（`scripts.e2e_web`）自己起的服务端把输出丢进了 `/dev/null`。

## 1. 业界怎么做

健康检查之外暴露一个只读的「最近错误」诊断端点（受内部令牌保护、内容脱敏、进程内环形缓冲），让探针与冒烟在失败时直接带出病因，是常见的运维做法。（本批没有另找外部来源。）

## 2. 规则

- 中间件接住未处理异常时（原来就在这里记带堆栈的日志），另在进程内留一条：时间、request_id、方法、路由、异常类型、**过脱敏**的一句话（最多 300 字）、出错位置（最深的一帧本仓代码，相对 `server/` 的路径与行号）。最多留 20 条，新的挤掉旧的；不存请求体、不存堆栈全文。
- `GET /errorz?limit=5`（1~20）：新的在前；与 `/metrics`、`/jobz` 同一把任务令牌（`X-Job-Token`），不对公网。进程重启即清空——这是排障的快捷方式，不是日志的替代。
- 冒烟某一步失败时，先打出这一步，再打「服务端最近的错误」（3 条）；取不到时说清楚是「连不上」还是「/errorz 返回 404（老版本）」，服务端没有异常时说「多半是业务校验没过，看上面的响应」。
- 真浏览器联调在关掉自己起的服务端**之前**取一次（进程一退就没了），有未通过项时打印。

## 3. 数据 / 接口

不新增表。新端点 `GET /errorz`（任务令牌）。

## 4. 两端

不涉及（运维与脚本）。

## 5. 隐私、授权与边界

内容与日志走同一道脱敏（手机号、证件号、卡号、token、`password=`、SQL 绑定参数）；只给持任务令牌的调用方。
