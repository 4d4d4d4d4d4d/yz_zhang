
# 320 子任务流拍时提醒与一键再推

> 状态：本批实现（V347）。编号 AI-DEC-023（安全的一半；自动重新招募记为 AI-DEC-023b）。
> 来源：现状台账 AI-DEC-023「子任务流拍 / 违约时自动重新招募」；BACKLOG V347（第三十一轮排期，分数 36）。
> 只增不减：按天补招（196 号）、已发布任务加价的规则、驾驶舱的「招募超过 3 天」提示都不变；只多一个每天的提醒 job 和一个「再推一次」接口。

## 0. 要解决的问题

单子发出去几天一个报名都没有，就一直停在那里。母任务下的子任务尤其麻烦，一个子任务没人接，整单都卡住。驾驶舱虽然会标「招募超过 3 天」，但发单的人不打开就看不到；按天补招（196 号）也只覆盖一单多天的名额。

全自动重新招募（自动加价、从预算池调剂）要动钱，需要发单人事先授权，这一批不做。这一批只做两件不碰钱的事：**提醒**和**一键再推**。加价由发单人自己填，钱照旧在签约托管时才冻结。

## 1. 业界怎么做

众包与本地服务平台在任务长时间无人接单时，普遍会提醒发布方「提高报酬或修改描述」，并提供「重新推送 / 置顶」入口；自动调价一般只在发布方事先选了「自动加价」时才做。本批没有另找外部来源。

## 2. 规则

- **提醒**（每天一次的 job）：
  - 条件：发布超过 3 天（`STALE_RECRUIT_DAYS`，与驾驶舱同一个数）、还在招、没人接、一条报名都没有。满足就通知发单人「「标题」招募 N 天还没人报名」，正文给出去处：「再推一次」、改说明、主动邀约。
  - 频率：同一单每 3 天最多提醒一次。
  - 带子任务的母任务（项目、一单多人或多天）自己不提醒，因为报名都在子任务、名额上。
  - 一单多人或多天的名额按单合成一条：「「标题」有 N 个名额招募 N 天还没人报名」，去处是「补招」，不逐个名额刷屏。
  - 项目下的子任务照常逐条提醒。
- **再推一次**（任务页按钮）：
  - 只有发单人能点；任务要还在招、没人接（否则 409 `not_recruiting`）。
  - 6 小时内只能推一次（409 `reboost_too_soon`，并说明什么时候可以再推）。
  - 可选加价：只许上调，并通知已报名的人。
  - 推送走「任务发布」事件，与发布时同一条推送；每次推送都在进度里留痕。
  - 带子任务的母任务拒绝（400 `use_day_reboost`）：一单多天、多人的到名额上补招，项目的到子任务上推。
- 两端的按钮只在「还在招、没人接、一个报名都没有、不是带子任务的母任务」时出现，判断由共享 SDK 的 `canReboostTask` 负责。

## 3. 数据 / 接口

- `tasks.stale_reminded_at`（可空）；迁移 c1d220260081，SQLite 与 Postgres 都验过。
- `POST /tasks/{id}/reboost`：请求体 `{raise_cents}`，返回 `{task_id, raise_cents, budget_cents}`；已登记进对象级授权表（party）。
- `POST /tasks/jobs/remind-stale-recruits`：需要任务令牌、单实例锁，已登记进调度表（每天一次）。job 总数 39 → 40。
- 共享 SDK：
  - 类型 `TaskReboostResult`；
  - 方法 `reboostTask(taskId, raiseCents)`；
  - `taskReboostLine`、`canReboostTask`；
  - 新错误码 `use_day_reboost` 已进 i18n。

## 4. 两端

- **Web 任务详情「报名列表」**：「暂无报名」下面多一块「再推一次」，含加价输入框（元，可不填）和按钮。加价写错会说清楚怎么写，不发请求；推完显示加了多少、现在预算多少、6 小时后可以再推。
- **App 任务详情「报名列表」**：同样的一块（`app/taskReboost.tsx`），文案与 Web 相同。

## 5. 隐私、授权与边界

- 只有发单人能再推。
- 提醒只发给发单人。
- 不动钱：加价只改预算，钱在签约托管时才冻结。
- 不替发单人做决定：不自动加价，也不自动重发。

**做的过程中发现并改了一处设计**：起初只拦「一单多天的母任务」，而一单多人、单天的母任务会出现「再推一次」，加价却只加在母任务上，名额拿不到。现在统一按「带子任务的母任务」拦截。删掉了重复的那条判断，否则对它的变异会存活。
