# 414 发布后改加选资质

> 状态：本批实现（V441）。编号 SCN-294c。
> 来源：407 号（V434）与 408 号（V435）「没做的」。413 号（V440）已经告诉发单人「几个人只差你加选的那一张」，可他改不了：
> - 加选资质只能在发单时选；
> - 发出去才发现这张证用不上、把人全挡了，只能撤单重发，报名和浏览记录都丢了。
>
> 只增不减：沿用任务编辑接口 `PATCH /tasks/{id}`，多收一个可选的 `task_certs`。不传这个字段的编辑与以前完全一样。

## 0. 要解决的问题

- **去掉加选资质**（放宽）：只会让更多人能接，随时可以。
- **加上加选资质**（加严）：已报名、还在等结果的人里，有人没有这张证，就不能悄悄加上。否则等于替发单人把这些人挡掉，他们还以为自己在候选里。

## 1. 业界怎么做（带来源链接）

本平台的任务编辑早有「防调包」规则（TASK-014）：
- 有人报名后，预算只能上调；
- 技能要求锁定。

道理一样：对已报名的人不利的改动，要么不许改，要么先处理好他们。资质这一项按同样的思路，只拦对已报名的人不利的那一半。本轮没有引用外部报道链接。

## 2. 数据

不改表：沿用 `tasks.task_certs`（407 号）。

## 3. 接口

`PATCH /tasks/{id}` 多收 `task_certs: string[]`（最多 5 张）。

- 与发单时同一套清洗：去空、去重，只认类目列出来可加的（否则 400 `task_cert_not_offered`）。发单与改共用 `_clean_task_certs`。
- **加上**：查还在等结果的报名，有人缺新加的证，就返回 409 `task_certs_locked`，例如：「已有 1 个报名的人没有「低压电工作业操作证」，加上他们就接不了这一单；先谢绝这些报名，或等他们补交证件，再加」。他们补交、审核通过以后再加就行。
- **去掉**：随时可以，有人报名也可以。
- **多人、多天的单**：还在招（草稿或已发布）的名额跟着母任务一起改；已经选了人的名额不动。
- 只有发单人能改（403）；已进入执行阶段的不能改（沿用 `not_editable`）。

## 4. 两端

- **SDK**：
  - `editTask` 的入参类型多 `task_certs`；
  - `relaxableCerts(gap)`：可以一键去掉的加选资质，即只差人数大于 0、而且确实是这一单加选的；
  - `dropCertPatch(task, cert)`：去掉一张，其余照留；
  - 新错误码 `task_certs_locked` 进 i18n。
- **Web**：任务详情「AI 推荐人选」卡片里，「只差这一张」那句下面给按钮「这一单不要「…」了」，点了改完重新加载。
- **App**：`RecommendationsBlock` 同样给按钮。改完用返回的任务重新算人数和推荐；改不了时说清楚为什么。

## 5. 隐私、授权与边界

- 拦下加严时只说人数，不说是谁（发单人在报名列表里本来就看得到报名的人）。
- 只认审核通过、未过期的证件（与报名准入同一个判断 `holders_of`）。
- 只有发单人能改，沿用任务编辑的授权。
