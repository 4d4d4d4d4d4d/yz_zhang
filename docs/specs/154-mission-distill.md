# 154 从编排复盘一步蒸馏成「我的方法」

> 状态：本批实现（V164）。编号 AGT-093。
> 来源：134 号「没做的」AGT-093「现在要先存笔记、再到知识库里选笔记蒸馏」；BACKLOG V164。
> 只增不减：「存进我的知识库」（AGT-092）行为与响应不变（内部抽成共用函数）；知识库里从笔记蒸馏（KB-106）不变。

## 0. 要解决的问题

- 一次编排做成了，最值得留下的是「这件事怎么做成的」。此前要三步：存复盘笔记 → 去知识库选这条笔记 → 蒸馏（按编号 / 圆点从文字里猜步骤）。
- 而编排的步骤本来就是结构化的（标题、验收标准、状态），不必先变成文字再猜回来；从文字猜还会把失败的步骤一起收进去。

## 1. 业界怎么做

- 项目复盘（retrospective）之后把「这次怎么做成的」沉淀为可复用的模板或清单，是 Notion、Asana 等工具的常见做法（项目转模板：<https://asana.com/guide/help/projects/templates>）。
- 只沉淀做成了的部分：失败的步骤属于「教训」，留在复盘里，不进可复用的方法。

## 2. 数据

不加表：复盘笔记沿用 `nb_notes`（标签「编排复盘」）；方法沿用 `nb_methods`，由用户确认后才写。

## 3. 规则与接口

| 编号 | 内容 |
|---|---|
| AGT-093-1 | `POST /missions/{id}/summary/distill`（只有发起人；管理员也不行）：先把复盘存进知识库（与「存进我的知识库」同一条，再蒸馏不会多出一条），作为方法的出处 |
| AGT-093-2 | 把**做成了的步骤**按顺序收成方法草稿：步骤名作标题、验收标准作说明；失败的、进行中的、被替换的不收，返回没收进来的步数 |
| AGT-093-3 | 只出草稿、不写方法；还没有做成的步骤时 `found=none`、步骤为空 |
| AGT-093-4 | 用户确认后走已有的 `POST /notebook/methods`（`createMethod`），出处是那条复盘笔记 |

## 4. 两端

- **Web「AI 编排」复盘卡片**：「蒸馏成我的方法」→ 显示方法名、步骤、几步没做成没收进来 →「保存为我的方法」；没有做成的步骤时如实说、不给保存按钮。
- **App「AI 编排」复盘**：同样的按钮、草稿与保存。

## 5. 隐私与边界

- 只读发起人自己的编排，写进发起人自己的知识库；管理员能看复盘（运营排查），但不能替任何人蒸馏或保存。
- 草稿不经确认不落成方法。
- 端侧隐私沙箱开着时这个接口和建编排一样被拦（列进 `CLOUD_AI_ROUTES` 与 SDK 的 `CLOUD_AI_ENDPOINTS`）：蒸馏本身不调模型，但沙箱里本来就建不了编排（回归里沙箱闸门发现漏登记后补上）。
