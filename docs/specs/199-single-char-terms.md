# 199 检索里的单字降权

> 状态：本批实现（V226）。编号 SCN-109。
> 来源：138 号 spec「没做的」——「切完虚词后剩下的单个汉字（如『样』）仍按整词计 3 分，可能误命中……系统做法是单字词降权，要先评估对个人知识库短查询的影响」；191 号第 3 节排序；BACKLOG V226。
> 只增不减：虚词表、二字切片与覆盖率规则（COVERAGE）、相关笔记门槛（MIN_RELATED）都不变；只改单字的权重。
> 写明的行为变化：查询里有多字词时，单个汉字的权重从 3 降为 1；整个查询只有单字时不变。

## 0. 要解决的问题

个人知识库与服务包知识检索共用 `notebook.service.terms()`：先去掉虚词，再按空白与虚词切成若干段，每段整串权重 3。去掉虚词后常剩下单个汉字（「报税 和 社保 的 事」→「报税」「和」「社保」「事」），而「和」「事」几乎哪条笔记里都有——一条讲「和事佬」的闲聊能排到报税指南前面，助手也可能引一条不沾边的笔记。

## 1. 业界怎么做

常见的做法是给短词、高频字更低的权重（逆文档频率的直觉：越常见越不能说明相关），或者干脆当作停用词。真正的中文分词（jieba 一类）要引入依赖并重测各模块检索，138 号已记为暂不做。本批取最小的一步：有多字词可依靠时，单字降权；没有时不动（不让「搜『税』搜不到」）。

## 3. 规则

`terms(q)`：若切出的词里有长度 ≥ 2 的，长度为 1 的词权重改为 1；否则不变。（非汉字的单字符在前面就已丢弃，不受影响。）

## 4. 两端

不涉及界面：个人知识库搜索、「相关笔记」、助手引用、服务包知识问答的排序都走这一个函数。

变异：去掉降权 → 红；「有任意词」就降权（单字查询也降）→ 红；去掉「是汉字」的判断 → 存活，属等价变异（非汉字单字符在前面已被丢弃），已把这个多余条件删掉。
