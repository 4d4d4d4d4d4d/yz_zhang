
# 336 被发单拦截挡下时申请人工复核

> 状态：本批实现（V363）。编号 SCN-219。
> 来源：335 号 spec「没做的」：「被发单拦截挡下时申请人工复核（误拦的出路）」；BACKLOG V363（第三十七轮排期，分数 36）。
> 只增不减：六类拦截的词表、否定判断、错误码一字不变。提示句末尾多一句复核的出路，错误体多一个 `review` 字段。`assert_no_restricted_errand(text)` 不给 db 与用户的老调用照旧，命中就拦。

## 0. 要解决的问题

发单拦截（V321 起，现在六类：代开处方药、倒卖号源门票、无证陪练学车、代写学位论文代考、刷单虚假评价、刷粉刷量买卖账号）只看文字、不调模型，难免误拦：

- 「帮我写论文集的新书推介文案」里「写」和「论文」挨着，会被当成代写论文；
- 「号源」也可能只是自己排队。

被误拦的人只有两条路：会改写的绕过去（拦截形同虚设），不会改写的直接走掉（平台丢单）。缺的是一条正路：说清楚，让人来看。

## 1. 业界怎么做

内容平台对自动审核的处置普遍提供申诉、人工复核入口。欧盟《数字服务法》第 20 条要求平台为用户提供免费的内部投诉处理机制，处理不能只靠自动化手段。本批没有另找外部来源，做法与本平台已有的提额申请（V268）一致：用户写理由，运营批或驳回，驳回写理由，全程审计。

## 2. 规则

- **能申请的**：只有这六类「只看文字、会误拦」的拦截。金融红线、中小学学科类家教是业务红线，不给复核。
- **申请**：要写一句说明（至少 6 个字）。服务端重新判断这段文字：
  - 现在没被拦的：400 `errand_review_not_blocked`；
  - 同一段文字在等的：409 `errand_review_pending`；
  - 通过了还没用的：409 `errand_review_approved`（直接发就行）；
  - 最近一次被维持的：409 `errand_review_rejected`（附理由，改写后再发）；
  - 同时在等的最多 5 条：409 `errand_review_too_many`。
  - 申请成功通知运营。
- **只认同一段文字**：标题加说明的指纹（sha256），同一个人、一字不差才认。改一个字就是另一段文字；别人发同一段文字照拦。
- **运营处理**：
  - 通过：说明可不写，放行这段文字发一单；
  - 维持：理由至少 4 个字，对方会看到；
  - 运营不能处理自己提出的（403 `errand_review_self`）；
  - 处理过的不能再处理（409 `errand_review_decided`）；
  - 两种结果都通知本人、进审计。
- **放行一单**：
  - 发单表单那一道只看有没有还没用掉的通过；
  - 真正发布（`validate_publishable`）所有校验都过了，才把复核记在这一单上（写库放在调审核供应商之后，守住 CONC-067）。
  - 同一段文字再发第二单照拦；用掉了的可以再申请。

## 3. 数据 / 接口

- 新表 `errand_reviews`，迁移 c1d220260087，SQLite 与 Postgres 都验过。
- 用户接口：
  - `POST /tasks/errand-reviews`：请求体 `{title, description, explanation}`
  - `GET /tasks/errand-reviews`：我申请过的，最近 50 条
- 运营接口（只给运营角色，已登记进角色表与后台入口表）：
  - `GET /admin/errand-reviews?status=`：等得最久的在前
  - `POST /admin/errand-reviews/{id}/approve`：请求体 `{note}`
  - `POST /admin/errand-reviews/{id}/reject`：请求体 `{note}`
- 本人数据导出带上复核申请（有才带）。
- 共享 SDK：
  - 类型：`ErrandReviewItem`、`ErrandReviewAdminItem`
  - 方法：`requestErrandReview` / `myErrandReviews` / `errandReviews` / `approveErrandReview` / `rejectErrandReview`
  - `errandReview.ts`：`canRequestErrandReview`、`errandReviewLine`
  - 九个新错误码进 i18n。

## 4. 两端

- **Web 发布页**：被这六类拦下时，错误下面出现「觉得拦错了？申请人工复核」。
  - 原样带上被拦的标题与说明，写够一句话才能交；
  - 改了标题或说明，入口消失（那是另一段文字）。
- **Web 后台「城市与类目」**：资质别名下面多「发单复核」。
  - 列出原文、说明、发单人、等了多久；
  - 通过、维持（写够理由才能点）；
  - 自己提出的不给按钮。
- **App 发布页**：同样的申请入口；发布页下面列出「我的发单复核」（最近 5 条，通过的提示原样再发，维持的写出理由）。

## 5. 隐私、授权与边界

- 复核只放行一段文字发一单，不改词表；运营看到的是本人提交的原文与说明。
- 运营不能自己放行自己的单；全程审计。
- 申请只能本人看；运营接口只给运营角色。
