
# 126 任务画像与能力画像：说明完整度与补全建议、价格位置、风险、推断技能；被证明过的能力

> 状态：本批实现（V151）。编号 PROF-100~110。
> 来源：用户 2026-10-13：「对于平台来说需要任务画像。」VISION V-14；BACKLOG V151。
> 只增不减：不新增表；撮合原有的技能匹配、类目、可用性加分都不变，只在**发布方没写技能要求**时多一项小加分；
> 发布页、任务详情、个人空间、个人资料都只是**多一块**。

## 0. 要解决的问题

一单活说不清（没有验收标准、没有截止、预算离谱），接单的人不敢报、报了也扯皮；
推荐只能看发布方手填的技能，而很多人根本不填；一个人「会什么」只有自述，看不出哪些是做成过的。

## 1. 业界怎么做

- **发布前的完整度提示**：主流的自由职业与众包平台在发布流程里逐项提示「补上预算、截止、交付物能显著提高回复率」，
  并按同类成交给出预算区间。这里同样做：每一项缺失都写清**缺了会出什么问题**，价格用平台自己的成交分布（KB-021）。
- **画像 ≠ 自述**：口碑平台把「平台上做成过、被评价过」与「自己写的」分开展示（Upwork 的 Job Success 只算平台内合同、样本不足不显示）。
  这里同样：技能分「有成交佐证 / 自述」，准时率、返工率**样本少于 3 单不给**；资质只认平台核验通过且未过期的（CERT-005）。

## 2. 任务画像（`task_profile`，草稿与已发布的单都能算）

| 字段 | 说明 |
|---|---|
| `mode` | 线上 / 线下 |
| `declared_skills` / `inferred_skills` | 写明的技能；从标题与说明里认出的技能（平台技能词表：用户自述 + 任务写明，取最常见 500 个；长词优先，被包含的短词不重复） |
| `size` | 预算相对同类中位：small（<0.5 倍）/ medium / large（>2 倍）/ unknown |
| `price` | 同类近 180 天成交分布（城市优先，没有退全平台）与预算位置：低于最低 / 低于中位（<0.9）/ 相当 / 高于中位（>1.1） |
| `risks` | 类目要求资质；上门（线上的活不提示）；涉及未成年人；需要垫付；金额 ≥5000 元建议分期 |
| `checks` / `completeness` | 标题 ≥6 字、说明 ≥30 字、验收标准（字段或说明里写了）、截止时间、线下给城市与位置、预算、技能（写明或认出）；预算低于最低或中位时多一项；每项不通过都给一句**怎么补** |

## 3. 能力画像（`capability`）

做成过的类目（单数、平均星级）；技能逐项标「有成交佐证 / 自述」；已核验资质；准时交付率、返工率（样本 ≥3 单才给）；
回复邀约中位时长（V143 同一口径，样本 ≥5）；是否设了每周时段、是否少量接单；纠纷次数**只给本人**。

## 4. 接口

| 编号 | 接口 | 说明 |
|---|---|---|
| PROF-101 | `POST /profiles/task-draft` | 发布页实时调用，不落库 |
| PROF-102 | `GET /tasks/{id}/profile` | 公开招募中的谁都能看；草稿与非公开的只有双方 |
| PROF-104 | 撮合 | 发布方没写技能要求时，说明里认出的技能与候选人技能对上 → +0.05，理由「说明里提到了你的技能「X」」 |
| PROF-105 | `GET /users/me/capability` | 本人（含纠纷次数） |
| PROF-106 | `GET /users/{id}/capability` | 对外：资料不公开、封禁、注销的 404；不给纠纷次数 |

## 5. 两端

- **Web**：发布页「说明完整度」边写边提示（停下半秒再算）；任务详情「这单的画像」；个人空间（登录后可见）与个人资料页「能力画像」。
- **App**：发布页同样的提示；「我的 → 我的能力画像」。
- 画像是附加信息：取不到（或老服务端没有这个接口）就不显示，不挡发布、不带崩页面。

## 6. 闸门与红验

| 闸门 | 红验 |
|---|---|
| 缺什么逐项提示 | 去掉验收标准检查 → `test_draft_profile_flags…` 红 |
| 价格位置 | 改阈值 → 同上红 |
| 线上不提示上门 | 去掉 `remote` 判断 → `test_risk_flags` 红 |
| 推断技能长词优先、不重复 | 去掉包含判断 → `test_infer_skills_unit` 红 |
| 撮合加分 | 去掉 → `test_matching_gets_a_small_bonus…` 红 |
| 自述与佐证分开 | 全标佐证 → `test_capability_separates…` 红 |
| 小样本不给比率 | 去掉样本门槛 → `test_small_samples_give_no_rates` 红 |
| 对外不给纠纷、隐私与封禁 404 | 去掉 → `test_capability_privacy`、`test_capability_separates…` 红 |
| 草稿画像不外泄 | 去掉可见性判断 → `test_task_profile_visibility` 红 |
| 响应形状 | `test_responses_match_sdk_types`（TaskProfile* / Capability*） |
| 真浏览器 | `e2e_web.py`：发布页填标题后出现完整度与「验收标准」「截止时间」提示 |

## 7. 没做的

- **PROF-110 语义层面的技能识别**（「VI 设计」≈「品牌设计」）：与 V155 语义匹配一起做；现在是词表字面匹配。
- 工期估计：平台还没有可靠的工时数据。
- 画像进入排序权重的更多维度（准时率、返工率参与撮合）：要先看数据分布，避免对新人不公平。
