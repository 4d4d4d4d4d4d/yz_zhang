# 205 带着需求九项的问题报名

> 状态：本批实现（V229）。编号 SCN-135。
> 来源：194 号 spec「没做的」——「接单的人在任务详情上一键把这几句问题发到私信 / 报名留言里」；BACKLOG V229。
> 只增不减：「报名接单」按钮与留言（「我可以做」）不变；本批在画像块里多一个入口，走同一个报名接口。

## 0. 要解决的问题

V221 让接单的人在创作类任务详情上看到「说明里没写的 2 项，报名前可以先问问发单人：改稿次数……版权授权……」。但问题列出来了，要问还得自己抄进私信，或者先报名、再另外找发单人说——多数人直接点「报名接单」，问题就没问。

## 1. 业界怎么做

自由职业平台的投标 / 报名环节普遍带一段「附言」，发单人在报名列表里逐条看；好的附言会先确认需求里没写清的点（交付物、修改次数、授权范围），这也是创作类纠纷最常见的来源。本批让附言直接带上平台已经算出来的那几问。（本批没有另找外部来源。）

## 2. 数据

不加表、不加字段：问题写进报名的 `message`（原有字段），发单人在报名列表里看到。

## 3. 接口

不加接口：走 `POST /tasks/{id}/applications`，`message` 是共享函数生成的一段话。

SDK：共享函数 `briefApplyMessage`（「我可以做。报名前想先确认几件事：」+ 按顺序编号的没写项与该问的话；九项都写到、不是创作类、数据畸形时返回 null，不给入口）。

## 4. 两端

- **Web** 任务详情「这单的画像」里，接单的人在「需求九项」下面多一个「带着这些问题报名」；只在单子在招、自己不是发单人、已登录时出现。
- **App** 画像块里同一个按钮；任务详情只在能报名（`taskActions` 含 `apply`）时把它接上。
- 发单人自己看到的是「还可以补」，没有这个按钮（画像组件自己也守住这条）。

## 5. 隐私、授权与边界

- 报名是接单的人自己点的；留言只到发单人的报名列表（原规则）。
- 问题是平台按说明里没写的项生成的提问，不替任何一方回答，也不改任务内容。
