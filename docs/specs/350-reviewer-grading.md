
# 350 审核员分级：新人全抽、推翻多的重点看

> 状态：本批实现（V377）。编号 CERT-054。
> 来源：348 号 spec「没做的」；BACKLOG V377（分数 18）。
> 只增不减：高风险资质全抽、其他按 10% 抽的规则不变；只是在抽之前多看一眼审核员是谁。抽检列表里每位审核员多一个 `grade` 字段，`reason` 多两个取值。

## 0. 要解决的问题

V375 的抽检对所有审核员一视同仁：新来的审核员和干了几年的一样只抽一成，被推翻过好几次的人也一样。新人和放水多的人，最需要第二双眼。

## 1. 业界怎么做

审核质检通常按审核员分级：新人上岗期全量复核，差错率高的提高抽检比例，稳定的降到常规比例。本批没有另找外部来源。

## 2. 规则

- **新人**（`new`）：之前核准不满 20 份（`NEW_REVIEWER_APPROVALS`），这份核准全抽，`reason` 记为 `new_reviewer`。
  - 核准份数按审计记录里的「通过」来数：撤销会改写申请上的 `decided_by`，审计不会。驳回不算。
- **重点看**（`watch`）：复看过至少 5 份（`WATCH_MIN_CHECKED`），被推翻两成以上（`WATCH_OVERTURN_RATE`）。抽检比例提到五成（`WATCH_SPOT_RATE`），`reason` 记为 `watch`。
- **常规**（`normal`）：按 10% 抽。
- **高风险资质**：照旧全抽，优先于以上分级。
- **列表**：每位审核员写明分级。Web 上新人标「新人」，重点看的标「重点看」。

## 3. 数据 / 接口

- 不新增表与接口。
- `GET /admin/cert-spot-checks` 的 `reviewers[]` 多 `grade` 字段；`reason` 多 `new_reviewer`、`watch` 两个取值。
- 共享 SDK：`CertSpotReviewerStat.grade` 同步。

## 4. 两端

- **Web 后台「资质抽检」**：审核员后面标「新人」「重点看」；抽检原因写「新审核员全抽」「重点看的审核员」。
- **App**：不涉及。

## 5. 隐私、授权与边界

只给合规角色。分级只用于决定抽检比例，不对外展示。
