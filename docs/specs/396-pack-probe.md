
# 396 场景包问法离线试分工具（PACK-091）

> 状态：本批实现（V423）。编号 PACK-091。
> 来源：第四十七到五十三轮场景发掘（V409~V422），每轮都手写一段脚本给问法算分，再把挑好的问法抄进测试。BACKLOG V423。
> 只增不减：新增一个脚本 `server/scripts/pack_probe.py`，skill `scenario-discovery` 的做法多一步。场景包、检索与闸门都不变。

## 0. 要解决的问题

每轮场景包的测试有十八个问法，其中八个要「只靠标签」（PACK-090，377 / 378 号）。问法写不好有四种结局：
- 答不上：检索要求问句的二字切片过半命中，口语里的「要先」「打小」会拖后腿（V412）；
- 去掉标签也答得上：钉不住标签；
- 一句里命中两个标签：删一个另一个照样接住；
- 被助手问答前面的拦截挡下：含「报警」被转介 110（V422），说「帮我报价成交」踩到角色契约。

接口测试要 30 秒才知道结果。近十轮的做法是手写脚本先算分，脚本每轮重写、口径各不相同，还漏算了真实检索里的标签加分。

## 1. 做法

`python -m scripts.pack_probe <包 key> "问题=>知识 key" "!只靠标签的问法=>知识 key" …`

- 知识可以写 key，也可以写标题开头能唯一确定的几个字。
- 没指定助手的，用管这条知识的那个助手（老包一个包有几个助手）。
- 每一项依次查：
  1. 助手问答检索之前的三道拦截：想伤害自己、人身安全与刑事风险词、角色契约禁区——被拦下的拿不到引用；
  2. 用助手问答**真正的检索函数**（`_knowledge_hits`，含概念展开与标签加分）取前三条，目标知识在不在里面；
  3. 带 `!` 的再查：去掉标签算分够不够「相关」（PACK-090）、是不是正好命中一个标签（V404）。
- 每项一行 ✓ / ✗ 和原因；一项不行不影响别的项；有 ✗ 就非零退出。
- skill `scenario-discovery` 的第 4 步写明：写测试里的问法之前先跑它，全 ✓ 再抄进测试。
