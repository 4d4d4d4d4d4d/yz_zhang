
# 283 合约卡片开票入口的显示条件端上测试

> 状态：本批实现（V310）。编号 APP-095。
> 来源：136 号 spec「没做的」——「合约卡片开票入口的显示条件没有端上测试（只在放款后、发布方本人看到；服务端照旧拦）」；BACKLOG V310。
> 只增不减：显示条件不变（放款 `released` 或分账 `split` 之后、发布方本人），只是从任务详情里的内联判断提成一个函数并测住。

## 0. 要解决的问题

App 任务详情的合约卡片上，「开票」只该在放款后给发布方本人看。条件写在界面里、没有测试；改坏了服务端还会拦（`not_party` / `not_settled`），不会开错票，但会多一个按不通的按钮，或者该有的入口消失。

## 1. 规则

`app/invoiceEntry.ts` 的 `canRequestInvoice(contract, meId)`：合约状态是 `released` 或 `split`，且看的人是发布方（`requester_id`）。任务详情的合约卡片改用它。

## 2. 数据 / 接口 / 两端

不涉及接口；App 内部重构 + 测试。

## 3. 闸门与红验

| 闸门 | 红验 |
|---|---|
| `app/invoiceEntry.test.ts`（3 条：放款 / 分账后发布方看得到；执行方、别人、未登录看不到；其余八个状态都看不到） | 3 处变异全部变红（去掉状态条件、去掉分账、去掉本人条件） |

## 4. 没做的

无新增欠账。
