
# 309 经验单元的使用范围：仅自己与项目内

> 状态：本批实现（V336）。编号 KB-093（「项目内」拆成 KB-093b）。
> 来源：72 号台账 KB-093「经验单元的使用范围只开放全平台：仅自己 / 项目内两档直接拒」；BACKLOG V336。
> 只增不减：可用的范围与以前一样只有「全平台」；拒绝的错误码不变（`unit_scope_invalid`），只是两种被拒的范围各自说清为什么、去哪里。

## 0. 要解决的问题

排期时写的是「想先自己用、不公开的经验只能不上传」。动手前先看清了单元是什么：

- 经验单元（109 号）是**运营从子类里蒸馏**出来的：来源是多个任务、双方都同意复用的样本，注册的人是管理员。它没有一个「自己」可言——「仅自己」给谁？给蒸馏的管理员没有意义，给某一位贡献者又等于把多人的经验私有化。
- 用户「只想自己用的经验」本来就有地方放：个人知识库（147 号，笔记、链接、收件箱，只有本人能看、助手只读引用）与「我的方法」（AGT-094，套到新编排作第一轮计划）。

所以这一批的结论是：**「仅自己」不做成单元的一档**，被拒时把人带到已有的私有去处；「项目内」要先定「项目」是协作空间还是母任务，单独记成 KB-093b。

## 1. 业界怎么做

知识平台通常把「个人笔记 / 私有知识」与「组织共享的知识资产」分成两套对象，而不是在共享资产上加「仅自己」的可见性——后者会让「这条经验到底归谁」说不清。（本批没有另找外部来源。）

## 2. 规则

- 注册单元时选「仅自己」：400 `unit_scope_invalid`，「经验单元是从多人的样本里蒸馏出来给大家复用的，没有『仅自己』这一档：只想自己用的经验，请记在个人知识库（笔记）或『我的方法』里，那里本来就只有你能看」。
- 选「项目内」：400 `unit_scope_invalid`，「『项目内』范围还不开放（要先定项目指协作空间还是母任务）：先选『全平台』，或者先不注册这个单元」。
- 端上的兜底文案（i18n）同步改成指向个人知识库与「我的方法」。

## 3. 数据 / 接口

不涉及。

## 4. 两端

注册单元只在运营后台；用户侧的私有经验入口（个人知识库、我的方法）两端已有。

## 5. 隐私、授权与边界

不改变任何授权；私有经验照旧只在个人知识库里、只有本人能看。
