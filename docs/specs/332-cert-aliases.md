
# 332 资质名别名：同一张证的两个叫法互认

> 状态：本批实现（V359）。编号 SCN-212。
> 来源：331 号 spec「没做的」（做第二十一轮时发现）：种子类目「电工维修」要「电工」，V352 的「水电维修」要「低压电工作业操作证」，持一张的人接不了另一个类目；BACKLOG V359（第三十五轮排期，分数 54）。
> 只增不减：两个类目、两个资质名都不改；资质申请的有效期规则不改（「电工」这个旧名照旧不强制填有效期，新申请建议用正式名称）。只是准入、重复申请判断认别名，提示多半句。

## 0. 要解决的问题

同一张特种作业操作证（低压电工作业），平台里有两个名字：一个是最早种子类目用的「电工」，一个是 V352 按证上正式名称加的「低压电工作业操作证」。结果是：

- 持「电工」的师傅接不了「水电维修」的单，反过来也一样；
- 同一张证能换个名字再申请一遍，审核员审两次；
- 发单人招不到本来合格的人。

## 1. 业界怎么做

资质与证照系统常维护一张「同义名 / 别名」表，把同一证件的不同叫法归到一个规范名下。本批没有另找外部来源。

## 2. 规则

- **别名表**：`cert_service.CERT_ALIAS_GROUPS`，目前一组：{「电工」,「低压电工作业操作证」}。
- **准入**：类目要其中一个名字，持组里任一个已核准且未过期的资质都算满足。
- **重复申请**：已经持有组里任一个，再申请另一个，提示「已持有该资质」（`certification_exists`）；已有在审的，提示「已有待审申请」（`application_pending`）。
- **提示**：拦下时，有别名的类目写明「该类目需『电工』职业资质（持『低压电工作业操作证』也可以），……」；没有别名的类目一字不变。

## 3. 数据 / 接口

不新增表与接口。新增 `cert_service.cert_aliases(name)`。

## 4. 两端

不涉及界面改动。两端原样显示服务端的提示。

## 5. 隐私、授权与边界

只放宽「同一张证换个名字」的情形，不放宽任何准入。新增别名要写进别名表并配测试，不在后台随手加：把两个不同的证误认成一张，就是放松准入。
