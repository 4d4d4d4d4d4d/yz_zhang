
# 381 App 上的核验台（VER-053）

> 状态：本批实现（V408）。编号 VER-053。
> 来源：374 号「没做的」：被点名的核验人在 App 上只收到通知，处理不了。BACKLOG V408。
> 只增不减：App 多一个子页（「我的」里的「核验台」）。不改接口，网页核验台不变。

## 0. 要解决的问题

V399 起，发单人可以点名一位信得过的人来核验 AI 的产出；V401 起，被点名的人可以当场拒绝。通知会把人叫来，可 App 上没有核验台，他只能换到电脑上打开网页。点了通知却无路可走，比不通知更糟（APP-066 的同一条教训）。

## 1. 业界怎么做

审批、评审类产品的移动端通常都能看单、接单、给结论，长内容可以滚动查看。这是常见的公开产品做法，本轮没有引用外部链接。

## 2. 数据 / 接口

不新增。用的都是网页核验台已有的 SDK 方法：
- `openVerificationOrders`
- `claimVerificationOrder`
- `verificationOrder`
- `submitVerificationOutcome`
- `declineVerificationOrder`
- `me`

## 4. 两端

**App「我的」→「核验台（核验 AI 产出 / 被点名的单）」**：

- **列表**：
  - 每一单写标题、类目、报酬，以及来路（`verifyTriggerLabel`：自动升级平台付费 / 发布方主动 / 发布方点名，发布方付费）；
  - 不能接的写出服务端给的原因，「接下」点不动（CLI-064）。
- **被点名、还没接的单**：多一个「不方便，拒绝」，提示「已拒绝，核验费已退回给发布方」。点名别人的、平台派的都没有这个按钮。
- **接下以后看详情**：
  - 任务说明、验收标准（标出平台自动判的）、AI 产出（可选中复制）；
  - 助理自报的置信度，写明「自报值，仅供参考」（AGT-013）；
  - 平台判据逐条结果。
- **给结论**：
  - 通过 / 已修正 / 不通过；
  - 不通过或已修正时理由写得太空，当场提醒（KB-063b，不拦提交）；
  - 已修正要写修正稿，并说明会重新过平台判据（VER-030）；
  - 提交后提示「结论已提交」。
- 网页核验台不变。

## 5. 隐私、授权与边界

授权全在服务端，不变：
- 只能看到能看的单：点名别人的单不出现；
- 详情只给发单人与接单的核验人。

App 不另做判断。
