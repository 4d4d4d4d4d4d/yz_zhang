
# 136 App 补齐：开票、证据包导出、团队成员管理

> 状态：本批实现（V156）。编号 APP-090~094；一并做完 APP-076（开票只有 Web）、TEAM-065（团队成员增删改两端都没有界面）、APP-074 里的 `requestInvoice` / `myInvoices` / `exportEvidence`。
> 来源：BACKLOG V156「App 补齐：发票、证据包导出、团队成员管理（TEAM-065）」；台账 APP-074 / APP-076 / TEAM-065；VISION V-3「团队成员增删仍仅 web」、V-4「证据包导出仍仅 web」。
> 只增不减：服务端只给 `GET /teams/{id}` 的成员多带一个 `nickname`；开票、证据包、成员管理的接口、关口与错误码一行不改。

## 0. 要解决的问题

- 执行方和小团队多半只有手机，而这三件事在手机上做不完：
  - 放款后要一张平台服务费发票，只能去电脑上开；
  - 纠纷里要把证据包交给律师或仲裁机构，App 上导不出来；
  - 建了团队之后只能靠接口加人——**两端都没有成员管理界面**（TEAM-065），Web 也没有。
- 团队详情的成员只有用户编号，列表上看不出是谁。

## 1. 业界怎么做（带来源链接）

- **移动端分享导出**：iOS / Android 的系统分享面板（React Native `Share`，<https://reactnative.dev/docs/share>）把一份内容交给用户自己选的去处（邮件、网盘、聊天），App 不需要自己做上传或存储。证据包照此原样交出，不做二次加工。
- **团队成员与额度**：Slack、飞书、钉钉的企业版都是「所有者 / 管理员 / 成员」三级，只有所有者改角色与额度；移出前二次确认。本平台 53 号 spec 的规则（管理员能批支出但不能给自己提额度）不变，界面只把它摆出来。
- **发票入口在单据上**：电商与 SaaS 平台的发票入口都挂在订单或账单上（例如订单详情里的「申请开票」），不在个人中心让人自己填单号。所以合约卡片里放一个已填好合约号的入口（APP-076 的要求），钱包里保留按合约号申请与全部发票列表（与 Web 一致）。

## 2. 数据

无新表、无迁移。`GET /teams/{id}` 的 `members[]` 多一个 `nickname`（从用户表一次查出，不是逐个查）。

## 3. 接口与规则

| 编号 | 内容 |
|---|---|
| APP-090 | App 钱包页「平台服务费发票」：按合约号申请、列出我申请过的；文案照服务端口径（只开平台佣金那部分，劳务报酬平台不能开） |
| APP-091 | App 合约卡片：合约放款（`released` / `split`）后，发布方看到这一单的开票入口——合约号已填好、只列这一单的发票（APP-076） |
| APP-092 | App 纠纷块「导出证据包」：取 `exportEvidence` 整包，原样交给系统分享面板（含服务端写的证明力边界说明），不删字段、不改内容 |
| APP-093 / TEAM-065 | 团队成员管理两端：成员列表显示昵称、角色、月度额度；所有者能加人（用户编号 + 月度额度）、设为管理员 / 成员、改额度、移出（先确认）；不是所有者只能看，并写明「只有团队所有者能管理成员。」 |
| APP-094 | `GET /teams/{id}` 成员带 `nickname`（共享 SDK `TeamDetail.members[].nickname`） |

关口全在服务端，界面只是摆出来：开票的「仅发布方」「放款后」「无服务费不开」，成员管理的 `insufficient_role`、`owner_immutable`，都照旧由服务端判，界面把错误原样说清。

## 4. 两端

- **Web 团队页**：团队详情里加「成员」一块（`TeamMembers`）：昵称链接到个人空间、角色、月度额度；所有者的加人、改角色、改额度、移出（确认框）。
- **App**：钱包页 `InvoicesBlock`；合约卡片 `InvoicesBlock contractId`；纠纷块 `EvidenceExportButton`；团队详情 `TeamMembersBlock`（与 Web 同样的规则与文案）。

## 5. 隐私、授权与边界

- 成员昵称只给团队成员看（`GET /teams/{id}` 本来就要求是成员，对象级授权不变）。
- 证据包只交给系统分享面板，App 不落盘、不上传到别处；去哪儿由用户自己选。
- 开票与成员管理都不涉及新的钱的动作：发票是申请，由运营开具；成员额度只是上限。

## 7. 没做的

- **APP-095 合约卡片开票入口的显示条件没有端上测试**：只在放款后、发布方本人看到；服务端照旧拦（`not_party` / `not_settled`），所以显示错了也开不出票，只是多一个按钮。
- **APP-096 证据包存成文件**：现在交给系统分享面板（文本）；存成 PDF 或 ZIP 要先定格式与签名口径（与司法存证的「外」一起）。
- 团队邀请链接（对方点链接加入，而不是所有者填用户编号）：要先定邀请的有效期与撤回口径，记作 TEAM-066。
