
# 271 报价助手与任务画像用去重后的中位价

> 状态：本批实现（V299）。编号 KB-094。
> 来源：266 号 spec「没做的」——「报价助手（V150）与任务画像的预算位置改用去重后的中位价」；BACKLOG V299。
> 只增不减：样本**不集中**时，报价助手与任务画像的数字、文字与以前一字不变；`p50_cents` 等原字段任何时候都不变，只在集中时多 `concentrated / reference_cents` 两个字段。

## 0. 要解决的问题

V293 只在「查参考价」那句话里提示「一家刷屏」。报价助手（V150）还在劝接单的人照被压低的 ¥50 报价，任务画像也还在说「预算高于同类成交中位」——用的是同一个被带偏的中位。

## 1. 业界怎么做

同 266 号：聚合统计按来源去重后再用于建议。（本批没有另找外部来源。）

## 2. 规则

- 参考价 `concentrated=true`（一位发布方占了一半以上且至少 3 单）时：
  - 报价助手：「比中位高 / 低」与建议报价都按 `p50_by_publisher_cents`；依据里多一句「其中大半来自同一位发布方；按发布方去重后，N 位发布方的中位是 ¥X，下面按这个数对照」；响应多 `concentrated / reference_cents`。
  - 任务画像：预算位置（`position`）与单子大小（`size`）都按去重后的中位比；`price` 多 `concentrated / reference_cents`。两端画像括号里写「按发布方去重后的中位 ¥X」（共享 SDK `profileMedianText`）。
- 不集中：一切照旧。

## 3. 数据 / 接口

不新增表与接口。`GigQuote`、`TaskProfilePrice` 加两个可选字段。

## 4. 两端

- **Web / App 发单时的「说明完整度」**：括号里的中位按上面的规则写。
- 报价助手的依据是服务端写好的句子，两端原样显示。

## 5. 隐私、授权与边界

只用聚合数，不出现是哪位发布方。
