
# 138 场景包知识检索：标签整词、连接词与技能概念展开

> 状态：本批实现（V165）。编号 SCN-105（含 SCN-105a~c）。
> 来源：137 号 spec「没做的」SCN-105：「雇人还是发临时单」命中不到「平台上的临时单不能替代用工合同」；BACKLOG V165。
> 只增不减：检索仍是摘录式、可解释的字面匹配（出处、有效期、人工关口照旧）；三处改动都只会**多认出**，原来命中的照样命中、排序靠前的照样靠前。
> 写明的行为变化：个人知识库与经验检索共用同一个切词函数，「还是 / 或者 / 或是 / 以及 / 并且 / 而且 / 怎么样」从此不当成检索词——问「A 还是 B」时两边都能找到。

## 0. 要解决的问题

场景包助手的知识检索沿用个人知识库的切词：中文长串整串算一个词，再切成二字片，二字片要命中一半以上才算相关。
带连接词的问法（「雇人还是发临时单」）整串不在条目里、二字片又被「人还」「还是」「是发」稀释，命中不到；
运营挑好的标签（「雇人」「临时单」）明明整词出现在问题里，也没被当回事。
另外 V155 的技能概念表只接进了个人知识库，场景包问答还认不出「零工单」就是「临时单」这类别名。

## 1. 业界怎么做（带来源链接）

- **停用词**：检索前去掉不承载主题的虚词与连接词是标准做法（例如 Elasticsearch 的 stop token filter，<https://www.elastic.co/guide/en/elasticsearch/reference/current/analysis-stop-tokenfilter.html>；中文常用停用词表都包含「还是」「或者」「以及」）。
- **关键词 / 标签加权**：人工维护的关键词字段命中时给更高权重（例如 Elasticsearch `multi_match` 的字段 boost，<https://www.elastic.co/guide/en/elasticsearch/reference/current/query-dsl-multi-match-query.html>）。
- **同义词扩展**：查询时把词展开成同义词（135 号已引用的 synonym token filter）。

## 2. 数据

无新表、无迁移、无新接口。

## 3. 规则

| 编号 | 内容 |
|---|---|
| SCN-105a | 连接词不当检索词：`还是` `或者` `或是` `以及` `并且` `而且` `怎么样` 进切词的虚词表（个人知识库、经验检索、场景包共用） |
| SCN-105b | 标签整词出现在问题里，每个标签加 6 分（`TAG_IN_QUESTION`，相关门槛是 3 分）；一个字的标签不算，重复标签不重复计分，大小写不敏感 |
| SCN-105c | 场景包问答按技能概念表展开问题（种子 + 运营在后台加的概念），与个人知识库同一个 `expand_query` |

## 7. 没做的

- **SCN-109 单字检索词**：切完虚词后剩下的单个汉字（如「样」）仍按整词计 3 分，可能误命中；本批只把「怎么样」加进虚词表兜住最常见的一种，系统做法是单字词降权，要先评估对个人知识库短查询的影响。
- 真正的中文分词（jieba 一类）：要引入依赖并评估各模块的检索回归，暂不做；现在的标签与概念表覆盖常见问法。
