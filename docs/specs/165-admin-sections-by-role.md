# 165 后台按角色显示板块

> 状态：本批实现（V188）。编号 SEC-061d。
> 来源：141 号 spec 第 7 节「没做的」——「现在所有板块都显示，没权限的点了会看到说清楚的 403；按角色隐藏要逐个板块改」；BACKLOG V188；VISION V-11 安全。
> 只增不减：服务端按角色事前拦的规则一条不改；没分配过角色的管理员仍按超级管理员对待（照旧全部可见）；只是界面不再显示、不再请求看不了的板块。

## 0. 要解决的问题

- 后台一页挂着 22 个板块。财务打开就能看到场景包、法律知识、工单……点开都是 403；更糟的是页面顶部那段「指标 + 举报 + 用户」是一次加载的，财务没有举报权限，整段加载跟着失败。
- 界面上「谁看得到」如果另写一份，迟早与服务端「谁调得了」对不上：多放一个角色，他点开就是 403；少放一个，他有权限却找不到入口。

## 1. 业界怎么做

| 做法 | 说明 |
|---|---|
| 后台导航按权限裁剪 | 常见的运营后台（如 Django admin 的按权限显示模型、各云控制台按 IAM 策略隐藏菜单）都是「服务端定权限，界面按权限裁剪」，界面只是权限的投影 |
| 权限投影要可核对 | 界面权限表单独维护容易漂移；常见做法是从服务端权限声明生成，或用测试比对 |

本批取「界面表记 probe，测试与服务端角色表逐条比对」。

## 2. 数据

不新增表。共享 SDK `packages/core/src/adminSections.ts`：每个板块 `{label, probe, roles}`，`probe` 是这个板块加载数据用的那个接口。

## 3. 规则

| 规则 | 说明 |
|---|---|
| 生效角色 | 与服务端 `roles_of` 一致：没分配过角色（或只有不认得的角色）的管理员按超级管理员；不是管理员什么都看不到 |
| 能不能看 | 超级管理员都能看；否则自己的角色与板块的 roles 有交集 |
| 板块的 roles | **恰好等于**服务端给 probe 接口定的角色（`test_admin_roles.py` 的 ROUTE_ROLES，它又与运行中的路由逐个核对） |

## 4. 两端

- **Web 管理后台**：22 个板块各自按角色显示；看不到的不渲染、不请求；页脚一句「这些板块不在你的职责里，所以没有显示：……需要的话请超级管理员在『管理员与角色』里给你加上对应角色」。
- **App**：没有管理后台，不涉及。

## 5. 隐私、授权与边界

- 隐藏只是体验：权限仍然由服务端事前拦，绕过界面直接调接口照样 403（141 号 spec 的闸门不变）。

## 6. 闸门与红验

| 闸门 | 测试 | 红验 |
|---|---|---|
| 每个板块的 roles 恰好等于服务端给它 probe 的角色；扫描器没认全就先红 | `server/tests/test_admin_sections.py::test_every_section_shows_exactly_the_roles_the_server_allows_on_its_probe` | 给「服务包」多加财务 → 红 |
| 每个登记的板块都真的在后台页面上按角色收起，页面不用没登记的板块 | `test_every_section_is_actually_gated_on_the_admin_page_and_every_gate_has_a_section` | 去掉「法律知识」的收起 → 红 |
| 生效角色与可见性规则 | `packages/core/src/adminSections.test.ts` | 可见性不看角色 → 红 |
| 财务看不到、也不请求不相干的板块，页脚说清；老管理员照旧全可见 | `web/src/Admin.test.tsx` | 举报不按角色就加载 → 红 |

## 7. 没做的

- **SEC-061h 板块内的按钮级权限**：一个板块里有的按钮要另一个角色（例如工单板块里「指派」要客服主管、封禁要合规），现在仍靠服务端 403 的说明；按钮级隐藏要把每个按钮也记上 probe（欠）。
