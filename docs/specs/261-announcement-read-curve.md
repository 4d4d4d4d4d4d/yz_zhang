
# 261 公告阅读率按发出后的时间看

> 状态：本批实现（V288）。编号 NTF-072（NTF-069 的阅读曲线部分；推送点击率拆成 NTF-073）。
> 来源：252 号 spec「没做的」——「阅读率按发出后的时间曲线（1 小时 / 1 天 / 3 天）看」；台账 NTF-069；BACKLOG V288。
> 只增不减：标已读、全部已读的接口与响应不变；公告列表的 `read` / `read_rate` 口径不变。

## 0. 要解决的问题

159 号的阅读率只有一个总数：看不出是发出一小时内就有人点开，还是三天后才陆续看到。后者说明推送没起作用，下一条要换时间段或换标题——运营要的就是这个判断。

## 1. 业界怎么做

站内信 / 推送平台的消息统计一般按发出后的时间窗口给累计打开数（1 小时、24 小时、几天），用来比较发送时段与标题。（本批没有另找外部来源。）

## 2. 规则

- 通知第一次被点开时记下时间（单条标已读、全部已读都记；再点一次不改）。
- 曲线：发出后 1 小时 / 1 天 / 3 天 / 7 天内点开的**累计**人数与比例；比例的分母是送达人数（与列表同口径）。
- 还没到的时间点标 `reached=false`，数字是到现在为止的。
- 这一版之前就点开过的，点开时间不详：算进总数、单列 `untimed` 并写明，不硬塞进某个时间点。
- 还没发出的（定时中）：`points` 为空并写明。

## 3. 数据

`notifications.read_at`（可空；迁移 `c1d220260065`）。通知随用户注销的既有处置走，不新增处置。

## 4. 接口

| 接口 | 说明 |
|---|---|
| `GET /admin/announcements/{id}/read-curve` | 运营；`{announcement_id, sent_at, delivered, read, untimed, points[{hours,label,read,read_rate,reached}], note}` |

SDK：`announcementReadCurve`；类型 `AnnouncementReadCurve`。登记：后台角色表、后台覆盖表、功能面清单。

## 5. 两端

- **Web 后台「全站公告」历史**：已发出的每条多一个「看曲线」，点开才加载，逐个时间点写累计人数与比例，没到的写明。
- **App**：后台只在 Web，不涉及。

## 6. 隐私、授权与边界

只给聚合数字，不给谁在什么时候点开；只有运营角色能看。
