# 88 · 独立个体网络、公开空间与合作入口

更新：2026-10-07。本篇是新产品定位和信息架构的当前设计基准；功能状态以 [实现核对表](../IMPLEMENTATION-MATRIX.md) 为准。设计要求不等于已交付能力。

## 1. 用户愿景与边界

用户原意：平台是人与人之间的窗口。每个人拥有可独立经营的虚拟门面，汇总文章、视频、小店、直播等；人、人机、机机均能协作。AI 补充不熟悉的法务、财务、政策等能力，或分发给专家。通过协议、执行记录和智能合约建立可信关系。经授权积累成功和失败案例，使 Agent 和平台能力持续改进。

场景从遛狗、外卖、社交，延伸到机器人和工业品的跨专业共创，再到长期经营、公司 VP 类工作及重组等复杂组织活动。“VP”的具体职能范围尚未澄清，不擅自将其改写为投融资或其他具体业务。

平台提供社会化组织能力，并兼容个人、公司、合伙、工厂等现有主体。扁平化保持明确的决策、授权、履约与验收责任。法定主体关系和真实资产权利不能仅由界面上的份额数字推定。

## 2. 产品对象与前后端分工

| 对象 | 前端职责 | 后端职责 |
|---|---|---|
| 个体空间 | 展示、编排、分享、公开/私有状态 | 所有权、版本、最小公开数据、隐私覆盖、注销清除 |
| 关系 | 从空间发起交流、关注、圈层 | 会话成员权限、拉黑、防骚扰与关系存储 |
| 合作意图 | 轻量表达、按复杂度展开 | 任务/编排/合作体复用，预算及状态约束 |
| 合作空间 | 成员、上下文、交付、资金和协议渐进展开 | 权限、依赖、变更、审计、结算、纠纷 |
| Agent | 显示代表谁、能力及授权边界 | 执行预算、权限、日志、升级人工及撤销 |
| 经验 | 展示来源、适用范围、验证和贡献 | 授权、去标识、检索、版本、质量评估及复用计量 |

保留模块化单体 + PostgreSQL + Redis。新增 `spaces` 模块，不另建用户、钱包或会话体系。链上索引是派生数据，不作为平台余额的第二来源。

## 4. API / 数据契约

`personal_spaces`：user_id 主键，revision，published，headline，introduction，theme，items JSON。条目为 title/kind/summary/url。无公网匿名写接口，无任意 user_id 更新接口。GET me 先于动态路由注册。

- GET `/api/v1/spaces?q=&after=0&limit=18`：最多 48 个空间，返回 items + next_cursor。排序目前按用户 ID，**不是个性化推荐**。
- GET `/api/v1/spaces/me`：本人完整编辑态与账户公开限制。
- PUT `/api/v1/spaces/me`：完整替换，revision 必填；非当前版本 409。未公开亦经过现有文本检查。
- GET `/api/v1/spaces/{user_id}`：公开详情；私有、封禁、注销统一 404。

## 5. 视觉与动效

Web 使用暖白背景、陶土强调色、苔绿/墨蓝辅助空间色，减少全局导航数量。CSS 几何窗口作为默认装饰，不能冒充用户作品或照片。作品主图上传、自由布局、空间封面视频仍未实现。

路径：`/` 发现；`/people/:id` 公开空间；`/space/edit` 私人编辑；`/cooperate` 合作入口；原任务广场迁至 `/opportunities`。原钱包、合约、团队、内容等路径保留并从相关场景/全部功能进入。

动画仅服务于空间层次和反馈：轻量浮动、渐入、卡片悬停，系统 reduce motion 时关闭装饰位移。原任务广场保留视差。跨页面共享元素过渡、完整原生 App 动效尚未实现。金额、权限、签署等关键文字不得为极简而删去。

## 7. 受众与商业验证

长期承载生活与生产协作；建议先以有真实目标的发起人、独立专业人士、小工作室和原型合作伙伴构成初始网络，保留日常场景。此为建议，首批社群未获用户最终指定。

个人专业订阅、合作服务费是首期验证假设；合作空间订阅和专家/Agent 使用分成为后续候选。当前没有上线订阅收费。衡量有效联系、按约交付、复合作、纠纷、知识复用效果和扣除 AI/客服等成本后的贡献毛利；不把注册数、内容数或测试数当作商业成熟度。
