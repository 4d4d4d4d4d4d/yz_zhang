> 来源：WorkBuddy 蓝皮书第 10、24、25 章（121 号 spec 对照表：「缺运行合同（负责人、超时、预算）、重试退避、降级交付、运行成本与耗时日志」「助手专家的角色契约写进 spec 和代码」）；BACKLOG V153。
> 只增不减：例行任务的运行合同**默认是「不重试、不降级」**，与 V141 行为完全一致（旧测试一条不改）；两端新建时才显式带上「重试 2 次、用尽降级」。
> **改了一处旧行为（写明）**：提醒类例行任务关联的工作台任务已经完成 / 取消 / 删除时，这次**跳过**并记一条「跳过」，不再照发提醒——给一件已经做完的事发提醒是噪音；跳过不算失败。

## 0. 要解决的问题

例行任务失败一次就是一次「失败」，第二天才再试；三次就暂停。人收到的是沉默或者一条「运行失败：RuntimeError」。
运行记录只有成功 / 失败和输出，不知道跑了多久、是第几次、为什么失败。
助手专家的角色契约（输入、输出、禁止动作）只写在场景包定义里，运行时没人检查：让它「帮我把税报了」，它照样去检索资料。

## 1. 业界怎么做（带来源链接）

- **指数退避加抖动、重试要有上限**：AWS Architecture Blog「Exponential Backoff And Jitter」（<https://aws.amazon.com/blogs/architecture/exponential-backoff-and-jitter/>）——
  只退避不抖动，重试仍会扎堆；Well-Architected REL05-BP03 要求限制重试次数并给退避设上限（<https://docs.aws.amazon.com/wellarchitected/latest/framework/rel_mitigate_interaction_failure_limit_retries.html>）。
  这里：1 / 5 / 25 分钟，±20% 抖动，最多 5 次，之后按 25 分钟封顶。
- **重试必须幂等**：同一次排期（slot）只送达一次——重试、job 重放、两个副本同时跑，都不会让人收到两条。
- **降级交付**：蓝皮书第 25 章「降级交付」——拿不到完整结果时给出能确定的最少内容，而不是沉默。
- **角色契约**：蓝皮书第 24 章「角色契约（输入 / 输出 / 禁止动作）」；这里让它在运行时生效，并把契约原样给人看。

## 3. 规则与接口

| 编号 | 内容 |
|---|---|
| REL-101 运行合同 | 新建 / 修改例行任务可带 `timeout_ms`（1~60 秒）、`max_retries`（0~5）、`degrade`；列表返回这几项与当前重试状态 |
| REL-102 重试退避 | 失败且还有重试次数：这次记「失败，等待重试」，不通知、不算失败次数，按退避（加抖动）重试**同一次排期**；成功后才排下一次 |
| REL-103 就绪检查 | 提醒关联的任务已删除 / 完成 / 取消：跳过，不算失败，照常排下一次 |
| REL-104 降级交付 | 重试用尽且开了降级：发一条「这次的内容没能完整生成……」（提醒类就发提醒本身），标「降级交付」，算一次失败（连续 3 次照样暂停） |
| REL-105 日志与健康度 | 每次运行记排期、第几次尝试、耗时、成本、错误类型；`GET /workbench/routines/{id}/health`：最近 30 次的成功率、送达、降级、重试、跳过、失败、耗时中位与 95 分位、错误类型分布、成本、当前合同 |
| REL-106 只送达一次 | 同一 `slot_at` 已有「成功 / 降级送达」：不再发，只把排期往后挪 |
| REL-101 超时 | 生成超过 `timeout_ms` 按失败处理（错误类型 `timeout`），走重试 / 降级 |
| REL-107 角色契约 | `GET /packs/{key}/assistants/{akey}/contract`：人设、需要你给什么、它给你什么、不会做什么、只用哪些工具（中文名）、哪些事必须你本人确认、答不了建议发哪类单；提问时如果是「让它去做」禁区里的事（帮我 / 替我 / 直接…… + 禁区动作），直接拒绝并说明，记一次 `refused` |

`run-routines` job 的返回多了 `routines_retrying` / `routines_skipped` / `routines_degraded`（原有三个键不变）。

## 4. 两端

- **Web 工作台 → 助手**：新建表单多「失败后重试」「重试用尽时降级交付」（默认 2 次、开）；列表写清合同与上次状态（成功 / 失败 / 等待重试 / 跳过 / 降级送达）；运行记录写第几次尝试；「健康度」一行。
- **App 工作台 → 助手**：同样的状态、合同与健康度；一键新建的两个例行任务默认带合同。
- **服务包里的助手专家（两端）**：「看完整的角色契约」。

## 5. 隐私、授权与边界

- 运行日志只记异常类型，不记异常文本（测试钉住：异常里带身份证号也不会落库）。
- 健康度只给本人（别人的例行任务 404，走工作台的对象级授权规则）。
- 角色契约的拒绝是**词面规则**：「帮我看看 / 算算 / 解释」是问，不拒；只对「替你 / 动用你的 / 把你的」开头的动作类禁区生效。漏判的情况仍有人工关口兜底（钱、签署、申报一律只给草稿）。

## 7. 没做的

- **REL-110 真实模型调用的成本**：现在例行任务都走模板，`cost_cents` 恒为 0；接入模型生成摘要时按调用量记账，并给每月成本上限（运行合同里的预算）。随 AGT-084（V154，助手调用平台经验工具）一起做。
- 场景包助手的回答耗时：事件表刻意不存任何多余的列（PACK 的旧测试钉住「不存提问原文」的列集合），不往里加；需要时单独建表。
- 平台级的例行任务运行看板（运营看全体的失败率）：先看个人健康度的数据，再决定要不要做。
