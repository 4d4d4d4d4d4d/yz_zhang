# 244 方法的版本历史

> 状态：本批实现（V271）。编号 AGT-098。
> 来源：239 号 spec「没做的」——「方法的版本历史（每一版的步骤原文，可以对比改了哪一步、退回旧版）」；BACKLOG V271。
> 只增不减：方法的增删改、版本号与按版本统计（239 号）都不变；没改过步骤的方法导出与以前一样。
> 写明的行为变化：新表 `nb_method_versions`（迁移 c1d220260060）；改步骤时多存一份旧步骤；删方法时连旧版一起删；新增 2 个接口。

## 0. 要解决的问题

239 号让人看得出「改了之后变差了」，但看不到改了哪一步，也退不回去：旧步骤一改就没了，只能凭记忆重写。

## 1. 业界怎么做

文档、模板、工作流编辑器普遍有「版本历史」：每次保存留一版，能看每一版、和新一版对比，能「恢复此版本」——恢复本身也是一次新的保存，不抹掉中间的历史。（本批没有另找外部来源。）

## 2. 规则

- 只有步骤真的变了才存旧版（与 239 号升版的条件同一处判断）；改名、改说明不存。
- 每一版存当时的步骤原文与被替换的时间；当前版仍在方法本身上。
- 看历史：当前版 + 旧版（版本号倒序）。两端在每个旧版旁写明「下一版加了哪几步、去掉了哪几步」（按步骤标题比；标题一样时说「顺序改了」或「备注改了」，共享 SDK `methodStepDiff`）。
- 退回某一版：把那一版的步骤设为当前——这也算一次修改（升一版、把当前的存成旧版），历史不丢；和现在一样的不用退回（409）。
- 只能看、退回自己的方法（别人的 404）。删方法时连旧版一起删；注销时与方法一起物理删除；导出时有旧版的方法多 `old_versions`。
- 本批之前改过的步骤没有存下来，历史从本批开始记。

## 3. 数据

`nb_method_versions`：方法、所有者、版本号、步骤（JSON）、被替换时间。迁移在 SQLite 与 Postgres 上 `upgrade head` + `check` 通过。

## 4. 接口

| 接口 | 说明 |
|---|---|
| `GET /notebook/methods/{id}/versions` | `{method_id, current: {version, steps}, versions: [{version, steps, replaced_at}]}` |
| `POST /notebook/methods/{id}/versions/{version}/restore` | 返回方法（与列表同形状） |

错误码（进 `i18n.ts`）：`nb_method_version_not_found`、`nb_method_version_same`。SDK：`methodVersions`、`restoreMethodVersion`、`NbMethodHistory`、`methodStepDiff`。

## 5. 两端

- **Web 知识库「我的方法」**：改过步骤的方法多「看历史版本」，点开列出每个旧版的步骤、和下一版的差别、「退回这一版」。
- **App 知识库「我的方法」**：同样的内容，「退回第 N 版」按钮；退回后重新读列表。

## 6. 隐私、授权与边界

方法与历史只属于本人；注销即物理删除（KB-109 同一条）。
