# 432 场景包变异红验工具进仓库

> 状态：本批实现（V459）。编号 PACK-094。
> 来源：431 号（V458）发现的问题。新容器的 scratchpad 是空的，第五十四轮以来各批 spec 写的「`scratchpad/mutXXX.py` 共 N 处，全红」，那些脚本一个都找不到了：红验这一步说做了，却没人能复现。
> 只增不减：只加一个脚本和它的测试；已有测试、种子数据都不改。

## 0. 要解决的问题

每批场景包都要做同一套变异：
- 删关键禁止项；
- 删「只靠标签」那几行命中的标签；
- 改类目的资质。

过去每批复制上一批的脚本改文件名，放在临时目录，用完即丢。要的是一个仓库里的工具：写完测试就能跑，换容器、换人都能复现。

## 1. 业界怎么做（带来源链接）

变异测试工具一般从被测代码与测试自动生成变异，不靠手写清单。这里的「被测代码」是种子数据，所以直接从测试文件里推出要改的地方。本轮没有引用外部报道链接。

## 2. 数据

不涉及。

## 3. 接口

`server/scripts/pack_mutate.py`：

    python -m scripts.pack_mutate tests/test_v458_packs.py          # 逐个改坏、跑、改回，列出谁没变红
    python -m scripts.pack_mutate tests/test_v458_packs.py --list   # 只列出会改哪些地方

从测试文件推出三类变异：

| 类 | 从哪推 | 怎么改坏 | 跑哪些测试 |
|---|---|---|---|
| 关键禁止项 | 测试函数里的 `any("…" in f for f in a.forbidden)`，加上同一函数里 `_load("key")` 指明的包 | 删掉种子里唯一含这段话的禁止项 | 那条测试函数 |
| 只靠标签 | 参数表里注释「只有标签里的口语才接得住」之后的每一行 | 删掉问法命中的那一个标签 | 那一行（按参数下标 `phonesN`） |
| 类目 | 测试里 `_categories()["…"]` 提到的类目 | 不要资质的加 `"required_cert": "x"`，已经要资质的去掉它 | 整个测试文件 |

另有几条约束：
- 推不出唯一目标时直接报错，不猜。例如一段话命中两条禁止项，或者一个标签在文件里出现两次。
- 每处改坏都在 `finally` 里改回原文。

## 6. 闸门与红验

**存量清点**（V420 以来的 20 个场景包测试文件）：419 处里 417 处一跑就红。剩下 2 处是工具自己的等价变异：
- 「空调加氟维修」「高空外窗外墙清洗」本来就要资质，往前插的 `"required_cert": "x"` 被后面原有的同名键覆盖，等于没改；
- 修成「已经要资质的就去掉它」以后，两个文件分别 21/21、20/20 红。

推导出来的禁止项变异比以前手写的多：每个包 5 条都覆盖，以前一般挑 4 条。

| 闸门 | 红验 |
|---|---|
| `server/tests/test_pack_mutate.py`（5 条）：<br>从 V458 的测试推出三类各几处、参数下标对得上；已要资质的类目用「去掉」；V420 以来的每个场景包测试都推得出来；歧义的拒绝不猜；改坏后一定改回（真跑一次 pytest 自检，红与不红两种都试） | 6 处，全红：<br>不改回原文；参数下标错一位；不走「去掉资质」；不查歧义；红与不红判反；推不出禁止项 |
| `server/tests/test_script_rot.py` | `pack_mutate.py` 登记进 EXERCISED 表 |

skill `scenario-discovery` 写明：测试写完跑这条命令，spec 里写命令和「N/N 红」，不再写 scratchpad 里的脚本。
