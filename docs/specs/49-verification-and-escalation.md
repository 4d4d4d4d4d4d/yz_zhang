# 49 人类核验闭环与争议升级阶梯（VER / ESCA）

> 补 V73 留下的 AGT-050：`escalated` 当时只做到「拦住 + 可退款」，
> **没有接到人类专家**。需求里那句「agent 无法完成或者需要人类专家核验」，
> 核心是后半句——不是「换个人重做」，是**让人来判 AI 做得对不对**。
>
> 同批补 AGT-032：客服 → 纠纷 → 法务三级在代码里都存在，
> 但它们是三个互不相识的模块，**没有任何一条路把用户从一级送到下一级**。

## 0. 核验是一种独立的工作，不是「重做」

这是这一批最重要的一条判断。

「AI 做完了但没把握」和「AI 做不了」是两件事，对应的成本差一个数量级：

| | 要做的事 | 合理定价 |
|---|---|---|
| **核验** | 看一遍 AI 的产出，判对错，必要时改 | 原任务的 5%~20% |
| **重做** | 从头执行 | 原任务全价 |

把核验做成「重新发一个任务招人干」，就是按重做收费——
**发布方为 AI 的不确定性付了两次全价**，这个产品立刻不成立。

所以核验是独立实体 `VerificationOrder`，不是一个 `Task`。

**为什么不复用 Task**（这与 V73 「agent 复用 User」的判断方向相反，要说清楚）：

- V73 复用 User，是因为托管/纠纷/信用/账本**全部以 `user_id` 为键**，
  不复用就得各写第二遍。收益极大。
- 这里复用 Task 的收益是招募/合约/托管那一套——但核验是一笔 ¥10~50 的活，
  **而且常见情形下付款方是平台自己**。让平台对自己做资金托管，
  是用重机制办轻事，除了复杂度什么也没换来。

判断标准是同一条：**复用能省掉重复实现的，就复用；复用只能带来仪式的，就不复用。**

## 1. 谁付这笔钱：一个有立场的判断

分两种情形，答案不同：

| 触发方式 | 付款方 | 理由 |
|---|---|---|
| **agent 置信度不足自动升级** | **平台** | 平台自有 agent 没把握，是**平台的问题**。让发布方为 AI 的不确定性买单，等于把自己技术不成熟的成本转嫁给用户 |
| **发布方主动要求核验**（哪怕 run 成功） | 发布方 | 这是他额外买的一份确定性 |

第一行是这一批的立场。它有直接的经济后果——agent 置信度阈值调得越松，
平台自己掏的核验费越多——**这正是它该有的激励**：调松阈值的成本由调的人承担。

### VER-010 资金走预付，不走托管

下单时从付款方可用余额扣到平台账户（`verify_hold`），核验完成时转给核验人
（`verify_payout`），取消或超时未接单则退回（`verify_refund`）。

不走 escrow 三态，理由同上（平台对自己托管没有意义）；但**必须预扣**——
核验人做完了拿不到钱，这个角色就没人做。三个科目都走 `_log()`，
按 SYNC-002 必须同时在 `LEDGER_KINDS` 与 SDK 文案表里声明。

## 2. 核验人是谁

### VER-020 核验人不能是 agent

**让 AI 核验 AI 的产出，是把同一个不确定性叠两遍，不是降低它。**

这条要写在代码里而不是指望没人这么配。整条升级链路的价值就建立在
「最后有一个人负责」上，一旦允许 agent 核验，升级就变成了原地打转。

### VER-021 准入：实名 + 该类目有完成记录 + 信用分达标 + 非本单当事人

不要求职业资质——那是受限类目的事（V76 单独做）。这里要的是
「干过这类活、口碑没问题、与本单无利害关系」。

**非本单当事人**包括：不是发布方、不是执行方、不是原 agent 的任何相关方。
利益冲突不是靠自觉。

## 3. 核验结论只有三档，每档都有明确出口

| 结论 | 含义 | 原任务怎么走 |
|---|---|---|
| `approved` | AI 做对了 | 解除交付闸门，可正常交付验收 |
| `revised` | 基本可用，我改了 | **修正稿成为交付物**，可交付 |
| `rejected` | 推翻 | 回到「需人工执行」：发布方可取消退款或重新招募 |

没有「部分通过」这档。理由是它不可执行——发布方拿到「部分通过」
之后不知道该干什么，而不可执行的结论等于没有结论。

### VER-030 `revised` 的修正稿必须重新过判据

核验人改完，**平台的 `auto` 判据要重新跑一遍**。

不这样做就有一个漏洞：判据拦住了 agent 的输出，核验人（可能只是想早点结单）
提交一份同样不过判据的修正稿，却因为「人工核验通过了」而放行。
**人工核验是加上去的一道，不是用来豁免原有那道的。**

## 4. VER-040 核验结果回流经验库：这才是飞轮

需求里说「能够持续帮助迭代任务完成」。现在的 `KnowledgeCard` 只记
类目/城市/价格/工期/分解结构——**记不下「怎么做才对」**。

核验结论恰好是这个信息，而且是带标注的：

```
输入（任务描述 + AI 产出） → 人的判断（对/改成这样/错） → 理由
```

所以核验完成时写一条 `VerificationLesson`：类目 + 判据 + 结论 + 修正差异摘要 + 理由。
它的用途是喂给同类任务的 agent 提示词，以及给发布方写验收标准时做参考。

**脱敏与 KB-002 同规矩**：不含个人信息、不含精确位置、不含合同金额细节。

## 5. ESCA 争议升级阶梯：把三个互不相识的模块连起来

三级都已存在（`support/` 工单、`dispute/` 纠纷、`legal/` 文书与协议），
缺的是**「转」这个动作本身**。

| 级 | 入口 | 时限 | 出口 |
|---|---|---|---|
| 0 自助 | `support.ask` 知识库问答 | 即时 | 解决 / 开工单 |
| 1 客服 | 工单 | `SUPPORT_SLA_HOURS` | 解决 / **转纠纷** |
| 2 纠纷 | 两造兼听 + 裁决 | 答辩期 + 裁决期 | 裁决自动执行 / **申诉** |
| 3 法务 | 申诉复核 + **完整证据链导出** | — | 仲裁/诉讼的材料 |

### ESCA-001 工单转纠纷必须带上下文

不带的话用户要把话重说一遍——而他刚刚已经在工单里说过一次了。
重说一遍不只是麻烦：**两次陈述不一致会被当成翻供**，在纠纷里对他不利。

所以转的时候把工单正文与客服回复写进纠纷的 `evidence.from_ticket`，
并在工单上留下 `escalated_to_dispute_id`，两边都能互相找到。

### ESCA-002 升法务 = 导出一份能拿去用的证据链

现在 `evidence` 是开案那一刻的快照。升到法务这一级，要导出的是**完整的**：

合同全文与其哈希、双方签署留痕（含哪条是平台代签的）、交付记录、
**逐条验收判据结果**、agent 的 run 记录（含置信度与成本）、
核验结论、纠纷全部陈述、裁决与申诉。

一份自洽的、可以直接交给律师或仲裁机构的材料。

### ESCA-003 agent 任务在阶梯上没有豁免

平台是责任主体（AGT-017），所以被诉的是平台自己。

这一点必须在代码里成立而不是只写在文档里——`open_dispute` 要求
「仅任务当事人可发起」，而 agent 任务的执行方是一个平台账号。
必须验证：**发布方能对一个 agent 执行的任务正常开纠纷并走到裁决。**

## 6. 验收点

| 编号 | 验收点 |
|---|---|
| VER-010 | 预扣→支付/退款三条路径资金守恒，五条不变量仍成立 |
| VER-011 | agent 升级触发的核验由**平台**付费；发布方主动要求的由发布方付 |
| VER-020 | agent 不能成为核验人 |
| VER-021 | 本单当事人不能核验；无该类目完成记录/信用不达标不能核验 |
| VER-022 | `approved`/`revised` 解除原任务交付闸门；`rejected` 不解除 |
| VER-030 | `revised` 的修正稿不过 `auto` 判据时仍然拒绝 |
| VER-040 | 核验完成写出一条经验，且不含个人信息 |
| VER-041 | 超时未接单自动退款并可重新下单 |
| ESCA-001 | 工单转纠纷带上下文，两边可互相定位 |
| ESCA-002 | 证据链导出包含合同哈希/签署留痕/判据结果/run 记录/核验结论 |
| ESCA-003 | agent 执行的任务能正常开纠纷并裁决 |

## 7. 这一批没做的（明确记账）

- **VER-050**：核验人是**发布方自己挑**还是平台派单？这一批只做「平台按资格
  池派单给第一个接单的人」。竞价/指定/抢单的差异留给有真实供给数据之后再定。
- **VER-051**：`VerificationLesson` 只落库，**还没有真的喂回 agent 提示词**。
  喂回去要先解决「用哪些、怎么排序、多少条」，那是检索问题（KB-040 那条线）。
- **VER-052**：核验人自己的质量没有反向评估。核验人乱判（全部 approved）
  目前只有信用分这一层软约束。抽检机制留给后续。
- **ESCA-050**：法务这一级只做到「导出材料」。真正的对接（仲裁机构、
  律师协作）涉及外部签约，代码侧只能到这里。
- **ESCA-051**：工单的 SLA 只有时限字段与超时可见，**没有自动升级**。
  自动把超时工单升成纠纷是有风险的（纠纷会冻结资金），留给人决定。
