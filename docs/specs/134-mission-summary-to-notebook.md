
# 134 编排复盘一键存进个人知识库

> 状态：本批实现（V163）。编号 AGT-092~093。
> 来源：133 号 spec「没做的」AGT-092（复盘的「下一步」建议存进知识库，但没有按钮）；VISION 1.6「门户＝助手＋知识库」；BACKLOG V163。
> 只增不减：复盘接口与知识库都不变，只多一个写接口与两端各一个按钮。

## 0. 要解决的问题

编排做完了，经验留在编排的时间线里；下次做同类的事，人要去翻旧编排。个人知识库（122 号）才是放「我的做法」的地方——问笔记、拆清单引用、蒸馏方法都从那里取。

## 1. 业界怎么做

复盘的产出要进团队 / 个人的知识沉淀（wiki、笔记），否则复盘只是一次性的会议。这里存成一条普通笔记（标签「编排复盘」），后续的检索、问笔记、拆清单引用、方法蒸馏都自动用得上。

## 2. 接口

`POST /missions/{id}/summary/save`（只有发起人；管理员能看复盘但不能存）：

- 笔记标题「编排复盘：目标（#id）」，标签「编排复盘」，状态「已归档到知识库」（filed）；
- 正文：目标、状态、轮次、完成与整改、花费与上限、平均评审、步骤清单（含验收要点）、要点、下一步；
- **再存一次更新同一条**（按标题认，修订号 +1），不会重复；超过笔记上限时说清楚（`nb_limit_reached`，与知识库同一个码与补救入口）；
- 返回 `note_id`、`created`、`title`、`saved_at`。

## 3. 两端

Web 与 App 的编排详情「复盘」一块多「存进我的知识库」；第一次说「已存进」，之后说「已更新」。
