# 52 合同缺的两条，和一档能做的浮动对价（IPC / OUT）

> 两个来源：
>
> 1. 我在需求回顾里查出的缺陷——**合同模板里没有知识产权归属，也没有保密条款**。
> 2. 用户对「早期合作」的回应里那句「合规只是路径上的一些需要」——
>    V75 做了合作体内部分配；这一批补**任务侧**可以合规做的那一档：
>    与交付成果挂钩的**浮动对价**。

## 0. IPC：发布方花钱买了 logo，默认不拥有它

实测 `contract/service.py` 生成的条款有四段：金额、验收、争议、性质声明。
**没有知识产权归属，没有保密条款。**

后果按《著作权法》第十七条（委托作品）：**受托人与委托人没有约定或者
约定不明的，著作权属于受托人。**

翻译成平台上的事实：

| 场景 | 现在实际发生的 |
|---|---|
| 发布方花 ¥3000 买一套 logo | 著作权归**执行方**，发布方拿到的只是一份使用许可（范围还不明） |
| 发布方委托开发一个小程序 | 同上。执行方可以把同一套代码再卖一遍 |
| 执行方拿到发布方的客户名单/后台密码 | **没有任何保密义务的书面约定** |

`软件开发` 类目的发布模板里甚至写着 checklist「约定源码归属」——
**平台自己提示用户去约定，然后没有提供任何约定的地方。**

### IPC-001 归属要成为一个必须做的选择，不能有默认值

最容易犯的错是「默认归发布方」。那对执行方不公平，而且对**通用组件**、
**字体/素材的第三方权利**这些情况直接就是错的。

所以发布任务时必须选一档（无默认、不选不让发）：

| 档位 | 含义 | 适合 |
|---|---|---|
| `assign`（转让） | 交付成果的著作权（人身权除外）转让给发布方 | 定制 logo、定制文案 |
| `license_exclusive`（独占许可） | 著作权仍归执行方，发布方获独占使用权 | 需要排他但执行方要保留作品集 |
| `license_nonexclusive`（普通许可） | 发布方获使用权，执行方可再许可他人 | 通用模板、批量内容 |
| `retain`（执行方保留） | 发布方只获约定范围内的使用权 | 咨询产出、方法论 |

**人身权（署名权、修改权、保护作品完整权）依法不可转让**，条款里必须
写明这一点——把「著作权全部转让」写进合同是一句无效的话，
而写无效的话比不写更糟：当事人会以为自己拿到了实际上没有的东西。

### IPC-002 保密条款是双向的

发布方交给执行方的（客户名单、后台账号、未公开的产品计划）要保密；
执行方交给发布方的（报价逻辑、未采用的方案）同样要。
**只约束一方的保密条款在谈判上站不住，在履行上也不公平。**

期限、例外情形（已公开、独立开发、法律要求披露）写进条款。

### IPC-003 归属随**已签署的那一版**走

合同条款是有版本的（变更单会 +1 并重新签署）。归属条款必须跟着版本走，
而不是读任务当前的字段——否则事后改一下任务字段，就等于单方面改了归属。

## 1. OUT：浮动对价，这是「早期合作」在任务侧能做的那一档

V75 把合作体内部的份额与分配做了。任务侧还有一档没做：
**报酬与交付成果挂钩**。

现状 `ALLOWED_PRICING = ("fixed", "milestone", "hourly", "bidding")`，
`finance/compliance.py` 把「分红/股权/保本」拦在发布环节。那条红线不动——
它防的是**面向不特定多数人发行可分享收益的权益**。

但「做得好多给钱」不是那个东西。它是**承揽合同的对价条款**，
前提是三条同时成立：

### OUT-001 与**交付成果**挂钩，不与「收益/利润」挂钩

`按下载量分成` ❌（挂的是经营收益）
`达到约定的验收指标则加付` ✅（挂的是交付质量）

判定标准写进代码：浮动部分必须绑定到**本任务的 `acceptance_criteria`**
（V73 建的那套客观判据），不能绑定到任何外部经营指标。

### OUT-002 必须封顶

`base_cents` + `bonus_cents`，`bonus_cents` 是一个**确定的上限金额**，
不是一个比例、不是一个开放式承诺。

封顶是把它与「收益分成」分开的关键：一个有确定上限的附加对价是价款，
一个随收益浮动的比例是分配。

### OUT-003 浮动部分同样要**预先托管**

不托管的话，「做得好多给钱」就变成了一句口头承诺——执行方把活干到了
约定水平，发布方不给，平台没有任何东西可以执行。

所以 `fund` 时托管 `base + bonus` 全额；验收时按判据结果决定 bonus
放款还是退回发布方。

### OUT-004 谁判浮动达标：**平台按客观判据判**，不由任一方说了算

与 AGT-030 同一条道理。`auto` 判据由平台跑；有 `manual` 判据时，
发布方确认，但**驳回必须给理由**且执行方可以对此开纠纷——
否则「浮动对价」就是一个发布方随时可以不给的空头承诺。

## 2. 验收点

| 编号 | 验收点 |
|---|---|
| IPC-001 | 发任务不选归属档位被拒（无默认值）；合同条款含所选档位的准确表述 |
| IPC-002 | 条款含**双向**保密义务与例外情形 |
| IPC-003 | 人身权不可转让写进条款；`assign` 档不写成「著作权全部转让」 |
| IPC-004 | 归属随已签署版本走；改任务字段不改变已签合同 |
| OUT-001 | `outcome` 计价必须带 `acceptance_criteria`，否则拒绝发布 |
| OUT-002 | `bonus_cents` 必须为正且有上限；比例式/开放式表述被拒 |
| OUT-003 | 托管金额 = base + bonus；未达标时 bonus 退回发布方，资金守恒 |
| OUT-004 | 达标判定走平台判据；发布方不能在判据通过时单方扣掉 bonus |

## 3. 这一批没做的（明确记账）

- **IPC-050**：条款是**中文模板**，不是律师起草的正式合同文本。
  上线前必须由执业律师过一遍——代码里对此有显式声明。
- **IPC-051**：没有处理**第三方素材权利**（执行方用了付费字体/素材库）。
  这需要在交付时声明来源与授权，属于交付物清单的范畴，留到后续。
- **IPC-052**：职务作品、合作作品这些更复杂的归属情形没有覆盖。
- **OUT-050**：浮动对价目前只支持**一档 bonus**（达标/不达标）。
  分档递增（达到 A 加 X，达到 B 加 Y）没做——先把一档做对。
- **OUT-051**：`manual` 判据下发布方拖着不确认时，走的是既有的
  `AUTO_ACCEPT_DAYS` 自动通过。这条是对的，但**自动通过时 bonus 怎么算**
  需要一个判断：本批按「auto 判据通过则 bonus 照付」处理，
  纯 manual 判据的 bonus 在自动通过时**退回发布方**——
  没有人确认过达标，就不能算达标。
