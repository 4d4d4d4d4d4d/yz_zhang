# 232 App 上的邀请链接清单与作废

> 状态：本批实现（V259）。编号 TEAM-072。
> 来源：228 号 spec「没做的」——「App 上的邀请链接清单与作废」；BACKLOG V259（第九轮排期 18 分）。
> 只增不减：App 上「生成并分享邀请链接」的行为不变（生成请求仍是第一个请求）；服务端不改。
> 写明的行为变化：App 团队成员块的「邀请链接」下多「查看已发的链接」，点开后列出链接并可作废。

## 0. 要解决的问题

147 号把邀请链接的清单与作废放在了 Web。链接被转发出去、有不认识的人加入了（228 号会通知所有者），所有者多半是在手机上看到通知——而手机上作废不了，只能去找电脑。

## 1. 业界怎么做

邀请链接的管理（查看、作废）通常在所有端都能做，外泄时越早作废越好。（本批没有另找外部来源。）

## 2. 数据与接口

不改服务端：用已有的 `GET /teams/{id}/invite-links`（带 228 号的 `joined`）与 `POST /teams/{id}/invite-links/{link_id}/revoke`。SDK 加共享常量 `INVITE_STATE_LABEL`（与 Web 同一组词）。

## 3. 两端

- **App**：「查看已发的链接」点开才加载（打开团队页多半只是想发一条新链接，省一次请求）；每条写「#编号 额度 · 已用 x/y · 状态 · 已加入：……」；有效的旁边有「作废 #编号」，作废后提示「再有人点开会看到『链接无效』」并刷新；生成新链接时清单已展开就一并刷新。
- **Web**：不变（147、228 号已有）。

## 4. 隐私、授权与边界

清单与作废原本就只给所有者（服务端校验），App 只是多一个入口。

## 5. 闸门与红验
