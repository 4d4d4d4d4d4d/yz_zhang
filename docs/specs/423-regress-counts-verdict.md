# 423 回归脚本漏判前端计数不一致

> 状态：本批实现（V450）。编号 REG-003。
> 来源：自查。be38570（V443~V445）的回归日志开头写着「文档里的前端计数与真实结果不一致：DELIVERY.md 写着 core 246，真实通过 253」，最后一行却是「回归全绿」。往回翻，84f7125（V439~V442）那次回归也打印了同样的不一致（core 250），照样「全绿」，**而且已经推送了**。
> 只增不减：回归脚本只是多判一处；文档计数改成真实数。

## 0. 要解决的问题

`tools/regress.sh` 里前端计数核对那一行有三个毛病：
1. `check_frontend_counts` 把不一致写在 stderr，而这一段只把 stdout 收进 `fe.txt`，最后的判定只 grep `fe.txt`，看不到；
2. 这一行没像别的步骤那样检查退出码、写「步骤失败」；
3. core / web 与 app 用 `&&` 连着，前一半失败后 App 的核对根本不跑。DELIVERY.md 里 App 写的 582 早就过时了（实际 600），一直没人发现。

DOC-011（103 号）立这道闸门，就是为了让手抄的计数跟着测试输出走；判定漏了，等于这道闸门从某次改动以后一直没生效。

## 1. 业界怎么做（带来源链接）

CI 脚本里每一步都看退出码、错误输出并进日志，是基本做法。本仓库 REG-001（V171）、CI-002 已经对其他步骤这样做了，只漏了这一行。本轮没有引用外部报道链接。

不改接口。`tools/regress.sh`：
