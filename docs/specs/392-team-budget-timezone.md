
# 392 团队账期按团队选的时区 0 点起算（TEAM-056b）

> 状态：本批实现（V419）。编号 TEAM-056b。
> 来源：370 号「没做的」：账期一律按 UTC 起算，东八区的团队 1 号的额度要到当地早上 8 点才重置。BACKLOG V419。
> 只增不减：团队多一个可空字段 `budget_tz`；不选（或选 UTC）与原来一字不变。账期日、预算池、预警、个人额度的规则都不变。

## 0. 要解决的问题

TEAM-054 当初把「额度按 UTC 自然月重置、东八区是早上 8 点」写成了已知代价；TEAM-056 加了「每月几号重置」，同样按 UTC。企业按自己当地的财务月结账：
- 北京时间 1 号 0 点到 8 点之间花的钱，会算进上一期；
- 「本期已用」与财务的账对不上几个小时的量。

## 1. 业界怎么做

企业 SaaS 的计费与预算周期通常按账户设置的时区计算，由管理员在设置里选，不跟着某个成员的设备走。这是常见做法，本轮没有引用外部链接。

## 2. 数据 / 接口

- `teams.budget_tz`（字符串，可空），迁移 `c1d220260096`。空 = UTC。
- `POST /teams/{id}/budget` 多收 `budget_tz`，只能从一张固定的表里选：
  - UTC、北京、香港、台北、东京、新加坡、伦敦、纽约、洛杉矶；
  - 别的值返回 422；不传就不改；选 `UTC` 等于清掉。
  - 只有所有者能改，与原来改预算池的权限一样。
- 团队详情与设预算池的返回多 `budget_tz`（没选过为 `"UTC"`）。
- 换算方法：
  1. 把「现在」换成团队时区的当地时间；
  2. 按原来的规则算当地的本期起点和下次重置；
  3. 再换回 UTC。

  平台内部仍然全是 UTC；夏令时由时区库处理。
- 库里出现不在表里的值（手改、老数据）：按 UTC 算，不报错。
- 接口允许的取值和服务端认的表是同一张：有测试钉住，只改一边会红。

**为什么不推断时区**：平台刻意不存个人时区（TZ-065）。团队的时区是所有者明确选的一项团队设置，不跟着某个成员的设备、IP 走。

## 4. 两端

- **网页团队页**：账期那一行，所有者多一个时区下拉；选了非 UTC 的，账期说明写「每月 25 日重置（按北京时间 0 点）」。成员只看不改。
- **App 团队页**：所有者多一排时区按钮，当前选中的带「●」，点当前那个不发请求；改完提示「预算池改为按北京时间 0 点重置」。成员只看不改。
- 两端共用 SDK：
  - `BUDGET_TIMEZONE_OPTIONS`、`budgetTimezoneLabel`；
  - `budgetCycleLine` 在选了时区时多一句，没选与原来一字不变（原有断言照过）；
  - `setTeamBudget` 多一个可选的时区参数，不传不带字段。
- 老服务端没有这个字段时，两端都不显示时区选择。

## 5. 隐私、授权与边界

- 只改团队设置，不碰个人数据，不推断个人时区。
- 只有所有者能改（与预算池同一条，TEAM-052）。
