## 0. 要解决的问题

检索按整串和二字切片打分（`notebook.terms / score`）。「天气不好还走」切成「天气、气不、不好、好还、还走」，知识里只沾上「天气」一片，不到一半，整组不算。同一件事用了另一个说法就接不住，例如：
- 天气不好 / 变天 → 下雨、打雷；
- 暴雨 → 下雨；
- 下大雨 → 暴雨；
- 下雪 → 结冰；
- 恶劣天气 → 下大雨、大风。

416 号定过方向：靠一张近义表，不在打分规则里硬凑。

## 1. 业界怎么做（带来源链接）

检索系统一般用同义词表在查询时扩展（query-time synonym expansion）。上位词（「恶劣天气」）只单向展开到下位词，免得问「下雨」时把「大风」的结果也拉进来。本轮没有引用外部报道链接。

## 2. 数据

`server/app/modules/packs/synonyms.json`：

| 字段 | 意思 |
|---|---|
| `groups[].name` | 组名，必须是组里的一个写法 |
| `groups[].words` | 互为近义的写法，问题里出现一个，其余的都加进检索 |
| `groups[].includes` | 单向包含的组：问「天气不好」也找「下雨」「大风」「下雪」三组；反过来不成立 |

这一批有五组：下雨、大风、下雪、高温、天气不好（上位词）。

不放进技能概念表：那张表管撮合与认技能，天气词混进去会被当成技能。

## 3. 接口

不新增 HTTP 接口。`app/modules/packs/service.py` 新增三个函数：
- `synonym_groups()`；
- `synonyms_in(q)`：问题里认出的组（加上它包含的组）中，问题里还没有的写法；
- `pack_terms(q, db)`：问题本身的词（含技能概念展开）加上近义词。近义词的处理规则：
  - 每个近义词自成一组，只算整词、不切二字，权重 3；
  - 排在问题本身的词后面，不受 `MAX_TERMS` 截断。

`pack_terms` 有三个调用方，免得三处算法不一样：
- 助手问答（`_knowledge_hits`）；
- 离线试问法（`scripts/pack_probe.py`）；
- 只靠标签的闸门（`tests/test_pack_tag_only_questions.py`）。
