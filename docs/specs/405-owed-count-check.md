
# 405 现状文档的欠账条数由 harness 对数

> 状态：本批实现（V432）。编号 DOC-022。
> 来源：自查。现状文档（`docs/STATUS-2026-10-13.md` 第 5.4 节）写着「台账「欠」（58 条，2026-11-03 按台账实数核对）」。之后几批关了几条、又记了几条，这个数没人改；同一格还把 V411 已做完的甘特时间线（AI-DEC-021c）列成欠账。这是写给决策人看商用差距的数字。
> 只增不减：harness 多一项检查；已有检查都不变。

## 0. 要解决的问题

- 现状文档里的欠账条数会悄悄过期：每批都可能关掉或新记几条，只靠人记得去改。
- V426 查出 AGT-050 早已做完却还记着「欠」，说明台账本身也会过期。台账里「本批实现」点名的编号已有 DOC-021（368 号）管，现状文档里的那个数没人管。

## 1. 业界怎么做（带来源链接）

文档里的数字由脚本从同一份数据算出来、在 CI 里对数，与本仓库的计数闸门（DOC-010 测试数、DOC-011/012 前端与结构计数）同一个做法。本轮没有引用外部报道链接。

## 2. 数据

不涉及。

## 3. 接口

`python -m scripts.harness check` 多一项：

- 现状文档（`docs/STATUS-*.md`）里每一处「台账「欠」（N 条」，N 必须等于台账逐条索引里记作「欠」的编号数（`harness.owed_ids()`）；
- 对不上时报：「写着 N 条，实际是 M 条：改成 M」。

## 4. 两端

不涉及界面：工程工具。

## 5. 隐私、授权与边界

不涉及。

|---|---|

| `harness check` 本身 | 加上当场就报出现状文档的 58 与实际 57 不符。<br>已改成 57，并把那一格里已做完的 AI-DEC-021c 换成仍欠的 AI-DEC-021e |
