## 0. 探针：84 条绿色的 web 测试证明了什么

用户问「前端是否能够跟后端功能对接」。先去看现有证据。

```
$ grep -rl "vi.stubGlobal\|mockFetch\|vi.mock" web/src | wc -l
（全部 web 测试文件）
```

这个仓有 84 条 web 测试，**每一条都把 `fetch` 换掉了**。它们能证明
「按钮按下去会调这个方法、参数是这些」——这是有价值的，V80 的形状闸门
就靠它们。但它们证明不了最基本的那件事：

> 前端与后端真的能对接吗？

差别不是假设出来的。mock 掉 `fetch` 之后，下面这些**结构性地**看不见：

| 看不见的东西 | 为什么 mock 看不见 |
|---|---|
| 构建产物里 API 基址写错 | 开发时走 vite 代理，生产走同源，**是两条路** |
| CORS 没配对 | 拦请求的是浏览器，而 mock 里没有浏览器 |
| 真实响应体形状与 TS 声明不一致 | 形状闸门（80 号）钉的是服务端测试里的端点，不是前端真收到的那一份 |
| token 存取、路由守卫、首屏时序 | 拿不到 `me` 时画什么，只有真时序能暴露 |

而 `scripts/smoke.py` 走的是真实 HTTP，但它是 `urllib` 打上去的——
**它证明后端好，不证明前端连得上后端**。两条闭环各证一半，中间正好留了
一条缝，而「前端连不上后端」是上线当天最常见的那一类事故。

## 1. E2E-010 第三条闭环

所以补第三条闭环，与 `smoke.py`（主链路）、`sandbox_check.py`（存管合规态）
并列：

```
npm run build:web && (cd server && python -m scripts.e2e_web)
```

三个决定，每个都是为了不给自己放水：

### 1a 跑构建产物，不跑 dev server

要验的是**构建出来的东西**。dev server 有 vite 代理，它会把 `/api`
转走——那正好把「基址写错」这一类问题盖住。所以脚本自己起一个静态服务，
直接伺服 `web/dist`。

### 1b 同源，用反向代理而不是放宽 CORS

静态服务把 `/api/*` 反代到 uvicorn，这样浏览器看到的是同源请求——
**和生产部署（Nginx 同源）一致**。反过来做（前端一个端口、后端另一个端口、
在服务端放开 CORS）是给测试改生产配置，验出来的就不是要上线的那套。

SPA 回退到 `index.html`，否则直接访问 `/wallet` 会 404 ——顺便也验证了
部署时那条必需的回退规则。

### 1c 走「钱与权利」，不走首页

一个只 `goto('/')`、看见标题就算过的联调，和 `curl /readyz` 没有区别。
所以主路径钉死在：

注册 → 拿到 token → 深色底与视差层在 → 钱包 → 通知偏好 →
**发任务（含 77 号的必填归属）** → 在广场上看见它 → 自助开工单

## 2. 失败判据：一个假报警多的闸门会被人关掉

第一次跑，脚本报了 `404 /api/v1/tasks/1/dispute`。

去查，这是**设计如此**：DSPC-010 规定「该任务没有纠纷」就回 404，
前端据此画「暂无纠纷」。也就是说**我的检查错了，不是应用错了**。

如果留着这条报警，下一个人第一次看见它会去查，第二次就会加 `|| true`。
所以判据改成：

```python
defects = [f for f in interesting if f.startswith("5") or f.startswith("422")]
noted   = [f for f in interesting if f not in defects]
```

- **5xx**：服务端炸了，永远是缺陷。
- **422**：前端发的形状后端不认——这正是这一篇要抓的那一类。
- **其他 4xx**：打印出来，不判失败（401/403/404 常常是设计好的答案）。

这条边界本身写进了闸门（`test_e2e011_script_checks_the_money_and_rights_paths`
断言 `5xx`/`422` 判据与非零退出都在），因为**一个只打印不判失败的脚本，
在 CI 里永远是绿的**——那是最糟的一种绿。

## 3. E2E-011 覆盖记账

联调能走多少页面是有限的（管理后台要整套运营数据，站内信要两个用户）。
但「走不到」和「忘了走」必须区分开，否则半年后它只剩首页。

所以有一张账：从 `web/src/App.tsx` 的**路由表**里扫出页面（不手抄），
与脚本里的 `page.goto(...)` 对齐，差集必须出现在 `E2E_EXEMPT` 里
并写明理由。值是理由不是布尔（V90 那条）：

```python
"/messages": "站内信要两个用户对话，联调是单用户脚本；IM 由服务端测试覆盖",
"/ventures": "合作体要先有份额与贡献记录，前置比断言本身贵；份额与分配由服务端测试覆盖",
```

理由里不许出现「还没做 / 待补 / TODO / 以后」——**那是欠账，归 72 号台账**，
不是豁免理由。混在一起的后果是欠账被伪装成决定。

这张账当场发挥了作用：它指出 `/support` 没被走到。而 `/support` 是
V102 才补的自助入口、**没有前置条件的写路径**——正好适合真浏览器验一遍。
所以没有豁免它，而是加了一步。**闸门该带来的就是这个：不是多一条豁免，
是多走一步。**

## 4. 闸门

| 闸门 | 内容 |
|---|---|
| E2E-010 | CI 的 `web-e2e` job：装 Chromium，构建 web，跑联调，非零即红 |
| E2E-011 自检 | 路由与访问都要扫得到（≥10 条路由、≥4 个访问，且已知的 `/wallet`/`/notifications` 在内） |
| E2E-011 覆盖 | 新页面要么被联调走到，要么在豁免表里写理由 |
| E2E-011 诚实 | 豁免理由 ≥12 字、不含欠账词；表里不留已删除的路由 |
| E2E-011 主路径 | 脚本里必须有注册/token/发任务/广场/钱包这几步，且有 `return 1 if bad else 0` |

红验（四条各自单独验过）：新增一个未登记页面 → 红；把「发任务」那一步
删掉 → 红；把退出码改成恒 0 → 红；豁免理由改成「这条还没做」→ 红。

## 6. 这一批没做的

- **单用户**：站内信、纠纷、核验都要多方，脚本起不来第二个角色。要做得
  先有一套「造前置数据」的夹具，那本身是一篇 spec。
- **不跑支付**：真实支付要沙箱回调，`sandbox_check.py` 已经在盯存管态。
- **不截图比对**：视觉回归要基线图与容差策略，且在 CI 里最容易变成
  假报警（字体/渲染差异）。现在只断言「深色底 + 视差变量在动」。
- **App 端没有联调**：RN 要模拟器，CI 成本量级不同；APPB-050 的类型闸门
  与 45/79 号的运动层测试是现在的替代。记在 72 号台账。
