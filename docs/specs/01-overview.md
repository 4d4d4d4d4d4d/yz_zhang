# 01 · 产品总览：角色、术语、核心流程

## 1. 用户角色

| 角色 | 说明 |
|---|---|
| 发布者（Requester） | 发布任务的个人或企业，可对子任务分别付款 |
| 执行者（Worker/服务者） | 接单执行任务的个人或团队，具备技能标签与信用分 |
| 内容创作者 | 发布视频、博客、知识分享的用户（与上述角色可重叠） |
| 圈层/社群管理员 | 创建与管理兴趣/能力圈层与群组 |
| 平台运营 | 审核内容、处理风控、配置推荐策略 |
| 客服（AI + 人工） | 智能客服兜底转人工 |
| 纠纷仲裁员 | 处理交易/任务纠纷（平台仲裁 + 外部法律通道） |

## 2. 核心术语

- **任务（Task）**：一次有明确交付物或行为的请求，可大可小（一个软件项目 / 一笔二手交易 / 一次打扫卫生）。
- **母任务 / 子任务**：AI 或用户将大任务分解后的层级结构；母任务的完成 = 全部关键子任务闭环。
- **任务闭环**：任务经历「发布 → 匹配 → 执行 → 验收 → 结算 → 评价」全流程结束。
- **智能合约（Contract）**：对任务金额、里程碑、验收条件、违约条款的程序化托管与自动执行。首期可为「平台托管账本 + 规则引擎」实现，链上化为演进方向（见 05）。
- **圈层（Circle）**：按兴趣或能力聚合的半开放社区，是匹配与协作的加速器。
- **知识库（Knowledge Base）**：由闭环任务沉淀出的结构化经验（方案、报价、工期、坑点），反哺 AI 分解与推荐。

## 3. 核心流程（主闭环）

```
发布者描述需求
   │
   ▼
AI 需求澄清（对话式补全要素：预算/时间/地点/交付物）
   │
   ▼
AI 任务分解（可选）：母任务 → 子任务树，估价/估时/所需技能
   │
   ▼
逐个子任务发布 → 推荐人选（AI 匹配 + 圈层曝光 + LBS 附近的人）
   │
   ▼
双方确认 → 生成智能合约（资金托管、里程碑、验收条件）
   │
   ▼
执行（过程沟通走 IM，进度打卡，材料上传）
   │
   ▼
验收（发布者确认 / 超时自动确认 / 争议进入纠纷流程）
   │
   ▼
合约结算（放款、分账、平台抽佣）→ 双向评价 → 信用分更新
   │
   ▼
经验入库（AI 提炼任务摘要、成本、工期、评价 → 知识库）
   │
   └──► 反哺：下次 AI 分解更准、推荐更准、报价更准
```

## 4. 次级流程

- **内容流**：创作 → 审核 → 分发（关注流/推荐流/圈层流）→ 互动 → 为创作者积累能力标签与信任背书 → 提升被推荐概率。
- **社交流**：单聊/群聊/圈层 → 沉淀协作关系 → 熟人复购与转介绍。
- **客服流**：用户提问 → AI 客服（基于平台知识库+FAQ）→ 解决 / 转人工 / 转纠纷。
- **纠纷流**：协商 → 平台仲裁（证据链来自任务留痕）→ 法律通道（法律知识 AI、文书生成、律师对接）。

## 5. 平台差异化假设（供后续验证）

1. **AI 分解 + 分别发布**：大任务不再依赖单一承包方，平台像"总包调度器"推动整体完成。
2. **任务经验知识库**：闭环数据是壁垒，任务做得越多，分解/估价/匹配越准。
3. **圈层信任**：兴趣与能力圈层降低陌生人协作的信任成本。
4. **全颗粒度**：同一套体系覆盖"一次打扫卫生"到"一个外包项目"。

## 6. 不做 / 边界（首期）

- 不做自营履约团队（平台只做撮合与保障）。
- 不做通用电商货架（交易型任务是 C2C 委托，不是商城）。
- 链上智能合约首期不上线，先用中心化托管 + 合约规则引擎，接口预留（见 05）。
- 法律服务不提供正式法律意见，仅提供信息、文书模板与律师转介（见 11）。
