## 0. 先说结论

WorkBuddy 是**个人电脑上的 AI 工作台**，我们是**合作网络**。蓝皮书里的能力分成三类：

1. **门户自己要有的**（助手管理、知识库、可靠的自动化）：这是对外合作的前提。V141 做了助手的一半；**知识库整个没有**，助手的专家化和自动化的可靠性只做了一半。
2. **合作网络能做得比单机更好的**（专家团、技能蒸馏、岗位与行业落地）：我们有真实的人、真实的闭环和经验库。蓝皮书里「专家团」的团长拆解、并行执行、汇总，在我们这里就是**拆解树 + 合作驾驶舱 + 平台 Agent**。缺的是把这些能力以「助手专家」的形态交到每个人手上。
3. **单机才有意义、或者要靠外部机构的**（本机文件、远程控制电脑、第三方 IM 绑定）：不照搬。IM 和第三方连接器走开放 API（已有），绑定微信、飞书需要外部账号，记作「外」。

## 2. 不照搬的，以及为什么

- **本机文件和远程控制电脑**：我们是服务端加两端客户端，不碰用户的电脑。
- **算命、星盘、医疗判断**（第 14 章自己也写了「不越界」）：平台不内置。
- **第三方 IM 绑定、第三方连接器市场**：需要外部账号和审核，记作「外」；我们先把开放 API 做好，别人的连接器接我们。

排期以 [`docs/BACKLOG.md`](../BACKLOG.md) 为准（harness 维护）。用户在同一天补充了一句（VISION 1.8）：「场景千变万化……
提炼一些方法……快速发掘并部署……agent、skill、知识库就是平台重要的资产之一。」因此排期按下面的顺序：

1. **V146 harness**（本篇）：规则、skills（含 `scenario-discovery`）、spec 脚手架、待办、追溯闸门。
2. **V147 个人知识库**：门户的另一半。
3. **V148 场景包引擎与平台资产**：助手专家、方法、知识条目、模板可以登记、有版本、审核后上线，用户一键启用；附带场景雷达。
4. **V149 / V150 第一批场景包**：OPC 与接单者。**它们是场景包，不是硬编码的功能**，同时用来验证引擎。
5. 之后是任务画像、影响力与专家、助手可靠性、经验工具接入、语义匹配、App 补齐，以及雷达跑出来的下一批场景。
