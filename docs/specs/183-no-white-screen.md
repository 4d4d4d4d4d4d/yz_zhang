# 183 每一页都不白屏：错误边界与全路由闸门

> 状态：本批实现（V210，并入 V211）。编号 APP-091、APP-092。
> 来源：182 号 spec 第 7 节「没做的」——「APP-091 同样的闸门扩到其他页面」「APP-092 两端加错误边界」；BACKLOG V210、V211。
> 只增不减：各页正常时的显示与行为不变；只在一页渲染出错时，把这一页换成说明卡（以前是整个应用白屏）。

## 0. 要解决的问题

- 把 182 号的探针扩到 Web 的全部 35 个路由：**140 个组合里 91 个整页白屏**，约 30 个页面组件拿到 `{}` / `null` / 字符串就 `.map` 崩掉，React 把整棵树卸掉——连顶部导航都没了，用户只能关掉标签页。
- 一页一页补数据防护治标不治本：下一个新页面照样会漏。

## 1. 业界怎么做

React 官方：渲染出错由错误边界接住，只替换出错的那一部分，并在边界里给出替代界面（<https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary>）。

## 2. 做法

| 端 | 边界 | 复位 | 替代界面 |
|---|---|---|---|
| Web | `RouteBoundary` 包住整个路由表（导航在边界外） | 按路径：点到别的页自动复位 | 「这一页没加载出来」：为什么（网络或服务暂时不正常）、怎么办（刷新；一直这样到客服提单，写上是哪一页），带「刷新」「去客服」 |
| App | `ScreenBoundary` 包住主体区域（顶栏、底部 Tab 在边界外） | 按当前屏（任务 id / 浮层 / Tab）复位 | 同样的说明，带「← 返回」（回到上一层） |

两端都只记错误类型（`page_render_failed` / `screen_render_failed` + 错误名），不记内容：屏幕上的数据可能有个人信息（SEC-065）。

## 3. 闸门

- `web/src/RoutesResilience.test.tsx`：35 个路由 × 四种畸形响应，顶部导航必须还在；另有一条「路由表里的每一页都在探针里」（从 `App.tsx` 读路由表对照，新页面漏了就红）。
- `web/src/RouteBoundary.test.tsx`、`app/screenBoundary.test.tsx`：替代界面、只记错误类型、换页复位、返回；App 主框架确实套着边界且按屏复位。
- 182 号的任务详情页逐块闸门保留：那一页最重要（验收、放款按钮），要求的是**块级**不坏，而不只是「不白屏」。

## 4. 红验

8 处变异全部变红（`scratchpad/mut210.py`）：去掉 Web 路由边界 → 红；边界不按路径复位 → 红；把错误内容写进日志 → 红；边界不接错误 → 红（两端）；App 返回不起作用 → 红；App 边界不按屏复位 → 红。
