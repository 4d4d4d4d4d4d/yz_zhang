
# 404 举报附截图

> 状态：本批实现（V431）。编号 RISK-017。
> 来源：V426（399 号）「没做的」。举报只有一句说明时，审核员常常判断不了，尤其是：
> - 对方撤回了的私信；
> - 已经改掉的动态；
> - 站外的聊天记录。
>
> 只增不减：`POST /reports` 多一个可选的 `images`，不传与以前一样；队列、「我的举报」多一个 `images` 字段；SDK `report()` 多一个可选参数。

## 0. 要解决的问题

让举报人能附上截图，审核员不用只凭一句话判断；同时不能让举报变成「把任意一张图塞进审核员眼前」的口子。

## 1. 业界怎么做（带来源链接）

- 常见做法：举报时可选附几张截图，提示遮住无关的个人信息。
- 本平台客服工单附图（ESCA-057，231、233 号）已有同一套规矩：只收本人刚上传的图、敏感材料不收、存图片名读时再拼地址。
- 本轮没有引用外部报道链接。

## 2. 数据

`reports.images`（JSON，迁移 `c1d220260099`，SQLite 与 PostgreSQL 都做过 `upgrade head` 和 `check`）：图片名列表。

## 3. 接口

- `POST /reports` 的 `images`：图片地址，最多 3 张，重复的只存一次。
  - 超过 3 张：400 `report_too_many_images`；
  - 不是举报人自己上传的、不存在的、证件类敏感材料：400 `report_image_not_yours`。
  - 两个错误码进 i18n。
- `GET /admin/reports`、`GET /reports/mine`：每条多 `images`（地址列表）。数据导出跟着「我的举报」一起带上。

## 4. 两端

- **SDK**：
  - `report(..., category?, images?)`，不传时请求体不变；
  - `MAX_REPORT_IMAGES = 3`；
  - `MyReport.images`、`adminReports` 的类型多 `images`。
- **Web**：
  - 举报表单多一个选图（复用 `PhotoPicker`，先压缩再上传，最多 3 张），提示截图前遮住无关的个人信息；
  - 「我的举报」写「附图 N 张」；
  - 后台队列的「理由」后面列出「截图 1」「截图 2」……，点开看原图。
- **App**：
  - 举报块多「＋ 附截图」，从相册选、超 2MB 拦下，附满 3 张后不再出现；
  - 「我的举报」写「附图 N 张」。
  - 选图函数在 `report.tsx` 里单独写一份：客服页已经引用了这个文件，再反过来引用客服页会成环。

## 5. 隐私、授权与边界

- 只收举报人自己上传的图：上传时已过内容审核，被拒的根本不落库。
- 敏感材料（证件、交付原图）不收。
- 截图里可能有第三人的信息：表单上提示先遮住；图随举报作为平台处置记录保留。
