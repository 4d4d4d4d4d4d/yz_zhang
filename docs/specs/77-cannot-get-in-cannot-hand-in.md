# 77 进不去，也交不上（ACC-041 / CERT-033 / NTF-065 / CS-032 / TAX-024 / CLI-082）

> 状态：本批实现（V102）
> 依赖：02 号（账户）、51 号（资质核验）、57 号（客户端可达性闸门）、
> 65 号（必达通知）、76 号（运营侧人审队列）

## 0. 探针

共享 SDK 有 266 个方法，**两端都没有人调用的有 87 个**。抽掉「有意不给端」
那类之后逐个看，掉出五条闭环断了的：

```
PROBE 账号找回
PROBE   resetPassword            sdk=True  web=False app=False
PROBE   smsLogin                 sdk=True  web=False app=False
PROBE   sendSmsCode              sdk=True  web=False app=False
PROBE 资质提交
PROBE   submitCertification      sdk=True  web=False app=False
PROBE 工单自助
PROBE   createTicket             sdk=True  web=False app=False
PROBE   myTickets                sdk=True  web=False app=False
PROBE 发票
PROBE   requestInvoice           sdk=True  web=False app=False
PROBE 通知开关
PROBE   notificationPrefs        sdk=True  web=False app=False
PROBE   setNotificationPref      sdk=True  web=False app=False
```

每一条的服务端都是通的，SDK 也是通的，**端上没有人调**。

## 1. 为什么这五条是一件事

V101 刚把运营侧的**出口**装齐：资质核验台、工单队列、团队企业核验。
而这一批的探针说明其中几条的**入口**不存在：

- 资质核验台会一直是空的——**没有任何端能提交一份资质申请**，
  受限类目对所有人永久关闭。我上一批给出口装了门，而没有人进得来。
- 团队企业信息现在核得过了（V101），而**开票的入口不存在**：
  `requestInvoice` 两端都没人调。核过了依然开不出票。
- 工单只有 FAQ 机器人升级时会自动生成。用户不能主动开单，
  也看不到自己的工单与回复线程——运营在 V101 的界面里认真回了，
  而提问的人只收到一条通知，回到平台上无处可看。

另外两条不是「入口缺失」，是更硬的：

- **忘了密码就进不去**。`resetPassword` / `smsLogin` / `sendSmsCode`
  三条端到端都在，而登录页上只有「密码登录」和「注册」。
  V68 补的是**登录之后**改密码。忘了密码的人登不进去，
  于是那个入口对他毫无意义。这是「钱能进不能出」的账号版。
- **通知开关不存在**。65 号那张 `MUST_REACH` 表的全部论证建立在
  「用户能关掉别的通知」之上——「把所有通知都做成不可关，等于把开关
  变成摆设，用户会连真正重要的这几条一起屏蔽掉」。而那个开关
  **两端都没有**。一条用来做减法的规矩，减的是一个不存在的东西。

## 2. ACC-041 账号找回，以及 App 上一个更糟的做法

Web 与 App 的登录页各补两条路：**忘记密码**（手机号 + 验证码 + 新密码）
与**验证码登录**（免密码）。

App 那边还有一件必须一起改的事。它现在的登录是这样的：

```tsx
const res = await client.login(phone, password)
  .catch(() => client.register(phone, password, `用户${phone.slice(-4)}`));
```

**密码打错会走到注册**，而注册会因为手机号已存在而失败，于是用户看到的
提示是「该手机号已注册」——他输错的是密码，平台告诉他的是手机号的事。
更糟的一半是：**手机号打错一位会静默注册出一个新账号**，而他会以为
自己"登录成功了"，然后发现钱包是空的、任务不见了。

所以 App 的登录要拆开：登录是登录，注册是注册；登录失败原样显示服务端
的错误码文案，并把「忘记密码」「验证码登录」摆在旁边。

## 3. CERT-033 资质提交入口

Web 的实名页加一块「职业资质」：提交（名称、持证人、证号、发证机关、
有效期、证件影像）与「我的资质」列表（状态、驳回理由）。

两条硬要求：

- 证件影像走**敏感上传**那条路（V76 已有：`_mark_images_sensitive`），
  不是普通图床。
- 驳回理由要**显示出来**。V101 让运营必须写理由，理由写了却看不见，
  那条强制就只是给运营加了道手续（V92 起反复出现的同一条）。

## 4. NTF-065 通知开关，以及「哪些关不掉」必须来自服务端

Web 的通知页加一块开关：`task` / `system` / `interaction` 三类可关，
`funds` 类服务端直接拒绝关闭（`funds_mandatory`）。

关键在第二半：界面必须说清**哪些通知不受开关影响**，而那份清单
**不许写在界面里**。`MUST_REACH` 是一张会变的表（V65 立、V100 加过一行），
界面里抄一份，它第二天就过期了——这是 V61/V90 那条「文案里的数字不许是
字面量」的同一形状。所以 `GET /notifications/prefs` 的响应扩展成：

```json
{
  "prefs": {"task": true, "system": true, "interaction": true},
  "always_on_categories": ["funds"],
  "always_on": [{"category": "task", "title": "待验收提醒",
                 "why": "不处理就等于默认同意：到期自动验收并放款"}, ...]
}
```

`why` 直接取自 `MUST_REACH` 的值——那一列本来就是写给人看的。

## 5. CS-032 工单自助

Web 客服页加：开单、我的工单（状态 + 运营的回复原文）、以及在有争议时
升级为纠纷（`escalate-to-dispute`，服务端在 V49 就建好了）。

顺手修两条形状漂移（V64 那一类，「声明了却不给」）：

| 方法 | 声明 | 服务端实际 |
|---|---|---|
| `createTicket` | `{id, status, reply}` | 只有 `{id, status}` |
| `myTickets` | 每行含 `body` | 没有 `body` |

修**服务端**而不是改声明：工单列表里没有正文，用户看到的是一排标题，
点进去没有内容——那不是类型问题，是这个页面缺了东西。

## 6. TAX-024 发票入口

钱包页加「平台服务费发票」：已放款合约可申请（`requestInvoice`）、
我的发票列表（`myInvoices`）。

文案照搬服务端的口径，一个字都不加：**只开平台佣金那部分**，
执行者的劳务报酬平台没有开票资格。含糊其辞地"帮你开全额发票"是虚开，
不是服务。

## 7. CLI-082 闸门：SDK 方法必须落进三类之一

V82 的闸门问的是「服务端端点在端上到达得了吗」。反过来那一半一直没人管：
**SDK 里的方法有没有人调**。87 个没人调的方法里，这一批挑出五条闭环断了的，
剩下的必须被**分类**，而不是继续躺着：

1. **有端调用**（扫描器能在 web / app / admin 里找到调用）；
2. **有意不给端**（豁免表，写一句人话理由——job 类、供应商回调类）；
3. **台账排期**（72 号台账里有行，写明是哪条线、为什么还没做）。

三类都不在 → 红。新增 SDK 方法时必须回答「谁来调它」，
这正是 V82 对服务端端点立下的规矩，现在两个方向都有了。

再加一条反向检查（便宜且今天就是绿的，要让它保持绿）：
**SDK 里的每条路径都必须在服务端存在**。`escalateTicket` 指的
`/support/tickets/{id}/escalate-to-dispute` 今天确实在（在 verify 模块里），
而 V82 那次 `addCertification` 打的就是一个服务端已经改掉的契约。

## 9. 这一批没做的

- **短信是沙箱桩**：`sendSmsCode` 在开发态回显验证码（`dev_code`）。
  找回密码这条线因此在生产上**等真实短信供应商**（19 号 spec 的既有约定），
  代码侧已经不再是缺口。
- 忘记密码**没有做频率限制之外的风控**（例如异地找回要二次核验）。
  现有的是 `guard` 的限流与人机验证阶梯，够用但不是账号安全的全部。
- 工单**没有多轮对话**：现在是「一问一答、答完即结」。
- 发票只做**平台服务费**那一张；劳务报酬的代开渠道（TAX-023）仍未做。
- 通知开关只做三类**整类开关**，没有做按通知类型的细粒度。
- 87 个 orphan 里这一批只接了 10 个左右，其余进三分类表；
  **社交（好友/群聊）、知识库检索、内容收藏**三条线整体仍在台账里排期。
