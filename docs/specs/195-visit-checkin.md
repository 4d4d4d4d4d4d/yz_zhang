# 195 上门回报时带上到场打卡

> 状态：本批实现（V222）。编号 SCN-124。
> 来源：176 号 spec「没做的」——「回报时带上到场打卡」；191 号第 3 节排序（分数 48）；BACKLOG V222。
> 只增不减：`POST /tasks/{id}/visits` 不带位置时行为与返回不变（返回多一个 `at_site_m: null`）；`POST /tasks/{id}/checkin` 行为不变，只多记一个距离。
> 写明的行为变化：`progress_logs` 加一列 `distance_m`（迁移 c1d220260043）。

## 0. 要解决的问题

V203 让接单人每上门一次交一条回报（勾清单、备注、照片），GEO-021 早有「到场打卡」。但两者是分开的：

- 发单人看回报里写着「喂了、换了水」，**到底到没到场**，要另去翻打卡记录；而网页上根本看不到打卡。
- 接单人每次要点两个按钮，常常只交了回报、忘了打卡，纠纷时少了一条到场证据。

## 1. 业界怎么做

上门服务的履约凭证通常是「到场签到 + 服务记录」合在同一条记录里（打卡带位置与时间，服务记录挂在这次签到下面）。本平台 GEO 系列（34 号等 spec）已有打卡的规则（打卡即位置同意、打卡半径、任务结束后清坐标），本批不另立规则，回报直接复用。

## 2. 数据

- `progress_logs.distance_m`（整数、可空）：打卡或带位置的回报离任务地点多远（米）。
- 坐标照旧存在 `lat` / `lng`，任务结束后由 `purge-locations` 清掉（GEO 规则，不分记录类型）；**距离是一个数字、不是位置，留着当履约证据**。

## 3. 接口

| 接口 | 变化 |
|---|---|
| `POST /tasks/{id}/visits` | 可选 `lat`、`lng`（要么都给、要么都不给，否则 `visit_location_incomplete`）。给了就按打卡规则：线上单或没有任务坐标 → `no_checkin_needed`；打卡即位置同意；超出打卡半径 → `too_far`，消息写明差多远、并告诉他「先不带位置交回报」；通过就记下坐标与距离，通知发单人时写「到场打卡（距任务地点 N 米）」。返回多 `at_site_m` |
| `GET /tasks/{id}/visits` | 每次回报多 `at_site_m`（没带位置是 null） |
| `POST /tasks/{id}/checkin` | 多记 `distance_m` |

新错误码 `visit_location_incomplete` 进 `i18n.ts`。SDK：`reportVisit` 的请求体可带 `lat` / `lng`；`TaskVisit.at_site_m`。

## 4. 两端

- **App**：上门回报里多一个勾选「带上当前位置（证明到场，和到场打卡一样）」——只有线下单、且主框架能取定位时显示；勾了才取定位。每次回报后面写「· 到场（距 N 米）」。
- **Web**：只读——每次回报后面写「· 到场（距 N 米）」。网页不取定位（GEO-021 的决定：浏览器里的定位在上门场景没有意义）。

## 5. 隐私、授权与边界

- 位置是敏感个人信息：只在接单人勾选后取一次；打卡即单独同意（LAW-031），撤回同意后会被拒（与打卡一致）。
- 坐标在任务结束后清掉；距离保留。回报只给成交双方与管理员看（原规则）。
