# 05 · 智能合约与资金结算

模块前缀：`SC`（合约）/ `PAY` 的资金部分见 12

## 定位与演进路线

- **阶段一（MVP，P0）**：“智能合约”=平台侧**合约规则引擎 + 资金托管账本**。合同条款程序化（状态机 + 规则），资金走持牌支付通道的担保/分账能力。对用户呈现为“智能合约”，但不上链。
- **阶段二（V2，P2）**：条款哈希上链存证（防篡改），结算仍在链下。
- **阶段三（探索）**：特定场景真实链上合约（如跨境、DAO 协作），需独立合规评估。

> 设计约束：合约服务接口从第一天起抽象为 `ContractEngine` 接口，链下/链上实现可替换。

## A. 合约生命周期

```
生成（成交触发）→ 双方签署 → 资金托管 → 生效
 → [里程碑交付 → 验收 → 分期放款] × n
 → 全部完成 → 终结（结算+评价）
 分支：变更（双签变更单）/ 违约终止 / 纠纷冻结 → 仲裁执行
```

| 编号 | 功能点 | 优先级 | 说明 / AC |
|---|---|---|---|
| SC-001 | 合约自动生成 | P0 | 成交后由任务要素生成：双方、金额、里程碑、验收条件、期限、违约条款、取消规则；模板按任务类型区分 |
| SC-002 | 电子签署 | P0 | 双方 App/Web 内确认签署；留存签署时间、IP、设备指纹；对接电子签章服务（P1 增强法律效力） |
| SC-003 | 资金托管（Escrow） | P0 | 签署后发布者资金进入托管；执行者可见"已托管"状态；未托管不进入执行中 |
| SC-004 | 里程碑分期结构 | P0 | 每个里程碑：金额、交付物、验收期限；与任务里程碑一一对应 |

## B. 资金安全与合规（硬约束）

- **不碰资金红线**：托管与分账必须通过持牌支付机构（如银行存管/支付机构分账产品），平台不自建资金池。
- **对账**：每日与支付通道对账，差错自动挂起人工处理。
- **幂等**：所有资金操作幂等 + 流水号追踪；放款/退款失败自动重试并告警。
- **审计日志**：合约每次状态变更、每笔资金动作全量审计留痕（不可修改）。
- **限额与风控**：单笔/单日限额、异常交易（自买自卖刷信用）识别联动 12 风控。
