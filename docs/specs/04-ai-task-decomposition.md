# 04 · AI 任务分解与编排

模块前缀：`AI-DEC`

## 目标

把一个大而模糊的需求，借助 AI 模型分解为可独立发布、独立结算、可并行/有依赖关系的子任务树，
并在执行过程中持续编排（调度、监控、重排），推动母任务整体完成。

## A. 需求理解与澄清

| 编号 | 功能点 | 优先级 | 说明 / AC |
|---|---|---|---|
| AI-DEC-001 | 对话式需求澄清 | P0 | 多轮追问补全：目标、预算、期限、地点、质量标准、交付物；产出结构化需求单（JSON Schema 固定） |
| AI-DEC-002 | 需求可行性预判 | P1 | 结合知识库给出：预算是否合理、周期是否现实、平台是否有匹配供给 |
| AI-DEC-003 | 违规/高风险需求拦截 | P0 | 分解前先过内容安全（联动 12 风控） |

## B. 任务分解

| 编号 | 功能点 | 优先级 | 说明 / AC |
|---|---|---|---|
| AI-DEC-010 | 生成子任务树 | P0 | 输出：子任务列表（标题/描述/所需技能/预估工期/预估价格/交付物/验收标准）+ 依赖关系（DAG，串行/并行） |
| AI-DEC-011 | 用户可视化编辑分解结果 | P0 | 树/看板视图；增删改子任务、调整依赖与预算；AI 结果仅是草稿，用户确认后生效 |
| AI-DEC-012 | 基于知识库的分解模板 | P1 | 同类历史闭环任务的分解结构作为 few-shot/模板（依赖 06） |
| AI-DEC-013 | 估价与估时 | P1 | 参考知识库同类任务实际成交价与工期，给出区间与置信度 |
| AI-DEC-014 | 重新分解/局部再分解 | P1 | 某子任务仍过大时可对其继续分解（多级树，限制最大深度，默认 3 层） |
| AI-DEC-015 | 小任务直通 | P0 | 识别为简单任务（如一次保洁）时跳过分解，直接进入发布流程 |

## C. 分发与编排（Orchestration）

| 编号 | 功能点 | 优先级 | 说明 / AC |
|---|---|---|---|
| AI-DEC-020 | 子任务批量/按依赖顺序发布 | P0 | 无前置依赖的子任务先发布；前置完成后自动发布后继（可设自动/手动确认） |
| AI-DEC-021 | 母任务驾驶舱 | P0 | 甘特/看板视图：各子任务状态、负责人、预算消耗、关键路径、整体进度 % |
| AI-DEC-022 | 风险监控与预警 | P1 | 子任务延期/流拍/纠纷 → 评估对关键路径影响 → 通知发布者并给出建议（换人/加价/调整范围） |
| AI-DEC-023 | 自动重新招募 | P1 | 子任务流拍或执行者违约时，自动重新进入匹配流程 |
| AI-DEC-024 | 跨子任务上下文共享 | P2 | 在授权范围内向后继子任务执行者共享前置产出物 |
| AI-DEC-025 | 母任务整体验收与结项报告 | P1 | 全部关键子任务闭环后，AI 生成结项摘要（成本、工期、交付清单）供发布者归档 |

## D. 预算与合约联动

| 编号 | 功能点 | 优先级 | 说明 / AC |
|---|---|---|---|
| AI-DEC-030 | 母任务总预算拆分到子任务 | P0 | 拆分后每个子任务独立托管、独立结算（依赖 05）；剩余预算池可调剂 |
| AI-DEC-031 | 子任务超支审批 | P1 | 子任务加价需从预算池扣减并经发布者确认 |

## E. 模型与工程要求

- **模型接入层**：统一 LLM 网关（支持多模型路由/降级/超时重试）；分解类请求走高能力模型，澄清追问可走轻量模型。
- **结构化输出**：所有 AI 输出必须符合 JSON Schema 并做服务端校验，不合规自动重试/降级为人工模板。
- **人机协同底线（P0）**：AI 分解结果一律需用户确认后才发布；AI 不直接动资金。
- **评估**：离线评测集（分解合理性/估价误差），线上 A/B（母任务完成率、发布转化率）。
- **成本控制**：分解结果缓存；同类需求命中知识库模板时减少 token 消耗。
