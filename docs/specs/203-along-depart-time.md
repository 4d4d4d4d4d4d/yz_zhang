# 203 顺路单可设出发时间

> 状态：本批实现（V227）。编号 SCN-134。
> 来源：192 号 spec「没做的」——「顺路单可以设出发时间（按出发后几小时内的名额筛），不只按『现在有空』」；BACKLOG V227。
> 只增不减：不带出发时间时 `/gig/along` 的参数、筛选与返回不变（返回多两个字段，都是 null）；「附近」与新单推送不变。

## 0. 要解决的问题

V220 起顺路单按名额时段筛：开着「现在有空」时只看「现在 → 有空截止」对得上的，没开就只去掉已经过去的。但顺路单最常见的用法是**提前看**：今晚想好明早上班路上带一单。现在要么看到一堆三天后的名额（没开「有空」），要么只剩眼下两小时的（开着「有空」）。

## 1. 业界怎么做

顺风车、同城顺路带货这类产品，普遍让用户先填「出发时间」，再按出发后的一段时间窗口匹配订单，而不是只看当前时刻。本平台已有名额时段的换算（192 号，北京时间换 UTC），本批只把窗口的起点从「现在」换成「出发时间」。（本批没有另找外部来源。）

## 2. 数据

不加表、不存出发时间：只在这次查询里用。

## 3. 接口

| 接口 | 变化 |
|---|---|
| `GET /gig/along` | 可选 `depart_at`（北京时间 `YYYY-MM-DDTHH:MM`，带时区的按时区换算）与 `within_hours`（1~12，默认 3）。带了出发时间：有日期的名额只返回时段与 `[出发, 出发 + within_hours]` 重叠的（不按天的单不受影响），不再按「现在有空」那一段。格式不对 `gig_depart_invalid`；早于一刻钟前 `gig_depart_past`；晚于 7 天后 `gig_depart_too_far`；`within_hours` 超范围 422。返回多 `depart_at`、`within_hours`（没带是 null） |

新错误码进 `i18n.ts`。SDK：`gigAlong` 的入参多 `depart_at`、`within_hours`；`GigAlong.depart_at`、`within_hours`；共享函数 `departAt`（「今天 / 明天」+「HH:MM」换成北京时间的 `YYYY-MM-DDTHH:MM`；没填是 undefined，写错是 null）、`departLine`（结果上的一句「按 01-07 08:30 出发、之后 2 小时内的名额筛」）、`DEPART_HINT`。

## 4. 两端

- **Web** 接单页「顺路单」多一个「出发：现在 / 今天 / 明天」；选了今天或明天，再填几点、之后几小时（1 / 2 / 3 / 4 / 6）。时间没写或写错不发请求，就地说明。结果上方写一句按什么筛的。
- **App** 顺路单里多「今天 / 明天」与「几点出发」输入（空着 = 现在），之后 3 小时；写错不发请求；结果上方同一句。

## 5. 隐私、授权与边界

- 出发时间不入库、不进日志，只用于这次筛选；起点终点的处理不变（常用地点粗化到约 1 公里，当前位置只用于这次计算）。
- 最多看 7 天以内：再往后的名额还会改时段、被接走，看了也不准。

## 6. 闸门与红验
