
# 144 平台财务按期间报表；合约导出与证据包写明时区

> 状态：本批实现（V172）。编号 FIN-061、TZ-069。
> 来源：台账 FIN-061「平台财务只有累计数，没有按期间报表：本月佣金 / 本季结算看不到」、TZ-069（143 号「没做的」）；BACKLOG V172。
> 只增不减：`GET /admin/platform-finance` 的累计口径不变；新增按期间的报表与导出。
> 写明的行为变化：合约导出文本里「结算凭证」各行的时间从 ISO UTC 改为北京时间，并在小标题写明「北京时间 UTC+8」；证据包多一个 `time_zone` 字段说明口径（时间本身仍是 ISO UTC，便于机器核验）。

## 0. 要解决的问题

- 财务对账、报税、给投资人看数都按月 / 按季，而后台只有「累计佣金、已结算、余额」三个数；要知道本月佣金只能导出流水自己算。
- 自己算还容易算错：流水时间是 UTC，按 UTC 切月会把每月 1 日北京时间 0~8 点的单算进上个月。
- 合约导出是给人看、交给律师的文本，时间却是 `2026-10-14T00:30:00Z` 这种裸 UTC，读的人会以为是凌晨零点半。

## 1. 业界怎么做（带来源链接）

- **按会计期间出报表，期初 + 本期发生 = 期末**：《企业会计准则——基本准则》第七条规定会计分期（年度与中期：半年度、季度、月度），报表按期间列示；本期净额与期初、期末余额的勾稽是最基本的自检。
- **按业务所在时区切期间**：Stripe 的余额报表按账户所在时区出月报并在报表上写明时区（<https://docs.stripe.com/reports/balance>）。

## 2. 数据

无新表、无迁移。数字全部来自平台账户（`user_id = 0`）的资金流水——与累计口径同一个事实来源。

## 3. 接口

| 编号 | 内容 |
|---|---|
| FIN-061a | `GET /admin/platform-finance/periods?granularity=month|quarter&start=YYYY-MM&end=YYYY-MM`：北京时间自然月 / 季度；默认最近 12 个月 / 4 个季度；一次最多 24 个期间（`period_range_too_long`），结束早于开始（`period_range_invalid`）；财务角色 |
| FIN-061b | 每个期间：佣金收入与笔数、结算划出、补贴支出、其他调整（没归类的科目不会漏，进「其他」）、本期净额、期初 / 期末余额（各自独立查询），以及自检「期末 − 期初 = 本期净额」 |
| FIN-061c | `GET /admin/platform-finance/periods/export`：CSV，期间起止写成北京时间并在表头写明；导出进审计 |
| TZ-069 | 合约导出的结算凭证改为北京时间并写明；证据包写明「时间均为 UTC，换算北京时间加 8 小时」 |

## 4. 两端

- **Web 管理后台「平台财务」**：多一块「按期间」：按月 / 按季度切换，新的在上；期末与期初对不上的期间标出来；导出 CSV（说明时区、已记入审计）。
- **App**：管理后台只在 Web，不涉及；合约导出与证据包的时区说明两端共用服务端文本。

## 5. 隐私、授权与边界

- 报表与导出只给财务角色（141 号）；只含平台自己的账，不含任何用户个人信息。

## 7. 没做的

- **FIN-062 按期间的成交额（GMV）与代扣税额**：GMV 要按放款流水跨用户汇总，代扣税额在独立专户（与平台收入分开），各自出表时口径要和财税确认后再做。
- **FIN-063 报表锁账**：已出过的期间不能再变（补记只能记在当期），要先定补记规则。
