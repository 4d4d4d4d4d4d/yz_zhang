
# 147 团队邀请链接

> 状态：本批实现（V175）。编号 TEAM-066（含 TEAM-066a~e）。
> 来源：136 号 spec「没做的」与台账 TEAM-066「团队没有邀请链接（现在由所有者填对方用户编号加人）」；BACKLOG V175。
> 只增不减：所有者按用户编号加人、改角色、改额度、移出（TEAM-065）都不变；新增一条「发链接、对方自己加入」的路。

## 0. 要解决的问题

所有者要加人，只能填对方的用户编号——对方得先把编号报过来，而编号藏在个人空间的地址里。真实的做法是发一条链接，对方点开、看清楚、自己加入。

## 1. 业界怎么做（带来源链接）

- **可配置有效期与次数的邀请链接**：Slack 的工作区邀请链接可设有效期并随时停用（<https://slack.com/help/articles/201330256-Invite-new-members-to-your-workspace>）；Discord 的邀请可设过期时间与最大使用次数（<https://support.discord.com/hc/en-us/articles/208866998>）。
- **令牌只存哈希、只显示一次**：与本平台 API Key 同一条道理（54 号 spec）。

## 2. 数据（迁移 `c1d220260025`，SQLite 与 Postgres 都验过）

| 表 | 字段 |
|---|---|
| `team_invites` | 团队、令牌哈希（唯一）、加入后的月度额度、最多使用次数、已用次数、生成人、到期时间、作废时间 |

## 3. 规则与接口

| 编号 | 内容 |
|---|---|
| TEAM-066a | `POST /teams/{id}/invite-links`（所有者）：额度、次数（1~50）、天数（1~30，默认 7）；令牌只在响应里出现一次，库里只存哈希；同时有效的链接最多 20 条（`team_invite_limit`） |
| TEAM-066b | `GET /teams/{id}/invite-links`、`POST …/{link}/revoke`（所有者）：每条的状态（有效 / 已用完 / 已过期 / 已作废）与已用次数，不再显示令牌 |
| TEAM-066c | `GET /team-invites/{token}`（登录后）：团队名、邀请人、角色（普通成员）、额度、有效期、我是否已经是成员；**不给成员名单** |
| TEAM-066d | `POST /team-invites/{token}/accept`：只能把自己加进去，一律普通成员、额度按链接；已是成员 `already_member`；AI 助理 / 合作体 / 团队账号不能加入；无效统一 `team_invite_invalid`（说清可能是过期、用完或作废）；使用次数用条件更新占位，两个人抢最后一个名额只有一个能进 |
| TEAM-066e | 对象级授权总表：`/team-invites/` 归「自己」——令牌本身就是授权 |

## 4. 两端

- **Web**：团队成员一块下面多「邀请链接」：设额度与次数生成（只显示一次）、列表与作废；新页面 `/teams/join/:token`：说清团队、邀请人、额度与有效期，再「加入团队」。
- **App**：团队成员里「生成并分享邀请链接」（交给系统分享；没配网页地址时只分享邀请码）；团队页「用邀请链接加入团队」：粘贴链接或邀请码，先看清楚再加入。

## 5. 隐私、授权与边界

- 预览不暴露成员名单与团队财务；加入后才按成员的权限看。
- 通过链接只能成为普通成员；提成管理员、提额度仍是所有者手动做（TEAM-010 的「审批闸门不能自己绕过」）。
