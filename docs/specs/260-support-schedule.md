
# 260 按排班表自动暂停与恢复接单

> 状态：本批实现（V287）。编号 ESCA-068。
> 来源：256 号 spec「没做的」——「按排班表自动暂停 / 恢复（每周几、几点到几点在岗）」；BACKLOG V287。
> 只增不减：临时暂停（240 号）、主管替人暂停 / 恢复（248、256 号）都不变；不设排班的人行为与以前完全一样，`my-categories` 的响应也不多字段。

## 0. 要解决的问题

240 / 256 号的暂停要有人记得点。天天如此的上下班却每天都得点一次；忘了点，下班后的新工单照样分到不在线的人手上，超时提醒也先叫他。

## 1. 业界怎么做

客服系统一般给坐席配「工作时间 / 排班」，排班以外自动置为离开、不进自动分配，到点自动上线；临时请假另用手动状态，两者叠加。（本批没有另找外部来源。）

## 2. 规则

- 排班：一组时段，每段是「周几（0=周一）+ 几点到几点」，**北京时间**，含开始不含结束；结束可以写 `24:00`。跨午夜拆成两段。最多 21 段。
- **在岗** = 没有暂停，且（没设排班，或现在落在某一段里）。不在岗的人：自动分配跳过（237 号）、超时提醒先叫别人（234 号）；全员都不在岗时照旧叫全部（不让工单没人管）。
- 没设排班 = 一直在岗（与以前一样）；传空列表即取消排班。
- 排班以外不是「暂停」：`paused_until` 仍只表示临时暂停，另用 `on_duty` 说明在不在排班里。
- 结束不晚于开始 → 400 `support_schedule_bad_window`；格式不对 → 422。
- 进审计（`support_schedule`）。

## 3. 数据

`support_agent_scopes.schedule`（JSON，可空；迁移 `c1d220260064`）。随这一行一起走：注销、导出沿用原有处置（客服范围是后台配置，不进用户数据导出）。

## 4. 接口

| 接口 | 说明 |
|---|---|
| `PUT /admin/support/my-schedule` | 客服角色；`{windows: [{weekday, start, end}]}`；返回 `{schedule, on_duty}` |
| `GET /admin/support/my-categories` | 设了排班时多带 `schedule`、`on_duty`（没设时响应不变） |
| `GET /admin/support/agents` | 每行多 `on_duty`、`schedule` |

SDK：`setMySupportSchedule`；类型 `SupportScheduleWindow`、`SupportScheduleResult`，`SupportScope.schedule? / on_duty?`，`SupportAgentStatus.on_duty / schedule`。登记：后台角色表、后台覆盖表、i18n、功能面清单。

## 5. 两端

- **Web 后台工单台「我负责」一行**：显示排班与「现在在 / 不在排班里」；「设排班 / 改排班」勾周几、填上下班时间保存（勾的每一天一段）；「取消排班」。
- **Web「客服状态」（主管）**：没暂停但不在排班里的写「不在排班里」，并列出排班。
- **App**：后台只在 Web，不涉及。

## 6. 隐私、授权与边界

只能设自己的排班（客服角色）；财务等其他角色 403。时间一律按北京时间判断（与工作台 `local()` 同一口径）。
