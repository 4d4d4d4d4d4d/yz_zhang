
# 402 举报超时叫醒合规

> 状态：本批实现（V429）。编号 RISK-018。
> 来源：上一批（V428，401 号）「没做的」。举报有了处理时限，超时的只在队列里标红；没人打开后台，就没人知道。客服工单那边早有超时升级（ESCA-051，150 号），举报这边还没有。
> 只增不减：新增一个定时任务和一个列；举报的提交、处置、队列、「我的举报」都不变。

## 0. 要解决的问题

诈骗举报超过 24 小时没人处理，平台要有人被点名，而不是等审核员哪天打开后台才看到。

## 1. 业界怎么做（带来源链接）

- 《网络信息内容生态治理规定》第十六条要求「及时受理处置」。常见做法是超时自动升级给更高一级的人，并且只点名真正能处理的人。
- 本平台工单升级（ESCA-051）已经定下的两条：
  - 发给全体管理员，等于谁都没被点名；
  - 每级只叫一次。
- 本轮没有引用外部报道链接。

## 2. 数据

`reports.escalated_at`（迁移 `c1d220260098`，SQLite 与 PostgreSQL 都做过 `upgrade head` 和 `check`）：已经叫过合规的时间，每条只叫一次。

## 3. 接口

`POST /admin/jobs/escalate-reports`：调度器每小时一次（进调度表 `app/core/jobs.py`，锁名 `report_escalations`），管理员也能手动触发；不带调度凭证、也没登录的调不动。

| 规则 | 说明 |
|---|---|
| 找哪些 | 没处理、还没叫过、已超时限（违法、诈骗、色情 24 小时，其余 72 小时，见 401 号）的举报 |
| 叫谁 | 有合规角色的管理员（超级管理员也算）：能下架、能封禁的人。<br>客服不叫，因为不能封禁 |
| 怎么叫 | 一人一轮一条汇总通知：条数、其中急的几条、编号（最多列 20 个），并说去后台勾「最急的在前」。<br>通知必达，不受偏好开关影响 |
| 返回 | `{escalated, notified}` |

## 4. 两端

不涉及界面：通知走已有的通知中心，两端都能看到；后台队列已经有「最急的在前」和超时标红（401 号）。

## 5. 隐私、授权与边界

通知里只有举报编号和条数，不带举报人是谁，也不带举报说明。
