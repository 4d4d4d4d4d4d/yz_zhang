# 441 App 补齐发动态、草稿、点赞与评论

> 状态：本批实现（V468）。编号 APP-074f（APP-074「网页有而 App 没有的 SDK 方法」的又一批）。
> 来源：台账 APP-074；439 号第 7 节留下的「内容的发布、编辑与评论、点赞、草稿」。
> App 的内容流只能看、只能关注作者，发不了动态、点不了赞、回不了评论。只有手机的执行方没法在个人门户（VISION V-1）上展示自己做了什么，也接不住别人在评论里的询问。
> 只增不减：服务端与 SDK 方法都不改，网页不改；App 内容流原来的卡片、关注、举报、点赞评论数都照旧，只是多加东西。

## 0. 要解决的问题

App 用上这几个 SDK 方法：
- `createContent`（发布、存草稿）；
- `myDrafts`、`editContent`、`publishContent`；
- `likeContent`；
- `contentComments`、`commentContent`。

规则都在服务端：
- 发布与草稿的状态（已发布的再发布返回 409，App 原样说出来）；
- 点赞幂等，返回当前是否已赞和总数；
- 评论的审核与举报。

## 1. 业界怎么做（带来源链接）

社区类 App 的内容流顶部都是发帖入口，草稿放在发帖处；点赞计数以服务端返回为准（并发点赞时本地加一会算错）；评论展开时才拉。本轮没有引用外部报道链接。

## 4. 两端

- **App**（新文件 `app/contentCompose.tsx`，挂在「发现 → 内容」里）：
  - `ComposeBlock`，放在内容流最上面：
    - 写一段话，可以「发布」或「存草稿」，内容去掉首尾空格，空的不让发；
    - 发布后刷新内容流，存草稿不刷新；
    - 下面列「我的草稿」，可以「改」（PATCH 保存）或者单独「发布」。
  - `ContentActions`，放在每张卡片下面：
    - 赞和取消赞，以服务端返回的总数为准；
    - 评论：展开时才拉，收起不拉；发送后计数加一并重拉；
    - 出错时原样说出服务端的理由。
- **Web**：不改（`Community.tsx`、`BlogEditor.tsx` 早就有）。

## 5. 隐私、授权与边界

- 草稿只拉自己的（`/contents/mine?status=draft`）。
- 评论与点赞按服务端的可见性与审核放行。
