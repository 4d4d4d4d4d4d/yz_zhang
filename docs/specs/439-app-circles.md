# 439 App 补齐圈层

> 状态：本批实现（V466）。编号 APP-074e（APP-074「网页有而 App 没有的 SDK 方法」的又一批）。
> 来源：台账 APP-074。V465 之后清点：网页调用、App 没调用的 SDK 方法还有 196 个，去掉后台运营用的，用户侧还有 136 个。
> 418 号第 7 节点过名「内容与评论、圈子、草稿」，这一批先做圈层，因为它卡住接单：
> - 发单人可以把任务发成「仅圈层可见」，定向发给能力圈、地域圈里的人；
> - 执行方多半只有手机，App 上看不到圈子、进不了圈，圈内任务板一个字都看不到。
>
> 只增不减：服务端与 SDK 方法都不改，网页不改；App「发现」页多一个「圈层」分段，原来四段照旧。

## 0. 要解决的问题

App 用上这几个 SDK 方法：
- `circles`、`getCircle`；
- `joinCircle`；
- `circleFeed`、`circleTasks`；
- `createContent`（发圈内帖）；
- `createCircle`。

规则都在服务端：
- 开放加入还是要审核；
- 信用分门槛不够时服务端拦，App 原样说出理由；
- 圈内动态与任务只对成员可见。

## 1. 业界怎么做（带来源链接）

社群类产品在移动端都把「我加入的圈子」与圈内板块放在发现页的同一层；没加入的只看简介和门槛。本轮没有引用外部报道链接。

## 2. 数据

不涉及。

## 3. 接口

不改接口。SDK 新增 `packages/core/src/circles.ts`，两端共用：
- `CIRCLE_KIND_LABEL`：兴趣圈、能力圈、地域圈；
- `circleJoinLabel()`：开放的写「加入圈层」，要审核的写「申请加入」，已加入和待审核的不显示按钮；
- `circleSummary()`：有描述用描述，没有就写人数；有信用分门槛的写出来；人数畸形时当 0。

## 4. 两端

- **App**（新文件 `app/circles.tsx`，挂在「发现」的「圈层」分段）：
  - 列表：每个圈层的类型、人数，写明已加入或待审核。
  - 进圈：简介、门槛，加入或申请加入的按钮。
  - 已加入的，另外看得到：
    - 圈内任务板，点任务打开详情；
    - 圈内动态，可以发帖（发帖前去掉首尾空格）。
  - 没加入的，不去拉圈内内容。
  - 建圈：类型、技能标签或城市、开放还是审核；名字为空不让建。
- **Web**：不改（`web/src/pages/Circles.tsx` 早就有）。

## 5. 隐私、授权与边界

- 圈内动态与任务由服务端按成员身份放行。
- App 对没加入的圈不请求圈内内容，免得给人「能看到」的错觉。
