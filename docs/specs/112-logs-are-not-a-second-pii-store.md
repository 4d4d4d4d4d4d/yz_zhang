
# 112 日志不是第二份个人信息库（SEC-065）

> 状态：本批实现（V137）。
> 承接用户的商业化要求：「实际商业化的一些问题，例如部署的并发，安全性，也考虑解决一下」。

## 0. 为什么是它

日志会成为第二份个人信息库：它被拷进日志平台、交给外包排障、保留得比业务库还久，
而且**不在「删除我的数据」的范围里**——用户注销后业务库里的手机号被抹掉了，日志里那一份还在。
台账 SEC-065 记着「日志有没有写进手机号/证件号/token，没有系统性检查」。

## 1. 量过之后（不是读代码得来的）

按 Dockerfile 那条命令起真 uvicorn（INFO 级别），跑完整笔闭环（`scripts/smoke.py`），逐行读输出：

| # | 发现 | 后果 |
|---|---|---|
| 1 | **51 行里 26 行不是我们的格式**：uvicorn 自带的访问日志与启动/错误日志走它自己的格式化器 | 这一半**没有经过任何脱敏**，也没有 request_id |
| 2 | uvicorn 访问日志带**完整查询串**与客户端 IP | `/search?q=…` 的原始搜索词每条都进日志——V127 刚定下搜索词是个人信息（不存身份、k-匿名） |
| 3 | SQLAlchemy 异常默认带**绑定参数**（`[parameters: ('13812345678', …)]`），引擎没开 `hide_parameters` | 注册撞唯一约束的那一次 500，日志里就是手机号与密码哈希；未处理异常的堆栈正是由 uvicorn 原样打出的（见 1） |
| 4 | 我们自己的格式化器把**异常堆栈整个丢掉**（只输出 message） | 生产出 500 时日志里只有一句「request」，查不了；而直接补回堆栈又会带出 3 |
| 5 | 脱敏只认三种数字（手机号 / 证件号 / 卡号） | 不认本平台的 token、`Bearer …`、`password=`、`sms_code`、邮箱 |
| 6 | 没匹配上路由的请求，指标标签与日志用的是**原始路径** | 任何人请求随机 URL 就能让指标标签无限增长（进程内存跟着涨）；URL 里塞的东西原样进日志 |

业界做法（OWASP 日志备忘单的要点、各家日志平台的 PII 处置建议）一致：**首选不写**，脱敏是第二道；
脱敏要作用在最终输出的字符串上（包括异常文本）；脱敏出错时丢内容、不丢脱敏。

## 2. 做了什么

- **一个出口**：`setup_logging` 把 `uvicorn` / `uvicorn.error` 汇入根处理器（JSON + 脱敏），
  关掉 uvicorn 的访问日志（访问日志由 `ObservabilityMiddleware` 记：路由模板、不记查询串）。
- **不写**：两个引擎（SQLite / Postgres）都开 `hide_parameters=True`——SQL 异常里不再有绑定参数。
- **脱敏扩到凭据**：本平台 token（base64 载荷 . 64 位 HMAC）、`Bearer …`、`key=value` 与 JSON 形式的
  `password / token / secret / api_key / sms_code / verify_code / captcha / id_number / authorization / signature`、
  邮箱（留首字母与域名）、SQL 参数块（第二道）。**不吃排障要用的东西**：错误码、状态、业务 id 保留。
- **堆栈补回来、并过脱敏**：格式化器输出 `exc` 字段；未处理异常由中间件记一次（带 request_id），
  uvicorn 那条不带 request_id 的重复记录过滤掉。
- **脱敏失败兜底**：格式化本身出错时输出「content dropped」，不输出原文。
- **未匹配路由只记一个标签** `<unmatched>`。

## 3. 闸门（`test_log_hygiene.py`，15 条）

| 闸门 | 红验 |
|---|---|
| **真进程**：按 Dockerfile 的 CMD 起 uvicorn，注册 / 登录（含错误密码）/ 按手机号与邮箱搜索 / 带 token 的 404，**每一行都是 JSON** | uvicorn 错误日志不汇入 → 红 |
| 手机号、密码、搜索词、邮箱、token 都不原样出现在任何一行 | 不认 Bearer → 红 |
| 任何一行都没有查询串；访问日志只有路由模板；未匹配的只记 `<unmatched>` | 重新打开 uvicorn 访问日志 → 红；未匹配记原始路径 → 红 |
| 撞唯一约束的 500：堆栈在（`IntegrityError`），手机号不在 | 堆栈丢掉 → 红；SQL 参数不藏 → 红 |
| 凭据脱敏（Bearer、`password=`、JSON 里的验证码、SQL 参数块、邮箱、证件号） | — |
| 脱敏不吃错误码、状态、业务 id | — |
| 格式化失败时丢内容 | 不兜底 → 红 |
| 应用代码里没有 `print` | — |
| 扫描器自检：埋一个手机号必须被扫到 | — |

八条变异全红。过程中有一条变异是绿的：只去掉 `access.disabled` 不红——因为 `propagate=False` 与
`disabled=True` 是**互为备份的两道**，去掉任何一道另一道都兜着。真正的退化是两道一起去掉（重新打开访问日志），
那一条为此补了「任何一行都不许出现查询串」的断言后才红。

## 4. 这一批没做的

- **日志保留期与访问控制**（`SEC-065b`）：日志平台上谁能看、留多久，是部署侧的配置，不在代码里；
  上线手册里写了要求（OPERATIONS），没有闸门。
- **自由文本里的人名**：与 KB-065 同一个问题——平台不知道「李强」是谁。这里只能保证我们自己**不主动写**
  请求体与 SQL 参数进日志。
