
# 348 资质审核抽检

> 状态：本批实现（V375）。编号 CERT-053。
> 来源：台账「欠」CERT-053：「审核员没有分级与抽检，放水只能事后审计」。
>   最近几轮受资质门槛的类目越来越多：代驾、代办年检、住院护工、私房烘焙、上门宴席。所以把它排到第四十轮排期的最前面，场景发掘顺延到 V376。
> 只增不减：资质申请、核准、驳回、撤销的接口与行为不变；核准后多一步抽检，抽检不拦已生效的资质。

## 0. 要解决的问题

资质一核准就生效，准入只看一个审核员的判断。审核员看错了、放水了，平台只能等出了事再翻审计日志。受资质门槛的类目越来越多，其中不少和人身安全、未成年人直接相关：开别人的车、在病房陪护、做几十桌的饭、接近孩子。

## 1. 业界怎么做

人工审核的质量控制通常靠抽检复核（质检）：按比例抽取已审结的案子交给另一位审核员复看，并统计每位审核员的差错率，用于培训和分级。本批没有另找外部来源；做法与本平台已有的四眼（V176、V361）一致：第二个人看，原审核员不能复看自己的。

## 2. 规则

- **抽什么**：
  - 核准时，高风险资质全部抽检：无犯罪记录证明、驾驶证（三年以上驾龄）、医疗护理员培训合格证明、低压电工作业操作证、高处作业操作证、开锁备案证明；
  - 其他资质按 10%（`SPOT_CHECK_RATE`）抽；
  - 驳回的不抽；同一份申请只抽一次。
- **抽不抽怎么定**：按申请编号与平台密钥算哈希。同一份申请结果固定、可复算，审核员事先猜不到。
- **复看**：
  - 只给合规审核员；原审核员不能复看自己审的（403 `cert_spot_self`）；
  - 维持就结束；
  - 推翻要写理由（至少 4 个字，`cert_spot_reason_required`），资质立刻撤销（与人工撤销同一处）、通知持证人；
  - 处理过的不能再处理（409 `cert_spot_decided`）；
  - 维持、推翻都进审计。
- **审核员统计**：列表一起给出每位审核员被抽了多少、被推翻多少，推翻多的排前面。
- **抽检不拦准入**：资质核准即生效，抽检是事后复核。

## 3. 数据 / 接口

- 新表 `cert_spot_checks`，迁移 c1d220260089，SQLite 与 Postgres 都验过升级、降级、再升级。
- 接口（只给合规角色，已登记进角色表与后台入口表）：
  - `GET /admin/cert-spot-checks?status=`：返回 `{items, reviewers}`
  - `POST /admin/cert-spot-checks/{id}/confirm`：请求体 `{note}`
  - `POST /admin/cert-spot-checks/{id}/overturn`：请求体 `{note}`
- 共享 SDK：
  - 类型：`CertSpotCheckItem`、`CertSpotReviewerStat`、`CertSpotCheckList`
  - 方法：`certSpotChecks` / `confirmCertSpotCheck` / `overturnCertSpotCheck`
  - 三个新错误码进 i18n。

## 4. 两端

- **Web 后台**：「受限类目资质待核验」下面多「资质抽检」。
  - 列出待复看的与每位审核员的抽检、推翻次数；
  - 自己审的不给按钮；
  - 推翻写够理由才能点。
- **App**：没有管理后台，不涉及。

## 5. 隐私、授权与边界

- 只给合规角色；抽检列表只有资质名、申请编号、原审核员，不带证件影像（复看时到资质列表里看）。
- 推翻的通知只写理由与「可以补充材料后重新申请」。
