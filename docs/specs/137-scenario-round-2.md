## 0. 要解决的问题

1.7 节的第一批人群是 OPC、接单者、发布方、想成为专家的人。场景包引擎的人群枚举里还有 `creator`（创作者）和 `buyer`（发单方），但一个包都没有。
按 skill 的方法走一轮：找信号 → 写场景卡 → 打分 → 写成场景包。

### 场景卡 A：自由创作者（设计、文案、剪辑）

| 项 | 内容 |
|---|---|
| 人群 | 接设计、文案、剪辑单的个人（平台类目「设计」等） |
| 要办的事 | 把甲方一句话需求变成能报价、能验收的单；控制改稿；收到钱；说清版权 |
| 现在怎么办 | 微信里来回问，做完才发现尺寸或用途不对；改稿靠自觉；版权不提 |
| 痛点 | 频率：每单都有（周）；严重度 4：返工与拖欠直接是钱 |
| AI 能做几成 | 0.6：需求单缺项检查、追问话术、报价与改稿约定清单可以做；谈价、确认、签授权必须人做 |
| 商业价值 | 抽佣（需求写清的单成交率更高）、减少纠纷成本 |
| 交付成本 | 2：一个种子文件 + 一个纯文本规则工具（需求单体检） |
| 风险关口 | 钱（money）、版权授权（sign）、对外发出报价（publish） |

### 场景卡 B：小店临时帮手

| 项 | 内容 |
|---|---|
| 人群 | 个体小店、小商家（开业、促销、盘点、深度保洁、同城取送货） |
| 要办的事 | 临时找个人干一天或几小时的活 |
| 现在怎么办 | 找熟人、在群里喊；价钱拍脑袋；人来了不知道干什么 |
| 痛点 | 频率：每月（节假日、活动）；严重度 4 |
| AI 能做几成 | 0.5：写清任务说明与验收标准、给成交价参考、讲清用工常识；发布、选人、付款、签协议由人做 |
| 商业价值 | 抽佣；发单方是平台的需求侧 |
| 交付成本 | 1：只有数据（复用 `gig.quote` 成交价参考与已有任务模板机制） |
| 风险关口 | 钱、对外发布任务、签署；**长期固定排班属于用工关系，平台的临时单不能替代**——助手必须把这一点说在前面 |

## 1. 业界怎么做（带来源链接）

- **拖欠付款**：Remote《State of Freelance Work 2025》称 85% 的自由职业者至少有时遇到拖欠；Bonsai 对 10 万+ 自由职业者三年开票数据的分析是 29% 的发票逾期（均转引自 <https://agiled.app/statistics/late-payment-statistics>，二手汇总，引用前应核对原报告）。平台的托管 + 自动验收正好接得住。
- **过多轮修改**：Pica9 对 100+ 平面设计师的调查称几乎所有人都经常遇到过多轮修改（<https://www.pica9.com/blog/the-price-of-perfection>，厂商调查、方法说明不全）。通行做法是在合同里约定修改次数、超出的另算——平台对应变更单（SC-007b）。
- **门店排班**：Toast 对 624 名美国餐饮员工的调查（<https://pos.toasttab.com/blog/on-the-line/restaurant-labor-shortage>）与 Turnozo 对 228 名经理的整理（<https://turnozo.com/blog/what-228-managers-said-about-scheduling>）都指向早晚班与节假日最难排人；两者都是排班软件厂商，有利益相关。
- **法规**：委托作品的版权归属（《著作权法》第十九条）、非全日制用工（《劳动合同法》第六十八至七十二条）、禁止招用未满十六周岁（《劳动法》第十五条）、非全日制工伤保险（劳社部发〔2003〕12号）——都写进知识条目并标出处。

## 4. 两端

场景包的用户侧界面（Web `/packs`、App「我的 → 服务包」）与问助手接口两端早已接上（V148）；新包上线后两端直接可见、可启用、可提问，不用改前端。Web「接单者工具」页的链接方式同样适用于以后在设计类任务旁放「问需求与改稿顾问」的入口（见「没做的」SCN-106）。

## 5. 隐私、授权与边界

- 需求单体检只看用户这一次贴进来的文字，不落库、不读别人的任务或私聊。
- 知识条目里的法律内容只陈述条文与平台规则，写明「具体纠纷请咨询律师」；答不了的转「法律咨询」类目发单。
- 碰钱、签署、对外发布的事，助手只给草稿与清单。
