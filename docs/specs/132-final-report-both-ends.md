
# 132 母任务结项报告上两端：实付按合约放款、是否全部完成

> 状态：本批实现（V161）。编号 AGT-090~091。
> 来源：131 号 spec「没做的」AGT-090；SDK 分诊表里 `finalReport` 一直没有任何一端调用（ORC-066 那一组的最后一个）。BACKLOG V161。
> **更正**：131 号把 `finalReport` 写成了「编排的最终报告」；核对代码后它是**拆解母任务**的结项报告（`GET /tasks/{id}/final-report`，AI-DEC-025），与编排无关。
> 只增不减：原有字段（`total_cost_cents` 等）口径不变，只多 `paid_cents` 与 `ready` 两个字段。

## 0. 要解决的问题

一个拆成多步的项目做完了，发布方看不到一页「花了多少、用了多久、谁交付了什么」；接口早就有，两端都没接。
而且原接口的「实际支出」是已完成子任务的**预算**合计——按报价成交、纠纷分账时，这个数和真正付出去的钱对不上。

## 1. 业界怎么做

项目管理工具的结项报告（project close-out report）一般给：预算对比实际、工期、交付清单、遗留问题。这里取前三项，实际花费按资金流水（合约放款）算，和合作驾驶舱同一口径。

## 2. 数据与接口

不新增表。`GET /tasks/{id}/final-report`（只有发布者）多两个字段：

| 字段 | 含义 |
|---|---|
| `paid_cents` | 按合约放款算的实付（与合作驾驶舱 `budget.paid_cents` 同一函数算出） |
| `ready` | 所有步骤（叶子、不含取消的）都已完成 |

## 3. 两端

- **Web 任务详情 → 合作驾驶舱**：全部步骤完成后出现「看结项报告」：总结、实付（按合约放款）、计划、用时、交付清单（可点进每一步）。
- **App 合作驾驶舱**：同样的按钮与内容。
- 还有步骤没完成时不出现。

## 4. 闸门与红验

| 闸门 | 红验 |
|---|---|
| 实付按合约放款，不是预算合计 | 改成预算合计 → `test_report_shows_real_payout…` 红（按报价 80 元成交的那一步让两种口径不同） |
| 全部完成才 ready | 恒为真 → 同上红 |
| 原口径不变 | `test_v3_features.py` 的结项报告断言照旧通过 |
| 只有发布者 | 执行方 403 / 404 |
| 响应形状 | `_assert_inline_shape(…, "finalReport")` |
| 两端 | `web/src/FinalReport.test.tsx`、`app/finalReport.test.tsx` |

## 5. 没做的

- **AGT-091 编排（mission）达标后的总结页**：编排有时间线与评审分，但没有一页面向发起人的总结（花了多少、几轮、哪些步骤整改过）。排进 BACKLOG V162。
