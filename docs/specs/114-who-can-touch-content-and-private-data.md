
# 114 谁能碰作品、私聊与证件：行为验与授权总表（SEC-060f / SEC-061）

> 状态：本批实现（V139）。设计见 [111 号](111-audit-industry-and-remaining-design.md) 第 4.2 节。

## 0. 为什么

V124 把 166 个带资源 id 的端点全部写进了归属规则表，并对钱与身份那一批做了两账号行为验。
台账还剩两条：内容类只有规则、没有人拿 B 的 token 碰过 A 的对象（SEC-060f）；
授权判据没有总表，「管理员能不能看私聊与证件影像」没有明文——**沉默等于默认可以**（SEC-061）。
OWASP API1:2023（BOLA）的业界共识是：扫描器判断不了哪个对象该给谁，只能靠显式判据 + 换账号换 id 的测试。

## 1. 第一次跑就红的（V139 之前）

**作品（四个账号：作者、路人、粉丝、圈友）**

| # | 洞 | 后果 |
|---|---|---|
| 1 | `GET /contents/{id}` 只看「已发布」，不看可见性 | 设成**仅自己可见**的作品，任何登录用户按 id 就能读；「仅粉丝」「仅圈内」同样 |
| 2 | `GET /contents/{id}/comments` 不要登录、不看状态、不看可见性 | 草稿、已删除、仅自己可见的作品下面的评论，**未登录也能读** |
| 3 | 点赞与评论只看「已发布」 | 不是粉丝也能在「仅粉丝」的作品下面评论——评论本身就泄露了作品存在 |
| 4 | 按作者列作品只给 public | 粉丝在作者主页看不到「仅粉丝」的作品——同一件作品，按 id 读与按作者列的结论不一样 |

**管理员**

| # | 洞 | 后果 |
|---|---|---|
| 5 | 会话鉴权「参与者或管理员」一句放行 | 任何管理员能读任何人的私聊（**连撤回的原文**），**不留痕** |
| 6 | 同一个判断也用在发消息上 | 管理员能**往别人的私聊里发消息** |
| 7 | 撤回原文按 `is_admin` 显示 | 一个管理员在**自己的**私聊里能看到对方撤回的内容 |
| 8 | 敏感材料读取「本人或管理员」 | 任何管理员能读任何人的证件影像，不留痕 |

## 2. 做了什么

- **作品只有一个可见性判据** `can_view`：按 id 读、按作者列、评论列表、评论、点赞都用它；
  看不见一律 404（403 会告诉别人这个 id 上确实有东西）；评论列表要登录。
- **私聊**：参与者能读能写；管理员不是参与者时**只能读**，必须写明理由（≥8 字）并进审计；
  撤回原文只在这条审计读取里可见。
- **证件影像**：管理员每次读取都进审计；审这份材料所属的资质申请时自动记「资质审核」，
  其余情形必须写明理由；审计**先于读取落库**（读取失败也知道有人试过）。
- **授权总表** `docs/AUTHZ-MATRIX.md`：五种判据、作品可见性、以及代码里每一处管理员绕过——
  14 处「职责内」（客服与仲裁要用）与 2 处「受限」（写理由 + 审计）。

## 3. 闸门

`test_content_authz.py`（14 条）与 `test_authz_matrix.py`（8 条）：

| 闸门 | 红验 |
|---|---|
| 四种可见性 × 四个账号按 id 读（看不见是 404） | 去掉 `can_view` 回到只看「已发布」→ 红 |
| 评论跟着作品走；未登录不给；草稿与已删除下的评论不可读 | 评论列表去掉鉴权 → 红 |
| 看不见的作品不能评论、点赞，计数不变；粉丝可以 | — |
| 路人改 / 发布 / 删别人的作品被拒且对象不变 | — |
| 按作者列与按 id 读结论一致 | 按作者列只给 public → 红 |
| 只有圈层管理员能审批与移除成员；圈层 feed / 任务 / 统计要成员 / 管理员 | — |
| 代码里每一处管理员绕过都在总表里，反之亦然 | 新加一处不写进总表 → 红 |
| 「受限」的位置真的调用审计、有「必须写理由」的分支 | — |
| 管理员不写理由读不了别人的私聊；写了能读、进审计、看得到撤回原文 | 去掉理由检查 → 红 |
| 管理员不能往别人的私聊里发消息、不能替别人标已读 | 写操作也放行管理员 → 红 |
| 管理员在自己的私聊里看不到对方撤回的原文 | 按 `is_admin` 显示 → 红 |
| 读与资质审核无关的证件影像要理由并进审计；路人一律 403 | — |

## 4. 这一批没做的

- **管理员分级**（`SEC-061b`）：只有一个 `is_admin` 位，受限访问靠「写理由 + 审计」事后可查，
  不是事前按角色（客服 / 仲裁 / 合规）拦。
- **外部渗透测试**（`SEC-062`）：需要外部机构。
