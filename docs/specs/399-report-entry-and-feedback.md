
# 399 举报入口两端补齐与处理结果反馈

> 状态：本批实现（V426）。编号 RISK-010~015。
> 来源：自查。台账 SPACE-030 写着「内容举报（SPACE-022）……举报在 web 上同样未做」；App 的代码注释却说「Web 上早就有」。查下来：
> - Web 上普通用户**一个举报入口都没有**，只有后台的处置队列；
> - App 只能在任务详情里举报任务，不能选类型；
> - 举报人提交以后再也看不到结果。
>
> 举报入口是内容平台上架和合规的硬要求，商用前必须补上。
>
> 只增不减：`POST /reports` 原来的请求体照旧能用（不传类型就是「其他」），返回多一个 `duplicate` 字段；后台处置队列多两个字段；SDK 的 `report()` 多一个可选参数；App 任务详情原来的「举报 / 拉黑」入口保留，举报换成能选类型的那一块，拉黑不变。

## 0. 要解决的问题

1. **没有入口**：普通用户在 Web 上举报不了任何东西；App 只能举报任务。私信里的诈骗、骚扰，动态里的低俗内容，冒用别人身份的个人空间，都没有地方举报。
2. **没有反馈**：交了就石沉大海，举报人不知道有没有人看、怎么处理的。
3. **队列会被冲掉**，原因有三个：
   - 不核对对象，举报一个不存在的 id 也进队列；
   - 同一个人对同一个对象能连点几十次；
   - 没有任何上限。
4. **私信可被试探**：任何人拿消息 id 去举报，就能试出哪些消息存在。
5. **审核员分不清轻重**：只有一段自由文本，诈骗和「我不喜欢」排在一起。

## 1. 业界怎么做（带来源链接）

- 《网络信息内容生态治理规定》第十六条：网络信息内容服务平台应当在显著位置设置便捷的投诉举报入口，公布投诉举报方式，及时受理处置公众投诉举报并反馈处理结果。
- 常见做法：在内容、用户主页、私信旁边放「举报」，举报时先选类型（违法、色情、诈骗、骚扰、侵权、其他），再写说明；在「我的举报」里能看到处理结果。
- 本轮没有引用外部报道链接。

## 2. 数据

`reports` 表加两列（迁移 `c1d220260097`，SQLite 与 PostgreSQL 都做过 `upgrade head` 和 `check`）：

| 列 | 说明 |
|---|---|
| `category` | 举报类型，默认 `other`，老数据也是 `other` |
| `resolved_at` | 处理时间，处置时写入 |

## 3. 接口

| 接口 | 变化 |
|---|---|
| `POST /reports` | 见下表 |
| `GET /reports/mine`（新） | 我提交过的举报（最近 50 条）与处理结果、类型表。<br>不带审核员是谁；处理结果只说「经核查没有发现违规」「已下架违规内容」「已处理违规账号」 |
| `POST /admin/reports/{id}/resolve` | 写处理时间，并通知举报人「你的举报已处理」。<br>系统自动生成的风控举报（`reporter_id=0`）不通知 |
| `GET /admin/reports` | 多 `category` 和 `category_label` |
| `GET /users/me/export` | 有举报才带 `reports`；没举报过的导出与以前一样 |

`POST /reports` 的变化：

| 项 | 说明 |
|---|---|
| 新字段 | 可选的 `category`：illegal / porn / fraud / harassment / infringement / other |
| 对象要存在 | 否则返回 404 `report_target_not_found` |
| 私信 | 只有会话里的人能举报；会话外的人也只得到 404，看不出消息在不在 |
| 不能举报自己的 | 自己发的任务、自己的内容、自己、自己的消息：400 `report_own_target` |
| 不重复 | 同一对象已有一条没处理的举报，就返回原来那条，`duplicate: true`；不算新的一次 |
| 每天上限 | 一个人 24 小时最多 20 次：429 `report_daily_limit`，带 `Retry-After` |

三个新错误码进 `packages/core/src/i18n.ts`。

## 4. 两端

- **SDK**：
  - `report()` 多一个可选的 `category`，不传时请求体与以前一样；新增 `myReports()`；
  - `reports.ts`：类型表与服务端同序，另有类型名、对象名、提交后的提示、处理结果一行；
  - `adminReports` 的类型多了 `category` 和 `category_label`。
- **Web**：
  - `Report.tsx` 的举报按钮四处用：
    - 任务详情（不是自己发的才有）；
    - 动态流（自己的不画）；
    - 别人的个人空间；
    - 私信里对方发的消息。
  - 客服页多一块「我的举报」；
  - 后台处置队列多一列「类型」。
- **App**：
  - `report.tsx` 的举报块（选类型、写说明）用在四处：
    - 任务详情，换掉原来只发说明的按钮；
    - 动态流（自己的不画）；
    - 别人的个人空间（登录后）；
    - 私信里对方发的消息（先查我是谁，查不到不画）。
  - 客服页多一块「我的举报」。

## 5. 隐私、授权与边界

- 「我的举报」只给举报人自己，不带审核员是谁，也不说对方被怎么处罚的细节。
- 私信举报只对会话成员开放，审核员要看私信全文仍走原来的「写明理由并进审计」的口子（IM 模块），这里不放宽。
- 举报说明可能含个人信息：注销时作为平台处置记录保留（与审计同一口径），不随注销删除；数据导出里给本人。
