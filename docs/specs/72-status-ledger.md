# 72 状态台账：做了什么、没做什么、哪些「没做」其实已经做了

> 每个 spec 末尾的「这一批没做的」都是**写那一批时的实况**，写完就冻在那儿了。
> 26 个 spec 里一共 101 条这样的记录，而其中**有 20 条早就被后面的批次做掉了**。
> 一个今天来读这些 spec 的人，会得到一份系统性偏悲观的印象。
>
> 这一篇是那 101 条的收口：去重、判定现状、分类卡在哪。
> 它由测试钉着（`server/tests/test_status_ledger.py`），新批次加了缺口
> 而这里没记，CI 就会红。

## 0. 三句话现状

- **闭环是通的**：发布 → 分解 → 匹配 → 合约 → 双签 → 托管 → 执行 → 交付 →
  验收 → 放款抽佣 → 互评 → 经验入库，有 1004 个后端测试与两条闭环自检钉着。
- **不能上线**：不是功能问题，是**资金存管、个税方案、可靠电子签名、
  司法存证、实名/支付/短信/内容安全供应商**这几项需要持牌机构与账号。
  这些已经硬编码成启动拦截（见 [GO-LIVE.md](../GO-LIVE.md)）。
- **最大的自查缺口**：约 88 个共享 SDK 方法两端都没有人调用。
  V91~V96 只清了「卡住钱、人身安全、账号安全」的那些。
