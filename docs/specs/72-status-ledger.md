# 72 状态台账：做了什么、没做什么、哪些「没做」其实已经做了

> 2026-10-08 合并说明：本页的 V113/V114 端点和调用数量是该批次的历史探针结果；当前产品方向和分端实现边界以 [实现核对表](../IMPLEMENTATION-MATRIX.md) 与 [Spec 88](88-individual-network-and-spaces.md) 为准。

> 每个 spec 末尾的「这一批没做的」都是**写那一批时的实况**，写完就冻在那儿了。
> 26 个 spec 里一共 101 条这样的记录，而其中**有 20 条早就被后面的批次做掉了**。
> 一个今天来读这些 spec 的人，会得到一份系统性偏悲观的印象。
>
> 这一篇是那 101 条的收口：去重、判定现状、分类卡在哪。
> 它由测试钉着（`server/tests/test_status_ledger.py`），新批次加了缺口
> 而这里没记，CI 就会红。

## 0. 三句话现状

> 这一节的数字在 V114 之前过期了很久：写着「1004 个后端测试」（真实 1200）、
> 「约 88 个共享 SDK 方法两端都没有人调用」（真实 73，且全部已交代）。
> 而 V111 刚建的计数闸门**看不见它**——那条正则要求数字后面紧跟「个测试」，
> 中间多两个字（「个**后端**测试」）就瞎了。它不会报错，它只是什么都不查。
>
> **这一篇是 README 里「现状一页看清」指向的那一页**，所以它过期的代价不是
> 排版问题，是读者对整个系统的判断错：低估已经有的保障，高估还没做的部分。
> 现在两个数字都由闸门钉着（`test_doc_counts.py` / `test_sdk_method_triage.py`）。

- **闭环是通的**：发布 → 分解 → 匹配 → 合约 → 双签 → 托管 → 执行 → 交付 →
  验收 → 放款抽佣 → 互评 → 经验入库，有 2073 个后端测试与**三条**闭环自检钉着
  （主链路 / 存管合规态 / 真浏览器联调，见 `docs/OPERATIONS.md` 4.3b）。
- **不能上线**：不是功能问题，是**资金存管、个税方案、可靠电子签名、
  司法存证、实名/支付/短信/内容安全供应商**这几项需要持牌机构与账号。
  这些已经硬编码成启动拦截（见 [GO-LIVE.md](../GO-LIVE.md)）。
- **自查缺口换了位置**：共享 SDK 266 个方法，web 调 188 / App 调 81 / 运营台调 33。
  三端都没人调的 73 个**全部有交代**（17 条有意不给端 + 56 条本台账排了期），
  未交代 0 条。**真正的缺口是两端不齐**：web 有而 App 没有的 79 个方法里，
  V113 清掉了唯一一条「服务端叫他做、而他的设备上做不到」的（提交职业资质），
  剩下的按「卡不卡住钱 / 卡不卡住法定权利」排期（见 2.2 的 APP-074）。
