
# 364 接单人「出发了」：告诉发单人和服务对象预计几点到

> 状态：本批实现（V392）。编号 SCN-122c。
> 来源：356 号 spec 第 7 节「没做的」——「链接页显示『已出发 / 预计几点到』」；台账 SCN-122c；BACKLOG V392。
> 只增不减：`progress_logs` 多一列 `eta_at`（迁移 `c1d220260091`，SQLite 与 Postgres 都 `upgrade head && check` 过）、一个接口、进度链接页的响应多两个字段（`departed_at`、`eta_at`）；打卡、上门回报、进度链接原有行为不变。

## 0. 要解决的问题

V383 给了服务对象一条进度链接，能看到「谁来、几点、到没到」。但「到没到」只在接单人打卡或交上门回报之后才有。在那之前，替爸妈发单的人和爸妈最常问的是：「人出发了吗？大概几点到？」

现在只能打电话问接单人。号码一来一回，又回到了平台外。

## 1. 业界怎么做

出行与外卖都有「司机 / 骑手已出发，预计几点到」，到达后这一条就消失。这是常见的公开产品功能，本轮没有引用外部链接。

本批只做最小的一半：接单人自己报出发与预计时间，不做实时位置。实时位置已有 GEO-021 的行程共享，那要接单人自己开。

## 2. 数据

`progress_logs` 加一列 `eta_at`（可空）。

「出发了」是一条 `kind=depart` 的进度记录：
- 记出发时间（即 `created_at`）与预计到达时间；
- 正文是「已出发，预计 HH:MM 到（北京时间）」；
- 不记位置。

## 3. 接口

**`POST /tasks/{id}/depart`**，请求体 `{eta_minutes: 5~240}`：
- 只有接这一单的人能报，否则 403 `depart_not_executor`；
- 线上任务不能报，400 `depart_remote_task`；
- 只在已成交或进行中时能报，否则 409 `depart_not_active`；
- 十分钟内再报一次只改预计时间，返回 `updated=true`，不再发通知，免得刷屏；
- 新报一次就通知发单人「接单人已出发」。

**`GET /recipient-progress/{token}`**：多 `departed_at`、`eta_at` 两个字段。取最近一次「出发了」，且之后还没有打卡或上门回报；已经到了就是 null。

## 4. 两端

- **SDK**：
  - `departTask(taskId, etaMinutes)`；
  - 类型 `DepartResult`，`RecipientProgress` 加两个字段；
  - 可选分钟数 `DEPART_ETA_MINUTES`（15 / 30 / 45 / 60 / 90）；
  - 进度页多一行「已出发，预计几点到」；
  - 三个错误码进 i18n。
- **Web 任务详情**：接单人、线下单、待上门时出现「出发了」。选预计分钟数，点了以后提示「已告诉发单人：预计几点到」；再点一次可以改时间。
- **App 任务详情**：同样一块。
- **进度链接页（`/r/:token`）**：多一行「已出发，预计几点到」。

## 5. 隐私、授权与边界

- 只记时间不记位置。位置共享仍是接单人自己决定开不开（GEO-021）。
- 服务对象的链接页只多一个预计时间，不多任何能联系或定位接单人的信息。
- 对象级授权表加一条：报「出发了」限接单人。
