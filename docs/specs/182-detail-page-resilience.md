# 182 详情页每一块都扛得住畸形响应

> 状态：本批实现（V209）。编号 APP-090。
> 来源：179 号 spec 核对时发现：App 任务详情页上，变更单块拿到 `{}` 就把整个详情页带崩（白屏）；BACKLOG V209。
> 只增不减：各块的正常显示与行为都不变，只在响应不像预期时「这一块不画 / 当作空表」。

## 0. 要解决的问题

- 任务详情页由十几块拼成（合约、变更单、纠纷、上门回报、子任务进度、报名、推荐、AI 助理……），每块各自请求。以前只有少数几块写了「响应不像预期时不画」（V95 起的子任务进度、驾驶舱等），其余拿到 `{}` / `null` / 字符串就 `.map` / `.some` 崩掉——用户看到白屏，而不是那一块没出来。
- 探针一跑：**Web 96 个组合里 70 个白屏**（进展、报名、推荐、变更单、纠纷陈述、AI 助理列表），**App 96 个组合里 21 个**（报名列表、变更单）。
- 服务端正常时不会回这些形状，但网关错误页、代理改写、版本错配、半截响应都会：一块出错不该连累整页（尤其是验收、放款按钮在同一页上）。

## 1. 业界怎么做

React 官方建议用错误边界把局部失败限制在局部（<https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary>）。本批先在数据入口把形状收住（成本最低、对两端都适用）；错误边界留在第 7 节。

## 2. 共享 SDK

`asList<T>(x)`：不是数组就当空表。两端列表型响应都过它。

## 3. 改了哪些块

| 端 | 块 | 改法 |
|---|---|---|
| Web | 任务详情：进展、报名、推荐、变更单 | `asList` |
| Web | 纠纷：纠纷本身 / 陈述列表 | 纠纷没有数字 id 就当没有纠纷；陈述 `asList` |
| Web | AI 助理：助理列表、候选、运行记录 | `asList`；运行记录响应不是对象时不画 |
| App | 报名列表、变更单 | 不是数组当空表 |
| App | 纠纷 | 同 Web（179 号已改，本批补测试） |

## 4. 闸门

`web/src/DetailResilience.test.tsx`、`app/detailResilience.test.tsx`：每个状态（招募中、已成交、进行中、待验收、已完成、纠纷中）× 发单人 / 接单人 × 四种畸形响应（`{}`、`null`、`[]`、字符串）× 合约正常 / 合约也畸形，各 96 个组合，详情页标题必须还在；另有两条纠纷专项（纠纷畸形不画、陈述畸形不崩）。

## 5. 边界

只处理「形状不对」：接口报错（4xx / 5xx）原本就由各块的 `catch` 处理，不变。

## 6. 红验

11 处变异全部变红（`scratchpad/mut209.py`；首轮纠纷的两道防护互相兜底而存活，补了两条专项后变红）：去掉 Web 进展 / 报名 / 推荐 / 变更单 / 纠纷陈述 / 纠纷 id / AI 助理任一处防护 → 红；去掉 App 报名 / 变更单 / 纠纷 id → 红；`asList` 不判断数组 → 红。
