
# 108 经验按子类生长：实现（KB-070~076）

> 状态：本批实现（V134）。设计见 [94 号](94-experience-grows-by-clusters-not-samples.md)，本篇记实现、偏差与验证。
> 承接用户 2026-10-10：「知识图谱体系不可能把每个样本都添加，需要类似聚类一样，
> 把额外信息或者经验加到具体某个子类里，或者如果没有新建子类」。

## 0. 改之前

知识库只有两层：**大类（人定的）**与**样本（机器攒的，一笔闭环一行）**。检索是对全部样本算余弦，
样本涨到上万时 Top-5 返回的是最像的五条——而用户想知道的是「这一类通常怎么做、通常多少钱」。

## 1. 数据

| 表 | 内容 |
|---|---|
| `knowledge_clusters` | 子类：大类、名字、质心 + 模型名、样本数、结果构成、状态（active / merged / retired）与合并去向、谁建的 |
| `knowledge_cluster_thresholds` | 每个大类的 τ_merge / τ_near，**带标定时的模型名**、几对标注、误判几对、谁标的 |
| `knowledge_cards` 新列 | `cluster_id`、`cluster_state`（pending / assigned / undecided / held / excluded / retracted）、`cluster_hint`（最像的子类与相似度） |

**样本是证据，子类是结论，结论能回溯到证据。** 质心、样本数与结果构成增量维护；价格与工期的分位数、
共识与分歧在读的时候从成员精确算——增量维护分位数做不到精确。

## 2. 归并（KB-070/071）

`/knowledge/jobs/cluster`（调度表里，一小时一次，**串行**，单实例锁）处理 pending 与 held：

1. **风控排除**：任务有未结清的可疑活动标记、或当事人已被封禁 → `excluded`。一次刷单进了质心就一直在里面。
2. **阈值**：这个大类没标定 → `held`（没标定）；阈值的模型名 ≠ 当前模型 → `held`（须重标）。
   两种都计入 `knowledge_cluster_held_total{reason}` 并在运营台大声提示。**宁可不归并，不要用错的阈值归并。**
3. 同大类、同模型的最近子类：`sim ≥ τ_merge` → 并入；`τ_near ≤ sim < τ_merge` → 待定区；`sim < τ_near` → 新建（单样本）。
4. **退化模式**（缺省词袋哈希，`semantic=false`）：不自动新建，只并入**运营建的**子类，其余进待定区。

待定区进 `QUEUE-010` 声明表（`knowledge`），有 SLA 与催办；**不通知样本背后的用户**——那是平台内部整理经验，
没有人在等这个答复（理由写在表里）。

**标定（KB-071）**：运营台取一组候选对（相似度均匀铺开——全是一眼能判的对子没有信息量），逐对判
「是不是一回事」，服务端扫出误判最少的 τ_merge（并列取高的，保守），τ_near 取「被标成一回事的最低相似度」。
至少 6 对、两类各至少 2 对；对子必须同一大类。标定动作进审计。

## 3. 对外（KB-073~075）

- `GET /knowledge/clusters?category=&q=`：每个结论都带样本量与时间范围、结果构成（含纠纷与取消）、
  近 180 天占比；样本少于 5（可配）的标「样本过少，仅供参考」。
- `GET /knowledge/clusters/{id}`：再加**共识流程**（出现在至少一半有拆解的样本里、且至少 2 个任务）与
  **分歧**（偏离共识、但成功闭环的做法，按出现次数）。只出现过一次的做法**只数不展示文字**——
  分歧没有被抹掉，个案也没有被暴露（k-匿名，与 V127 热词同一条规矩）。个案证据要双方授权才展示（KB-002），
  平台尚未开放这项授权，所以只给聚合结果并说明。合并掉的子类仍可读，指向合并去向。
- `GET /knowledge/price-reference?cluster_id=`：样本不够的子类**不出价**。

两端「不懂就问」页多一块「这一类活儿通常怎么做、通常多少钱」；运营台多一块：待定区逐条判、阈值标定、
旧模型阈值告警、撤回、合并、改名。

## 4. 结果构成是真的（KB-072b）

改之前只有 `task.completed` 会建卡，`outcome` 永远是 completed——「失败率是子类的属性」这句话没有数据。
现在：经过纠纷才结项的记 `disputed`；**成交后**取消的记 `cancelled`（没人接过的草稿撤回不是经验）；
逐层拆解的容器步骤（自己不干活）不建卡。参考价仍只从 completed 算。

## 5. 闸门与红验

`test_knowledge_clusters.py`（18 条），每条都对应一条「改回错的做法」的红验，十条全红：

| 闸门 | 红验 |
|---|---|
| KB-070 三条判定是三种结果 | — |
| KB-070a 增量质心 = 全量重算（随机向量 25 个） | 质心只取最新一条 → 红 |
| KB-070b 不跨大类 | 找最近子类不看大类 → 红 |
| KB-071 没标定 → held + 指标；标定后重试 | 没阈值就用默认值 → 红 |
| KB-071a 阈值模型不符 → held | 不查阈值的模型 → 红 |
| KB-071b **退化模式不生长图谱** | 退化模式也自动新建 → 红 |
| 标定：扫出的值、标注太少、跨大类 | — |
| KB-072a 分歧保留、只出现一次的只数不展示 | 分歧被平均掉 → 红 |
| KB-072b 纠纷与取消进结果构成 | 取消不记经验 → 红 |
| KB-073 样本量、时间范围；样本少不出价 | 样本少也出价 → 红 |
| KB-074 个案不展示 | — |
| 风控排除 | 风控标记不排除 → 红 |
| KB-076 撤回并精确重算 | 撤回不重算 → 红 |
| 运营：二选一、只有管理员、合并后旧引用可读、待定区在声明表里、job 在调度表里 | — |

另：Postgres 上迁移往返与这组测试全绿（进 CI 的 Postgres job）；web 5 条、App 3 条，客户端红验四条；
真浏览器联调新增「按子类看经验」。

**过程里的一个错**：运营台新块第一版对「响应不像预期」不设防——既有的 25 条运营台测试里，没桩的接口返回 `[]`，
`view.thresholds.filter` 抛错，**整个运营台白屏**。只跑新测试文件时看不见，跑全套才红。
与 V133 子任务进度块同一条教训：一个角落的数据不该决定整页能不能用。

**第二个错，回归才抓到**：待定区进了 QUEUE-010 声明表、写的是「不告知提交方」，而那张表的闸门假定
「不告知」只有一种理由——反洗钱的保密义务。待定区不告知是另一种理由：**根本没有提交方**。只跑相关闸门
看不见，全量回归才红。修法不是放宽断言，而是把两种正当理由都写进闸门、要求理由点名是哪一种，
并单独钉住可疑活动复核那一行必须是保密义务（两条变异都红）。

## 6. 这一批没做的

- **个案引用授权**（`KB-077`）：子类详情不展示个案，因为平台还没有「双方同意被引用」这项授权。
- **分歧的条件标签**（`KB-078`）：94 号设想按「老小区没电梯」这类条件标注分歧；现在只按做法分组、按次数排，没有条件。
- 层级子类、跨大类合并、自训 embedding：94 号已明确不做。
