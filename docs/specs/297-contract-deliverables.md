
# 297 跟拍成片交付走平台：原图放款完毕前锁着

> 状态：本批实现（V324）。编号 SCN-166。
> 来源：294 号 spec「没做的」——「跟拍成片交付走平台：验收前只给带水印的预览，验收后放全部底片」；BACKLOG V324。
> 只增不减：图片上传、执行动态的附图、逐期交付与放款都不变；新增一张表、三个接口、两端各一块「交付文件」。

## 0. 要解决的问题

活动跟拍（294 号）最常见的两种纠纷是「先交片后不付」与「付了不交片」：成片在私下传，谁先给谁吃亏。平台托管了钱，却没有托管成片。

## 1. 业界怎么做

摄影交付平台的常见做法：先给带水印或低分辨率的预览供客户挑选，付清尾款后开放原图下载。（本批没有另找外部来源。）

## 2. 规则

- **不在服务端加水印**（仓库没有图像处理依赖，本批不新增）：执行方自己传「预览图」（建议自己加水印或缩小）和「原图」两类文件。
- `POST /contracts/{id}/deliverables`（`{ref, kind: preview|original}`）：只有执行方（`not_party`）、合约在托管中且没冻结（`not_active`）、只能挂自己上传的图（`deliverable_file_not_found`）、一份合约最多 50 个（`deliverables_full`）。挂原图时把这张图标成敏感文件：**匿名能力链接 `/files/{name}` 随之失效**（与证件影像同一道门，CERT-010）。
- `GET /contracts/{id}/deliverables`：只给合约双方。预览图带公开地址；原图对执行方始终可取，对发布方在合约**放款完毕（released）**之前 `locked: true`、`url: null`。
- `GET /contracts/{id}/deliverables/{did}/file`：带登录态读取；发布方在放款完毕前取原图 403 `deliverable_locked`（写明「先看预览图，验收没问题就放款」）；响应不缓存。
- 纠纷中仲裁员仍可按 CERT-010 的规则（写明理由、进审计）读这张敏感文件。

## 3. 数据 / 接口

表 `contract_deliverables`（迁移 `c1d220260075`）。共享 SDK：`ContractDeliverable`、`addDeliverable`、`contractDeliverables`、`downloadDeliverable`（带登录态取 Blob）；i18n 三条。

## 4. 两端

- **Web 任务详情的合约卡片**：「交付文件」——预览图缩略图；原图锁着时写「原图 N 张：验收放款后可以下载」；放款后「下载原图 #id」（带登录态下载）。执行方在托管期间有「上传预览图」「上传原图」，原图不压缩、超过 2MB 先在本地拦下说明。
- **App 任务详情**：同一块只看不传：预览图、原图锁着几张；放款后提示「请在网页版下载」（App 端上传与保存到相册记入「没做的」）。

## 5. 隐私、授权与边界

只有合约双方看得到；原图不再有匿名链接；钱与原图同时在平台托管，放款与开放原图是同一个条件。
