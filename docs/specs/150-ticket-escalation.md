# 150 客服工单超时自动升级与 App 我的工单

> 状态：本批实现（V178）。编号 ESCA-051（并补上 App 端的 CS-013）。
> 来源：台账 ESCA-051「工单 SLA 只有时限与超时可见，没有自动升级」；BACKLOG V178。
> 只增不减：工单的提交、回复结单、转纠纷不变；`/admin/tickets` 默认排序和原有字段不变（多了字段与可选参数）；人审队列积压汇总（QUEUE-011）与提单人超时告知（QUEUE-012）照旧。
> 写明的行为变化：超时工单除了进汇总，还会**逐级点名**叫醒具体的人；`SUPPORT_SLA_HOURS` 旁边原来的注释「超时只做可见，不自动升级」改为「只在平台内部逐级叫人，不转纠纷、不动钱」。

## 0. 要解决的问题

- 超过 SLA 的工单只出现在「人审队列积压」那条汇总通知里——发给**全体管理员**。谁都收到等于谁都没被点名；接手的客服不会被单独叫醒，主管也不知道哪张单已经拖了两天。
- 客服没有「我来处理」：两个客服可能同时回同一张单，也可能都以为对方在处理。
- **App 上根本没有工单**：用户在 App 里提不了工单、看不到客服回复，只能收到一条通知后去网页上找。

## 1. 业界怎么做（带来源链接）

- **分级升级（tiered escalation）**：Zendesk、Freshdesk 都按 SLA 设升级规则——到时限先提醒接手人或所在组，再超时升级给主管（Zendesk SLA policies：<https://support.zendesk.com/hc/en-us/articles/4408829459866>；Freshdesk escalation：<https://support.freshdesk.com/support/solutions/articles/37626>）。
- **认领 / 指派（assignee）**：工单有明确的接手人，提醒只发给接手人，避免「旁观者效应」。
- **告诉等的人进展**：客户能看到「已有人处理」「已升级」，而不是一片沉默。

## 2. 数据（迁移 `c1d220260028`，SQLite 与 Postgres 都验过）

| 表 | 字段 |
|---|---|
| `tickets`（加列） | `assignee_id`（接手的客服）、`claimed_at`、`escalation_level`（0 / 1 / 2，默认 0）、`escalated_at` |

配置：`SUPPORT_SLA_HOURS`（默认 24，第 1 级）、`SUPPORT_ESCALATE_L2_HOURS`（默认 48，第 2 级）。

## 3. 规则与接口

| 编号 | 内容 |
|---|---|
| ESCA-051-1 | `POST /admin/jobs/escalate-tickets`（调度表每小时一次，`ticket_escalations`）：等了 SLA 时长 → 第 1 级，叫醒接手人；没人接手叫醒全体专职客服（没有专职客服时叫能处理工单的超级管理员）。等了升级时长 → 第 2 级，叫醒超级管理员（主管），并告诉提单人「已升级给主管」 |
| ESCA-051-2 | 级别写在工单上，每一级只叫一次；一次跳到第 2 级（调度停过）时两级都叫；结了单的不升级 |
| ESCA-051-3 | `POST /admin/tickets/{id}/claim`（客服角色）：「我来处理」，可以从别人手里接过来（返回此前接手人），进审计；结了单的不能认领；认领不重置计时（承诺的是多久解决） |
| ESCA-051-4 | `GET /admin/tickets` 每行加接手人、等了多久、承诺多久、超了多久、升级级别与说明；可选 `escalated_only`、`mine`、`sort=urgent`（级别高的在前，同级等得久的在前）。时间差在服务端算好 |
| ESCA-051-5 | `GET /support/tickets`（提单人）加 `claimed`（有没有人接手）与同样的等待 / 升级信息；**不返回接手的是哪位管理员** |

## 4. 两端

- **Web 管理后台「待处理工单」**：升级标记、「已等 N 小时（承诺 24 小时，已超 M 小时）· 接手人」、「我来处理 / 改由我处理」、三个筛选（只看已升级的 / 只看我接手的 / 最急的在前，默认最急在前）。
- **Web「客服」我的工单**：处理中的工单显示「已有客服接手 / 排队等待」、已等多久、是否已催办或已升级给主管。
- **App「我的 → 客服与工单」（新）**：提交工单、看客服回复、看同样的处理进度。

## 5. 隐私、授权与边界

- 提单人看不到接手管理员的身份；通知里只说「客服」「客服主管」。
- 升级只在平台内部叫人：不转纠纷、不冻结资金、不动钱（转纠纷仍是 ESCA-001 由人发起）。
- 认领与结单都只能是客服角色（141 号角色总表已登记）；认领进审计。
