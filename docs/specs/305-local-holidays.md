
# 305 地区性假日与公司自定的假期

> 状态：本批实现（V332）。编号 ESCA-073。
> 来源：288 号 spec「没做的」——「地方性假日与公司自定的假期」；BACKLOG V332。
> 只增不减：全国日历（276、288 号）的录入、导入、调休规则都不变；没设地区的客服、没录地区假日时，在岗判断与以前完全一样。客服看板的行只在设了地区时多 `region`。

## 0. 要解决的问题

- V315 只能按国务院的通知导入全国的放假与调休。民族自治地方的节日只在当地放假（如新疆、宁夏的古尔邦节、肉孜节）：录进全国日历，别的地区的客服也被当成不在岗；不录，当地的客服又被当成在岗，工单派过去没人接。
- 公司自定的全员假期（年会日、公司周年）：全国日历本来就能录「放假」并写说明，**这一半不需要新东西**，本批只在页面上说清楚录在哪里。

## 1. 业界怎么做

排班与工单系统（客服中心、呼叫中心的排班）通常有「按地点 / 团队的假日日历」：每位坐席属于一个地点，地点的假日只影响这个地点的人；全员假日放在公司日历里。（本批没有另找外部来源。）

## 2. 规则

- 主管在客服看板上给每位客服「设地区」（自由填写，如「新疆」；留空 = 不分地区），进审计。
- 主管录「地区性假日」：日期 + 地区 + 说明。同一天不同地区可以各录一条；同一地区同一天重复录 409 `holiday_exists`；地区空白 400 `holiday_region_required`。
- **在岗判断**：设了排班、所在地区与假日地区相同的客服，那天整天不在岗——**哪怕全国那天是调休上班**（当地放假优先）。没设排班的人不受任何日历影响（与 276 号一样）。自动分配、超时提醒都沿用同一个判断，所以当地放假那天不会派给他、超时先叫别人。
- 列表每一天带「这个地区现在有几位客服」：0 位时页面标红「还没有客服设为『宁夏』，这一天不起作用」——防止录了地区却忘了给人设地区（或写法对不上，如「新疆」与「新疆维吾尔自治区」）。

## 3. 数据 / 接口

- 新表 `support_local_holidays`（day + region 唯一）；`support_agent_scopes.region`（可空）。迁移 c1d220260077，SQLite 与 Postgres 都验过升级、回退、`alembic check`。
- `GET /admin/support/local-holidays`（客服都能看）、`POST`（超级管理员）、`DELETE /admin/support/local-holidays/{id}`（超级管理员）、`PUT /admin/support/agents/{user_id}/region`（超级管理员）。都登记进角色表与后台入口表。
- 共享 SDK：`SupportLocalHoliday`、`SupportRegionResult`、`SupportAgentStatus.region?`；`supportLocalHolidays` / `addSupportLocalHoliday` / `deleteSupportLocalHoliday` / `setSupportAgentRegion`；新错误码进 i18n。

## 4. 两端

- **Web 后台客服看板**：多「地区」一列与「设地区」；节假日日历下多「地区性假日」一块（列出、影响几位、录入、删掉）。
- **App**：后台只在 Web，不涉及。

## 5. 隐私、授权与边界

地区只是排班用的工作地点标签，由主管设置，不对用户公开；只有超级管理员能改日历与地区，客服只能看。
