
# 288 按国务院放假通知一键导入全年放假与调休

> 状态：本批实现（V315）。编号 ESCA-072。
> 来源：276 号 spec「没做的」——「按国务院通知一键导入全年放假安排」；BACKLOG V315。
> 只增不减：一天一天录、删掉都不变；多一个批量保存接口和后台「按通知导入」一块。

## 0. 要解决的问题

V302 的节假日日历只能一天一天录。国务院每年发一份放假通知，七个节日加调休上班，一年要录二十七八天，录错一天就有客服在放假那天被派单。

## 1. 业界怎么做

排班与考勤系统普遍提供「导入法定节假日」：按官方公布的安排生成日历，管理员核对后生效。通知的写法多年不变（「一、元旦：1月1日（周三）放假1天，不调休。二、春节：1月28日（农历除夕、周二）至2月4日（农历正月初七、周二）放假调休，共8天。1月26日（周日）、2月8日（周六）上班。」），可以按条解析。（本批没有另找外部来源；测试里用的是 2025 年通知的写法。）

## 2. 规则

- **解析只出草稿**（共享 SDK `parseHolidayNotice(text, year)`，纯函数）：只读编了号的条目（「一、」「二、」……），抬头与附言不算；括号里的注释先去掉（即使写了日期）；每条「放假」前面的日期是放假（「至」连起来的是连续几天，后一个省略月份时沿用前一个），「上班」前面的日期是调休上班；写了年份的用那一年，不存在的日期不出。标签取条目名（「国庆节、中秋节」），调休上班标「××调休上班」。
- 通知里不写调休上班按哪天的排班，草稿默认**按周五**（与手工录入的默认一致），主管逐条可改；解析错的可删。编了号却一个日期都没认出来的条目原样列出，请主管手工录，不猜。
- **一次保存**（主管）：要么全存、要么一条不存——这次导入里同一天出现两次 400 `holiday_duplicate_in_batch`、调休上班没写按周几 400 `holiday_weekday_required`（沿用），都写明是哪一天；已经录过的日子跳过、不覆盖手工录的，结果里列出跳过了哪几天；放假那天不带按周几。记一条审计（`support_holiday_bulk_add`：导入几天、跳过几天）。

## 3. 数据 / 接口

不新增表。`POST /admin/support/holidays/bulk`（`{items: [{day, kind, label, as_weekday}]}`，1~60 条，超级管理员）→ `{created: SupportHoliday[], skipped: string[]}`。共享 SDK：`parseHolidayNotice`、`HolidayDraft`、`DEFAULT_MAKEUP_WEEKDAY`、`SupportHolidayBulkResult`、`addSupportHolidaysBulk`；i18n `holiday_duplicate_in_batch`。

## 4. 两端

- **Web 后台「客服状态 → 节假日日历」**：下面多「按国务院放假通知导入」：贴原文、填年份（默认明年）→「解析成草稿」→ 逐条核对（调休上班的「按周几的排班」下拉、删掉）→「保存这 N 天」→ 写出导入几天、哪几天已经录过被跳过。一个日期都没认出时说清要贴什么。
- **App**：后台只在 Web，不涉及。

## 5. 隐私、授权与边界

只有超级管理员（客服主管）能导入（角色表已登记）；通知是公开文件，不涉及个人信息。解析在浏览器里做，服务端只收核对后的草稿，照旧逐条校验。
