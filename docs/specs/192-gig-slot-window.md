# 192 接单推送按名额时段过滤

> 状态：本批实现（V220）。编号 SCN-129。
> 来源：180 号 spec「没做的」——「『现在有空』推单与顺路单也按名额时段过滤」；191 号第 3 节排序（分数 90）；BACKLOG V220。
> 只增不减：`/gig/nearby`、`/gig/along` 的参数与原有字段不变，卡片只加三个字段；不按天的单行为完全不变。
> 写明的行为变化：时段已经过去的名额不再出现在「附近」「顺路」里；开着「现在有空」时，有日期的名额只出现与「现在 → 有空截止」对得上的；新单推送同一条规则。

## 0. 要解决的问题

V205 让多天单的名额写明「哪天几点到几点」（北京时间），V207 让推荐按时段比。接单者那一侧还没跟上：

- 「附近」「顺路」只看截止时间：**昨天的名额**只要截止时间没到，就还挂在列表里。
- 「现在有空」的推送只看距离和类目：说了「接下来两小时有空」的人，会收到**下周三上午**的名额推送。推多了就是骚扰（每段「有空」最多推 6 条，被对不上的名额占掉）。
- 卡片上看不出这是哪天的名额，要点进去才知道。

## 1. 业界怎么做

125 号 spec 第 1 节引用的即时配送派单规则，前提是「这一单现在能履约」，再比插进路线后多走多少。本批把同一个前提补到有日期的名额上：先按时段筛掉对不上的，再按原来的距离 / 多走的路排序。（本批没有另找外部来源，不引用未核实的平台规则。）

## 2. 数据

不加表。名额那天的时段（`work_date` + `shift_start` / `shift_end`，北京时间）换算成 UTC 与库里的时间比；没写时段按北京时间整天。

## 3. 接口

| 接口 | 变化 |
|---|---|
| `GET /gig/nearby`、`GET /gig/along` | 时段已结束的名额不返回；本人开着「现在有空」时，只返回时段与 `[现在, 有空截止]` 重叠的名额（不按天的单不受影响）；每张卡片加 `work_date`（`YYYY-MM-DD` 或 null）、`shift_start`、`shift_end` |
| 新单推送（`task.published` 事件） | 名额时段与这段「有空」对不上的不推 |

SDK：`GigTaskCard` 加三个字段；新函数 `gigWhenLabel(card)`：「10-24 09:00–18:00」「10-24 全天」，不按天的单是空串。

## 4. 两端

- **Web**「接单」页与 **App**「接单」屏：附近、顺路的卡片在地址后面写「· 10-24 09:00–18:00」；不按天的单不写。

## 5. 隐私、授权与边界

- 不多存任何位置或时间；「有空」的截止时间本来就存着。
- 时间比较用北京时间（与发单时的时段一致，V205）；跨时区的接单者不在本批范围（平台不存用户时区，TZ-065 记为「意」）。
- 没开「现在有空」时不按时段收窄（只去掉已经过去的），因为那时是主动浏览，提前几天看到也有用。
