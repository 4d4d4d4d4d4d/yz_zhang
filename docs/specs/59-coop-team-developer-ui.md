# 59 有后果的界面：合作体、团队与开发者（UI-070~077）

> 承 57 号 spec 的 CLI-065：合作体（COOP）、团队（TEAM）、开放 API（OAPI）
> 三条线在 V82 只补到了 SDK，**网页上仍然没有页面**。
>
> 其中合作体是整个产品里立意最重的一条——需求原话是「为了颠覆公司组织形式」，
> 而它到现在为止只能用 curl 访问。

## 0. 这一批的判断：有后果的界面不能把风险写成小字

这三条线有一个共同点：**每一次点击都有真实后果，而且后果不对称。**

| 动作 | 点的人以为 | 实际后果 |
|---|---|---|
| 加入合作体 | 「加个群」 | 投入可能**血本无归**，份额会**被后来者稀释**，且**不可转让、不可赎回** |
| 确认一笔贡献并计价 | 「点个确认」 | 直接改变**所有人**的份额比例 |
| 发起分配 | 「发钱」 | 按**当下快照**分配，分完不可撤销 |
| 生成 API 密钥 | 「复制一下」 | **明文只出现这一次**，关掉页面就没了 |
| 提交企业信息 | 「填资料」 | 材料进人工审核，**审核通过前不能开票** |

所以这一批的验收点里，有一半不是「功能可用」，而是**「该说的话说到了」**：

> **风险不是免责声明，是决策所需的信息。**
> 把它折叠进一行小字，等于知道它会影响决定、却又不希望它影响决定。

具体到实现，就是三条硬要求（UI-070/071/072），见下。

## 1. 合作体页面 `/ventures`

### UI-070 风险揭示书在加入路径上，不在角落里

加入（以及创建）之前**整篇展示** `GET /ventures/risk-disclosure` 返回的正文，
四条要点逐条列出；用户勾选「我已阅读」之后才能提交，
且提交时带上**服务端给的版本号**（不是客户端写死的字符串）。

版本号来自服务端这条很重要：写死意味着风险揭示书改版后，
**用户签的是旧版而界面显示新版**——签署记录会与他实际看到的内容对不上。

### UI-071 份额要说清楚它是算出来的、且会被稀释

份额页显示每人的 `share_bps` 与计价，并**原样显示服务端给的 `basis` 文案**
（「份额 = 本人已确认贡献计价 ÷ 全体已确认贡献计价；他人后续贡献会稀释你的份额」）。

不自己拼这句话：它是一条有后果的解释，应该和服务端算法同源。

### UI-072 「确认贡献」按钮读服务端的 `can_confirm`

自己的贡献不能自己确认（COOP 的规矩）。客户端**不重算**这个条件，
直接读服务端返回的 `can_confirm`——与 V82 的 CLI-064 同一条：
判断只有一个来源。

### UI-073 分配只分已实现收益

分配表单的上限提示用 `realized_funds_cents`，并写明「只能分配合作体**已经实际
收到**的钱」。这不是 UI 细节：它是这个模式不变成「承诺收益的募集」的结构性
条件之一。

### UI-074 合规路径照原样显示，包括那句免责

`documents` / `registrations` 逐项显示 `title` + `why` + `action` + 状态，
并**显示 `disclaimer`**（「不是法律意见」）。

`why` 必须显示：只给清单不给理由，用户不知道哪些能省、哪些不能，
最后要么全不做、要么全找律师。

## 2. 团队页面 `/teams`

### UI-075 审批按钮读服务端的 `can_decide`，开票按钮读 `invoice_block`

和上面同一条规矩。`can_decide` 里已经包含「自己不能批自己」，
`invoice_block` 里已经包含「企业信息未核验」——客户端重写一遍就是第二份实现。

超额支出提交后服务端返回 `needed_approval: true`，界面要说明
**申请已建立、在等审批**，而不是报一个失败。这两件事对用户是完全不同的处境。

## 3. 开发者页面 `/developer`

### UI-076 明文密钥只显示一次，且界面必须说出来

创建/轮换后把明文 key 显示在一个**需要用户主动关闭**的区域，
并原样显示服务端给的 `warning`。关掉后不再显示——因为库里只有哈希，
界面也拿不回来。

### UI-077 Webhook 停用原因要显示

连续失败自动停用时，服务端写了 `disabled_reason`。
**悄悄停掉比不停更坏**：集成方会以为平台还在发。

## 4. 验收点

| 编号 | 验收点 |
|---|---|
| UI-070 | 加入/创建合作体前整篇显示风险揭示书，且提交带服务端版本号 |
| UI-071 | 份额页显示服务端给的 `basis` 口径说明 |
| UI-072 | 「确认」按钮读 `can_confirm`，自己的贡献不可自确认 |
| UI-073 | 分配界面标明只能分「已实现收益」，并显示可分配金额 |
| UI-074 | 合规路径逐项显示理由与状态，且显示免责声明 |
| UI-075 | 审批读 `can_decide`、开票读 `invoice_block`；超额支出显示「待审批」而不是失败 |
| UI-076 | 明文密钥只显示一次，并显示服务端的一次性提示 |
| UI-077 | Webhook 被自动停用时显示原因 |

## 5. 这一批没做的

- **UI-078**：App（React Native）侧仍然只有任务/纠纷/视频三块，这三条线没有页面。
- **UI-079**：合作体的「合作协议」「贡献确认书」目前只在合规路径里列为待办，
  **没有真的生成文书**。生成有法律效力的文件需要模板 + 签署流程，
  与 V50 的合同签署可以共用，但那是另一批。
- **CLI-067**（仍未做）：写这一批时发现 V82 给 `CompliancePath` 写的 TS 类型
  是错的（`items` 实际是 `documents`/`registrations`/`notices`），
  **类型对不上却没有任何东西会红**——这正是「闸门只看路径不看形状」的代价。
