# 219 API Key 用量记录的保留期清理

> 状态：本批实现（V247）。编号 API-055。
> 来源：152 号 spec「没做的」——「用量记录的保留期：到量时按 90 天清理（用量页最多也只看 90 天）」；BACKLOG V247（台账「欠」第七轮排期，分数 30）。
> 只增不减：用量的记账、每日配额、账号总配额、用量页（最多 90 天）都不变。
> 写明的行为变化：新定时任务 `/openapi/jobs/purge-usage`（一天一次），删除北京日期早于 90 天前的用量行；job 总数 35。

## 0. 要解决的问题

每把 API Key 每天一行用量（152 号 spec）。用量页最多只看 90 天，更早的行既没人看、也不参与配额（配额只读当天那一行），却一直留着。数据只留需要的时间，是数据最小化的基本要求。

## 1. 业界怎么做

API 用量明细通常保留与控制台可查询范围一致的时长（例如 90 天），更早的只保留汇总或直接清理。本平台没有对外承诺更长的用量明细，按 90 天清。（本批没有另找外部来源。）

## 2. 数据

不加表。按 `api_key_usage.day`（北京日期字符串，YYYY-MM-DD，可按字典序比较）删除早于「今天 − 90 天」的行；第 90 天当天的保留。

## 3. 接口

| 接口 | 说明 |
|---|---|
| `POST /openapi/jobs/purge-usage`（job 令牌 + 单实例锁 `api_usage_purge`） | 返回 `{purged, kept_from}` |

调度表登记（86400 秒）；功能面清单同步。

## 4. 两端

不涉及界面：用量页本来就只看 90 天。

## 5. 隐私与边界

用量行里只有 Key 编号、日期、次数，不含请求内容；清理不可恢复，但用量页看不到的数据本来也不再展示。
