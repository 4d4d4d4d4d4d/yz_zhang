
# 119 报价卡接上两端；变更单可以改期、改范围（IM-009 / SC-007b）

> 状态：本批实现（V144）。两项都是「服务端早有一半，两端用不上」：
> 报价卡的接口和 SDK 方法一直都在，**两端都发不出去也画不出来**；
> 变更单只能改价，而真实的「加了两个房间」通常同时要改期、改范围。
> 原则：只增不减。原有的改价调用方式、通知措辞、已有消息的显示都不变。

## 1. IM-009 报价卡

**服务端**（补校验与快照）：
- 报价对应的任务必须存在。
- 发布方报自己的单（「我出这个价请你做」），任何会话里都可以发。
- 执行方报别人的单，要求发布方在这个会话里（`quote_wrong_party`）。在这单自己的任务会话里不限状态（成交后为追加的活报价，是原有用法，保留）；在别处报价要求这单还在招募。
- 卡片里存一份任务标题和发起方角色（`title`、`from_creator`）的快照，两端不用再查一次就能画出来。旧卡片没有这两项，界面退回显示任务编号。

**两端**：
- **Web 消息页**：消息里的报价卡显示为卡片，包括金额、任务（可点进任务页）和说明。
  - 发布方报的价，对方可以「按这个价报名」：带着报价走原有的报名接口。
  - 执行方报的价，发布方看到「去任务页的报名列表里选 TA」。
- **Web 发报价**：私聊里点「发报价」，从「我发布的招募中任务」里选一单；任务会话里直接报这一单。
- **Web 任务详情**：想接单的人多了一个「私信报价」入口（报名入口保留）：自动开私聊、发报价卡，然后跳到对话。
- **App 私聊**：同样显示报价卡，也能「按这个价报名」。
- 两端共用 `parseQuoteCard`：解析不了的（旧消息、被撤回的）就按普通消息显示。

## 2. SC-007b 变更单改期 / 改范围

- **请求**：`POST /contracts/{id}/change-orders` 新增可选的 `new_deadline`、`scope_change`，`new_amount_cents` 也变成可选。三样可以单独改，也可以一起改；只传金额的老调用，行为和以前完全一样。
- **约束**：
  - 改价的约束不变：放款开始后不可改价，多里程碑合约不可整体改价。
  - 只改期或改范围不动钱，所以分期放款开始后、多里程碑合约也可以提。
  - 什么都不改返回 `change_empty`；截止时间在过去返回 `deadline_in_past`。
- **接受后**：
  - 合约版本 +1，条款末尾追加「变更附录」，写明金额、截止时间、范围各改成了什么，以及提案人。附录里的提案人按 SC-030 的格式写：昵称、平台账号、实名（姓加星号）。
  - 任务的截止时间跟着改；临期和逾期提醒都按新的时间算，原来「建议协商改期」的逾期通知现在有了真的改期工具。
  - 范围调整追加到任务说明末尾，原文不删。
  - 双方各记一条新版本的签署留痕（与改价相同）。
- **通知**：一句话说清改了什么，两端和附录共用同一个描述。改价沿用原来的「¥X」写法。
- **两端**：
  - **Web 合约区**：新增「新的截止时间」和「范围调整」，金额可以不填。
  - **App**：新增「新的截止日期」（当天 23:59 截止，格式写错先拦下）和「范围调整」。
  - 列表里一句话说清这张变更单改了什么。

## 3. 闸门与红验

| 闸门 | 说明 |
|---|---|
| 只改期 + 改范围：钱包不动，合约附录和任务截止、说明同步 | 后端 |
| 改价 + 改期 + 改范围一起：托管补足，附录写全 | 后端 |
| 老调用：同金额返回 `invalid_amount`；空单、过去的截止时间被拒；只改价照旧 | 后端 |
| 报价卡：给无关的人报价被拒；发布方报自己的单可以；卡片带标题快照与角色；不存在的任务 404 | 后端 |
| 原有测试：任务会话里成交后报价、通知里写「¥300.00」、两端「改为 ¥300.00」——全部保持通过 | 兼容 |
| Web / App：报价卡渲染与按价报名；从我的招募中任务发报价；变更单只发要改的字段 | 前端 |
