
# 319 第十七轮场景发掘：防水补漏、上门开锁

> 状态：本批实现（V346）。编号 SCN-193（防水补漏）、SCN-194（上门开锁）。
> 来源：skill `scenario-discovery` 按方法每轮补充；上一轮是 V343（316 号）。BACKLOG V346。
> 只增不减：两个种子文件、两个新类目，「上门开锁」沿用持证类目准入（新资质名「开锁备案证明」）；已有包、类目、资质规则都不变。

## 0. 找信号

- 防水补漏与 V337 的疏通、V333 的搬家是同一个病：价格在动手之后才出现，而且更隐蔽——报的是「每斤胶多少钱」，客户以为是总价。V344 刚做的「上门回报确认」正好能接住「闭水验收」。
- 开锁是急事（钥匙锁屋里了、半夜），最大的风险不在价格而在**给谁开**：不核验就开，等于帮人入室。多地把开锁业按特种行业管理，要求备案、核验、登记——平台的持证类目准入可以直接接住。

## 1. 场景卡

### SCN-193 防水补漏

| 项 | 内容 |
|---|---|
| 人群 | 做防水维修的师傅；发单的是漏水到楼下的住户、房东 |
| 要办的事 | 先查漏点（防水层还是暗管）；报总价不按斤报胶；免砸砖只在合适时用；砸砖改管走变更单；闭水 24~48 小时验收、约质保 |
| 现在怎么办 | 搜索广告、小区广告，结账时才知道按胶水重量算 |
| 痛点 | 频率 1；严重度 4（上万元、还漏、邻里纠纷） |
| AI 能做几成 | 0.4：问清单、报价写法、验收与质保写法 |
| 商业价值 | 3：单价较高 |
| 交付成本 | 1：只写数据 + 一个类目 |
| 风险关口 | 钱先托管、加价只能走变更单；闭水验收后放款 |
| 证据 | 维修工称注入 62.5 公斤胶、收费 1.5 万元，业主一周后发现仍然漏水（[澎湃新闻](https://m.thepaper.cn/newsDetail_forward_33748209)） |

分数 = 4 × 1 × 4 × 0.4 × 3 ÷ 1 = **19.2**。

### SCN-194 上门开锁

| 项 | 内容 |
|---|---|
| 人群 | 开锁师傅；发单的是钥匙锁在屋里、丢了车钥匙的人 |
| 要办的事 | 核验身份（证件与门对得上）、对不上不开；备案；分项报价、夜间加价提前说；每单留登记；不硬推换锁芯 |
| 现在怎么办 | 门上的小广告、搜索，备案与否看不出来 |
| 痛点 | 频率 1；严重度 4（被冒充开锁导致失窃、临时加价） |
| AI 能做几成 | 0.3：核验清单、报价写法、登记写法；开锁在人 |
| 商业价值 | 2：单价低 |
| 交付成本 | 1：数据 + 一个持证类目 |
| 风险关口 | 核验身份（不开错门）；备案（平台审核）；登记只写最小必要（证件类型与后四位） |
| 证据 | 多地把开锁业按特种行业管理：开锁企业到公安机关登记备案、开锁前核验身份并实名登记（各地《开锁业治安管理规定》《特种行业治安管理条例》；本轮找到的网上材料多为商家推广，没有引用链接） |

分数 = 4 × 1 × 4 × 0.3 × 2 ÷ 1 = **9.6**（分数不高，但给错的人开锁的后果严重，平台用准入兜底的价值大于分数）。

## 2. 做了什么

- `server/app/modules/packs/seeds/leak-repair.json`：「防水补漏接单顾问」，两个方法、五条知识（先查漏点、报总价不按斤、免砸砖的适用范围、砸砖改管走变更单、闭水验收与质保——回报拍闭水照片、客户可点「对得上」）、一个模板（回报两次：查漏、闭水）。新类目「防水补漏」。
- `server/app/modules/packs/seeds/locksmith.json`：「开锁接单顾问」，两个方法、五条知识（先核验对不上不开、要备案、分项报价、每单登记最小必要、不硬推换锁芯）、一个模板。新类目「上门开锁」，要审核通过的「开锁备案证明」。

## 3. 数据 / 接口

不新增表与接口；新资质名常量 `LOCKSMITH_CERT`。

## 5. 隐私、授权与边界

两个助手都只出草稿；钱、发布、分享个人信息都是人工关口；不建议按斤报胶、不查漏点就施工、不核验就开锁、给对不上的人开、没备案接单、教人开锁技术、硬推换锁；开锁登记不拍证件全照。
