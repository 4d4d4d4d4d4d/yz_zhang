# 426 发布后加上加选资质的界面入口

> 状态：本批实现（V453）。编号 SCN-294f。
> 来源：414 号（V441）「没做的」。发布后改加选资质的接口当时就做全了：去掉随时可以；加上时，已报名的人里有没证的就拒（`task_certs_locked`）。两端却只给了「去掉」的按钮。
>
> 发单人发出去才想起「这活要上 3 米」，只能撤单重发。421 号（V448）的门头招牌、活动音响灯光两个类目，正好都是「要不要证取决于这一单」，这个入口用得上。
>
> 只增不减：不改接口；两端各多一个入口，原来的「去掉」按钮不动。

## 0. 要解决的问题

发单人在任务详情里，看得到这个类目还能另外要哪几张证，点一下就加上。加不上时（已报名的人里有没证的），说清为什么、怎么办。

## 1. 业界怎么做（带来源链接）

同 414 号：加严的改动对已报名的人不利，服务端拦，界面只负责把理由说清楚。本轮没有引用外部报道链接。

## 2. 数据

不涉及。

## 3. 接口

不改接口，沿用 `PATCH /tasks/{id}` 的 `task_certs`（414 号）。SDK 新增：
- `addableCerts(task, category)`：类目可加选、这一单还没加的；
- `addCertPatch(task, cert)`：加上一张，原有的照留，重复的不重复加；
- `ADD_CERT_HINT`：「加上以后，没有这张证的人报不了名；已报名的人里有没证的，会加不上，要先处理他们的报名」。

## 4. 两端

两端都只给发单人、只在招募中显示：
- **Web**：任务详情「这一单另外要」那行下面，`AddTaskCert` 给每张可加的证一个「加上「…」」按钮，加完重新加载。加不上时显示错误码的文案（`task_certs_locked`，418 号起进 i18n）。
- **App**：`TaskCertsAdd` 放在任务详情的 `TaskCertsNote` 下面，行为同上。

类目没有可加的、或都加过了，整块不画。

## 5. 隐私、授权与边界

只有发单人能改，服务端已有授权。加严的保护在服务端，界面不另判断。
