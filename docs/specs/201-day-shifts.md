# 201 多天单每天不同时段

> 状态：本批实现（V225）。编号 SCN-127。
> 来源：178 号 spec「没做的」——「每天不同时段（周六 9–18、周日 10–16）」；191 号第 3 节排序（分数 12）；BACKLOG V225。
> 只增不减：统一时段（`shift_start` / `shift_end`）的规则与行为不变；不传 `day_shifts` 时与以前完全一样。

## 0. 要解决的问题

V205 让多天单写「每天几点到几点」，但只能写一个统一时段。周末快闪店常是周六 9:00–18:00、周日 10:00–16:00，只能拆成两张单——报名、选人、补招都分成两处。

## 1. 业界怎么做

排班类工具按「班次」建模，每个班次有自己的日期与起止时间；整周统一时段只是所有班次相同的特例。本平台的名额就是班次（一个名额 = 某天某人），本批让每天的名额带上各自的时段。（本批没有另找外部来源。）

## 2. 数据

不加表、不加列：名额本来就有自己的 `shift_start` / `shift_end`，生成时按天写入。母任务保留统一时段（可以为空）。

## 3. 接口

`POST /tasks` 新增可选 `day_shifts: Array<{start, end} | null>`：

- 只给多天单（`days > 1`），否则 `day_shifts_without_days`；长度必须等于天数，否则 `day_shifts_length`；
- 某天 `null` 或两端都空 → 沿用统一时段；
- 每天的规则与统一时段相同（成对、HH:MM、结束晚于开始），错误消息写明「第 N 天」；
- 名额标题照写那天的时段；撮合（V207）、接单推送（V220）按名额自己的时段走，不用改。

SDK：`DayShiftInput`、`TaskCreateInput.day_shifts`；共享函数 `dayShiftsPayload`（每天一行组装请求，全空不带、空的那天传 null）、`dayLabel`（标出第 N 天是几月几号）。

## 4. 两端

- **Web 发布页**：多天单多一个勾选「每天时段不一样」，勾上后每天一行（标出日期）、各填起止时间；取消勾选就不带。
- **App 发布页**：同样的勾选与每天一行。

## 5. 隐私、授权与边界

不涉及隐私。跨夜的班照旧拆成两天写（与 V205 一致）。
