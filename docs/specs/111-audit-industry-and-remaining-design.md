### 2.1 本次实测发现的新问题（上线级）

| # | 发现 | 怎么量的 | 后果 | 排期 |
|---|---|---|---|---|
| 1 | **日志里一半的行没经过脱敏**：uvicorn 自带访问日志带查询串（原始搜索词）；未处理异常由 uvicorn 原样打出，SQL 异常带绑定参数（手机号、密码哈希）；我们的格式化器把堆栈整个丢掉 | 按 Dockerfile 命令起真进程跑完整闭环，逐行读 stdout | 日志成为第二份个人信息库，且不在注销删除范围内 | **V137**（112 号） |

## 3. 业界怎么做（与我们的对照）

| 领域 | 业界做法 | 我们 | 差距 → 决定 |
|---|---|---|---|
| 对象级授权（OWASP API1:2023 BOLA） | 每个按 id 取对象的函数都做归属检查；**扫描器判断不了哪个对象该给谁**，所以靠显式的归属记录 + 两账号替换 id 的测试 | 166 个端点全部有归属规则；钱与身份那批有两账号行为验 | 内容类缺行为验、规则散落无总表 → V139 |
| 日志（OWASP Logging Cheat Sheet；日志平台的 PII 指南） | **首选不写**，脱敏是第二道；脱敏作用在最终字符串（含异常文本）；脱敏失败丢内容 | 只认三种数字，且一半日志没经过 | → V137 |
| 外部调用与事务（Transactional Outbox） | **不在事务里调外部 API**：先在本地事务里记意图（outbox 行）并提交，事务外调用，回写结果；重试靠幂等键 | 259/260 次在事务内 | → V138：先「提交后调用 + 回写」，异步投递的那几类走已有的 outbox |
| 连接池（PgBouncer 事务模式） | 事务模式下**不能用服务端预编译语句**（psycopg 需 `prepare_threshold=None`，或 PgBouncer ≥1.22 + `max_prepared_statements`）；`idle in transaction` 多的话任何池子都救不了 | 连接预算闸门已有，未接 PgBouncer | 先消灭事务内的外部调用（V138，否则就是 idle in transaction），再在部署文档里给 PgBouncer 配置与 psycopg 参数（V140） |
| 撮合信号（Upwork 公开的可用状态与响应时长指标） | 档案显示「可用状态」与**响应时长**（按邀约的接受 / 拒绝速度算，样本够了才显示）；第三方分析普遍认为可用性与响应度是排序因子之一（权重未公开） | 推荐只看技能、信用、评分 | → V141：可用状态 + 时段 + 响应时长进推荐，**并作为理由显示**，样本不够不显示 |
| Agent 工具权限（OWASP LLM06 Excessive Agency、AI Agent Security Cheat Sheet） | 每个任务最小工具集、按工具区分只读 / 写、**写与花钱的动作要人确认**、审计记下 agent 身份 + 用户身份 + 工具 + 动作 + 结果；模型不直接碰工具，由受信网关执行 | 经验工具只出草稿、不碰钱（AST 闸门）、每次调用留痕 | 编排器调用（AGT-084）按同一套：工具白名单按步骤给、草稿挂在步骤上等人确认 |
| 资金托管 | 持牌第三方（存管银行 / 持牌支付机构）托管，平台只发指令 | 账本与状态机已有；存管未接 | 外部，启动拦截已在 |

## 4. 未实现部分的设计（可实现规格）

### 4.1 V138 外部调用不挂事务（CONC-067）

- **规则**：调用任何供应商（`get_provider` 返回的实现）时，调用线程**不得持有未结束的数据库事务**。
- **做法**：
  - 同步请求内的调用（实名、充值下单、内容审核）：先把需要的数据读出来、**提交（或回滚只读事务）释放连接**，
    再调供应商，拿到结果后开新事务回写；回写前重新加锁读取并校验状态（期间可能被并发改过）。
  - 出款（`create_payout`）：本来就是「先记出款单再打款」的两阶段，改成两段事务：记单提交 → 打款 → 回写；
    中间崩溃由已有的对账 job 按出款单状态补。
  - 审核（`moderation.check`）：发生在发布 / 编辑之前，先审后写，审的时候不开事务。
- **闸门**：运行期探针常驻测试——引擎 `begin/commit/rollback` 事件维护每线程的事务深度，所有供应商实现
  被代理，调用时若事务深度 > 0 就记一条违规；全量测试结束时违规数必须为 0（或在声明表里写明理由）。
  扫描器自检：故意在事务里调一次，必须被记到。

### 4.2 V139 内容类授权行为验与授权总表（SEC-060f / SEC-061）

- **行为验**：对 OWASP BOLA 的标准做法——两个账号，A 建对象，B 拿 A 的 id 调每一个写 / 读私有的接口，
  断言被拒且对象未变。范围：空间条目、内容 / 评论、圈层、作品、草稿。
- **授权总表**（`docs/AUTHZ-MATRIX.md`）：每类资源 × 每个动作 → 判据类型（本人 / 当事人 / 角色 / 团队档位 / 公开）
  与理由；**管理员对私聊正文与证件影像的访问必须有明文**：默认不可，仅在纠纷举证 / 法定调取时经四眼并留审计。
- **闸门**：总表里的每一行对得上归属规则表（`OWNERSHIP_RULES`）；规则表里的每一条在总表里有一行；
  管理员访问私聊与证件的接口必须在总表的「受限」节里且有审计调用。

### 4.3 V140 N+1 系统排查与容量证明（CONC-066 / CONC-062）

- **N+1**：所有返回列表的 GET 接口，造 5 条与 20 条数据各请求一次，**查询次数相等**（允许常数差）；
  例外进声明表并写理由。
- **容量证明**：压测打 Postgres（不是 SQLite）、记池等待时间（`pool_timeout` 前的排队）、覆盖闭环链路、
  同配置连跑三次；结论写成「在 N 副本 × 池 M 下，p95 < X ms 时的稳定吞吐」，并给出 PgBouncer 事务模式的
  配置与 psycopg 参数（`prepare_threshold=None`）。

### 4.4 V141 可用时间与响应时长进入撮合（SPACE-023）

- **数据**：个人可设可用状态（可接单 / 少量 / 暂停）与每周时段（附近服务按时段，远程按每周小时数）；
  响应时长由**邀约**的接受 / 拒绝耗时算中位数，样本 ≥ 5 才显示（与 Upwork 的做法同：样本不够不给标签）。
- **撮合**：暂停的人不进推荐；时段与任务期限不重叠的降权；推荐理由里**写出来**（「这周有空」「通常 6 小时内回复邀约」）。
- **隐私**：时段只给发布方看「是否有空」，不公开完整日程。
- **两端**：个人空间编辑可用状态；推荐卡显示理由。

### 4.5 之后（设计已定，排在 V141 后）

- **AGT-084 编排器调用经验工具**：按步骤给工具白名单（只读工具默认可用，写草稿的工具要发布方授权），
  草稿挂在步骤上等人确认；审计记 agent 身份 + 授权人 + 工具 + 版本 + 结果（与 OWASP 审计字段一致）。
- **SPACE-024 持续合作空间驾驶舱**：与 AI-DEC-021 合并做——树 + 关键路径 + 预算消耗，一个入口。
- **KB-077 个案引用授权**：双方各自同意、可撤回、撤回后从详情里消失；与 `experience_reuse` 分开（引用个案 ≠ 统计复用）。
