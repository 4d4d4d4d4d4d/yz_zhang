
# 133 编排复盘：花了多少、几轮、整改过哪些、评审分、草稿采用、下一步

> 状态：本批实现（V162）。编号 AGT-091~092。
> 来源：132 号 spec「没做的」AGT-091；BACKLOG V162。
> 只增不减：编排的详情、时间线、评审都不变，只多一个只读接口和两端各一块「复盘」。

## 0. 要解决的问题

编排的详情是给「过程」看的：每一步、每一轮的时间线。结束（或进行到一半）的时候，发起人想知道的是结论：花了多少、用了几轮、哪几步返工了、质量怎样、下一步该干什么。

## 1. 业界怎么做

项目复盘（retrospective / after-action review）的固定结构：目标与结果、偏差（预算、时间）、做得好与要改进的、下一步行动。这里按编排已有的数据算出来，不用模型。

## 2. 接口

`GET /missions/{id}/summary`（发起人与管理员）：

| 字段 | 含义 |
|---|---|
| `rounds` / `max_rounds` | 用了几轮 / 上限 |
| `spent_cents` / `committed_cents` / `cap_cents` | 实付 / 占用 / 上限 |
| `steps_total` / `steps_done` / `steps_failed` | **不含被整改替代的步骤** |
| `remedies` | 整改过几次 |
| `avg_review_score` | 已完成步骤的平均评审分（没有评审为 null） |
| `drafts_total` / `drafts_adopted` | 经验工具草稿（131 号）生成与采用的份数 |
| `duration_days` | 结束了才有 |
| `highlights` | 达标、整改过哪些步骤、花费接近上限、草稿采用情况 |
| `next` | 按状态给的下一步建议（达标：存进个人知识库下次套用；没完成：改验收要点或预算再建一个……） |

## 3. 两端

Web 编排详情与 App 编排详情都多一块「复盘」；取不到不影响详情。

## 4. 闸门与红验

| 闸门 | 红验 |
|---|---|
| 被整改替代的步骤不算进总数 | 改成全算 → `test_summary_after_a_remedy_and_success` 红 |
| 写出整改过的步骤 | 去掉 → 同上红 |
| 只有发起人与管理员 | 执行方 403 |
| 响应形状 | `MissionSummary` |
| 两端 | `web/src/Missions.test.tsx`、`app/missions.test.tsx` 的复盘断言 |
