# 210 直播话术自查工具

> 状态：本批实现（V238）。编号 SCN-142。
> 来源：209 号 spec 第 3 节（分数 72）；BACKLOG V238。
> 只增不减：场景包引擎、已有工具、已有 12 个包的行为都不变；本批加一个只读工具 `live.script_check`，并接到「小店直播顾问」上。

## 0. 要解决的问题

209 号的小店直播包上线后，最常被问的会是「这句能不能说」。开播前的自查清单是死的：店主要自己一条条对照。把清单变成一个工具，贴进话术，直接标出要看的词，省掉对照这一步。

## 1. 业界怎么做

电商与直播平台普遍在商家后台提供「违禁词 / 极限词检测」：按词表标出可能违反广告法的词，提示商家修改，不替商家判定。本平台照这个做法，但只做**提示**：标出词、写清为什么、出处是什么；算不算违规以市场监管部门认定为准。（本批没有另找外部来源；出处沿用 209 号已核对的《广告法》条文，并加第十七条：除医疗、药品、医疗器械广告外，禁止其他广告涉及疾病治疗功能。）

## 2. 数据

不加表。词表写在代码里（`server/app/modules/packs/live.py` 的 `RULES`）：三类——绝对化用语（《广告法》第九条第（三）项）、功效承诺（《广告法》第十七条）、价格与限时（《明码标价和禁止价格欺诈规定》）。

## 3. 接口

不加接口：走场景包原有的 `POST /packs/{key}/assistants/{assistant}/ask`。助手的工具白名单里有 `live.script_check`、问题像在贴话术（含「话术 / 文案 / 台词 / 口播 / 能不能说 / 这样说 / 帮我看看 / 帮我查」且不短于 15 个字）时，回答里多一条工具引用「话术自查（标出 N 处）」：逐个写「词：类别，为什么，出处」（最多 5 个）；一个没标出时写明「词表只是常见的那几类，以市场监管部门认定为准」。同一个词只报一次。

`schema.TOOLS` 登记新工具（工具白名单是平台红线的一部分：只读或只出草稿）。

## 4. 两端

不改界面：两端「服务包」里向「小店直播顾问」提问的地方原样显示工具引用（与 `creator.brief` 一样）。

## 5. 隐私与边界

- 只读用户自己贴进来的那段文字，不调模型、不读任何人的数据；提问原文的处理沿用场景包原规则。
- 不断定违规：标出来的是「要看」的词；词表之外的说法照样可能有问题，写在回答里。

## 6. 闸门与红验

`server/tests/test_live_script_check.py` 2 条（词按类别标出、出处对、同词只报一次、干净话术不标、空输入；顾问回答里带工具引用、干净话术写明认定以监管为准、太短的问题不跑）。

7 处变异（`scratchpad/mut238.py`）6 处首轮变红；「不看问题长短」首轮存活（短问题用例没碰上触发词），把用例换成带「这样说」的短问题后变红。
