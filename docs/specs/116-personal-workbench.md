
# 116 个人工作台：我的任务、进度与助手（PWB-001~012）

> 状态：本批实现（V141）。来源是用户 2026-10-13 的要求：「作为一个个人门户，一定需要能够管理个人的一些任务和
> 助手的功能，最直接的就是参考 WorkBuddy 蓝皮书的功能补充进来，至少能完成个人的任务和进度的维护。」
> 同时要求「功能增补应该兼容原有实现，而不是删除原有功能」：本批**只新增**一个 `workbench` 模块，
> 不改动平台任务、合约、平台自有 Agent（48 号）等任何既有行为，由 FEAT-001 闸门核对。

## 0. 参照了什么

蓝皮书站点（workbuddy.homes）在这个环境的网络策略里打不开（403），只能依据公开的教程和评测整理出 WorkBuddy 的要点：

| WorkBuddy | 含义 | 在这里对应 |
|---|---|---|
| 工作空间 + 按空间分组的任务列表，可搜索、可筛选 | 一个项目一个空间，任务不混在一起 | **项目**（PWB-001）+ 任务列表的分组与筛选（PWB-002） |
| 自然语言下达任务 → 自主拆解 → 交付可验收成果 | 先拆步骤再做 | **助手拆清单**（PWB-005）：只出草稿，人确认后才写入 |
| 专家 / 专家团 | 多角色分工 | 平台已有：找合作者（V136）、平台 Agent（48 号）、编排（ORC）。工作台里的任务可以**一键转成平台任务**去找人（PWB-008） |
| 记忆（跨会话的偏好，建议 ≤20 条、定期清理） | 助手记得我是谁、我喜欢怎么做 | **助手记忆**（PWB-006）：上限 20 条，用户可看可删，只在调用模型时带上 |
| 定时任务（每日 / 每周 / 每月 / 一次性，结果可查，客户端须在线） | 重复的事交给它 | **例行任务**（PWB-007）：在服务端运行，**不需要客户端在线**；有运行记录，连续失败会自动暂停并通知 |
| 运行合同：名称、频率、输出、超时、负责人 | 自动化要说清楚 | 每条例行任务都有名称、频率、类型、下次运行时间、最近结果，失败原因写给人看 |

## 1. 数据

| 表 | 关键字段 | 说明 |
|---|---|---|
| `wb_projects` | owner、name、color、archived、sort | 项目（工作空间）。有任务时不能删，只能归档 |
| `wb_items` | owner、project、parent、title、notes、status、priority、due_at、remind_at、progress、tags、linked_task_id、revision、completed_at | 个人任务；`parent` 用于清单子项（只有一层） |
| `wb_logs` | item、kind（note / status / progress / assistant）、body | 进展记录；状态和进度变化**自动记一条** |
| `wb_memories` | owner、content | 助手记忆，每人最多 20 条 |
| `wb_routines` | owner、name、kind（digest / review / reminder）、freq（once / daily / weekly / monthly）、time、weekday、monthday、run_at、note、item、enabled、next_run_at、failures | 例行任务 |
| `wb_routine_runs` | routine、status（ok / failed）、output、started_at | 运行记录 |

**状态**：`todo` 待办、`doing` 进行中、`blocked` 卡住、`done` 完成、`dropped` 放弃。个人任务不强制状态机：
人自己的事，怎么改都行，但每次改都会留下进展记录。

**进度**（PWB-003）三种来源，响应里用 `progress_source` 写明：
- `children`：有清单子项时，按完成的子项占比计算，**不能手填**（否则两个数会互相打架）；
- `platform`：关联了平台任务时，按平台任务的状态换算（招募 0 → 成交 25 → 进行中 50 → 待验收 80 → 完成 100），只读；
- `manual`：其余情况手填 0~100；标成完成时自动记为 100。

## 2. 接口（全部只对本人可见；访问别人的资源返回 404，不泄露是否存在）

| 能力 | 接口 |
|---|---|
| 项目 | `GET/POST /workbench/projects`，`PATCH/DELETE /workbench/projects/{id}` |
| 任务 | `GET /workbench/items?project_id=&status=&view=today\|overdue\|week\|all&q=`，`POST /workbench/items`，`GET/PATCH/DELETE /workbench/items/{id}` |
| 进展 | `GET/POST /workbench/items/{id}/logs` |
| 助手拆清单 | `POST /workbench/items/{id}/breakdown`（返回草稿）→ `POST /workbench/items/{id}/children`（确认写入） |
| 关联 / 转平台任务 | `PATCH` 时传 `linked_task_id`（必须是自己发布或执行的平台任务）；转成平台任务走既有的发布页，带着标题和说明过去 |
| 概览 | `GET /workbench/overview`：今天到期、已逾期、进行中、卡住、7 天没动静的任务，各项目进度，以及**平台上等我处理的事**（有人报名待我选、交付待我验收、我在执行的单） |
| 记忆 | `GET/POST /workbench/memories`，`DELETE /workbench/memories/{id}` |
| 例行任务 | `GET/POST /workbench/routines`，`PATCH/DELETE /workbench/routines/{id}`，`POST /workbench/routines/{id}/run`（立即运行），`GET /workbench/routines/{id}/runs` |
| 定时执行 | `POST /workbench/jobs/run-routines`，每分钟一次（调度表 JOB-001 登记），同时发送任务上的到点提醒 |

## 3. 助手（PWB-005~007）

- **拆清单**：走既有的分解网关（与平台任务拆解同一个，事务守卫与费用上限都沿用）。配了模型 Key 时由模型拆，
  并带上这个人的记忆；没配时，先查知识库模板和经验流程单元，都没有就给一份通用清单
  （明确目标与完成标准 → 准备资料 → 动手做 → 检查与收尾）。**只出草稿**，确认后才写入，与平台「AI 只出草稿」的原则一致。
- **记忆**：上限 20 条，每条 ≤200 字。只在调用模型时带上，不进日志。用户可以随时看、随时删，注销时一并删除。
- **例行任务**：
  - `digest` 概览：把 `overview` 写成一段话，发一条通知；
  - `review` 回顾：本周完成了什么、逾期了什么、哪些卡住了；
  - `reminder` 提醒：到点发一条通知（可以关联某个任务）。
  - **错过的不补跑一串**：服务停机期间错过的运行只补一次，并在输出里写明错过了几次；
  - **连续失败 3 次自动暂停**并通知本人：不让一条坏掉的例行任务每分钟往数据库里写一条失败记录；
  - 时间按 `Asia/Shanghai` 解释，数据库里存 UTC。
- 通知类目为 `assistant`，可以在通知偏好里关掉。

## 4. 隐私与边界

- 个人任务、记忆和例行任务**都不公开**，不进搜索，不进推荐，也不进经验库（经验只来自平台上闭环的任务）。
- PIPL 导出（`/users/me/export`）包含全部工作台数据；注销时全部物理删除。
- 数量上限：项目 50、任务 2000、每个任务的子项 50、进展记录 500、记忆 20、例行任务 20。超出返回 409 并说明原因。

## 5. 两端

- **Web** `/workbench`：「今天」「全部」「看板」三个视图，按项目分组；任务详情里有清单、进度条、进展记录和「让助手拆一下」；
  助手页可以管理记忆和例行任务，并查看运行记录。
- **App**：「我的工作台」页，提供同样的今天 / 全部视图、任务详情、清单勾选、进展记录、助手拆清单、记忆和例行任务。
- 入口：顶部导航新增「工作台」，「我的空间」里也加一个入口。原有导航项一个都不删。

## 6. 闸门

| 闸门 | 红验 |
|---|---|
| 别人的项目、任务、记忆、例行任务一律 404（对象级授权表 `self`） | 去掉 owner 过滤 → 红 |
| 有子项的任务不能手填进度；关联平台任务的进度只读 | 放开 → 红 |
| 关联的平台任务必须是自己发布或执行的 | 去掉校验 → 红 |
| 例行任务：按时触发、错过只补一次、连续失败 3 次暂停并通知 | 去掉暂停 → 红 |
| 到点提醒只发一次 | 去掉已提醒标记 → 红 |
| 拆清单只出草稿，不写库 | — |
| 导出包含工作台，注销清空 | 漏一类 → 红 |
| 列表接口不随数据量增长查询次数（115 号闸门自动覆盖） | — |
| 功能面清单（FEAT-001）登记新接口 | — |
