
# 278 作品展示授权

> 状态：本批实现（V305）。编号 SCN-156。
> 来源：274 号 spec「没做的」——「整理收纳前后对比照做成接单者作品（带客户授权记录）」；BACKLOG V305。
> 只增不减：空间作品不关联任务时与以前完全一样（存下来的也不多 `task_id` 这个键）；任务详情只在授权了、且看的人是成交双方时多一个字段。

## 0. 要解决的问题

V298 的整理收纳包教接单者「拍前后对比照先问」。可真想把做过的单放进空间当作品时，平台上没有一处记下客户同意过；客户反悔了，作品也还挂着。装修、设计、上门做饭的成品照都是一样的问题。

## 1. 业界怎么做

服务撮合与设计平台通常把「作品展示」做成需要委托方授权、可撤回的一项，作品页标注来自平台订单。（本批没有另找外部来源；依据是民法典隐私权、个人信息保护法的同意与撤回。）

## 2. 规则

- **授权**：已完成验收的单，发单人在任务详情里点「允许展示这一单」（`POST /tasks/{id}/showcase-consent`）；只有发单人能授权（接单人 403），没完成的单 400 `showcase_task_not_completed`。
- **撤回**：发单人随时点「撤回展示授权」（`DELETE`）。
- **关联**：接单人在空间编辑里给作品填「来自平台上的哪一单」（任务编号）。保存时检查：自己是那一单的接单人、且发单人已授权，否则 400 `showcase_consent_required` 并写明是哪几单。
- **公开**：空间公开页与发现页预览里，关联了任务、而那一单的授权已撤回的作品不显示（自己的编辑页还在，可以删或等对方重新授权）；公开页的作品上标「平台上做过的单 · 委托方已同意展示」。
- 授权时间只给成交双方看。

## 3. 数据

`tasks.showcase_consent_at`（迁移 `c1d220260070`）。空间作品（JSON）多可选的 `task_id`。

## 4. 接口

| 接口 | 说明 |
|---|---|
| `POST /tasks/{id}/showcase-consent` | 发单人；已完成的单 |
| `DELETE /tasks/{id}/showcase-consent` | 发单人 |
| `PUT /spaces/me` | 作品可带 `task_id`（要授权） |
| `GET /tasks/{id}` | 成交双方、授权了才带 `showcase_consent_at` |

SDK：`grantShowcaseConsent` / `withdrawShowcaseConsent`；`Task.showcase_consent_at?`、`SpaceItem.task_id?`；i18n 两个错误码；对象级授权表加一行（发单人的动作）。

## 5. 两端

- **Web**：任务详情（已完成、发单人）「允许展示这一单 / 撤回展示授权」；空间编辑每件作品多「来自平台上的哪一单」；公开页作品标注。
- **App**：任务详情同样的授权块（`app/showcase.tsx`）。App 的空间编辑暂不支持关联任务（SPACE-030 的一部分）。

## 6. 隐私、授权与边界

只有发单人能授权与撤回；只有那一单的接单人能关联；撤回立即生效于公开页与发现页。
