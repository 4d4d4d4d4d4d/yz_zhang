
# 85 手抄的数字没有人核对（DOC-010 / DOC-011）

> 状态：本批实现（V111）
> 依赖：57 号（调度表同源）、72 号（现状台账）、84 号（没有人跑的脚本）

## 0. 探针

V109 那一批**刚刚做过完整的 doc sync**：把 README、DELIVERY、追溯矩阵的
后端测试计数从 1164 改成 1182，逐份确认过。下一批开头顺手一查：

```
$ grep -rn "1164" docs/
docs/OPERATIONS.md:107: 这套组合已被 **1164 个测试**覆盖…
docs/OPERATIONS.md:606: …这些有 1164 个测试钉着。
```

**改了四份文档，漏了第五份里的两处。**

这不是粗心，是机制：同一个数字被手抄进五处，而**没有任何东西在核对**。
V57 早就立过同一条道理——「调度表是手抄的，手抄的清单一定会漂移」——
当时的解法是让调度器与声明表同源。文档不能「同源」，那就让闸门去核对。

顺带说明为什么这条值得单独做一篇：**过期的计数不是排版问题**。
读者用它判断「这套东西有多少东西钉着」，而 1164 与 1193 之间那 29 条，
恰好包含了 V107~V110 补上的那些闸门。一个把旧数字当现状读的人，
会低估也会高估——**低估已经有的保障，高估还没做的部分**。

## 1. 权威来源只能有一个

真实数字不自己数，跑 `pytest --collect-only -q` 去问 pytest。

理由和 V105 那次一样：手写的第二份实现必然与真实计数漂移。
自己数 `def test_` 在这个仓里当场就会差——`parametrize` 的一个函数
对应多条测试。**一个算不准的闸门比没有闸门更糟**：它会红在没问题的时候，
然后被人关掉。

## 2. 闸门只钉后端计数，理由写清

文档里还写着「前端 161 tests（core 56 + web 84 + App 21）」。这一批
**不扫它们**，因为它们的权威来源是三套 npm 测试的输出，回归里拿不到
（要 node 在位、跑一遍十几秒），而用 AST 数 `it(` 就又是第二份实现。

漏掉的这一半记在 72 号台账（`DOC-011`），不假装已经覆盖。
前端计数目前由 CI 的 `frontend` job 的输出兜着——人看得见，机器没在核对。

## 3. 历史记录不许为了闸门变绿被改掉

第一次跑闸门，它报了四处不一致，其中**两处是误报**：

| 匹配到的 | 实际含义 |
|---|---|
| `改了 314 个测试` | 那一批**改动了** 314 个测试里的断言——量词一样，含义不同 |
| `改坏之前 703 个测试全绿` | V45 当时的实况记录：那个缺陷在 703 个测试下全绿 |

第二条尤其不能改：**把它改成今天的数字等于伪造当时的证据**。
72 号台账第 3 节已经立过这条原则（「那些段落是当时的实况记录，
改掉就失去了『当时知道什么』的价值」）。

处理方式沿用这个仓里一贯的做法：给一张 `HISTORICAL` 明账，
**值是理由不是布尔**。而不是把正则调窄到谁也说不清它在查什么——
调窄正则是把误报换成漏报，而漏报是静默的。

这张表自己也要被钉住，否则它会变成「红了就往里塞」的后门：

- 表里的短语必须**真的还在文档里**（删掉了就该删表项）；
- 理由 ≥12 字，且不许是「还没做 / 待补 / TODO / 以后」——
  与 82 号 spec 禁掉的那类豁免理由同一条道理。

## 4. 这个闸门会咬自己

加测试就会改变计数，所以**加测试的那一批必须同时改文档**——
否则回归红。这是有意的：它把「doc sync」从一件靠记性的事，
变成一件不做就过不去的事。

代价：每批都要动一次文档。这个代价是划算的，因为漏掉它的成本
（文档里的数字慢慢失真到没人信）是不可逆的——一旦读者发现文档的数字
对不上，**整份文档的可信度一起没了**，而不只是那个数字。

## 5. 闸门

| 闸门 | 内容 |
|---|---|
| DOC-010 自检 | 至少在 4 份文档里扫到计数，且 README / DELIVERY / OPERATIONS 都在内 |
| DOC-010 一致 | 每一处声明的后端计数都等于 `pytest --collect-only` 的真实数 |
| DOC-010 诚实 | `HISTORICAL` 表里的短语必须还在文档里；理由 ≥12 字且不许是欠账词 |

红验四条走过：把 OPERATIONS 写回旧数字、把正则改歪（自检先红）、
把一条真的过期声明塞进豁免表、豁免表里留一条文档里已没有的短语。

## 6. 这一批没做的

- **前端计数没覆盖**（`DOC-011`）：见第 2 节。
- **别的数字也没覆盖**：迁移条数（32）、表数（88）、job 数（22）、
  spec 编号上限同样是手抄的。它们变动频率远低于测试数，而每加一条
  闸门都要多一条误报风险——**先钉最常漂的那一个**，其余按需再加。
  记在台账 `DOC-012`。
- **不检查计数是否被写成区间或约数**（「一千多个测试」）：这种写法不会
  过期，闸门也就没必要管它。
