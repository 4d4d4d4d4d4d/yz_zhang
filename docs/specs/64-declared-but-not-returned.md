# 64 声明了却不给，给了却不声明（TASK-060~063 / CLI-068）

> V85 的形状闸门只盯着 V73~V79 那六条新线。把同样的比对手工跑一遍**老接口**，
> 立刻掉出两条：
>
> ```
> KEYS Task: 声明有服务端没给=['bonus_cents', 'distance_m', 'ip_assignment']
> KEYS Me:   服务端给了没声明=['certifications', 'credit_level', 'referral_code']
> ```

## 0. 两条不是「字段没对齐」那么轻

### TASK-060 浮动对价的上限，没给要靠它决策的那个人

`dump_task` 返回 `pricing: "outcome"`，**不返回 `bonus_cents`**。

于是执行方在任务页上看到「浮动对价」四个字，却看不到浮动部分到底有多少。
而 OUT-002 的整个立论是：

> 浮动部分必须是**确定的正数上限**——这样它才是一个可执行的承诺。

一个确定的上限，**没有给到需要用它做决定的人**，那它对这个人不成立。
托管的时候钱是按 `budget + bonus` 全额托的（OUT-003），也就是说
平台已经把这笔钱锁住了，只有执行方不知道它存在。

### TASK-061 强制选了知识产权归属，执行方却看不见

V77 把 `ip_assignment` 改成必填，理由写得很清楚：

> 替发布方猜归属，对执行方不公平，对含第三方素材的交付物直接就是错的。

现在没有人猜了，但 `dump_task` 不返回这个字段——**执行方在报名前仍然
不知道自己做出来的东西归谁**。他能看到的最早时点是合同条款（签约时），
而那时他已经决定接这单了。

**「必须选」和「看得见」是两件事，只做前一件，公平没有兑现。**

### TASK-062 `Me` 上三个字段客户端根本不知道存在

`certifications`（已核过的资质）、`credit_level`（信用等级，对应费率折扣）、
`referral_code`（邀请码）——服务端一直在返回，TS 类型里没有，
于是没有任何界面能用上它们：用户看不到自己的资质通过了没有，
也看不到自己的信用等级带来了什么。

## 1. CLI-068 闸门扩到老接口，并且比类型

V85 的闸门留了三条「没做」，其中两条正是这次的漏点：

- **CLI-070** 响应比对只覆盖那六条线；
- **CLI-068** 只比键名，不比类型。

这一批都补上：

### 覆盖面

把 `Task` / `Contract` / `Me` / `Wallet` / `Dispute` / `DisputeStatement` /
`Notice` / `Conversation` / `Message` / `Mission` 等**老接口**纳入同一套比对。

补的时候会掉出历史遗留（比如 `Me` 那三个），**这正是目的**：
老接口没有一次性对齐过，闸门第一次覆盖它们时掉出东西是正常的，
把它们修掉、然后不许再漂。

### 比类型

在键名之外比**值的类型**：`number` 收到 `"200"`、`boolean` 收到 `0`
这类错，键名比对一个都抓不到。

规则要写得克制，否则会假报：

- 可选字段（`foo?:`）服务端不给**不算错**——它就是可选的；
- 联合类型逐个试，命中一个就算过（`number | null`）；
- 字面量联合（`'a' | 'b'`）按值比；
- 自定义别名（`IpAssignment`）当成字符串——**不去解析别名的定义**，
  那是编译器的活，闸门只要抓住「类型层级错了」这一类，
  而**一个假报警多的闸门会被人关掉**（V80 的教训）。

## 2. 验收点

| 编号 | 验收点 |
|---|---|
| TASK-060 | 任务详情返回 `bonus_cents`，浮动对价任务在页面上能看到浮动上限 |
| TASK-061 | 任务详情返回 `ip_assignment`，报名前就能看到归属，并显示成人话 |
| TASK-062 | `Me` 的 `certifications` / `credit_level` / `referral_code` 进类型并被界面用上 |
| CLI-068 | 闸门比字段**类型**：声明 `number` 而服务端给字符串时变红 |
| CLI-070 | 闸门覆盖老接口（Task/Contract/Me/Wallet/Dispute/…） |
| — | 可选字段缺失不报警；联合类型与字面量联合不误伤 |

## 3. 这一批没做的

- **CLI-071**：嵌套对象里的字段类型不比（只比顶层）。`members: Array<{…}>`
  里面写错仍然抓不到。要比就得把 TS 的类型表达式真正解析出来——
  到那一步，更合算的做法是**从 OpenAPI 生成 TS 类型**，那是另一批。
- **CLI-072**：请求体仍然只比字面量对象；透传 patch 的调用跳过（V85 已记）。
