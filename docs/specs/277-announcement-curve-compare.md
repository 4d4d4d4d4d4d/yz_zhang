
# 277 几条公告的阅读曲线放在一起比

> 状态：本批实现（V304）。编号 NTF-074。
> 来源：261 号 spec「没做的」——「几条公告的曲线放在一起比（按发送时段 / 标题长度）」；BACKLOG V304。
> 只增不减：单条「看曲线」不变；只多一个对比接口与界面上的勾选。

## 0. 要解决的问题

V288 能看一条公告发出后多久被点开。运营真正要的判断是「早上发和晚上发哪个好」「短标题是不是更多人点」，得把几条放在一起看。

## 1. 业界怎么做

消息推送平台的报表一般支持多条消息的打开率并排比较。（本批没有另找外部来源。）

## 2. 规则

- 勾几条已发出的公告（最多 5 条，至少 2 条才能比），按勾选的顺序列出：标题、北京时间几点发的、1 小时 / 1 天 / 3 天 / 7 天内的点开比例；没到的时间点标 `*`。
- 曲线口径与 261 号完全一样（复用同一个函数）。
- 传了不存在的公告 → 404 并写明是哪几条；超过 5 条 → 422。

## 3. 数据 / 接口

| 接口 | 说明 |
|---|---|
| `GET /admin/announcements/read-curves?ids=1,2,3` | 运营；返回每条的曲线 + `title` + `sent_local` |

SDK：`announcementReadCurves(ids)`；类型 `AnnouncementCurveCompareRow`。登记：后台角色表、覆盖表、功能面清单。

## 4. 两端

- **Web 后台「全站公告」历史**：已发出的每条多一个「对比」勾选；勾了出现「对比这 N 条的阅读曲线」，点了出对比表。
- **App**：后台只在 Web，不涉及。

## 5. 隐私、授权与边界

只有运营角色；只出聚合比例。
