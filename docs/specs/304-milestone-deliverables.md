
# 304 每一期挂各自的交付附件

> 状态：本批实现（V331）。编号 SC-017。
> 来源：296 号 spec「没做的」——「每一期挂各自的交付附件」；BACKLOG V331。
> 只增不减：交付文件不写期数时与 V324 完全一样（挂整份合约、全部放款后原图才解锁，文案一字不差）；挂文件的接口只多一个可选字段，响应只在挂了期数时多 `milestone_idx`。

## 0. 要解决的问题

- V323 一次交付多期只能共用一份交付说明，V324 的交付文件挂在整份合约上：验收第 2 期时，发布方分不清哪几张图是第 2 期的。
- 分期付款的人付了第 1 期也拿不到第 1 期的原图，得等全部放完——分期本来就是为了「交一期、验一期、付一期」。

## 1. 业界怎么做

外包与众包平台的里程碑（milestone）托管通常一期一个交付物：执行方按期提交文件，发布方按期验收放款，放款后这一期的成果归发布方。（本批没有另找外部来源。）

## 2. 规则

- 执行方挂交付文件时可以选「挂到第几期」：这一期要存在（否则 400 `milestone_not_found`，说清没有第几期）、还没放款（已放款 409 `invalid_milestone_state`：「挂到还没放款的那一期」）；交付了没放款的期可以补挂。
- **挂到某一期的原图，那一期放款后发布方就能下载**；挂整份合约的照旧等全部放完。执行方任何时候都能取自己的原图（不变）。
- 下载接口与列表用同一条判断（`_original_unlocked`），列表里的 `locked` / `url` 与真能不能下一致。

## 3. 数据 / 接口

- `contract_deliverables.milestone_idx`（可空，迁移 c1d220260076；SQLite 与 Postgres 都验过升级、回退、`alembic check`）。
- `POST /contracts/{id}/deliverables` 多可选 `milestone_idx`（1~100）；行多可选 `milestone_idx`。
- 共享 SDK：`ContractDeliverable.milestone_idx?`；`addDeliverable(contractId, ref, kind, milestoneIdx?)`；两端共用的文案 `deliverableLockedText`（锁着的原图说清各等哪一期）与 `deliverableStageTag`（「（第 N 期）」）。

## 4. 两端

- **Web 任务详情「交付文件」**：合约多于一期、执行方在托管期间时多「挂到哪一期」下拉（默认整份合约；已放款的期不在里面）；预览图与下载按钮标「（第 N 期）」；锁着的原图说「第 2 期 1 张在这一期放款后可以下载；其余 1 张全部放款后可以下载」。
- **App 任务详情「交付文件」**：同样的选择（一排可点的「整份合约 / 第 N 期 …」）与同样的文案。

## 5. 隐私、授权与边界

授权不变：只有执行方能挂、只能挂自己上传的图，只有合约双方能看；解锁只会因为钱真的放了才发生。
