
# 366 对话式需求澄清：说一句话，追问几句再发单

> 状态：本批实现（V394）。编号 AI-DEC-001。
> 来源：台账 AI-DEC-001「对话式需求澄清」（欠）；愿景 V-5「AI 协助：不懂领域」；BACKLOG V394。
> 只增不减：新增一个接口、一个网页页面、一个 App 子页；发布页多一个入口按钮，并多认一个 `budget` 查询参数（带了才用，不带与原来一样默认 200 元）。发布、拦截、K12 规则、任务画像都不变。

## 0. 要解决的问题

发单人常常只会说一句话：「家里要打扫一下」。发布页的表单一摆出来，他不知道该写什么。写出来的单缺时间、缺地点、缺「做到什么程度」、缺「怎么算做完」。接单的人看不懂、报不了价，双方来回问，或者干脆没人接。

已有的帮助都是「给一份已经写好的单挑毛病」：任务画像的完整度（126 号）、创作类九项（140 号）。缺的是从一句话开始的那一步。

## 1. 业界怎么做

客服机器人与预约类产品常见的做法是「槽位填充」：认出意图后，逐个追问缺的关键信息（时间、地点、规模），问齐了生成订单草稿，由用户确认。这是通行做法，本轮没有引用外部链接。

本批取：
- 规则版、不调模型：可预测、零成本、离线可用。模型版留作后续。
- 每次最多问 3 个，必答的问齐就可以带走。
- 发单拦截与 K12 规则一开始就先过一遍：别让人问了半天，最后发不出去。

## 2. 规则

| 问题 | 什么时候问 | 必答 |
|---|---|---|
| 类目 | 说明里没有类目名，也没有常见说法（打扫→保洁、遛狗→宠物照护、水龙头→水电维修……）；给几个常见类目让人选，不猜 | 是 |
| 在哪里做 | 没说线上、远程，也没答过 | 是 |
| 什么时候要 | 说明里没有今天、明天、周几、几号、几点这类说法 | 是 |
| 做到什么程度 | 说明不到 20 个字 | 是 |
| 怎么算做完 | 说明里没有验收、标准、交付这类说法 | 是 |
| 预算 | 没答过；可以跳过，发布页会给参考价 | 否 |
| 替谁发 | 说到爸、妈、老人、家里人时才问；提示发布页可以勾「替别人发」 | 否 |

草稿：标题取第一句（30 字内）；说明是原话加上每个答案一行（「地点：…」「时间：…」「要做到：…」「验收：…」「预算：…」「服务对象：…」）；是否线上、预算（元转分）随答案生成。

不认识的问题键整个忽略：里面写什么都不参与拦截判断、类目猜测和草稿。

## 3. 接口

`POST /tasks/clarify`，请求体 `{text: 2~500 字, answers: {键: 答案}, category?}`，要登录。不落库、不发布。

返回 `{questions: [{key, ask, required, options}], draft: {title, description, category, is_remote, budget_cents, on_behalf_hint}, ready, blocked: {code, message} | null, remaining_required}`。

被发单拦截或 K12 规则拦下时：`blocked` 给出原有的错误码与人话说明，不给问题，`ready` 为假。

## 4. 两端

- **SDK**：`clarifyTask(text, answers, category)`；类型 `ClarifyResult` / `ClarifyQuestion` / `ClarifyDraft` / `ClarifyBlocked`；草稿转模板 `clarifyTemplate`、转发布页查询参数 `clarifyPublishQuery`（有预算才带）、进度一行 `clarifyProgressLine`。
- **Web**：
  - 发布页多一个「💬 说一句话，帮我问清楚」按钮，进 `/publish/clarify`。
  - 在那一页说一句话、逐批回答（类目给下拉），问清后「带到发布页」，标题、类目、说明、预算预填。
  - 说到家里人时提示可以勾「替别人发」。
  - 被拦下说清原因。
  - 响应畸形说「稍后再试」，不白屏；新路由已进畸形响应探针。
- **App**：「我的」里多一项「说一句话发单」，同样的问答；问清后用已有的发布页模板通道（SCN-133）打开发布页预填。

## 5. 隐私、授权与边界

- 不落库：说过的话、答过的问题只在这一次请求里用，不存。
- 只出草稿：发不发、怎么改由人在发布页定（「钱、签署、申报、对外发布：AI 只出草稿，人确认」）。
- 不判断真假、不给专业意见；只问发单最常缺的几样。
