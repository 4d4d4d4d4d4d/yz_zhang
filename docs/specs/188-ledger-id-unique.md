# 188 台账编号唯一

> 状态：本批实现（V215）。编号 DOC-020。
> 来源：V213 改 APP-095 撞号时发现台账有 63 个编号出现两次；BACKLOG V215。
> 只增不减：台账的结构（详情段 + 逐条索引）不变；只给撞号的那条换号，原号保留给先登记的那件事。

## 0. 要解决的问题

现状台账（72 号）是「已做 / 欠 / 外 / 意」的总账，BACKLOG、spec、提交说明都按编号引用它。V212 新加的 APP-095（页面坏的人多了提醒运营）和 136 号早就登记的 APP-095（开票入口没有端上测试）撞号，一个号指两件事，「APP-095 已做」就说不清是哪一件。

逐个看 63 个重复编号：62 个是同一件事在详情段（2.1 / 2.2）与「2.4 逐条索引」各一行，这是台账有意的写法；真正撞号的是同一段里两行同号——除了 APP-095，还有 PAY-044（75 号的提现催办 / 143 号的批量操作）。

## 1. 业界怎么做

需求追踪矩阵要求每条需求有唯一标识，并在变更时保持引用稳定（ISO/IEC/IEEE 29148 对需求「可唯一标识」的要求）。本批照此：先登记的保留原号，后登记的换号并在行里写明原号，旧引用还能查到。

## 2. 数据

无。

## 3. 接口

`python -m scripts.harness check` 新增一项：台账同一段内同一编号出现两次就报「撞号」，写明哪一段、哪两行、怎么办（给后加的那条换个没用过的号）。`tests/test_harness.py::test_the_repo_passes_its_own_harness_check` 随之覆盖，`tools/regress.sh` 也跑这项。

## 4. 两端

不涉及界面。

## 5. 隐私、授权与边界

只读文档。详情段与逐条索引各一行不报（否则 62 处有意的写法都会误报）。
