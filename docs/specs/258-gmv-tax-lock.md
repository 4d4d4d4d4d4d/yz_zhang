# 258 成交额与代扣税表的锁账

> 状态：本批实现（V285）。编号 FIN-067。
> 来源：249 号 spec「没做的」——「成交额与代扣税表的锁账（与平台收支表同样的快照与补记规则）」；BACKLOG V285。
> 只增不减：锁账接口与平台收支表的锁账（223 号）都不变；没锁过账时成交额与代扣税表与以前一样，每行只多三个恒为默认值的字段。
> 写明的行为变化：`finance_period_locks.gmv_tax`（迁移 c1d220260063）；锁账时同时存这张表的快照。

## 0. 要解决的问题

223 号让平台收支表锁账后不再变，但 242 号的成交额与代扣税表仍然每次现算：锁账之后补记一笔放款或代扣，已经报出去的月成交额、代扣税就变了，和交给记账代理的表对不上。

## 1. 业界怎么做

与 223 号相同：关账（period close）后报表只读，迟到的分录单独列示并在后续期间处理。（本批没有另找外部来源。）

## 2. 规则

- 锁账（`POST /admin/platform-finance/lock`）时，对这次锁的每个月同时存一份成交额与代扣税表的快照。
- 读表时，有快照的月份：数字读快照、`closed` 为真，另报锁账后又记进来的成交额与代扣税差额（`late_gmv_cents`、`late_withheld_cents`），**不计入**这一行。
- 与平台收支表不同，这张表的补记不搬到下一个月（它不是余额连续的账户表）；差额只在锁过的那一行另列，财务据此在下一期申报中处理。
- 本批之前锁过的月份没有快照，照旧现算、`closed` 为假。
- 季度：三个月相加（锁过的月份读快照）；三个月都锁过才算已锁；期末待缴取季度最后一个月的；有锁账时被代扣人数是各月之和（同一人跨月会重复计）。
- CSV 导出同样读快照，最后多三列「锁账 / 锁账后又记进成交额 / 锁账后又记进代扣税」。

## 3. 数据

`finance_period_locks.gmv_tax`（JSON，可空）。迁移在 SQLite 与 Postgres 上 `upgrade head` + `check` 通过。

## 4. 接口

| 接口 | 变化 |
|---|---|
| `GET /admin/platform-finance/gmv-tax` | 每行多 `closed`、`late_gmv_cents`、`late_withheld_cents` |
| `GET /admin/platform-finance/gmv-tax/export` | 末尾多三列 |
| `POST /admin/platform-finance/lock` | 同时存成交额与代扣税快照（响应不变） |

SDK：`PlatformGmvTaxRow` 多三个可选字段。

## 5. 两端

- **Web 后台「成交额与代扣税」**：锁过的月份标「已锁」，有补记时写明「锁账后又记进成交额 X、代扣 Y，未计入上面的数」。
- **App**：后台只在 Web，不涉及。

## 6. 隐私、授权与边界

不变（只有财务）。锁账不能撤销（223 号）。
