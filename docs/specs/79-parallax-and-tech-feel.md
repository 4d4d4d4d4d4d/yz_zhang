# 79 视差与科技感（PRLX-050~056 / UI-090）

## 2026-10-07 视觉方向变更

当前界面以 [Spec 88](88-individual-network-and-spaces.md) 的暖白、个人窗口和四入口为准。本篇早期深色科技风作为历史方案保留。原任务广场在 /opportunities 保留视差；新发现/空间使用渐入、轻量浮动与卡片反馈，系统减少动态效果时关闭装饰位移。尚无完整跨页共享元素动画。合同、费用与授权决策文字必须保留。


> 状态：本批实现（V104）
> 依赖：45 号（App 发现流视差，PRLX-010/020/030 三条约束在那里立的）、
> 21 号（移动端与 PWA）

## 0. 这一批的要求与它的边界

用户的要求：**在满足基本功能的前提下，用视差滚动把 app 与 web 做出科技感。**

现状：App 的发现流已经有视差（45 号），而 **web 一处都没有**——
`styles.css` 131 行，是一套很干净的浅色样式，没有任何运动层。

先把边界说清楚，因为这一批的风险不在"做不出效果"，在"效果伤到功能"：

### PRLX-050 动钱与签署的页面不做位移

钱包、提现、合约签署、支出审批——这些页面**不加任何滚动位移**。

理由很具体：视差的本质是元素随滚动移动，而移动的元素包括按钮。
**一个在手指底下漂移的按钮不是效果，是功能缺陷**，而这几个页面上点错
一下的代价是钱。科技感在这些页面靠**静态**手段做：网格底纹、发丝级边框、
等宽数字、克制的辉光。

这条做成一张**声明表 + 扫描**（与 65 号 `MUST_REACH`、76 号
`ADMIN_EXEMPT`、78 号 `QUEUES` 同一种做法），不靠"记得别在那儿用"。

### PRLX-051 `prefers-reduced-motion` 是完全关闭，不是减半

45 号已经为 App 立过这条，web 照搬：

> 开着这个开关的人里有相当一部分是**前庭功能障碍者**——视差、缩放
> 这类大面积位移是明确的眩晕诱因。**减半仍然会让人难受。**

所以 reduced-motion 下：视差层位移为 0、入场动画直接到终态。
不是"距离乘 0.3"，是**根本不动**。

### PRLX-052 只有 `transform` 与 `opacity` 参与滚动动画

RN 上动别的属性会在**真机上**抛错而 CI 看不见（45 号 PRLX-010）；
web 上动 `top` / `height` / `margin` 会在滚动时触发重排，
**做出来比不做还卡**。两边都只允许 transform / opacity，各有一条扫描钉着。

### PRLX-053 滚动回调里不许 setState

45 号 PRLX-030 立过：每帧 setState 会让整棵树重渲染，比不做视差还卡。
web 这边的等价做法是：一个 `scroll` 监听 + `requestAnimationFrame` 节流，
把滚动量写进 **CSS 变量**，位移由 CSS `transform` 完成——
**React 一次都不重渲染**。

## 1. UI-090 科技感从静态层来

「科技感」如果只靠运动，滚动停下来之后就什么都不剩。所以主要工作在静态层：

- **深色底 + 网格**：`--bg` 转深色，叠一层 1px 网格与两处径向辉光。
  网格用 `background-image` 的线性渐变画，不是图片——零请求、任意分辨率清晰。
- **发丝边框与分层**：卡片用 `rgba` 白色描边而不是实色线，深色底下更像"面板"。
- **等宽数字**：金额一律 `font-variant-numeric: tabular-nums`。
  金额跳动时数字不再左右抖，这既是观感也是**可读性**——对账时眼睛能对齐列。
- **克制的辉光**：只在主色按钮与"已超 SLA"这类状态徽章上加，
  满屏发光会让文字可读性下降，而这个平台上要读的是金额与条款。

配色集中在 `:root` 的 token 里，**一处能改回去**——这是可逆的，
不是散落在 40 个组件里的硬编码。

## 2. 三个组件，一份实现

- `<TechBackdrop />`：整站固定背景（网格 + 辉光），随滚动做**慢速**位移。
  全站一个实例，挂在 `App` 根上。
- `<ParallaxHero>`：页面顶部的标题区，装饰层随滚动移动，**内容层不动**。
  只用在广场、任务详情、内容/发现这类"没有按钮在被按"的地方。
- `<Reveal>`：进入视口时淡入 + 小位移（≤12px，≤240ms）。
  用 `IntersectionObserver`，一次性触发，不做"滚出去再淡出"那种来回动。

App 侧**不新写**：把 `Discover.tsx` 里已有的 `useReduceMotion` 与
Animated 模式提到 `app/motion.tsx`，任务详情的 hero 复用它。
**第二份实现必然抄漏**——45 号的三条约束（native driver / reduced-motion /
不在回调里 setState）如果抄一遍，必然漏掉一条。

## 3. 闸门

| 闸门 | 内容 |
|---|---|
| PRLX-054 | `MOTION_FORBIDDEN` 表里的页面，源码里不许出现视差/入场组件 |
| PRLX-055 | 视觉层模块里，滚动驱动的样式只能是 transform / opacity |
| PRLX-056 | reduced-motion 下位移为 **0**（web 测试真的把 `matchMedia` 打开） |
| PRLX-057 | App 侧只有一份 `useReduceMotion`（不许出现第二个定义） |

`MOTION_FORBIDDEN` 的值同样是**理由**而不是布尔（V90 那条）：
「钱包」写的是"提现按钮在手指底下漂移，点错一下的代价是钱"。

## 4. 验收点

| 编号 | 验收点 |
|---|---|
| UI-090 | 深色科技底、网格、辉光在全站生效，金额用等宽数字 |
| UI-090 | 配色 token 集中在一处，可一次改回 |
| PRLX-050 | 钱包 / 提现复核 / 合约签署 / 审批页面**没有**视差与入场位移 |
| PRLX-051 | reduced-motion 下视差层位移为 0、入场直接到终态 |
| PRLX-052 | 视觉层里没有动 top/left/width/height/margin 的滚动样式 |
| PRLX-053 | 滚动时 React 不重渲染（位移走 CSS 变量） |
| PRLX-057 | App 侧 `useReduceMotion` 只有一个定义，hero 复用它 |

## 5. 这一批没做的

- **没做浅色主题切换**：现在是深色一套。要做主题切换得先把 token
  分成语义层与色板层，那是另一批的量级。
- 没有 **WebGL / 三维**：一个任务协作平台的首屏不该下载几百 KB 的
  渲染库，而且它会直接吃掉低端安卓机的电量。
- 没有**滚动劫持**（smooth-scroll hijack / 整屏翻页）：它会破坏
  浏览器原生的滚动条、键盘翻页与「查找」定位——**观感换掉了可用性**。
- 没做**首屏动画编排**（多元素依次入场）：那需要一个动画时间线抽象，
  现在的 `<Reveal>` 是各自触发。
- App 侧只把 hero 接上了，**列表卡片的视差没做**：RN 上列表项做视差
  要接 `FlatList` 的 `onScroll` 映射，代价与收益要先量一量。
