
# 120 合作驾驶舱（SPACE-024 / AI-DEC-021 / APP-007）

> 状态：本批实现（V145）。设计见 [111 号](111-audit-industry-and-remaining-design.md) 第 4.5 节：
> 「与 AI-DEC-021 合并做——树 + 关键路径 + 预算消耗，一个入口」。
> 只增不减：公开的进度接口 `/tasks/{id}/tree` 和任务页上的「子任务进度」都不变。

## 0. 要回答的四个问题

母任务拆成十几步、分给几个人之后，发布方要回答四个问题：
- **现在做到哪了？**
- **卡在谁那里？**
- **钱花了多少？**
- **哪里要我出手？**

原来的 `/tasks/{id}/tree` 只回答第一个（按预算加权的进度），而且只看一层。

## 1. 接口

`GET /tasks/{id}/cockpit`，**只给母任务发布方**（403 / 404）：里面有每一步托管了多少、付了多少，那是发布方自己的账。

| 字段 | 含义 |
|---|---|
| `progress_pct`、`steps_total`、`steps_done` | 只算叶子步骤（容器步骤自己不托管，算进去会重复） |
| `budget` | `planned`：母任务预算；`allocated`：各步骤预算合计；`committed`：已托管、还没付出去的；`paid`：已付；`remaining`：计划减已托管减已付 |
| `critical_path` | 剩余步骤最多的那条依赖链。没有工期估计，就不假装算「最长工期」；这条链上任何一步拖一天，整件事就晚一天 |
| `alerts` | 纠纷中（款项冻结）；过了截止时间（催办、改期或发起纠纷，改期就是 V144 的变更单）；招募超过 3 天没人报名（改价、改说明或主动邀约）；已交付等你验收；各步骤预算合计超出母任务预算 |
| `nodes` | 树上每一个节点：谁在做、状态、预算、截止时间、是否逾期、被哪几步卡住（`blocked_by`）、是否在关键路径上、是否在纠纷中 |

取数按层批量查，查询次数与节点数无关；最多 6 层、300 个节点。依赖关系是 V132 起的同层兄弟依赖，跨容器的依赖不计入关键路径（记为已知近似）。

## 2. 两端

- **Web 任务详情**（发布方、有子任务时）：在「子任务进度」下面新增「合作驾驶舱」一块，内容包括：
  - 四个钱数；
  - 「需要你出手」的预警，每一条都能点进对应的步骤；
  - 关键路径；
  - 每一步的表格：谁在做、状态、预算、截止、卡在哪几步。
- **App 任务详情**（APP-007 移动简化版）：进度、四个钱数、预警、关键路径。

## 3. 闸门

| 闸门 | 说明 |
|---|---|
| 确认拆解后：五步、账上 0 托管；关键路径上相邻两步有依赖，后一步被前一步卡住 | 行为 |
| 第一步成交托管后「已托管」等于它的预算，「还剩」相应减少；逾期出现在节点和预警里 | 行为 |
| 非发布方 403、不存在 404；公开的 `/tree` 照常可读 | 授权（对象级授权表 `party`） |
| 关键路径只数没完成的步骤；全部完成时为空；依赖成环的脏数据不死循环 | 单元 |
| 响应与 SDK 类型 `Cockpit` / `CockpitBudget` / `CockpitNode` / `CockpitAlert` 一致 | 形状 |
