
# 394 App 图片地址统一走 mediaUri，组件要的服务端地址一律传到（APP-120）

> 状态：本批实现（V421）。编号 APP-120。
> 来源：390 号「没做的」：发现页还有一处手写拼地址。动手时又发现一处和 V417 同类的缺陷。BACKLOG V421。
> 只增不减：发现页、视频页、前一步成果、客服工单截图改用 `mediaUri` 拼地址，对正常地址结果不变；详情页补传服务端地址；新增一道静态闸门。

## 0. 要解决的问题

- **又一处同类缺陷**：App 任务详情里，项目中一步的接单人能看「前一步的成果」（AI-DEC-024，321 号）。
  - 渲染这一块时没传服务端地址，组件默认空串；
  - 前一步开放的预览图因此是相对路径，真机上加载不出来。
  - 和 V417 修的交付预览一模一样：组件单测传了地址，所以一直是绿的。
- **手写拼法四处各写各的**：发现页、视频页、前一步成果、客服工单截图。它们对畸形地址（`javascript:`、协议相对的 `//…`）不设防，会拼出来去加载。
- 同一类问题第二次出现，说明靠记得不行，要有闸门。

## 1. 业界怎么做

把「服务端相对地址 → 客户端可加载地址」收成一个函数、用静态检查禁止手写拼接，是前端常见做法。本轮没有引用外部链接。

## 2. 数据 / 接口

不涉及。用的是 V417 新增的 SDK `mediaUri`。

## 4. 两端

**App**：
- 发现页图片、视频页视频、前一步成果预览、客服工单截图，都改用 `mediaUri`：
  - 拼不出来的（畸形、外链协议）不画；视频当没有；
  - 正常地址结果与原来一致，原有断言照过。
- 任务详情渲染「前一步的成果」时传上服务端地址。

网页不变（同源，相对路径本来就能用）。

## 5. 隐私、授权与边界

不涉及授权。不加载畸形或外链协议的地址，少一处被注入地址的口子。
