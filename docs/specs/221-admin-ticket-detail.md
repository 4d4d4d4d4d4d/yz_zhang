# 221 后台工单详情与完整往来

> 状态：本批实现（V249）。编号 ESCA-058。
> 来源：BACKLOG V249（「客服只看到最新一句」）；166 号 spec（提单人追加回复）之后，后台队列只露最新一句补充与回复次数。
> 只增不减：`GET /admin/tickets` 队列的字段与筛选不变；提单人一侧（`GET /support/tickets`）仍然只看到「客服」，看不到是哪位。
> 写明的行为变化：新增 `GET /admin/tickets/{ticket_id}`；Web 工单台每一行多一个「看完整往来」按钮。

## 0. 要解决的问题

工单被转手（指派、升级、换班）后，接手的客服在后台只看得到工单原文、提单人最新一句补充和「已回复 N 次」。前一位客服说过什么、提单人前面补过什么，后台哪里都看不到——只能再问一遍提单人，这正是工单系统要避免的事。

## 1. 业界怎么做

主流客服工单系统的工单页都以完整往来（时间线）为主体，每一条写明是客户还是哪位客服、什么时候；客服内部可以看到彼此的名字，对客户只显示「客服」或统一署名。本批照这个做法补上后台详情。（本批没有另找外部来源。）

## 2. 数据

不加表、不加列：读已有的 `tickets` 与 `ticket_replies`（`author_id`、`is_staff`）。

## 3. 接口

| 接口 | 说明 |
|---|---|
| `GET /admin/tickets/{ticket_id}` | 客服角色（`support`，超级管理员含未分级）可看。返回工单原文、状态、处理结果、提单人昵称、接手人、时限与优先级（与队列同一个 `sla_view`），以及 `thread`：每一句 `{body, is_staff, author, created_at}`，按时间先后；客服写昵称（没有昵称写「客服 #id」），提单人写「提单人」。没有这张工单 404；别的角色 403 |

SDK：`AdminTicketDetail`、`AdminTicketThreadItem`、`client.adminTicketDetail(ticketId)`。

## 4. 两端

- **Web** 后台「待处理工单」每一行「看完整往来」：展开提单人、提交时间、原文与每一句往来（客服写「客服 某某」），再点「收起往来」。还没有往来的写「还没有往来。」
- **App**：后台只在 Web（管理员不在手机上处理工单，SEC-061d 起后台板块只在 Web），App 不改。

## 5. 隐私、授权与边界

- 只给客服角色；财务、审核等别的角色看不到工单内容（403）。
- 客服之间可见彼此昵称；提单人一侧保持只显示「客服」（ESCA-053 的约定），测试同时断言。
- 只读，不改工单状态。
