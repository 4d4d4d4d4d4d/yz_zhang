
# 262 后端未用导入清零并进静态检查

> 状态：本批实现（V289）。编号 LINT-004（第一步：app/ 与 scripts/ 的未用导入）。
> 来源：台账 LINT-004「后端风格类 lint 未开（150 余条未用导入等）」；BACKLOG V289。
> 只增不减：只删了没人用的导入（没有任何接口、函数、名字被删）；ruff 规则只加不减。

## 0. 要解决的问题

V168（139 号）只开了「一定是错」的 ruff 规则，未用导入留着没管。未用导入会误导读代码的人：以为这个名字在这里有用，改的时候不敢动。它和 V168 的 `func` 没导入是同一类错的两面。前几批陆续清掉了一部分，到本批 app/ 与 scripts/ 只剩 14 处。

## 1. 业界怎么做

Python 项目普遍用 ruff / flake8 的 F401 拦未用导入，并给 `--fix` 自动删。只在清到 0 之后再打开，免得一打开就满屏、逼人加 `--quiet` 绕过。（本批没有另找外部来源。）

## 2. 做了什么

- `ruff --fix --select F401` 删了 app/ 与 scripts/ 的 14 处未用导入。逐个查过：没有被测试或别的模块从这里引用、也没有被 monkeypatch 的名字，也没有只为注册模型而导入的。
- `tests/test_metrics_truthful.py` 的 `RULES` 加上 `F401`：以后 app/ 与 scripts/ 里新写的未用导入，全量回归和 CI 都会变红。
