# 256 主管替客服设置暂停

> 状态：本批实现（V283）。编号 ESCA-067（主管安排暂停的部分；按排班表自动暂停拆成 ESCA-068）。
> 来源：248 号 spec「没做的」——「主管替客服设置暂停（例如安排排班、请假），与按排班表自动暂停 / 恢复」；BACKLOG V283。
> 只增不减：客服自己暂停（240 号）与主管替人恢复（248 号）都不变；同一路径多一个 POST。

## 0. 要解决的问题

248 号让主管能替人恢复接单，但请假、调班往往是主管安排的：客服本人可能已经不在线，忘了自己点暂停，新工单就照样分给他。

## 1. 业界怎么做

客服系统的主管视图通常可以替坐席切换状态（离开 / 在线），并通知坐席本人。（本批没有另找外部来源。）

## 2. 规则

- 主管（超级管理员）在「客服状态」里对在岗的人点「替他暂停」，填小时数（1~720，与 240 号相同的范围）。
- 效果与本人暂停完全一样：自动分配跳过、超时提醒先叫别人、到点自动恢复；本人也可以提前恢复。
- 只能给能处理工单的管理员设置（否则 `assignee_not_support`）；没声明过负责类别的补一行「什么都管」。
- 进审计（`support_pause_by_supervisor`），通知本人（给自己设的不通知）。

## 3. 数据

不新增表与字段。

## 4. 接口

| 接口 | 说明 |
|---|---|
| `POST /admin/support/agents/{user_id}/pause` | 超级管理员；`{hours}`；返回 `{user_id, paused_until}` |

SDK：`pauseSupportAgent`。登记：后台角色表。

## 5. 两端

- **Web 后台「客服状态」**：在岗的人多「替他暂停」，问几小时；暂停中的仍是「替他恢复」。
- **App**：后台只在 Web，不涉及。

## 6. 隐私、授权与边界

只有超级管理员；普通客服 403。
