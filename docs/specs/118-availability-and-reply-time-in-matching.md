
# 118 可用时段、少量接单与回复时长进入撮合（SPACE-023）

> 状态：本批实现（V143）。设计见 [111 号](111-audit-industry-and-remaining-design.md) 第 4.4 节；
> V142 已把「报名 / 做成过的类目 / 空间自述」三项相关性加进推荐（117 号）。
> 只增不减：原有的「可接单时间」文字描述、接单开关（下线不进推荐）都保留。

## 1. 数据

| 字段 | 说明 |
|---|---|
| `users.weekly_slots` | 每周可用时段，北京时间 `[{d: 0~6（0=周一）, from: "HH:MM", to: "HH:MM"}]`，最多 14 段，`to` 可以是 `24:00` |
| `users.limited_capacity` | 少量接单：还接，但这阵子忙 |
| `invitations.responded_at` | 回复邀约的时刻：接受或婉拒都算回复 |

## 2. 撮合（叠加在可配置的四项加权之上，不改后台权重）

| 信号 | 条件 | 加减分 | 写给发布方的理由 |
|---|---|---|---|
| 截止前有空 | 线下任务有截止时间，且本人设的时段在「现在到截止」之间出现过 | +0.04 | 「截止前有空（按本人设的时段）」 |
| 截止前没空 | 同上，但一段都没落在里面 | −0.06 | **不写**：只降权，不替他公开日程 |
| 回复快 | 回复邀约的中位时长 ≤ 12 小时，**样本 ≥ 5 次**（与 Upwork 同一做法：样本不够不给标签） | +0.03 | 「通常 N 小时内回复邀约」（样本够了就写，快慢都写） |
| 少量接单 | 本人勾选 | −0.03 | 「这阵子少量接单」 |

- 没设时段的人不加分也不减分：不能因为没填表就被压下去。
- 时段计算看「现在到截止」这一段，最多看两周。
- 三项一次查齐，查询次数与候选人数无关（115 号闸门守着）。
- 分数夹在 0~1 之间。

## 3. 两端

- **Web** 资料页新增「什么时候有空」：按星期勾选并设起止时间，另有「这阵子少量接单」；原有的「服务设置与隐私」不变。
- **App**「我的」里新增「我的可用时间」：同样的设置；时间写错会先拦下，不发请求。

## 4. 闸门与红验

| 闸门 | 红验 |
|---|---|
| 时段判断按北京时间，跨午夜、跨周、`24:00` 都对 | 判断恒真 → 红 |
| 截止前有空的写进理由；没空的只降权、理由里不出现日程 | 把「没空」写进理由 → 红 |
| 回复时长样本不够 5 次不显示 | 去掉门槛 → 红 |
| 婉拒和接受都记下回复时刻 | 婉拒不记 → 红 |
| 时段校验：结束早于开始、星期越界返回 422；原有字段照常可改 | — |
| 两端保存时发出的时段格式一致 | — |
