# 153 第三轮场景发掘：雷达新信号与三个场景包

> 状态：本批实现（V167）。编号 SCN-108（并新开 SCN-111、SCN-112 记在第 7 节）。
> 来源：BACKLOG V167「第三轮场景发掘：用雷达的真实聚合信号；每轮补充家庭事务、社区活动组织者、学生作品接单」；skill `scenario-discovery` 第 1 节「雷达还没覆盖的（法律问答转律师的类别、客服没解决的工单类别）手动查聚合计数」。
> 只增不减：雷达原有三路信号（搜了没有、有需求没人接、服务包要复核）不变；法律问答的响应不变。
> 写明的行为变化：法律问答答不上时，记一条「粗主题 + 提问人编号」的事件（**不存问题原文**）。

## 0. 要解决的问题

- skill 里写着两路信号「手动查」：法律问答答不上的是哪类问题、客服没接住的是哪类工单。**手动查就是没人查**——这两路恰好是最直接的「用户来了、平台没接住」。
- 法律问答此前不落任何记录：答不上的问题问完就没了，运营不知道该补哪类知识。
- 第三轮人群（家庭事务、社区活动组织者、学生作品接单）还没有场景包。

## 3. 规则与接口

| 编号 | 内容 |
|---|---|
| SCN-108-1 | `POST /legal/ask` 答不上（`out_of_scope`）时，按关键词把问题归到粗主题（劳动用工、租房买房、婚姻家庭、借贷欠款、消费维权、交通事故、知识产权、公司经营、邻里社区、其他）记一条事件；**原文不落库**；答得上的、紧急拒答的不记 |
| SCN-108-2 | 雷达 `legal_gap`：近 30 天某主题至少 3 个不同的人答不上 → 出现一条（主题、人数、「不存原文」） |
| SCN-108-3 | 雷达 `support_gap`：近 30 天的工单里**升级过**或**至今未结且已超过 SLA** 的，按标题关键词归到粗主题（提现到账、退款售后、账号登录、实名资质、发票税务、纠纷投诉、接单派单、其他），至少 3 个不同的人 → 出现一条；雷达上只有主题与人数，不出标题原文 |
| SCN-108-4 | 三个场景包过平台红线校验（工具白名单、按人群的人工关口、知识有出处、模板类目存在），助手能答出各自最要紧的几句（持证作业、劳务受伤责任、活动许可门槛、志愿者保险、出借银行卡的刑事风险、委托作品的著作权） |
| — | 主题表在 `server/app/modules/packs/topics.py`，写给人看、可直接增改 |

## 4. 两端

- **Web 管理后台「服务包 → 场景雷达」**：来源标签多两种「法律问答答不上」「客服没接住」。
- **用户侧**：三个新场景包上线后，在两端「服务包」里与其他包一样启用与提问（引擎与两端界面 V148 已有，本批只是数据）。
- **App 管理后台**：管理后台只在 Web，不涉及。

## 5. 隐私与边界

- 法律问答只记主题与提问人编号，不存问题；工单标题只在服务端归类，雷达只输出主题与人数；任何一路都要至少 3 个不同的人（K_ANON）。
- 主题是关键词粗分，会有误归；它只用来提示「该看看哪一类」，不用于对任何个人的判断。
- 场景包里的法律条文是常识性的出处说明，助手按包内约定不提供法律意见；活动许可只提醒、不替人判断，拿不准问当地公安机关。

## 7. 没做的

- **SCN-111 雷达主题按语义聚类**：现在是关键词粗分，落到「其他」的多了要人看；后续可用经验聚类（KB-070）同一套办法。
- **SCN-112 按雷达主题补法律知识**：`legal_gap` 出现后，补法律 FAQ 或对应场景包的知识条目仍是人工；可以做成雷达上一键「起草知识条目」（只出草稿，审核上线）。
- 三个包上线需要运营在后台导入种子、提交审核、另一位管理员上线（四眼，文件不能绕过）。
