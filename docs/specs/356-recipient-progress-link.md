
# 356 服务对象自己看进度：免登录只读链接

> 状态：本批实现（V383）。编号 SCN-122。
> 来源：175 号 spec 第 7 节「没做的」——「服务对象自己也能看到进度（给爸妈发一条只读链接或短信：谁来、几点到）」；台账 SCN-122「欠（短信通道外）」；BACKLOG V383。
> 只增不减：新增一张表、四个接口、两端一块面板与一个免登录页面；`purge-locations` 的响应多一个键 `purged_recipient_links`；注销多删一张表；数据导出多一个键。替别人发单（V202）、改服务对象（V223）的行为都不变。

## 0. 要解决的问题

子女替爸妈发单（SCN-119）之后，最常发生的对话是爸妈打电话问：「人几点来？叫什么？来了没有？」

- 发单人只能截图转述，或者把接单人的电话给爸妈。电话给出去以后，接单人和第三人之间就脱离了平台。
- 短信通知要持牌短信服务商，是「外」。
- 平台内能做的那一半：发单人生成一条链接，用微信等自己的渠道发给爸妈。爸妈不用注册、不用登录，点开就能看。

## 1. 业界怎么做

| 做法 | 说明 |
|---|---|
| 出行与外卖的「分享行程 / 分享订单」 | 下单人把一条只读链接发给家人：看得到司机或骑手、车牌或预计到达，看不到付款信息；行程结束后链接失效。这是常见的公开产品功能，本轮没有引用外部链接 |
| 本仓库的团队邀请链接（TEAM-066，147 号） | 令牌只返回一次、库里只存哈希、有有效期、可作废——本批照这个做法 |
| 《个人信息保护法》第六条 | 处理个人信息限于实现目的的最小范围：链接页只给服务对象要知道的几件事 |

## 2. 数据

新表 `recipient_links`（迁移 `c1d220260090`，SQLite 与 Postgres 都 `upgrade head && check` 过）：

| 字段 | 说明 |
|---|---|
| `task_id`、`created_by` | 哪一单、谁生成的（发单人） |
| `token_hash` | 令牌的 SHA-256；令牌本身不入库 |
| `expires_at`、`revoked_at` | 到期时间（1~14 天，默认 7 天）、作废时间 |
| `view_count`、`last_viewed_at` | 被打开过几次、最近一次 |

## 3. 接口

| 接口 | 谁能用 | 说明 |
|---|---|---|
| `POST /tasks/{id}/recipient-link` `{days}` | 发单人 | 只有替别人发的单（否则 `recipient_link_not_on_behalf`）、单子没结束（否则 `recipient_link_task_closed`）。令牌只在这个响应里出现一次；重新生成即作废这一单之前的链接 |
| `GET /tasks/{id}/recipient-link` | 发单人 | 状态：none / active / revoked / expired、到期时间、打开次数、最近一次；不含令牌 |
| `DELETE /tasks/{id}/recipient-link` | 发单人 | 作废，立刻打不开 |
| `GET /recipient-progress/{token}` | 任何人（免登录） | 令牌就是授权。按来访 IP 每分钟最多 30 次。作废或不存在的给 `recipient_link_invalid`，过期的给 `recipient_link_expired`，都说清「找发单的家人重新发一条」 |

链接页返回：服务对象的称呼、单子标题、进展（还在找人 / 已定好人 / 已开始 / 做完了等确认 / 已完成 / 取消了 / 暂停沟通）、接单人的昵称与是否实名、约定的日子与时段、计划上门几次与已回报几次、最近一次到达时间、链接到期时间。

**不给**：手机号、到场联系、精确地址与商圈、价钱、说明正文、照片、位置坐标、聊天、任何用户编号。

多人或多天的单：链接生成在整单上，链接页列出每个名额的接单人（带日期），进展按各名额汇总。到达只算接单人本人的打卡与上门回报。

其他登记：

- 发单人以外的人调用前三个接口，一律 403 `recipient_link_not_owner`。
- 对象级授权表：两条规则。
- 注销：删除这个人生成过的全部链接，链接立刻打不开。
- 数据导出：`recipient_links`（状态、有效期、打开次数，不含令牌）。
- 定时清理：`POST /tasks/jobs/purge-locations` 一起删过期或作废满 30 天的链接记录，响应多 `purged_recipient_links`。

## 4. 两端

- **共享 SDK**：类型 `RecipientLinkStatus` / `RecipientLinkCreated` / `RecipientLinkRevoked` / `RecipientProgress` / `RecipientProgressHelper`；方法 `createRecipientLink` / `recipientLink` / `revokeRecipientLink` / `recipientProgress`；文案 `recipientLinkLine` / `recipientLinkUrl` / `recipientProgressLines`；五个错误码进 i18n。
- **Web 任务详情**：替别人发、发单人本人、单子没结束时出现「给服务对象一条进度链接」。选有效天数，生成后显示完整地址（只显示这一次）和复制按钮；可重新生成（旧的作废）、可作废；一行说清有效到哪天、被打开过几次。
- **Web `/r/:token`**：免登录页面，字号放大，只有几行人话，末尾提醒「有疑问直接联系发单的家人；不要把验证码、银行卡号告诉任何人」。
- **App 任务详情**：同样的面板。选天数，生成后把完整网页地址交给系统分享（微信等）；可作废。部署没配网页地址时不生成，说清「请在网页上生成」，因为对方拿到令牌也打不开。

## 5. 隐私、授权与边界

- 服务对象是第三人。链接页只给他要知道的几件事，不给任何能用来联系、定位或付钱的信息。
- 令牌 32 个字符的随机串，只存哈希、有有效期、可作废、按 IP 限流；链接外泄时发单人一键作废。
- 发单人能看到被打开过几次，作为「爸妈看到了没有」的参考，也能发现链接是否外泄。
- 平台不替发单人联系第三人：链接由发单人自己发出（与 175 号「平台不联系第三人」一致）。
- 不碰钱、不碰验收；服务对象在链接页上不能做任何操作。
