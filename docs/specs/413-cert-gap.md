# 413 推荐里告诉发单人有几个人因为没证被排除

> 状态：本批实现（V440）。编号 SCN-294e。
> 来源：408 号（V435）「没做的」。408 号让要资质的单只推荐持证的人，但发单人看不到被挡掉了多少人。
> - App 的推荐区在一个推荐都没有时整块不显示，发单人分不清是没人可推，还是自己加选的证把人全挡了；
> - 这正是他最需要判断「这张证真要不要」的时候。
>
> 只增不减：推荐接口不变（仍返回列表），另加一个只读接口；推荐的候选池抽成一个函数，与新接口共用，召回规则一字不改。

## 0. 要解决的问题

让发单人看见：
- 有几个人因为没证没进推荐；
- 其中几个人只差他自己加选的那一张。

只给人数，不给是谁。

## 1. 业界怎么做（带来源链接）

招聘和撮合平台在筛选条件把人挡光时，常见做法是告诉发布方「放宽某个条件能多看到多少人」，而不是只给一个空列表。这里只对发单人自己加选的资质算「只差这一张」：类目要的资质、未成年人证明是平台规则，发单人放宽不了。本轮没有引用外部报道链接。

## 2. 数据

不改表。

## 3. 接口

`GET /tasks/{task_id}/recommendations/cert-gap`：只给发单人（别人 403，任务不存在 404）。返回字段：

| 字段 | 含义 |
|---|---|
| `required` | 这一单要的全部资质（与报名准入同一份） |
| `task_certs` | 其中发单人加选的 |
| `pool` | 过资质之前的候选人数（实名、开着接单、不是本人、不是 agent，双方没拉黑） |
| `eligible` | 张张都有的人数 |
| `excluded` | 因为资质被挡掉的人数，等于 `pool - eligible` |
| `only_missing` | 每张加选资质各有几个人「只差这一张」：其余都有、就缺它；为 0 的不列 |

- 不要资质的单：`excluded` 为 0，`only_missing` 为空。
- 推荐与这个接口共用 `matching._pool()`，两边数得上：拉黑的人两边都不算。

## 4. 两端

- **SDK**：
  - `recommendationCertGap(taskId)`；
  - 类型 `RecommendationCertGap`；
  - `certGapLine()`：没人被排除、响应畸形时返回空串，不画。有人被排除时出一句话，例如：
    - 「另有 4 个人因为没有「高处作业操作证」没进推荐；其中 3 人只差你加选的「高处作业操作证」。这张证真用不上的话，下次发单别勾」；
    - 没人能接时改成「现在没有人同时有……，N 个人因此没进推荐」。
- **Web**：任务详情的「AI 推荐人选」卡片里加这一句；推荐为空、但有人被排除时，卡片照样出现。
- **App**：`RecommendationsBlock` 同样处理；推荐为空时不显示「邀约是请对方来报名」那句。旧服务端没有这个接口、或响应畸形时，照旧不画。

## 5. 隐私、授权与边界

- 只给人数，不给名单、证号和有效期。
- 候选池小的时候，人数本身也透露不出是谁：发单人本来就看不到候选池里有谁。
- 只有发单人能看，进对象级授权表（与推荐同一条）。
