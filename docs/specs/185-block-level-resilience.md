# 185 页面内块级防护：畸形响应只坏一块

> 状态：本批实现（V213）。编号 APP-093。
> 来源：183 号 spec「没做的」——「APP-093 页面内块级防护扩到钱包、工作台、个人空间：这些页坏一块会整页换说明卡」；BACKLOG V213。
> 只增不减：错误边界（183 号）与上报（184 号）不变，仍是最后一道；SDK 所有方法的签名与返回类型不变，数组响应原样返回。

## 0. 要解决的问题

183 号让一页渲染出错时不白屏，而是整页换成「这一页没加载出来」。但探针显示，**拿到畸形响应（`{}`、`null`、字符串）时 Web 有 32 个页面组件、App 有 8 屏会落到这张整页说明卡**：钱包、工作台、个人空间、影响力、通知、后台……其中大多数只是某一个列表接口回的不是数组。坏一块就丢整页，用户连同一页上好的部分也用不了。

同一批里查到：后台工单列表、通知页在畸形响应下会在**异步里**抛错（不经过错误边界），vitest 以「未处理的异步错误」让 GitHub CI 红（CI-003，见台账）。

## 1. 业界怎么做

- React 官方建议错误边界按「出错时希望用户看到什么」分层摆放，而不是只包整页（<https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary>）。
- 客户端对服务端响应做运行时校验、校验失败按空态或局部错误处理，是常见做法（如 zod 的 `safeParse` 返回成功/失败而不抛错，<https://zod.dev/basics#handling-errors>）。本批不引入校验库：列表接口统一在 SDK 一层收成空表，对象接口只看「点名的列表字段是不是数组」。

## 2. 数据

无新表、无迁移。

## 3. 接口

无新服务端接口。共享 SDK（`packages/core`）：

| 新增 | 说明 |
|---|---|
| `listOf`（client.ts 模块内） | 返回类型是数组的 90 个调用点（`request<X[]>` / `request<Array<…>>`）都接上 `.then(listOf)`：数组原样返回，不是数组时给空表。调用点仍以 `this.request<` 开头，响应形状闸门照常解析 |
| `hasLists(x, ...keys)` | 对象响应像不像样：是对象（不是数组），且点名的字段都是数组 |
| `MALFORMED_TEXT` | 不像样时这一块显示的话：「这一块的数据格式不对，暂时显示不了。刷新一下试试；一直这样请联系客服。」两端同一句 |

## 4. 两端

- **Web**：工作台「今天」、个人空间（看别人 / 编辑自己 / 关注列表）、影响力、拆解页对象响应不像样时只在那一块显示 `MALFORMED_TEXT`；钱包代扣明细、隐私授权、新人任务、沙箱模型目录不像样时那一块不画；笔记标签、领券列表按空表处理；后台工单列表、通知页的异步加载不再抛错。
- **App**：我的空间、别人的空间、工作台概览、OPC 账本、能力画像、影响力显示 `MALFORMED_TEXT`；权利页的代扣与同意项各自独立（一段不像样不画，另一段照常）；沙箱模型目录不像样不画。

## 5. 隐私、授权与边界

- 不改变任何授权；不上报响应内容。
- 「当作空表」只用于显示：写操作的返回仍按原样交给页面（列表类写操作如「笔记转待办」也收成空表，页面会显示「没有」而不是崩）。
- 真正的服务端错误（非 2xx）照旧抛 `ApiError`，由页面显示原因，不会被当成空表吞掉。
