# 223 已出期间的报表锁账

> 状态：本批实现（V250）。编号 FIN-063。
> 来源：144 号 spec「没做的」——「已出过的期间不能再变（补记只能记在当期），要先定补记规则」；BACKLOG V250。
> 只增不减：一个月都没锁过时，`GET /admin/platform-finance/periods` 的数字与以前同一段计算、完全一样，只多几个恒为默认值的字段；导出 CSV 原有各列不动，「自检」仍在最后一列，新列插在它前面。
> 写明的行为变化：新表 `finance_period_locks`（迁移 c1d220260047）；新接口 `POST /admin/platform-finance/lock`；锁过的月份报表读快照。

## 0. 要解决的问题

按期间的报表每次打开都按流水现算。给记账代理、报过税的那个月，只要之后再有一笔流水落进那个月（跨零点提交的事务、补录、时区换算差），数就变了，而且没人知道它变过。财务需要「出过的数不再变；后来才知道的，记在当期并写明」。

## 1. 业界怎么做（带来源链接）

- 记账软件的「锁账日期」：设了以后，日期早于锁账日的交易不能再新增或修改；Xero 分「报告期锁账」与「年末锁账」两种（<https://help.dext.com/en/s/article/lock-dates>）。同一来源也指出 Xero 的锁账日可以随时被改、且不留修改记录——本平台因此**不提供解锁**，每次锁账进审计（审计本身是哈希链，ADMIN-062）。
- 会计上「前期差错更正」与「当期调整」的通行做法：已结账期间不再改动，更正记在当期并注明所属期间。本批的补记规则照此。

## 2. 补记规则（本批先定下的规则）

1. 锁账按**北京时间自然月**、按顺序：「锁到 M 月」= M 月以前（含）全部锁上。第一次锁从平台账户有流水的第一个月起逐月存快照；之后从上次锁到的下一个月起。只能锁已经过完的月份；锁过的不能再锁、不能解锁。
2. 已锁的月份：报表只读锁账那一刻的快照（佣金、笔数、结算、补贴、其他、净额、期初、期末、自检）。锁账后才写进这个月的流水另报 `late_cents` / `late_count`，**不改这个月的数**。
3. 这些补记全部记到**第一个未锁月份**：本期多出这些（按科目进对应栏目，佣金笔数也算），期初相应减去——于是它的期初正好等于上一个已锁月份快照的期末，账接得上、自检照样平。另报 `carried_in_cents` / `carried_in_count`。
4. 第一个未锁月份之后再被锁时，它的快照就带着这些补记；再往后的月份不会重复记。
5. 季度报表由月份汇总：三个月都锁了才算已锁；季度的期初取第一个月的期初、期末取最后一个月的期末。

## 3. 数据

`finance_period_locks`：`period`（唯一）、`snapshot`（锁账时这个月的报表行）、`in_month_cents` / `in_month_count`（锁账时记在这个月里的流水合计与笔数，用来算「锁账后又记进来多少」）、`cumulative`（锁账时月末以前的累计，按报表栏目、含笔数，用来算第一个未锁月份要记入的补记）、`locked_by`、`locked_at`。只含平台自己的账，不含用户信息。迁移在 SQLite 与 Postgres 上 `upgrade head` + `check` 通过；锁账用例在 Postgres 上也跑过。

## 4. 接口

| 接口 | 说明 |
|---|---|
| `POST /admin/platform-finance/lock` `{through: "YYYY-MM"}` | 财务角色。月份没过完 `period_not_ended`；已锁过 `period_already_closed`（两位财务同时锁，后到的也是这个，不是 500）。返回这次锁上的月份。进审计（「锁到 2025-02（2025-01~2025-02，2 个月）」） |
| `GET /admin/platform-finance/periods` | 每行多 `closed`、`late_cents`、`late_count`、`carried_in_cents`、`carried_in_count`；顶层多 `locked_through`、`locked_at` |
| `GET /admin/platform-finance/periods/export` | 「自检」前插入三列：锁账、锁账后又记进本期、本期含补记以前期间 |

新错误码进 `i18n.ts`。SDK：`PlatformFinancePeriod` / `PlatformFinancePeriods` 新字段、`PlatformFinanceLockResult`、`client.lockPlatformFinance(through)`。后台入口闸门（`test_admin_surface_coverage`）登记。

## 5. 两端

- **Web** 后台「平台财务 · 按期间」：一行写明「已锁到 2025-02（时间）：锁过的月份报表不再变」或「还没有锁过账：每次打开都按最新流水现算」；选月份「锁账到此月」，按下前确认（写明锁了不能解锁），锁完重新读报表；已锁的月份标「已锁」，有补记的写「锁账后又记进 N 笔（¥x），已记到下一个未锁月份」，第一个未锁月份写「含补记以前期间 N 笔（¥x）」。
- **App**：后台只在 Web，不涉及。

## 6. 隐私、授权与边界

- 只给财务角色；不含用户个人信息。
- 锁账不拦任何资金动作：流水照常写，只是报表口径按上面的规则归期。钱本身的动作仍然走原有的四眼与幂等。
- 不能解锁：出过的数要更正，就在当期记一笔调整，报表会把它显示在当期。
