# 224 自动核验单用量进运营看板

> 状态：本批实现（V251）。编号 AGT-073。
> 来源：217 号 spec「没做的」——「自动核验单的用量放进运营看板（今天下了几张、额度用了多少）」；BACKLOG V251。
> 只增不减：`GET /admin/metrics` 原有字段不变，多一个 `auto_verify`；AGT-072 的上限规则不变（判断改为调用同一个用量函数，条件一字未改）。

## 0. 要解决的问题

V245 给平台自费的自动核验单加了 24 小时上限（默认 50）。但运营看不到用了多少：额度用完以后，审核拿不准的 AI 交付就不再自动请人看，只通知发布方——这件事发生了、发生了几次，后台哪里都没写。上限要不要调、调多少，没有依据。

## 1. 业界怎么做

按量计费的外部依赖都在控制台上显示「已用 / 配额」，接近配额时预警、到了配额说明降级后果。本平台开放 API 的 Key 用量（API-052）已经这样做，本批照同一个样子。（本批没有另找外部来源。）

## 2. 数据

不加表。口径与上限判断**同一个查询**（`auto_verify_usage`）：近 24 小时 `verification_orders` 里 `trigger = escalation`、付款方是平台的张数与费用合计；「额度用完没下单」按近 24 小时执行记录里带「平台今天自费核验的额度已用完」说明的次数。

写明一处现有规则：拿不准时发布方在任务详情里手动下的核验单，按 V74 的规则也是平台付费、`trigger = escalation`，所以同样计入这份额度（上限判断一直是这么数的）。看板如实显示，不另起口径。

## 3. 接口

| 接口 | 变化 |
|---|---|
| `GET /admin/metrics` | 多 `auto_verify`：`used_24h`、`daily_max`、`remaining`（不为负）、`fee_cents_24h`、`skipped_24h` |

SDK：`AutoVerifyUsage`；共享函数 `autoVerifyLevel`（`ok` / 用到八成 `near` / 用完 `out`）、`autoVerifyLine`（一句话：用了几张、花了多少；快用完写还剩几张；用完写后果、漏了几次、调哪个配置）。

## 4. 两端

- **Web** 后台「平台指标」下一行：没到八成灰字报数，快用完或用完标红。旧服务端没给这一项时不显示。
- **App**：后台只在 Web，不涉及。

## 5. 隐私、授权与边界

只是计数与金额合计，不含任何用户或任务内容；和原有指标一样所有管理员角色可看。不改任何下单或付费规则。
