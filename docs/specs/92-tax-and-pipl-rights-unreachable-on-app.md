
# 92 代扣明细与 PIPL 权利在 App 上够不到（APP-075 / CLI-075b）

> 状态：本批实现（V119）
> 依赖：29 号（个税代扣）、52 号（协议与个人信息授权）、66 号（补救入口）、
> 87 号（服务端叫他做而 App 上做不到）

## 0. 核对

V113 之后 App 的覆盖又查了一遍，这三条还在：

```
myTax         web=True  app=False     TAX-021 代扣明细
revokeConsent web=True  app=False     LAW-031 撤回单独同意
exportMyData  web=True  app=False     LAW-032 数据可携
grantConsent  web=True  app=False
```

它们和「少一个页面」不是一回事：**三条都是法定权利**。

- **代扣明细**是执行方报个税、对账、与平台核对收入的唯一凭据。
  而执行方主要在手机上——「只能去电脑上看自己被扣了多少税」
  不是一种可行使的权利。
- **撤回单独同意**是《个人信息保护法》给的权利。撤回入口只在网页上，
  等于把这项权利绑在一台他可能没有的设备上。
- **数据可携**同样是法定权利。

与 V113 的资质提交同一条规矩（66 号 spec）：
**平台有这个能力、而用户在他的设备上够不到，等于没有。**

## 1. 三件必须照服务端说的办

### 1a 免责声明原样显示

`TaxSummary.disclaimer` 的类型注释写着「前端必须原样展示这句」。
平台出具的是**代扣明细**，不是税务机关的完税证明——
**这句话的法律含义不容客户端改写**。

### 1b 撤回后果要在点之前就在屏幕上

`SensitiveScope.revocation_effect` 的类型注释写着「必须在用户点撤回
**之前**就展示」。撤回证件信息同意会连带停掉实名、接单、提现（LAW-031）。

而手机上还多一层：**误触一下的代价是账号立刻不能接单、不能提现**。
所以撤回是**两步**——第一下只显示后果与「确认撤回 / 不撤回」，
不发任何请求。

### 1c 撤回的实际生效项由服务端给

服务端返回 `applied`（这一次实际停掉了哪些能力）。客户端不自己罗列：
平台将来改了联动范围，而界面上那句话还停在旧的说法上，
用户会据此做出错误判断。

## 2. 手机上「导出」是什么

PIPL 的数据可携要求数据**可获得**。手机上没有「下载到磁盘」这个动作，
所以走系统分享（`Share`，react-native 自带）——用户可以存进备忘录、
发给自己的邮箱。**刻意不引一个文件系统依赖**。

边界说清：分享的是文本，数据很大时系统可能截断。所以同时把**条目数**
显示出来——用户看得见「这次导出包含多少类数据」，
而不是只拿到一段不知完整与否的字符串。

## 3. 两段各自成立

代扣明细与同意项是两次请求。第一版写成 `Promise.all` + 一个 `catch`，
红验时发现：**税务服务异常会让同意项也一起看不见**。

改成各自 `then/catch`：一侧的故障不该带走另一侧。
这类写法在界面上很常见，而它的后果是「一个小接口挂了，整页空白」。

## 4. 这一批补的那个闸门，比这一批的代码更重要

红验第六条是「把入口从『我的』里摘掉」。结果：
**没有任何服务端闸门变红。**

原因：SDK 方法分类闸门（V102 的 `test_sdk_method_triage`）只问
「有没有**某个**端在调」——web 在调，于是它满意了。
删掉 App 这一页，没有人会知道。

所以把三条加进 `MUST_BE_REACHABLE`（V95 的表，判定标准是
「按不到这一条，用户会面临人身风险、账号被别人继续用，
或者**一笔钱/一个权利落空**」）。法定权利落空正是第三种。

**做完一件事和让它留得住，是两件事。** 没有这条闸门，
下一次重排导航时这一页会安静地消失。

## 5. 闸门

| 闸门 | 内容 |
|---|---|
| TAX-021 | 按年列出收入与代扣；免责声明原样显示；无记录时说清为什么是空的 |
| TAX-021b | 代扣明细读不到，同意项仍要看得见（反之同理） |
| LAW-031 | 撤回后果在点之前就在屏幕上；撤回要两步，第一下不发请求；生效项用服务端的 `applied` |
| LAW-031b | 履约必需（`revocable: false`）的同意项不给点 |
| LAW-032 | 权利清单按服务端给的原样列出；导出走系统分享并报告条目数 |
| CLI-075b | `myTax` / `revokeConsent` / `exportMyData` 必须在 **web 与 app** 都可达 |

红验六条走过：撤回变一步、不显示撤回后果、自己改写免责声明、
两段合成一次 `Promise.all`、撤回结果自己罗列、把入口摘掉（闸门红）。

## 6. 这一批没做的

- **发票没进来**（`requestInvoice` / `myInvoices`）：开票是**按合约**的动作，
  它该在合约/任务详情里，不是个人资料页。放进这一页会让用户在一个
  列着「我的权益」的地方找一张具体合约的发票。记在台账（`APP-076`）。
- **代扣明细没有逐笔列表**：`TaxSummary.items` 返回了每一笔，
  这一页只显示按年汇总。逐笔要分页与筛选（哪一单、哪个月），
  而手机上那是另一个页面的事。
- **导出不是文件**：见第 2 节。真要给文件得引 `expo-file-system` +
  分享附件，而那又是一个真机未验的原生依赖（`APP-073` 同一类）。
- **`grantConsent` 的授权入口在这一页，但「首次同意」仍走协议页**：
  两处都能授权是有意的——协议页是注册流程的一部分，这一页是事后管理。
