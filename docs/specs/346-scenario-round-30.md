
# 346 第三十轮场景发掘：上门办宴席、网店客服外包

> 状态：本批实现（V373）。编号 SCN-237（上门办宴席）、SCN-238（网店客服外包）。
> 来源：skill `scenario-discovery` 按方法每轮补充；上一轮是 V372（345 号）。BACKLOG V373。
> 只增不减：新增两个种子文件、两个新类目（上门宴席复用「健康证明」资质）。已有包、类目、资质规则、发单拦截都不变。

## 0. 找信号

- **上门办宴席**：县乡的寿宴、满月酒、乔迁宴，一办几十桌，靠流动厨师。风险最集中的是群体性食物中毒，各地都有农村集体聚餐管理规定：
  - 多数 50 人以上报备，四川为每餐次 100 人以上；
  - 厨师帮厨要有健康证明；
  - 原料要可追溯。
  上门做饭包（V298）管的是一家人的日常饭，不管几十桌的宴席。
- **网店客服外包**：小店最常外包的活，远程、按时段，学生、宝妈、工作室都接。坑集中在：
  - 给了主账号密码；
  - 前任客服带走买家名单；
  - 乱承诺被投诉；
  - 考核标准事后才说；
  - 客服自作主张退款。

## 1. 场景卡

### SCN-237 上门办宴席

| 项 | 内容 |
|---|---|
| 人群 | 流动厨师、帮厨；发单的是办酒的主家 |
| 要办的事 | 按当地规定报备；健康证上岗；原料正规渠道留票据、高风险菜不做；每样菜留样 48 小时；按桌报价、加桌走变更单 |
| 现在怎么办 | 村里熟人介绍，口头约定 |
| 痛点 | 频率 1；严重度 4（群体食物中毒） |

| 商业价值 | 3 |
| 交付成本 | 1：数据加一个类目（资质复用健康证明） |
| 风险关口 | 健康证明（《食品安全法》第四十五条）；禁止生产经营的食品（第三十四条）；当地集体聚餐报备 |
| 证据 | 各地农村集体聚餐管理规定（本轮从搜索摘要取得，多为地方文件，没有引用链接） |

分数 = 3 × 1 × 4 × 0.4 × 3 ÷ 1 = **14.4**。

### SCN-238 网店客服外包

| 项 | 内容 |
|---|---|
| 人群 | 网店客服兼职与工作室（工作室人群）；发单的是小店店主 |

| 现在怎么办 | 客服外包公司、兼职群 |
| 痛点 | 频率 3；严重度 3（信息泄露、被投诉、扣钱） |

| 商业价值 | 3 |
| 交付成本 | 1：只写数据加一个类目 |
| 风险关口 | 受托处理个人信息不得超出约定（《个人信息保护法》第二十一条）；虚假宣传（《广告法》第九条、《电子商务法》第十七条）；钱与签署是人工关口 |
| 证据 | 法律条文；本轮没有引用外部报道链接 |

分数 = 3 × 3 × 3 × 0.5 × 3 ÷ 1 = **40.5**。

## 2. 做了什么

- `server/app/modules/packs/seeds/banquet-chef.json`：「上门宴席接单顾问」。
  - 五条知识：按当地规定报备、健康证上岗、原料留票据与高风险菜不做、每样菜留样 48 小时、按桌报价。
  - 模板回报清单含「每样菜留样贴日期」。
  - 新类目「上门宴席」，要审核通过的「健康证明」。
- `server/app/modules/packs/seeds/online-store-cs.json`：「网店客服接单顾问」（工作室人群，人工关口含签署）。
  - 五条知识：用子账号、买家信息留在店铺、话术真实、考核计价写清、钱的决定交店主。
  - 新类目「网店客服」，不要资质。

## 5. 隐私、授权与边界

- 两个助手都只出草稿；钱、发布、分享个人信息都是人工关口，客服包另加签署。
- 客服包把「退款、赔付、改价交店主」写成规则，与平台「钱由人确认」的总规则一致。
