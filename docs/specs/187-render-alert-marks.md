# 187 后台页面出错标出已提醒的页与阈值

> 状态：本批实现（V217）。编号 APP-101。
> 来源：186 号 spec「没做的」——「后台『页面出错』表上标出哪一页已触发过提醒、阈值是多少」；BACKLOG V217。
> 只增不减：`GET /admin/client-errors` 原有字段与排序不变，每行只加两个字段；后台原有六列不变，加在最后一列。

## 0. 要解决的问题

186 号会在一页坏的人多时给运营发站内信，但后台表上看不出哪一页已经提醒过、到几个人才会提醒。运营收到提醒点进来，要在表里自己找；没收到提醒的人也不知道一页坏了 3 个人算不算多。

## 1. 业界怎么做

错误监控的问题列表会标出该问题是否已触发过告警，并在规则页写明阈值（如 Sentry 问题详情里的告警触发记录，<https://docs.sentry.io/product/alerts/>）。本批只做这两样：每行标「已提醒」和时间，表头上方一句阈值说明。

## 2. 数据

无新表。读 186 号的「已提醒」记号（`analytics_events.name = render_alerted:<端>`）。

## 3. 接口

`GET /admin/client-errors?days=7` 每行加：

| 字段 | 说明 |
|---|---|
| `alerted_at` | 这一端这一页在查询窗口内最近一次提醒运营的时间；没提醒过是 `null` |
| `alert_people` | 阈值（`PLATFORM_RENDER_ALERT_PEOPLE`） |

SDK：`ClientErrorRow` 加这两个字段。

## 4. 两端

- **Web 管理后台**：「页面出错」表加一列「提醒运营」：提醒过写「已提醒 时间」，没有写「—」；表上方一句「同一端同一页 24 小时内坏过的不同用户到 N 人，会给运营发站内信（每页 24 小时一次）」。老服务端没有这两个字段时，说明不显示、列显示「—」。
- **App**：后台只在 Web 上，不涉及。

## 5. 隐私、授权与边界

只给运营（与 184 号相同）；不多出任何与人有关的信息。
