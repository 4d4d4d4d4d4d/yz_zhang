# 257 方法建议带上做成那一轮补了什么

> 状态：本批实现（V284）。编号 AGT-101。
> 来源：251 号 spec「没做的」——「建议里带上做成的那一轮补了什么（成功的整改要求），不只是失败原因」；BACKLOG V284。
> 只增不减：建议的备注文字、写回规则（251 号）都不变；做成了的步骤多两个只读字段。

## 0. 要解决的问题

251 号的建议只写「上次这一步没做到什么」。对做成了的步骤，更有用的是「最后是补上了哪几项才做成的」——那正是下次一开始就该做到的。

## 1. 业界怎么做

复盘模板通常区分「出了什么问题」和「最后怎么解决的」，后者沉淀为下次的检查项。（本批没有另找外部来源。）

## 2. 规则

- 做成了的步骤多 `fixed_items`：之前几轮评审缺的项里，做成的那一轮不再缺的；多 `fixed_on_attempt`：做成那一步是第几次尝试。
- 仍没做成的步骤不带这两个字段。
- 建议的备注文字不变（发起人勾选写回的仍是 251 号那句）；两端在建议旁边多一行「第 N 次补上了：…」。

## 3. 数据

不新增表：读评审缺项（`mission_steps.review_missing`）与尝试次数。

## 4. 接口

| 接口 | 变化 |
|---|---|
| `GET /missions/{id}/method-suggestions` | 做成的步骤多 `fixed_items`、`fixed_on_attempt` |

SDK：`MissionMethodSuggestions.suggestions[]` 多两个可选字段。

## 5. 两端

- **Web / App 编排复盘「用这次的问题改进我的方法」**：做成的步骤旁多「第 N 次补上了：…」。

## 6. 隐私、授权与边界

不变（只有发起人）。

## 7. 闸门与红验

`server/tests/test_method_suggestions.py` 加 1 条（补上的是之前缺、做成时不再缺的；尝试次数取做成那一步自己的；没做成的不带）；Web 与 App 的复盘用例扩展。

6 处变异（`scratchpad/mut284.py`）：5 处首轮变红；「尝试次数按这一标题下有几步算」首轮存活，补「做成那一步是第 3 次」后变红。
