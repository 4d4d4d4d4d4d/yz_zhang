# 164 「我的方法」套到新编排上作第一轮计划

> 状态：本批实现（V187）。编号 AGT-094。
> 来源：154 号 spec 第 7 节「没做的」——「用方法套到新编排上（作为第一轮的计划）还没有；现在方法只能套到工作台任务上」；BACKLOG V187；VISION V-7「经验作为检索库与 skill tool」。
> 只增不减：不选方法时编排照旧由分解网关拆；方法、编排的其他接口与行为都不变；`POST /missions` 多一个可选字段，`Mission` 多一个 `method_id`。

## 0. 要解决的问题

- 154 号 spec 让编排做完后能蒸馏成「我的方法」（只收做成了的步骤）。可下次再做同一件事，编排还是从头让 AI 拆一遍：做成过的拆法用不上，闭环断在最后一步。

## 1. 业界怎么做

| 做法 | 说明 |
|---|---|
| 模板 / Playbook 启动工作流 | 项目管理与自动化工具普遍支持「从模板新建」：步骤先按模板铺好，再按这次的情况改 |
| Agent 的计划复用 | 把成功的计划存成 skill，下次同类目标直接用它作初始计划，失败了再让模型修 |

本批取「第一轮按方法铺、之后照旧观察 → 修复」：方法只决定第一轮，修复步仍由编排按观察结果生成。

## 2. 数据

`missions.method_id`（可空，迁移 `c1d220260035`）。方法本身（`nb_methods`）不变，被选一次 `uses` 加一。

## 3. 接口

| 接口 | 说明 |
|---|---|
| `POST /missions` `{…, method_id?}` | 只能选自己的方法（别人的或不存在：404）；返回的 `Mission` 带 `method_id` |
| 第一轮规划（`tick` 内） | 有方法：每个有标题的步骤一单（最多 10 步），预算把规划额度平分、零头给最后一步，说明里写「来自你的方法『名字』第 N 步」，验收要点照旧兜底，**不调分解网关**；方法被删或为空：退回分解网关，并在 `last_error` 写明「这一轮改由 AI 分解来拆」 |

## 4. 两端

- **Web「AI 编排」新建表单**：有方法时多一个「第一轮怎么拆」下拉（默认「让 AI 拆」）。
- **App「AI 编排」新建**：列出自己的方法，点一下选用、再点取消，上方写明当前怎么拆。

## 5. 隐私、授权与边界

- 方法只属于本人：别人的方法编号一律 404。
- 预算守恒：每步预算之和等于规划额度，重试预留金照旧保留。
- 按方法拆不调模型：开着隐私沙箱的人本来就建不了编排（云端 AI 清单），这条不改变它。

## 7. 没做的

- **AGT-095 方法的效果统计**：方法被编排用过后，那次编排做成了没有、花了多少，没有回流到方法上（只记了次数）。要能看到「这个方法用过 3 次、2 次做成」才知道该不该继续用（欠）。
- **AGT-096 修复步也参考方法**：现在方法只决定第一轮；某一步失败后的修复步仍按通用规则生成，没有参考方法里的备注（欠）。
