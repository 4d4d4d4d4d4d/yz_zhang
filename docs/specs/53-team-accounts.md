# 53 团队账户：预算、权限与审批（TEAM）

> 来自需求回顾里我列的 P1 缺口：「团队/企业账户、成员与权限、审批流、
> 预算池、对公结算与发票」——`16-traceability.md` 早就把
> 「企业认证与发票（ACC-021/PAY-008）」记在未实现里。

## 0. 先想清楚：团队要的到底是什么

「加个企业账号」很容易做成一个空壳——建个组织、拉几个人、然后什么也没变，
每个人还是用自己的钱包发任务。那没有解决任何真实问题。

企业客户真正会卡住的是四件事：

1. **钱是公司的，不是某个员工的。** 员工用自己钱包垫付再报销，
   在任何一家公司都走不通。
2. **谁能花、能花多少要事先定。** 不是「都能花」也不是「都要老板批」。
3. **超过某个数要有人批。** 而且审批要留痕。
4. **发票开给公司，不是开给员工。**

所以这一批的核心不是「组织架构」，是**预算与审批**。

## 1. 架构判断：团队也是一行 User

第三次用同一条判断（V73 agent、V75 合作体、这里）。标准没变：
**钱包、托管、合约、纠纷、发任务全部以 `user_id` 为键**。
团队要有公共资金池、要以团队名义发任务、要被开票，不复用就得各写第二遍。

`is_team` 标记，并在所有「人」的语义处排除（推荐池、核验人、接单）。

**与合作体（Venture）的区别要说清楚，否则两者会混**：

| | 合作体（COOP） | 团队（TEAM） |
|---|---|---|
| 成员关系 | 平等协作，**贡献即份额** | 有层级，**角色即权限** |
| 钱从哪来 | 合作产生的收入 | 公司充值 |
| 钱怎么分 | 按份额分配收益 | **不分配**，只用于支出 |
| 谁能动钱 | 分配须按份额 | 按角色与额度 |

一句话：**合作体是分钱的，团队是花钱的。** 两者都需要资金池，
但规则完全相反，所以是两个模块而不是一个带开关的模块。

## 2. TEAM-010 角色与额度：三档，不做自定义 RBAC

| 角色 | 能做什么 |
|---|---|
| `owner` | 全部；唯一能改角色、改额度、解散团队的人 |
| `admin` | 发任务、审批他人的支出、充值；不能改角色与额度 |
| `member` | 发任务，但**受个人单笔额度限制**；超额需审批 |

**刻意不做通用 RBAC**：一个可配置的权限矩阵在这个阶段只会让人配错。
三档覆盖了绝大多数团队，且每一档「能做什么」一句话说得清。
真需要更细的，等有客户提出具体场景再加——而不是先造一个框架。

### TEAM-011 额度是**单笔**的，不是月度池

月度池要处理周期、结转、跨月退款归属，复杂度高一个数量级，
而它解决的问题（防止一个人把钱花光）单笔额度也能解决大半。
先做单笔，把「够用」做对。

## 3. TEAM-020 审批：超额的支出要人批，且批完才生效

流程：

```
成员发起支出（发任务 / 托管）
  → 金额 ≤ 个人额度 ？直接执行
  → 超额 → 生成审批单，**资金不动**
      → owner/admin 批准 → 执行
      → 驳回 → 结束，需写理由
```

**关键：审批期间不预扣团队资金。** 预扣会让一堆待批的申请把预算占死，
而审批本来就可能被驳回。代价是批准时可能余额不足——那时明确报错，
比钱被占住好。

### TEAM-021 不能自己批自己的

与 COOP-010（贡献不能自己确认）、VER-021（当事人不能核验）同一条。
`owner` 发起的超额支出……**`owner` 没有额度限制**，所以不存在这个情况；
`admin` 发起的由 `owner` 批。

## 4. TEAM-030 发票开给团队

`InvoiceRequest` 已有（TAX 模块）。这一批接上：团队支出的发票抬头是团队的
**企业信息**（名称、税号），不是发起人的。

**企业信息需要核验**（营业执照），沿用 V76 建的那套：
提交材料 → 敏感文件标记 → 管理员审核。**没核过的团队不能开票**——
一个开给未核验抬头的发票，是税务风险不是便利。

## 5. 验收点

| 编号 | 验收点 |
|---|---|
| TEAM-001 | 团队有独立钱包；成员个人钱包不受影响 |
| TEAM-010 | 三档角色权限正确；member 不能改角色/额度 |
| TEAM-011 | 超过个人单笔额度的支出被拦成审批单，**资金不动** |
| TEAM-020 | 批准后才真正扣款；驳回必须写理由 |
| TEAM-021 | member 不能批自己的申请；也不能批别人的 |
| TEAM-022 | 批准时团队余额不足 → 明确报错，不产生半截状态 |
| TEAM-030 | 未核验企业信息的团队不能开票 |
| TEAM-040 | 团队账号不出现在接单人推荐里 |
| TEAM-041 | 团队资金变动全部走既有账本，五条不变量仍成立 |

## 6. 这一批没做的（明确记账）

- **TEAM-050**：**月度预算池与结转**。见 TEAM-011 的理由。
- **TEAM-051**：**部门/多级组织**。三档角色是扁平的。多级组织要处理
  额度继承与跨部门审批，等有真实客户结构再做。
- **TEAM-052**：**对公转账充值**。现在只能走既有的钱包充值路径
  （模拟/第三方支付）。真正的对公打款需要银行侧对账，属于持牌托管那一块。
- **TEAM-053**：营业执照核验仍是**管理员看图**，没有接工商核验接口
  （与 CERT-050 同一个缺口，同一个原因）。
- **TEAM-054**：成员离职后其发起的在途任务如何转交，没有做。
  当前只能由 owner 手动处理。
