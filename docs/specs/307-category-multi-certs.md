
# 307 一个类目要多张资质

> 状态：本批实现（V334）。编号 SCN-181。
> 来源：306 号 spec「没做的」——「一个类目要多张资质（母婴护理还应要无犯罪记录证明）」；BACKLOG V334。
> 只增不减：只设一张资质的类目，准入、报名报错文案（一字不差）、发布页提示、任务画像风险提示、合作体合规路径都与以前一样；`/categories` 只在要多张时多 `extra_certs`。**改了一处行为**：V333 刚加的「母婴护理」从「只要健康证明」变成「健康证明 + 无犯罪记录证明」（V333 还没推送上线）。

## 0. 要解决的问题

「母婴护理」照护的是新生儿：只看健康证明不够，还应像「陪练看护」那样要无犯罪记录证明。可类目表只有一个 `required_cert`，只能设一张。

## 1. 业界怎么做

家政与看护平台对母婴、育儿、养老类服务人员普遍同时核验健康证明与无犯罪记录证明；准入是「张张都要有」，缺哪张提示补哪张。（本批没有另找外部来源。）

## 2. 规则

- 类目多 `extra_certs`（主资质之外还要的，最多 5 张）：**张张都要有**、都要审核通过且在有效期内才能报名。
- 报名时缺资质：只要一张的类目文案不变；要多张的说「该类目需「健康证明」「无犯罪记录证明」2 项职业资质，你还缺「无犯罪记录证明」：请提交……」——只列还缺的。
- 运营建类目、改类目时可设其余资质（顿号或逗号分隔；去空、去重、去掉与主资质重复的；超过 5 张 400 `too_many_certs`，名字超 30 字 400 `cert_name_too_long`）；清空 = 只要主资质。
- 服务对象是未成年人的单（SCN-144）的规则不变：类目本身不要资质时才补要无犯罪记录证明。
- 「母婴护理」种子类目：健康证明 + 无犯罪记录证明；种子包的知识、模板同步写清两张都要。

## 3. 数据 / 接口

- `categories.extra_certs`（JSON，默认 `[]`；迁移 c1d220260078，SQLite 与 Postgres 都验过升级、回退、`alembic check`）。
- `GET /categories` 行多可选 `extra_certs`；`POST /admin/categories` 多可选 `extra_certs`；`PATCH /admin/categories/{id}` 多查询参数 `extra_certs`，响应多可选 `extra_certs`。
- 服务端 `category_certs(category)`：准入、任务画像风险提示、合作体合规路径共用。
- 共享 SDK：`Category` 类型（`categories()` 改用它）、`categoryCerts` / `categoryCertsText`（与服务端同一规则）、`createCategory` 第三个参数、`updateCategory` 的 `extra_certs`；两个新错误码进 i18n。

## 4. 两端

- **Web 发布页**：选了要多张资质的类目时提示「仅持「健康证明」「无犯罪记录证明」资质的执行者可接单」。
- **Web 后台「城市与类目」**：「需要资质」一列列出全部；有主资质的类目多「其余资质」按钮。
- **App**：报名被拒时原样显示服务端说的「还缺哪张」；资质上传沿用已有的资质页。

## 5. 隐私、授权与边界

只改准入条件；资质照旧由本人上传、平台人工审核。
