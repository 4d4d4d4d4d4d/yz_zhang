
# 390 App 里直接看进度照片；修好详情页交付预览图的地址（TASK-022d）

> 状态：本批实现（V417）。编号 TASK-022d。
> 来源：388 号「没做的」：App 执行动态只写「N 张图」，看不到照片。BACKLOG V417。
> 只增不减：App 执行动态多照片缩略图；详情页的交付预览改为拼上服务端地址；SDK 多 `mediaUri`。接口不变，网页不变。

## 0. 要解决的问题

- 照片是现场证据。V415 起 App 能拍照上传了，可回头看进度时只看到「1 张图」，照片本身看不到。
- 动手时发现一个**已经存在的缺陷**：
  - App 任务详情页渲染交付文件（V3xx，SCN-166）时没有传服务端地址，`DeliverablesList` 的 `baseUrl` 默认是空串；
  - 预览图地址于是是 `/api/v1/files/…` 这样的相对路径；
  - React Native 的 `<Image>` 加载相对路径会静默失败，**真机上交付预览一张都出不来**。
  - 交付文件自己的单测传了 `baseUrl`，所以一直是绿的；详情页这条接线没有测试。

## 1. 业界怎么做

移动端加载服务端图片都用完整地址；相对地址在原生端没有「当前页面」可以相对。这是通用做法，本轮没有引用外部链接。

## 2. 数据 / 接口

不新增接口。服务端的上传文件读取是能力 URL（FILE-013：名字来自安全随机数，匿名可读），App 拼上服务端地址即可加载，不需要登录态。

SDK 新增 `mediaUri(baseUrl, path)`：
- 完整的 http(s) 地址原样返回；
- 以 `/` 开头的拼上服务端地址（末尾斜杠不重复）；
- 其余（非字符串、相对片段、`//` 开头的协议相对地址、`javascript:`、`data:`）一律返回空串，不画。

## 4. 两端

- **App 执行动态**：每条进度下面画照片缩略图（64×64），地址拼不出来的不画；原有的「N 张图」文字保留。
- **App 任务详情**：
  - 交付文件传上服务端地址，预览图在真机上能加载；
  - 交付文件组件改用 `mediaUri` 拼地址，对正常路径结果与原来一致。
- 网页不变（同源，相对路径本来就能用）。

## 5. 隐私、授权与边界

- 进度只给成交双方（原有授权不变）。
- 不画外链、不画 `javascript:` / `data:` 之类的地址：服务端只收本平台上传的图片地址，App 再挡一道。
