
# 266 参考价按发布方去重

> 状态：本批实现（V293）。编号 KB-064。
> 来源：台账 KB-064「经验卡不去重：同一发布方反复发同类任务会拉低价格代表性，影响 `price_reference` 的可信度」；BACKLOG V293。
> 只增不减：`/knowledge/price-reference` 原有的 `sample_size / p50_cents / min_cents / max_cents / message` 口径与数值都不变（报价助手、任务画像等调用方照旧）；只多几个字段，没有样本时一个都不多。

## 0. 要解决的问题

参考价是「同类闭环任务的成交价中位数」。一家公司在一个城市反复按 ¥50 发跑腿，它的二十单就能把中位价压成 ¥50，而另外几位发布方的成交都在 ¥200 上下。发单的人看到 ¥50 照着定价，就招不到人。

## 1. 业界怎么做

价格与评分的聚合统计一般会防「单一来源刷屏」：按来源先聚合再统计，或者给单一来源设权重上限。（本批没有另找外部来源。）

## 2. 规则

- 卡片的发布方通过来源任务查（`source_task_id → tasks.creator_id`），与原查询合成一条 SQL，不逐张查；卡上不新增字段（经验卡不存是谁发的，最小必要）。
- 每位发布方先取自己那几单的中位价，算一个样本；再对这些样本取中位，得到 `p50_by_publisher_cents`。找不到来源任务的卡各算一位，不合并成一个「无名氏」。
- `top_publisher_share`：样本最多的那位发布方占了几成。至少 3 单、且超过一半时 `concentrated=true`，并在 `note` 里写明「这 N 单里有 X 单来自同一位发布方；按发布方去重后，Y 位发布方的中位价是 ¥Z」。正好一半不算集中。
- 只给人数与比例，不给是谁。

## 3. 数据

不新增表与字段。

## 4. 接口

`GET /knowledge/price-reference` 有样本时多 `publishers / p50_by_publisher_cents / top_publisher_share / concentrated / note`。SDK `PriceReference` 加上这几个可选字段。

## 5. 两端

- **Web 发布页「查参考价」**：集中时在原来那句后面接上 `note`；不集中时与以前一样。
- **App**：发单页还没有「查参考价」（App 端没有调用 `priceReference`），本批不涉及；记作 KB-095。

## 6. 隐私、授权与边界

只出聚合数；`note` 里不出现发布方的任何信息。
