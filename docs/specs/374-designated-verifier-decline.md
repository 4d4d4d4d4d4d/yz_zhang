
# 374 被点名的核验人当场拒绝（VER-050b）

> 状态：本批实现（V401）。编号 VER-050b。
> 来源：372 号「没做的」VER-050b 的前一半；BACKLOG V401。
> 只增不减：新增一个接口；核验单的下单、接单、提交结论、到期退回都不变。

## 0. 要解决的问题

V399 让发单人点名一位核验人。问题是被点名的人不方便时，他只能不理。结果是：
- 发单人的核验费被压到截止才退；
- 交付闸门一直卡着；
- 他也不知道该不该换人。

## 1. 业界怎么做

指定评审人的工具普遍允许被指定的人「拒绝 / 移除自己」，并通知发起人。这是常见的公开产品做法，本轮没有引用外部链接。

## 2. 规则

| 项 | 规则 |
|---|---|
| 谁能拒绝 | 只有被点名的人。别人 403 `verifier_not_designated`；发单人也不能替他拒，他要撤就等截止，或另走客服 |
| 什么时候能拒 | 只在还没接（`open`）时。接下以后不能拒，409 `verification_not_open`，走原来的提交结论或到期 |
| 拒绝以后 | 核验单变成 `cancelled`，核验费当场退回发单人（走原来的 `cancel_order` 退款路径，流水是 `verify_refund`）；通知发单人「你点名的核验人不方便」，写明退了多少、可以点名别人或由平台派单；对方填了理由就转告 |
| 理由 | 可不填，最多 200 字 |

平台派的单没有「拒绝」：不接就是了，别人会接。

## 3. 接口

`POST /verification-orders/{id}/decline`，请求体 `{reason?}`，`extra=forbid`，返回核验单（状态 `cancelled`）。对象级授权表加一条：只有被点名的人。

## 4. 两端

- **SDK**：`declineVerificationOrder(orderId, reason)`；错误码 `verification_not_open` 进 i18n。
- **Web 核验台**：
  - 点名请我核验、还没接的单，多一个「不方便，拒绝」按钮；
  - 点了以后可以填一句理由，然后提示「已拒绝，核验费已退回给发布方」；
  - 平台派的单、点名别人的单，都没有这个按钮。
- **App**：App 目前没有核验台。核验要看较长的 AI 产出和判据，原本就以网页为主（V101 起）。被点名的人在 App 上会收到通知，处理去网页。App 核验台记作 VER-053。

## 5. 隐私、授权与边界

- 拒绝理由只转告发单人。
- 钱只从「平台代管」退回原付款人，与原来的取消、到期是同一条路径，对账不变量不受影响。
