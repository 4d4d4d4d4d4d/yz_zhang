
# 296 执行方一次交付多期

> 状态：本批实现（V323）。编号 SC-015。
> 来源：146 号 spec「没做的」——「执行方一次交付多期：现在逐期交付；批量交付要先想清楚『交付物』怎么对应到每一期」；BACKLOG V323。
> 只增不减：逐期交付、逐期验收、一次放款已交付的几期（SC-014）都不变；分期多一个可选的 `delivery_note` 字段（只在写了时出现）。

## 0. 要解决的问题

分期合约里连着做完的几期（例如设计、施工图一起交），执行方要点好几次「交付本期」，发布方也不知道这几期对应的是哪份交付物。

## 1. 业界怎么做

按里程碑付款的平台通常允许一次提交多个里程碑的交付，附一份说明，客户逐个或一次验收。（本批没有另找外部来源。）

## 2. 规则

- `POST /contracts/{id}/milestones/deliver-batch`，`{idxs: [...], note: ""}`（1~50 期，说明可不写、最多 500 字）：
  - 只有执行方能交（`not_party`）；合约要在执行中、没冻结（`not_active`）；
  - **要么全交、要么一期不动**：同一期写两次 400 `duplicate_milestone`；有不存在的期 400 `milestone_not_found`（写明第几期）；有已经交付或放款过的 409 `invalid_milestone_state`（写明第几期、请去掉再交）；
  - 交付说明存到每一期上（几期共用一份）；**通知发布方一次**：哪几期、合计多少、说明的前 100 字、下一步（逐期验收或一次放款）。
- 「交付物怎么对应到每一期」：本批的答案是几期共用一份说明，由执行方写清；更细的「每期挂各自的附件」记入「没做的」。

## 3. 数据 / 接口

`milestones.delivery_note`（迁移 `c1d220260074`）；合约响应里分期多 `delivery_note`（写了才有）；共享 SDK `deliverMilestones(contractId, idxs, note)`、`Milestone.delivery_note?`；i18n `duplicate_milestone`。

## 4. 两端

- **Web 任务详情（执行方）**：进行中的期有 2 期以上时多一个「一次交付进行中的 N 期」，先列出这几期与金额、再填交付说明（可不写），取消就不发。分期表里写了说明的期显示「交付说明：……」。
- **App 分期块（执行方）**：同样的按钮，先列清楚、有「交付说明」输入框，再「确认交付」；分期行里显示交付说明。
- 只剩一期进行中、合约冻结、看的人是发布方时不出这个按钮。

## 5. 隐私、授权与边界

只有合约的执行方能交（对象级授权沿用 `/contracts/` 规则）；交付说明只在合约双方之间可见。
