
# 125 接单者服务包：现在有空推单、顺路单（新增绕行）、报价参考

> 状态：本批实现（V150）。编号 GIG-100~110。
> 来源：用户 2026-10-13：「普通接单用户就想要如何能够就近帮助打扫卫生，顺路送个单等，这些都需要 AI 来帮助实现。」
> VISION 1.7（V-17）；BACKLOG V150（打分 覆盖 5 × 频率 5 × 痛感 3 × AI 0.7 × 价值 4 ÷ 成本 3 = 70）。
> 只增不减：广场的「附近 10km」不变，只在旁边多一个入口；任务发布事件多一个订阅者（类目订阅推送照旧）；
> 场景包引擎只**加**两个白名单工具。

## 0. 要解决的问题

有空的时候刷半天找不到附近的单；上下班路上明明顺路，不知道能顺手做什么；报价报低亏、报高接不到；
第一次上门不知道先确认什么、怎么保护自己。

## 1. 业界怎么做

- **即时配送的派单**：派单不只看骑手离取件点多近，而是看「把这一单插进他现有路线后，总路程增加多少」，
  再叠加时效与顺路程度——这就是「顺路单」的本质（新增绕行最小）。本批用同一个量：
  `多走 = d(起点, 任务点) + d(任务点, 终点) − d(起点, 终点)`。没有道路数据，用**直线距离**估，出口都写明。
- **「我现在有空」式的接单开关**（外卖、网约车的「听单」）：司机 / 骑手主动声明在线，平台才推单；
  下线即停推。本批：「现在有空」有时长（1~12 小时），到点自动关闭，**每段最多推 6 条**（推多了就是骚扰）。
- **报价**：用平台自己的闭环成交价分布（KB-021，近 180 天、可按城市），给中位 / 最低 / 最高，对照预算，再算出扣服务费后的到手。
  不是模型猜的价，也不是承诺价。

## 2. 数据与隐私

| 表 | 说明 |
|---|---|
| `gig_availability` | 每人一行：到期时间、**粗化到 0.01 度（约 1 公里）**的位置、半径（1~30 公里）、类目、本段已推条数 |
| `gig_places` | 常用地点（家、公司……，每人最多 10 个），同样只存粗化坐标 |

- 位置是敏感个人信息：不展示给任何人；「现在有空」到点即删（读的时候顺手删 + `/gig/jobs/purge-expired` 每小时），手动关掉即删；注销全删。
- 查询时给的当前坐标只用于这次计算，不落库。

迁移 `c1d220260017`，SQLite 与 Postgres 都验过。

## 3. 接口（`/gig/*`）

| 编号 | 接口 | 说明 |
|---|---|---|
| GIG-101 | `GET/PUT/DELETE /gig/available` | 现在有空：位置、半径、时长、类目；PUT 重置本段推送计数 |
| GIG-102 | `GET /gig/nearby` | 半径内招募中、线下、有坐标、没过截止、不是自己发的单；按 500 米一档的距离排序，同档报酬高的在前；给出到手（扣服务费） |
| GIG-103 | `GET /gig/along` | 顺路单：起点＝常用地点或当前位置，终点＝常用地点；按多走的路排序，可设上限（默认 2 公里） |
| GIG-103 | `GET/POST /gig/places`、`DELETE /gig/places/{id}` | 常用地点 |
| GIG-104 | `POST /gig/quote` | 给一单（只看公开招募中的，或自己的）或一个类目：成交价分布、对照预算、建议价（预算 ≥ 中位用预算，否则用中位）、到手；城市没数据时退到全平台并写明 |
| GIG-105 | 事件 `task.published` | 新单发布 → 通知「现在有空」、半径覆盖、类目对得上的人（不含发布者），每段最多 6 条 |
| GIG-106 | 场景包工具 | `gig.nearby`（没开「有空」时直说要先打开）、`gig.quote`（从提问里认出类目）进白名单 |
| GIG-107 | 场景包 `gig-nearby` | 接单助手（钱与个人信息都是人工关口）；上门前确认清单、跑腿取送清单；有空怎么用、顺路怎么算、报价技巧、上门安全、不要私下交易、位置怎么用 |
| GIG-108 | 定时任务 | `/gig/jobs/purge-expired`（每小时） |
| GIG-109 | 注销 | 「有空」与常用地点全删 |

## 4. 两端

- **Web** `/gig`（入口：广场「我现在有空 / 顺路单」、服务包详情、接单助手）：开关「现在有空」（浏览器定位、半径、时长、类目）、
  附近的单（距离、预算、到手、看行情）、常用地点（把这里存为家 / 公司、删除）、顺路单（从当前位置或某个地点到某个地点、多走上限）、报价参考。
- **App**「我的 → 接单」：同上（设备定位；拿不到定位**不发请求**，直说）。

## 5. 闸门与红验

| 闸门 | 红验 |

| 注销 | 去掉处置 → `test_erase_removes_location_data` 红 |

## 6. 没做的

- **GIG-110 道路距离与路线**：要接地图服务（与路况、通行时间）；现在是直线估算，出口写明。
- 多点串单（一次带几单的最优顺序）：先看单点顺路用起来的情况。
- 平台代为调度（派单）：平台不替人接单，只推送与排序；接不接由本人决定。
