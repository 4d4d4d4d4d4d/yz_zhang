
# 317 上门回报的发单人确认与异议

> 状态：本批实现（V344）。编号 SCN-192。
> 来源：316 号 spec「没做的」——「回收称重的秤面读数拍照回报、客户一键确认」；BACKLOG V344。
> 只增不减：上门回报的提交、列表、通知、验收前提醒都不变；回报行只在发单人表了态时多 `confirmed_at` / `objection`。

## 0. 要解决的问题

上门收废品称了多少斤、上门喂猫做了什么，以前只有接单人交上来的回报：发单人当时心里有数，却没地方「签个字」；对不上也只能私下说，到验收时才翻旧账。V343 的「当面称」只是一句约定，事后说不清。

做的时候没有只给废品回收开口子：**任何带上门回报的单**（喂猫、助浴、保洁……）都需要同一个动作——发单人对每一次回报当场表态。

## 1. 业界怎么做

外卖、快递、家政平台在履约节点上普遍有「收货人确认 / 异议」：确认留痕，异议立刻通知服务方，而不是等到最后整单评价。（本批没有另找外部来源。）

## 2. 规则

- 每一次上门回报，**发单人**可以：
  - 「对得上」：记下确认时间（不碰钱、不等于验收）；
  - 「有异议」：写清哪里不对（2~300 字），**通知接单人**（「说清楚或补一张照片，别等到验收时再争」）。
- 两者互斥，后一次表态盖过前一次（再确认就撤回异议，提异议就撤回确认）。
- 只有这单的发单人能表态；回报必须属于这单、必须是上门回报（普通进展不行）。接单人、成交双方以外的人都不行。
- 废品回收的种子模板：清单多一项「秤面读数拍照」，说明里写明「回报附秤面照片，我在平台上当场点『对得上』」。

## 3. 数据 / 接口

- `progress_logs.confirmed_at`（可空）、`progress_logs.objection`（默认空）；迁移 c1d220260080，SQLite 与 Postgres 都验过。
- `POST /tasks/{id}/visits/{visit_id}/confirm`、`POST /tasks/{id}/visits/{visit_id}/object` `{reason}`，都返回这单的整份回报（与 `GET /tasks/{id}/visits` 同形状）；登记进对象级授权表。
- 共享 SDK：`TaskVisit.confirmed_at?` / `objection?`；`confirmVisit`、`objectVisit`。

## 4. 两端

- **Web 任务详情「上门回报」**：发单人每一次回报后面有「对得上」（已确认的不再显示）与「有异议」（问理由，空着不发）；显示「发单人已确认」或「有异议：……」。接单人只看到结果。
- **App 任务详情「上门回报」**：同样的两个按钮；「有异议」展开一个输入框，写清（至少两个字）再「提交异议」。

## 5. 隐私、授权与边界

只有这单的发单人能表态；异议只通知接单人；不改钱、不改任务状态。
