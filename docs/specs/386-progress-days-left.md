
# 386 开工以后接单人报「还要几天」，驾驶舱按它重排；App 补上执行动态（AI-DEC-021d / TASK-022b）

> 状态：本批实现（V413）。编号 AI-DEC-021d；顺带补 TASK-022b（App 上的执行动态）。
> 来源：384 号「没做的」：进行中的步骤按整段工期从现在算，只会估晚。BACKLOG V413。
> 只增不减：进度回报多一个可选字段 `days_left`；进度列表多回这个字段；驾驶舱时间线多一种 `basis = reported`。不带这个字段的请求行为不变。

## 0. 要解决的问题

- V411 的时间线只知道开工前填的工期估计。开工以后实际快了还是慢了，只有接单人知道；驾驶舱对进行中的步骤只能按整段工期从现在算，越做越估不准。
- 动手时发现另一个缺口：**App 上没有执行动态**。网页任务详情有「执行动态」（看进度、写进度），App 上一个入口都没有——接单人在手机上发不了进度，发单人也看不到。接单人大多在手机上干活，「还要几天」放在网页上没人报。

## 1. 业界怎么做

项目管理工具里，执行人更新任务时可以改「剩余工作量」或「预计完成日」，甘特图按最新的剩余量重排。这是通行做法，本轮没有引用外部链接。

## 2. 数据 / 接口

- `progress_logs.days_left`（整数，可空），迁移 `c1d220260095`。
- `POST /tasks/{id}/progress` 多收 `days_left`（0~365，0 = 今天做完）：
  - 只有接单人能报：发单人带这个字段返回 403 `days_left_executor_only`（「活在他手上，他最清楚。你可以在进度里问他」）；
  - 不带这个字段与原来一样。
- `GET /tasks/{id}/progress` 每条多回 `days_left`（没报为 null）。
- `GET /tasks/{id}/cockpit` 的时间线：
  - 接单人报过的步骤，以**最近一次报的**为准（没带天数的进度不算），`basis = reported`；
  - 完成时间 = 报的时间 + 天数；那个时间已经过了还没做完，就按「现在」，不往回画；
  - 每行多 `reported_at`、`days_left`；
  - 按报的天数赶不上这一步的截止，也进「需要你出手」，并写明是接单人报的（「接单人报的还要 9 天，会晚于这一步的截止：和他商量能不能加快，或者走变更单改期」）；
  - 所有步骤的报数一条查询取全，不按步骤逐个查。

## 4. 两端

- **网页**：
  - 执行动态里每条进度后面写「（还要 N 天）」或「（今天做完）」；
  - 接单人的进度表单多一个「还要几天（选填）」，填得不对（小数、负数、超过 365）不让提交并写清怎么填；
  - 发单人的表单没有这个框。
- **App**：新增「执行动态」块（`app/progressLog.tsx`），放在任务详情：
  - 成交双方、开工以后才有；
  - 列出进度、接单人报的天数、带了几张图；
  - 进行中可以写进度，接单人可以带「还要几天」，发完重新取；
  - 待验收以后只能看；
  - 响应畸形不白屏。
- 两端共用 SDK：
  - `daysLeftNote`、`parseDaysLeft`；
  - `addProgress` 多一个可选参数，不报就不带字段；
  - `timelineBasisLabel` 多「按接单人报的剩余天数」。

## 5. 隐私、授权与边界

- 进度只给成交双方看（原有授权不变）。
- 「还要几天」是接单人自报的估计，不改截止、不动钱：要改期仍走合约变更单。
