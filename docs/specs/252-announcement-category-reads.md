# 252 按类目定向的公告分类目统计阅读率

> 状态：本批实现（V279）。编号 NTF-071。
> 来源：246 号 spec「没做的」——「按类目定向的公告单独统计阅读率（哪一类的人点开得多）」；BACKLOG V279。
> 只增不减：公告列表上的总阅读率（159 号）不变；新增一个只读接口与一个入口。

## 0. 要解决的问题

246 号让一条公告能同时发给几个类目的人，但阅读率只有一个总数：「跑腿的点开了一半、设计的全点开了」看不出来，下次该怎么写、发给谁也就无从调整。

## 1. 业界怎么做

推送分群的效果报表通常可以按分群（标签）拆开看送达与打开；一个用户属于多个分群时各算一次，并单独说明重叠。（本批没有另找外部来源。）

## 2. 规则

- 对按类目定向的公告（单个或多个类目），列出每个类目：这次收到的人里属于这一类的有几个、其中点开了几个、比例（收到 0 人时为空）。
- 类目归属按**发出时**算：发出前 180 天内在这一类发过单 / 报过名（按公告的人群：只看发单的 / 只看接单的 / 两者之一），与圈人时同一口径。
- 一个人同时属于几个类目时各类都算一次，另报「重叠人数」。
- 没按类目定向、或还没发出的：返回空列表并说明。
- Web 只在多类目的公告上显示入口（单类目的总阅读率已经就是这一类的）。

## 3. 数据

不新增表：读通知的已读位（`notifications.announcement_id`）与发单 / 报名记录。

## 4. 接口

| 接口 | 说明 |
|---|---|
| `GET /admin/announcements/{id}/read-by-category` | 运营；`{announcement_id, categories: [{category, delivered, read, read_rate}], overlap, note}`；没有这条 404 |

SDK：`announcementReadByCategory`、`AnnouncementReadByCategory`。登记：后台角色表、后台端点覆盖表、功能面清单。

## 5. 两端

- **Web 后台「发过的公告」**：多类目的公告在「已读」一栏多「分类目」，点开列出每类几人点开、占多少，以及重叠人数。
- **App**：后台只在 Web，不涉及。

## 6. 隐私、授权与边界

只有运营；只给人数，不列名单。
