# 69 扫描闸门证明不了的那一半（APP-070）

> 闸门能证明**入口存在**。它证明不了**按下去做对了事**。

## 0. 三批攒下来的欠账

V91、V92、V93 一共给 App 加了：提现、绑收款账户、账单、人工核验、
协议重新同意、团队审批、合作体、开发者、消息、邀约、一键求助、行程分享、
修改密码。这些的验证方式全部是：

- **Python 扫描闸门**（`REMEDY_UI` / `NOTICE_ACTIONS` / `MUST_BE_REACHABLE`）：
  扫 `app/*.tsx` 的源码里有没有 `.someMethod(`；
- **共享 SDK 的类型**：`tsc --noEmit`。

这两样合起来能挡住的，是**「这个端上根本没有这条路」**——
那确实是前三批反复掉出来的缺陷形状，所以闸门有价值。

但它们对下面这些一律是绿的：

| 写错的方式 | 扫描闸门 | tsc |
|---|---|---|
| 按钮调了 `decideTeamSpend(id, false)`，**理由没传** | 绿（方法名扫得到） | 绿（参数可选） |
| 把服务端的中性话术换成自己编的「你触发了风控」 | 绿 | 绿 |
| 求助成功后把 `guidance` 吞掉，只显示「已提交」 | 绿 | 绿 |
| 客户端自己重写一遍「谁能审批」，与服务端判断不一致 | 绿 | 绿 |
| 把按钮摆给非当事人 | 绿 | 绿 |

**每一条都恰好是前三批 spec 里反复强调的那种错**，而现有的验证方式
一条都抓不到。三批下来这个缺口一直被如实记在「这一批没做的」里，
现在补上。

## 1. 用什么跑

`jest-expo` + `@testing-library/react-native`（RN 的官方组合）。
App **不在根 workspaces 里**（这是 V88 有意的决定：否则 Web 的流水线
要为一个它不碰的端装下整个 react-native），所以测试依赖装在 `app/` 内。

原生模块（AsyncStorage / expo-location / expo-network）在测试环境里
用官方 mock 替身。**这也是这批测试的边界，要写出来**：
替身能证明界面逻辑对，**不能证明真机上跑得起来**。

## 2. 先覆盖哪两条路

不追覆盖率。**先覆盖动钱的和关乎人身的**：

- **钱包**（APP-065 / PAY-030 / AML-030）：提现打对了端点、
  大额进人审的中性话术**原样显示**、绑卡带上 `holder_name`、
  账单科目的中文名走共享 SDK 而不是在 App 里另写一份。
- **求助**（GEO-023 / GEO-022）：求助打对了端点、
  **服务端的指引原样显示**、线上任务与非当事人不显示入口、
  行程分享读的是 `trip_share_enabled` 而不是 `enabled`。
- **团队审批**（APP-069 / TEAM-061 / UI-075）：驳回**把理由真的发上去**、
  审批按钮读服务端的 `can_decide`（客户端不重算）、
  已驳回的理由显示出来、开票能力读 `invoice_block`。

每条都做**红验**：把对应的实现改坏，测试必须红。
这一批的四次红验分别是——丢掉驳回理由、客户端重写审批判断、
把中性话术换成自编文案、把求助指引吞掉。四次全红。

## 3. CI

`app-typecheck` job 加一步 `npm test`。
在此之前 App 的 CI **只有 `tsc`**。

| 编号 | 验收点 |

| APP-070 | `cd app && npm test` 跑得起来并全绿 |
| APP-070 | 钱包、求助、团队审批三块的行为各有测试钉住 |

## 5. 这一批没做的

- **不是真机验证**。原生模块是替身，渲染是 `react-test-renderer`。
  **没有任何一次点击发生在真实设备上**，这一条从 V88 起就如实记着，
  现在依然如实记着。
- 覆盖的是钱与人身两条路；发现流、视频流、发布、纠纷答辩等仍未覆盖。
- 没有端到端（App ↔ 真实后端）测试。
