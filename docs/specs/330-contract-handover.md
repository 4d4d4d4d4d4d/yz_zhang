
# 330 建站交付的账号交接清单

> 状态：本批实现（V357）。编号 SCN-205。
> 来源：328 号 spec「没做的」：「建站交付时的账号交接清单（域名、小程序、服务器、商户号逐项确认已在客户名下，客户点『收到』）」；BACKLOG V357（第三十四轮排期，分数 18）。
> 只增不减：交付、验收、放款都不变，也不拿交接清单拦验收。合约多一张交接表、四个接口，两端交付文件下面各多一块。

## 0. 要解决的问题

建站最常见的纠纷：钱付完了，域名、小程序、服务器、支付商户号还在开发方名下，换人做就要从头来。开发方说「都给你了」，发单人说「没收到」，没有一张能逐项对得上的清单。

## 1. 业界怎么做

外包与并购的交付里常有一份「资产交接清单」：逐项列出账号与资产，接收方逐项签收。本批没有另找外部来源。

## 2. 规则

- **登记**：执行方在托管期间逐项登记要交接的账号：类别（域名 / 小程序 / 服务器 / 支付商户号 / 其他账号）、账号名、说明（可不填）。一份合约最多 30 项（`handover_full`）。
- **确认**：发单人逐项点「已在我名下」。
  - 只有发单人能确认，执行方不能替他确认。
  - 放款以后也能确认（账号转移常在上线之后）。
  - 再点一次不改时间。
  - 第一次确认时通知执行方。
- **删除**：执行方能删掉登记错的项，但发单人已经确认的不能删（`handover_confirmed`）。放款以后不能增删（`not_active`）。
- **进度提示**：两端显示进度一句话：「N 项账号都已确认在发单人名下」或「N 项账号里还有 M 项没确认在发单人名下」（标红）。**不拦验收**：先上线后转主体的情况很常见，只提醒。
- **谁能看**：合约双方都看得到；旁人 403；别的合约名下的项确认不到（404）。

## 3. 数据 / 接口

- 新表 `contract_handover_items`，迁移 c1d220260085，SQLite 与 Postgres 都验过。
- 接口（合约接口的对象级授权规则已覆盖）：
  - `GET /contracts/{id}/handover`
  - `POST /contracts/{id}/handover`：请求体 `{kind, name, note}`
  - `DELETE /contracts/{id}/handover/{item_id}`
  - `POST /contracts/{id}/handover/{item_id}/confirm`
  - 都返回整张清单。
- 共享 SDK：
  - 类型：`ContractHandoverItem`、`HandoverKind`
  - 方法：`contractHandover` / `addContractHandover` / `removeContractHandover` / `confirmContractHandover`
  - 两端共用：`HANDOVER_KIND_LABEL`、`handoverSummary`
  - 两个新错误码进 i18n。

## 4. 两端

- **Web 任务详情**：「授权清单」下面多「账号交接」。
  - 执行方：登记、删掉未确认的。
  - 发单人：每项有「已在我名下」，没确认完的进度标红。
  - 一项都没登记时，发单人看不到这一块。
- **App 任务详情**：同样一块（`app/handover.tsx`），文案与 Web 相同。

## 5. 隐私、授权与边界

- 只登记账号名，不登记密码：密码由双方当面或在私聊里交接，提醒发单人收到后改掉（建站包知识条目已写）。
- 平台不核验账号是否真的已转移（需要对接各平台的主体查询），以发单人的确认为准。
