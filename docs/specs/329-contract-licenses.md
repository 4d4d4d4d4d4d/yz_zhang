
# 329 交付附授权清单

> 状态：本批实现（V356）。编号 SCN-202。
> 来源：325 号 spec「没做的」：「剪辑交付时按授权清单逐项登记音乐与素材来源（结构化，不只是文字）」；328 号的建站包同样要求「授权清单随交付」；BACKLOG V356（第三十四轮排期，分数 27）。
> 只增不减：交付文件、分期、放款都不变。合约多一张授权清单表、三个接口，两端交付文件下面各多一块。

## 0. 要解决的问题

剪辑、建站这类活的交付物里夹着别人的作品：背景音乐、视频素材、字体、模板、图库图片。两个场景包都要求「交付附授权清单」，但以前只能写在交付说明或聊天里：发单人查不到，出了版权问题对不上。

## 1. 业界怎么做

素材平台和外包交付常附一份「素材与授权清单」：每项写名称、来源、授权类型与范围，作为交付物的一部分随项目存档。本批没有另找外部来源。

## 2. 规则

- **登记**：执行方在托管期间逐项登记。
  - 每项写类别（音乐 / 视频素材 / 字体 / 模板 / 图片 / 其他）、名称、授权来源（至少 2 个字）、授权范围（可不填）。
  - 托管期间也可以删掉登记错的一项。
  - 一份合约最多 50 项（`licenses_full`）。
- **谁能改**：只有执行方能登记和删除，发单人不能替他登记（`not_party`）。
- **放款以后**：清单就定了，不能再增删（`not_active`），但照样看得到。
- **谁能看**：合约双方都看得到；合约以外的人 403；别的合约名下的项删不到（404）。

## 3. 数据 / 接口

- 新表 `contract_license_items`，迁移 c1d220260084，SQLite 与 Postgres 都验过。
- 接口（合约接口的对象级授权规则已覆盖）：
  - `GET /contracts/{id}/licenses`
  - `POST /contracts/{id}/licenses`：请求体 `{kind, title, source, scope}`，返回整张清单
  - `DELETE /contracts/{id}/licenses/{item_id}`：返回整张清单
- 共享 SDK：
  - 类型：`ContractLicenseItem`、`LicenseKind`
  - 方法：`contractLicenses` / `addContractLicense` / `removeContractLicense`
  - 两端共用：`LICENSE_KIND_LABEL`、`licenseLine`
  - 新错误码 `licenses_full` 进 i18n。

## 4. 两端

- **Web 任务详情**：「交付文件」下面多「授权清单」。
  - 执行方：选类别、写名称、来源、范围，点「登记一项」；每项可以「删掉」。
  - 发单人只看。一项都没登记时，发单人看不到这一块。
- **App 任务详情**：同样一块（`app/licenses.tsx`），类别用一排可选的标签，文案与 Web 相同。

## 5. 隐私、授权与边界

清单由执行方自报，平台不核验授权的真假（需要对接版权方，记为欠账），但留痕可查。
