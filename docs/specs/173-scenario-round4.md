# 173 第四轮场景发掘：宠物上门照看与给爸妈办事

> 状态：本批实现（V200）。编号 SCN-115（并新开 SCN-119、SCN-120 记在第 7 节）。
> 来源：BACKLOG V200「第四轮场景发掘：雷达信号 + 业界调研，新增 1~2 个场景包；每四五批做一轮，防止只做用户举过的例子」；skill `scenario-discovery`；VISION 1.8「场景千变万化……快速发掘并部署方法到这个平台上」。
> 只增不减：已有 11 个类目、20 个技能概念、9 个法律主题都不动，只各加新的；已有场景包一个字不改。
> 写明的行为变化：新库与已有库启动时都会补上「宠物照护」「助老陪伴」两个类目（与 V149 补「财税」同一条路：只补一次，运营停用后不会被重新打开）；法律问答里问宠物的，雷达上从「其他」归到「宠物饲养」。

## 0. 要解决的问题

- 前三轮覆盖了 OPC、接单者、创作者、小店、家庭家务、社区活动、在校生；**两类高频的「托付」场景**还没有：
  - **人不在家，托人照看宠物**：节假日集中爆发，钥匙密码交接、每次上门看不见、宠物生病走失咬人谁负责，都是事后纠纷的来源。
  - **人不在爸妈身边，替爸妈找人办事**：装扶手防摔、上门陪伴；另一头是爸妈接到诈骗电话。子女是发单人，服务对象却是爸妈——信息怎么给、给多少没人提醒。
- 雷达信号：测试库里的「宠物上门喂养」就是现成的「搜了没有供给」样例（`test_packs.py` 的雷达用例）；技能概念表早有「宠物照护」，类目表却没有对应类目，发单只能落到「跑腿」。
- 法律问答里问宠物伤人、照看纠纷的，此前全部归到「其他」，雷达看不出该补哪类知识。

## 2. 数据

- 不加表、不加迁移。两个场景包是两个数据文件：`server/app/modules/packs/seeds/{pet-home-care,elder-family-help}.json`。
- 类目：`task/service.py` 的 `ADDED_CATEGORIES` 补「宠物照护」「助老陪伴」（模板的类目与「答不了时去发一单」的类目都要存在）。

## 4. 两端

- **用户侧**：上线后在两端「服务包」里与其他包一样启用与提问（引擎与两端界面 V148 已有，本批只是数据）；两个新类目自动出现在两端发布页的类目选择里。
- **Web 管理后台**：「服务包 → 导入仓库里的种子包」后成为草稿 → 提交 → 另一位管理员上线；雷达上多一个「宠物饲养」主题。
- **App 管理后台**：管理后台只在 Web，不涉及。

## 5. 隐私与边界

- 宠物包：门锁密码只给临时的、结束当天作废；家里摄像头先告诉上门的人（民法典第一千零三十二条）。
- 给爸妈办事：先问过爸妈再发单（个人信息保护法第十三条），身体情况写到够用为止，联系人填子女本人，上门地址只在接单后给；身份证号、银行卡、验证码任何时候都不给。
- 两个包的法律条文是常识性出处说明，助手按包内约定不提供法律意见、医疗意见；来电真假只教核对办法，不替人判断。
- 适老化改造涉及电路、燃气的，模板与知识都指向持证类目（电工维修、燃气维修）。
