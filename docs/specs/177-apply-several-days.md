# 177 一个人一次报多天

> 状态：本批实现（V204）。编号 SCN-118。
> 来源：167 号 spec 第 7 节「没做的」——「SCN-118 一个人一次报多天：同一个帮手要接三天得报三次（每个名额单独报名）；可以加『这几天我都来』的一键报名」；BACKLOG V204。
> 只增不减：单个名额上的报名接口与规则不变（规则抽成 `_apply_one`，两条路共用一份）；每个名额仍是独立的报名、独立的合约。

## 0. 要解决的问题

- 「5 个人干 3 天」的单，同一个帮手三天都能来，要找到三个名额、各报一次；名额是平铺在广场上的，帮手甚至不知道这几个名额是同一单。
- 名额详情上没有回到整单的入口。

## 1. 业界怎么做

| 做法 | 说明 |
|---|---|
| 按班次报名、可以一次选多个班次 | 灵活用工平台（Instawork 一类）把一个岗位的多个班次列在一起，帮手按班次接（<https://help.instawork.com/en/articles/10113606-what-to-expect-a-guide-to-managing-shifts-with-instawork>） |

本批取：在母任务上勾几天，每天报一个还在招的名额；发单人仍逐个名额选人（选人、签约、托管都按天，不新增资金路径）。

## 2. 数据

不加表、不加迁移：每天一条普通报名（`applications`），落在那天第一个还在招的名额上。

## 3. 接口

| 接口 | 说明 |
|---|---|
| `POST /tasks/{id}/apply-days` `{dates, message}` | 只在多天母任务上（`not_multi_day`）；日期去重、按日期排；每天：这单没有这一天 / 你已经报过这一天的某个名额 / 这一天没有还在招的名额 → 写进 `skipped` 并说明原因，其余照报；一天都报不了 → 409 `no_day_available`，原因逐日写在提示里。报名规则（协议、实名、资质、并发上限、拉黑、发单人失效、自己报自己）与单个报名同一份 `_apply_one` |
| 返回 | `{applied: [{date, task_id, application_id}], skipped: [{date, reason}]}` |

SDK：`applyDays`、`ApplyDaysResult`；2 个错误码进 i18n；对象级授权表登记（与报名同一条）。

## 4. 两端

- **Web 任务详情**：多天母任务的「按天看名额」下，不是发单人的人多一块「一次报多天」：只列还缺人的那几天，勾选后「报这几天」，结果写明报上了哪几天、哪几天为什么没报。名额详情多「这单一共好几天：回到整单，一次报多天 →」。
- **App 任务详情**：同一块（`TaskTreeBlock` 多 `meId`），名额详情同样能回到整单。

## 5. 隐私、授权与边界

- 报名不占名额（发单人还没选人）：两个人报同一天时，都落在那天第一个还在招的名额上，由发单人挑；发单人选了一人后，那个名额不再招，下一个人再报就落到下一个名额。
  - **V208（181 号）起**：发单人在那个名额上选了一人后，那个名额上其他人的报名挪到同一天下一个还在招、自己没报过的名额，而不是被拒；那天没有空名额时才照旧拒。
- 不新增资金路径：选人、签约、托管、验收、放款都按名额。
