# 208 常用路线到点前推顺路的名额

> 状态：本批实现（V236）。编号 SCN-140。
> 来源：203 号 spec「没做的」——「常用路线（家→公司、每天几点出发）存下来，到点前推顺路的名额」；BACKLOG V236。
> 只增不减：顺路单、常用地点、「现在有空」推单的接口与行为不变；删除常用地点时多删用到它的路线。
> 写明的行为变化：新表 `gig_routes`（迁移 c1d220260045）；新定时任务 `/gig/jobs/route-push`（十分钟一轮，job 总数 34）；数据导出多一节 `gig`（常用地点与常用路线）。

## 0. 要解决的问题

V227 让顺路单可以带出发时间，但每天都要自己打开、选地点、填时间再看。上下班这类固定路线，接单的人想要的是「到点前告诉我路上有什么单」，而不是每天操作一遍。

## 1. 业界怎么做

顺风车、同城顺路带货产品普遍支持「常用路线」：用户存下出发地、目的地与常用出发时间，平台在出发前推送匹配的订单，并控制推送频次。本平台的顺路单规则（192 / 203 号 spec：直线估算多走的路、按出发后几小时内的名额时段筛）不变，本批只加「存路线 + 到点前推一次」。（本批没有另找外部来源。）

## 2. 数据

`gig_routes`：`owner_id`、`from_place_id` / `to_place_id`（指向本人的常用地点）、`weekdays`（0 = 星期一，北京时间）、`depart_hm`（北京时间 HH:MM）、`within_hours`（1~12，默认 3）、`last_pushed_on`（北京日期，一天最多推一次）。**不存坐标**：坐标在常用地点上，已粗化到约 1 公里。迁移在 SQLite 与 Postgres 上 `upgrade head` + `check` 通过。

## 3. 接口

| 接口 | 说明 |
|---|---|
| `GET /gig/routes` | 本人的常用路线（带起终点名字） |
| `POST /gig/routes` `{from_place, to_place, weekdays, depart_hm, within_hours}` | 起终点必须是本人的常用地点（别人的 404）；起终点相同 `gig_route_same_place`；没选星期或超出 0~6 `gig_route_no_days`；时间不是 HH:MM `gig_route_time_invalid`；最多 5 条 `gig_routes_full`；多收字段 422 |
| `DELETE /gig/routes/{id}` | 只给本人（别人的 404）；对象级授权表登记 |
| `POST /gig/jobs/route-push`（job 令牌 + 单实例锁） | 十分钟一轮：今天是路线设的星期几、离出发不到一小时、今天还没推过的路线，按「出发 → 之后 within_hours 小时」算一次顺路单（多走 2 公里以内，最多 3 单）；有单就发一条「顺路单」通知（「08:30 从『家』去『公司』，顺路有 1 单：……」），没有就不打扰；两种情况今天都算看过了 |

新错误码进 `i18n.ts`。SDK：`gigRoutes()`、`addGigRoute()`、`deleteGigRoute()`、`GigRouteView`、`GigRouteInput`；共享函数 `gigRouteLabel`（「工作日 08:30 家 → 公司」「周末」「每天」「周一、周三」）。

## 4. 两端

- **Web** 接单页「顺路单」里，有两个以上常用地点时多一块「常用路线」：列出已存的（能删）；用上面选的起点（必须是常用地点，不能是「当前位置」）与终点，选「工作日 / 每天 / 周末」、填几点出发，点「存为常用路线」；时间没写或写错不发请求、就地说明。
- **App** 接单页同一块：「从哪」单选（终点用上面选的「到哪」）、工作日 / 每天 / 周末、几点出发、「存为常用路线」；列表能删。

## 5. 隐私、授权与边界

- 位置：路线不存坐标；常用地点仍是粗化坐标。删地点会连带删路线；注销时路线与地点一起清掉（注销处置表已登记）；数据导出里有本人的常用地点与路线。
- 打扰：一天一条路线最多推一次、最多列 3 单、没有就不推；最多 5 条路线。
- 距离仍是直线估算（不是道路距离），通知与页面的说法不变。
