# 34 · 人机验证的端到端闭环（CAP）

> 补 [31-security-events.md](31-security-events.md) SECEV-010~014 留下的缺口。

## 先说清楚：这是我上上批自己挖的坑

V56 在登录路径上加了人机验证阶梯：正常 → **要求验证码** → 封禁。
服务端做得很完整——`CaptchaProvider` 抽象、软阈值、事件留痕、
错误验证码计入失败，还写了测试。

**但是没有任何一个客户端能满足这道门。**

```
packages/core/src/client.ts:
  login(phone, password) {
    return this.request(..., { phone, password });   // 没有 captcha_token
  }

web/src/pages/Login.tsx:   没有任何验证码 UI
app/App.tsx:               同上
```

服务端加了参数 `captcha_token`，SDK 从来不传；网页与 App 上连一个能填的地方
都没有。也就是说：**这道门有锁，没有钥匙孔。**

### 为什么现在没炸

默认 `PLATFORM_CAPTCHA_PROVIDER=none` 是直通实现——`verify()` 永远返回
`True`，空 token 照样过。所以当前配置下一切正常。

### 什么时候会炸

`docs/OPERATIONS.md` 明明白白地建议：

> | **人机验证** | ✅ V56 已实现抽象与沙箱桩，默认 `none` 直通 |
> 配 `PLATFORM_CAPTCHA_PROVIDER` 接第三方（hCaptcha/腾讯云等） |

**运维照着这句话做，全站登录立刻半死**：任何用户连续输错 3 次密码后，
服务端开始要求验证码，而网页与 App 永远交不出来——他被锁在门外，
直到 5 分钟窗口自己过期，然后重复。

我建这道阶梯的理由是「给被误伤的真人一条自证的路」。
**没有客户端支持时，它反而变成了一堵比封禁更早生效的墙。**

这和 V51 的教训是同一句话的两半：
「接口预留了却跑不通，等于没预留」——而这里是**门建好了却没有钥匙孔**。

## 34.A 客户端必须能满足服务端的门（P0）

- **CAP-001** 凡是服务端会拒绝的条件，客户端必须有**可执行的**满足路径。
  这条听起来是废话，但它正是本 spec 存在的原因——
  服务端与客户端分开写、分开测，就会长出只有一半的功能。
- **CAP-002** `GET /auth/captcha-config`（**公开**）：返回 provider 名、
  是否 enforcing、站点公钥与脚本地址，客户端据此渲染。
- **CAP-003 反应式，不是主动式**：客户端**不**预先询问「我现在需不需要验证」。
  那等于把「这个 IP 已经触发风控」告诉任何人，白送一个探测风控状态的接口。
  正确顺序是：正常提交 → 收到 `captcha_required` → 渲染挑战 → 带 token 重试。

## 34.B 客户端（P0）

- **CAP-010** SDK：`login(phone, password, captchaToken?)`、`captchaConfig()`。
- **CAP-011** Web 登录页捕获 `captcha_required` → 拉配置 → 渲染挑战 → 重试。
- **CAP-012** 挑战组件按**标准形态**实现（脚本地址 + 站点公钥 + 回调拿 token），
  hCaptcha、Cloudflare Turnstile、腾讯云验证码都是这个形状，
  接哪家只改环境变量。
  未配置脚本地址时（sandbox / 自建）退化为可输入的令牌框——
  **诚实地标注它是什么**，不假装是一个真的滑块。

## 34.C 机器闸门（P0）

- **CAP-020** 生产启动自检：`CAPTCHA_PROVIDER` 是**会真的拦人**的实现，
  却没有配站点公钥 → **拒绝启动**。
  一个客户端渲染不出来的强制验证，等于把全站用户锁在门外——
  这正是本 spec 要防的事故，所以它必须是硬拦截而不是一行日志。

## 34.D 验证（P0）

- **CAP-030 端到端**：按文档流程（提交 → 收到 `captcha_required` → 带 token
  重试）能真的登进去。这是缺口的直接反面。
- **CAP-031** SDK **确实把 token 发出去了**——UI 做了而 SDK 不传，等于没做。
- **CAP-032** 配置端点无需登录即可访问（登录页还没有 token）。
- **CAP-033** 配置端点**不泄露**当前 IP 是否已触发风控（CAP-003）。
- **CAP-034** 生产 + enforcing provider + 无站点公钥 → 启动自检失败。
- **CAP-035** 默认 `none` 配置下，登录流程与改造前**完全一致**（不回归）。

## 验收标准

- 运维照 OPERATIONS 的建议接上真实验证码后，**登录仍然可用**；
- 没有任何「服务端要求、客户端给不出」的字段；
- 配置端点不成为风控状态的探测器。

## 必须由用户提供（代码无法替代）

- 第三方验证码服务的**站点公钥与密钥**（hCaptcha / Turnstile / 腾讯云等）
- ⚠️ 服务端校验用的私钥要接到 `CaptchaProvider` 的真实实现里；
  本仓库只提供协议与沙箱桩
