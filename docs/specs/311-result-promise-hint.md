
# 311 发单与报价里出现结果承诺时提示

> 状态：本批实现（V338）。编号 SCN-185。
> 来源：310 号 spec「没做的」——「发单与报价里出现『保 offer、包就业、保录取』这类结果承诺时提示」；BACKLOG V338。
> 只增不减：发单、报名都**不拦**；发单时的说明体检多一种风险提示；发单人看到的报名列表只在留言承诺了结果时多 `promise_flag`。

## 0. 要解决的问题

V337 只在「求职辅导接单顾问」里不建议保 offer。可结果承诺不只出现在助手里：发单的人会写「找人辅导，要求保 offer」，报名的人会在留言里写「我们团队包就业，拿不到全退」。平台此前什么也没说——而这正是「保 offer」套餐纠纷的起点。

## 1. 业界怎么做

教育培训、求职服务的广告规范普遍禁止对升学、考试、就业结果作保证性承诺；平台通常在发布环节提示，而不是一律拦截（「不保 offer」「不通过退款」这类正当说法需要区分）。（依据同 310 号，本批没有另找外部来源。）

## 2. 规则

- `app/modules/task/promises.py` 的 `has_result_promise`：「保 / 包 / 保证 / 确保 / 承诺」+「offer、录取、录用、就业、入职、过、拿证、上岸、通过、分配、中标」，或「100% 录取 / 通过 / 上岸」；**前面 6 个字里有「不 / 没 / 无 / 非 / 拒绝 / 别」的不算**（「不保 offer」「绝不承诺包过」「没有包就业这回事」）。「保洁」「包装」「保存」「不过退款」不误报。
- **发单时**：说明体检（任务画像）多一条风险 `result_promise`：「写了『保 offer / 包就业 / 保过』这类结果承诺：录用、录取、考试结果由用人单位、学校或考试机构决定，谁也保证不了。平台不支持结果承诺——请写清交付什么（改几版简历、练几次面试、讲几节课），按次托管、按次验收」。两端已有的风险列表原样显示。
- **报名时**：照常报名；发单人看到的报名列表上，留言承诺了结果的那条多一行提醒「这条报名承诺了结果……选人时多留个心」。

## 3. 数据 / 接口

不新增表与接口。`GET /tasks/{id}/applications` 行多可选 `promise_flag`；任务画像的风险多一种 `result_promise`。共享 SDK `listApplications` 的行类型加 `promise_flag?`。

## 4. 两端

- **Web 任务详情的报名列表**、**App 任务详情的报名列表**：有 `promise_flag` 时在留言下面标红一行。
- **两端发单时的说明体检**：已有的风险列表，自动多出这一条。

## 5. 隐私、授权与边界

只看文字，不存命中；报名列表照旧只有发单人能看。
