## 二、已钉死的核心契约（全部有测试）

**业务闭环**：发布 → AI 分解（预算守恒）→ 推荐（可解释）→ 报名/邀约 →
合约生成 → 双签 → 托管 → 执行留痕/打卡 → 交付 → 验收/自动验收 → 放款抽佣 →
互评 → 信用 → 经验入库 → 参考价。

**安全与资金不变量**：
- 状态机白名单穷举：非法流转全拒（`test_state_machine`）
- 资金三不变量（全局守恒/托管有据/冻结有据），随机生命周期 fuzz（`test_money_property`）
- 防重放：重复接受/托管/交付/验收/里程碑全拒且零副作用（`test_concurrency_guards`）
- 变更单守恒：加价补托管/减价退款/多轮随机改价（`test_change_order_money`）
- 分期×纠纷交叉：部分放款后只分剩余、冻结期禁放款（`test_milestone_dispute_cross`）
- 多人任务名额预算守恒 + 自动验收边界（`test_multiperson_autoaccept`）
- 存证哈希链防篡改：自洽伪造/删行/脱链全被定位（`test_anchor_chain`）
- 幂等（Idempotency-Key）、限流、资源级越权拒绝（`test_hardening`）

**迭代中修复的产品级缺陷**（测试先行暴露）：
存证链重复注册膨胀、刷单阈值差一、多人任务余数蒸发（每单丢分钱）、
dispute 响应缺复核基数字段、圈层创建者角色丢失等。

| V76 CERT | **受限类目的资质门槛一直是虚的**：`POST /users/me/certifications` 的实现是一行 `user.certifications += [name]`，注释写着「模拟审核即通过」——任何实名用户 POST 一个字符串就拿到「电工」资质，而电工维修/燃气维修/法律咨询的接单准入正是靠它，管理后台里连队列都没有。一个无证的人接了电工单，出事的是人身安全。改为：提交的是**申请**不是资质、必须附证件影像、**证件姓名必须与实名完全一致**（一张别人的电工证也是一张真证件）、人工核过才写入且驳回必须带理由、**资质有有效期**（「发了就永久有效」是几年后才伤到人的错）。顺带补一个真实安全缺口：证件影像是敏感个人信息，而 `/files/{name}` 是**匿名**能力 URL——加 `sensitive` 标记后匿名读一律拒绝，另开鉴权端点只对本人与管理员开放且不缓存。存量自助资质由迁移转成待补材料的申请（保留可见性）并清空快照字段，**准入立刻收紧**；已用真实数据实测迁移效果 |
| V75 COOP | 早期合作体——需求定位是**颠覆公司组织形式**。核心与公司股权最本质的区别：**份额不是分的，是长出来的**。传统公司先分股权再干活，分的那一刻谁干多少还不知道，干到一半有人不干了股权还在他手里；这里 `份额 = 已确认贡献 ÷ 全体已确认贡献`，**每次现算不存字段**（存下来就会漂且不会有任何东西报错）。三条硬约束让它落在合作内部分配而非涉众性金融：**邀请制**（没有公开加入端点）、**只分已实现收益**（代码里根本不存在「预期收益」字段）、**份额不可转让**（故意不做，不是以后再说——一旦可转让它就是可流通的权益凭证）。贡献必须被**另一名成员**确认才计份额，且**计价由确认人给**（贡献人说做了什么，确认人说值多少），自报贡献等于自己发股份。风险揭示书是加入前置，四条必备内容在代码里是常量。合规路径引擎按合作体客观属性给清单与门槛并说明每项**为什么**需要，**不阻断任何操作**，并显式声明不是法律意见。贡献确认与收益分配入存证哈希链 |
| V74 VER/ESCA | 补 V73 留下的 AGT-050：`escalated` 当时只做到「拦住 + 可退款」，**没有接到人类专家**。核心判断是**核验不是重做**——看一遍判对错该按原价 5%~20% 收，做成「重发一个任务招人干」就是让发布方为 AI 的不确定性付两次全价。**谁付费是有立场的**：agent 置信度不足是平台的问题，平台付；发布方主动要核验的自己付（阈值调越松平台掏越多，这正是该有的激励）。三条硬约束：**agent 不能当核验人**（让 AI 核验 AI 是把同一个不确定性叠两遍）、本单当事人不能核验、**`revised` 的修正稿要重新过平台判据**（人工核验是加上去的一道，不是用来豁免原有那道的）。核验结论回流 `VerificationLesson`——这才是「持续帮助迭代」的载体，`KnowledgeCard` 只记价格工期，记不下「怎么做才对」。ESCA 把客服→纠纷→法务三个互不相识的模块连起来：工单转纠纷**带上下文**（两次陈述不一致会被当成翻供），证据包补进 AI 执行与核验记录。过程中两处自查：我先自己写了一个证据导出端点，发现 `legal` 里已有更完整的一个，删掉去扩展既有的（V58 教训）；平台给自己预扣核验费导致账实不符，被对账不变量当场抓到 |
| V73 AGT | **产品定位是「AI 驱动」，但 LLM 只用在「拆解」一个点上**——编排器唯一的 tool 是 `publish_task`，也就是它只会把活派给人。补平台自有 Agent 执行层：agent = 一行 User + 一行 profile（复用托管/纠纷/信用/账本，不另建平行实体）。四条硬闸门：**非远程任务不许接**（不拦的话 agent 会去报名上门保洁单然后交付一段文字）、领域必须命中、预算上限（赔付能力）、置信度低于阈值转人工且不许交付。验收改为**平台执行客观判据**——置信度是 agent 自报的，让它同时给自己判卷等于没有验收。顺带查出两条既有缺陷：平台账户对账不变量是**五组科目手抄相加**（加一种新科目就误报，已改为按账户求和）、**SQLite 连接池跨请求留下过期读快照**导致已吊销的会话还能通过鉴权 |
