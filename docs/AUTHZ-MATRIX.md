# 授权总表：谁能碰什么（SEC-061）

> 由 `server/tests/test_authz_matrix.py` 钉着：代码里每一处「管理员绕过」都必须在第 3 节有一行，
> 第 3 节的每一行都必须在代码里找得到；「受限」那一类的接口必须真的调用审计。
> 带资源 id 的端点归属规则在 `test_object_level_authz.OWNERSHIP_RULES`（SEC-060，166 条），这一页不重复，
> 只回答规则表回答不了的那个问题：**判据是哪一种、为什么是这一种**。

## 1. 五种判据

| 判据 | 含义 | 典型资源 |
|---|---|---|
| **本人**（self） | 资源属于调用者，id 只是自己名下某条的编号 | 钱包、收款账户、通知、草稿、API Key、订阅、自己的上传 |
| **当事人**（party） | 一件事有固定的几方：任务的发布方与执行方、合约双方、会话参与者、圈层管理员 | 任务、合约、纠纷、私聊、核验单、编排 |
| **角色**（admin） | 运营职责，要求管理员 | `/admin/*`（逐条由 CLI-080 闸门覆盖） |
| **公开**（public） | 本来就是给别人看的；**钱与身份不得标公开**（V124 闸门） | 公开空间、已发布作品（按可见性过滤）、子类与可复用单元 |
| **机器**（machine） | 按 API Key 主体与机器委托额度 | `/open/v1/*` |

## 2. 作品的可见性：只有一个判据

`content/router.py::can_view` 是唯一的判据，按 id 读、按作者列、评论、点赞都用它（SEC-060f，V139）：

| 可见性 | 谁看得见 |
|---|---|
| public | 所有登录用户 |
| followers | 作者与关注了作者的人 |
| circle | 作者与该圈层的活跃成员 |
| private | 只有作者 |
| 草稿 / 已删除 | 只有作者（草稿）/ 没有人（已删除） |

**看不见就是不存在**：一律 404，不用 403——403 会告诉别人这个 id 上确实有东西。
评论不是独立的公开资源：作品看不见，它下面的评论也看不见。

## 3. 管理员绕过：哪些是职责，哪些必须写理由

### 3.1 职责内（客服与仲裁要用，不单独审计）

| 位置 | 管理员能做什么 | 为什么 |
|---|---|---|
| `contract/router.py::_get` | 读合约 | 纠纷仲裁、客服核对条款 |
| `contract/router.py::get_contract_by_task` | 按任务读合约 | 同上 |
| `finance/router.py::contract_settlements` | 读分账指令 | 对账与差错处理 |
| `anchor/router.py::contract_anchors` | 读存证锚定 | 举证 |
| `dispute/router.py::get_dispute` | 读纠纷 | 仲裁 |
| `dispute/router.py::get_task_dispute` | 按任务读纠纷 | 仲裁 |
| `dispute/router.py::list_statements` | 读双方陈述 | 仲裁 |
| `legal/router.py::evidence_export` | 导出证据包 | 仲裁与司法协助 |
| `task/router.py::list_progress` | 读任务进度记录 | 纠纷核实 |
| `task/router.py::list_reviews` | 读未揭晓的双盲评价 | 处理恶意差评的申诉；揭晓前双方仍互相看不见 |
| `agent/router.py::list_runs` | 读 AI 助理运行记录 | 平台是 AI 履约的责任主体 |
| `verify/router.py::get_order` | 读核验单 | 核验争议 |
| `orchestrator/router.py::_get_mission` | 读编排 | 编排失控时的人工接管 |
| `content/router.py::delete_content` | 删除作品 | 内容处置（UMOD） |

### 3.2 受限（默认不可；写明理由才可读，每一次都进审计）

| 位置 | 资源 | 允许的情形 |
|---|---|---|
| `im/router.py::_get_conv` | **私聊**（含撤回的原文） | 纠纷举证、举报核查、法定调取。**只读**：管理员不能往别人的私聊里发消息 |
| `files/router.py::read_sensitive_file` | **证件影像等敏感材料** | 审核这份材料所属的资质申请（自动记为「资质审核」）；其余情形必须写明理由 |

改造前（V139 之前）这两项都是「管理员一句话放行」：任何管理员都能读任何人的私聊（连撤回的原文），
还能往别人的私聊里发消息；能读任何人的证件影像；**都不留痕**。沉默等于默认可以——这一页把它写成明文。

### 3.2b 按角色拦（V169，141 号 spec）

| 位置 | 说明 |
|---|---|
| `app/core/admin_roles.py::roles_of` | 管理员的生效角色：客服、仲裁、合规、财务、运营、超级管理员；没分配过角色的按超级管理员对待（兼容此前全部管理员，后台标成「未分级」）。每个管理员接口都声明了角色（`tests/test_admin_roles.py` 的总表）；3.2 的两项受限读取另外要求「仲裁」或「合规」角色 |

### 3.3 没有管理员入口

| 资源 | 说明 |
|---|---|
| **个人工作台**（项目、个人任务、进展、助手记忆、例行任务；116 号 spec） | 只属于本人，管理员也没有读取入口；别人的 id 一律 404。它与平台交易无关，纠纷举证用的是合约、交付和私聊，用不到个人待办。用户可以自己导出（PIPL），注销时全部物理删除 |

## 4. 这一页没回答的

- **管理员之间的分级**（客服 / 仲裁 / 合规 / 超管）：现在只有一个 `is_admin` 位。受限访问靠「写理由 + 审计」
  事后可查，而不是事前按角色拦——分级是 SEC-061b。
- **审计日志本身谁能看**：审计表在后台可查，但没有「只读审计员」角色。
