## 二、后端并发设计（现状 + 生产化路径）

### 2.1 现在真实具备的并发安全手段

| 手段 | 位置 | 防什么 |
|---|---|---|
| **幂等键 + 请求指纹** | `core/idempotency.py` | 网络重试重复扣款；同 key 不同金额（吞单）；跨操作串味 |
| **状态机白名单** | `task/service.py::transition` | 并发双击导致重复放款——第二次必落在非法流转上 |
| **事务边界整体回滚** | `core/db.py::get_db` | 任一步失败则整笔回滚，不留半截状态 |
| **DB 唯一约束** | `contracts.task_id UNIQUE` 等 | 一任务一合约的最后一道防线 |
| **限流（滑动窗口）** | `core/ratelimit.py` | 注册/登录/改密/换绑的暴力尝试 |
| **对账不变量** | `risk/service.py::reconcile` | 四条硬不变量兜底，不平自动开工单+告警 |

这套组合已被 **258 个测试**覆盖，其中 `test_concurrency_guards.py` 专门验证
「重复接受报名 / 重复托管 / 重复交付 / 重复验收 / 重复里程碑放款」全部拒绝且零副作用。

### 2.2 ⚠️ 明确缺口（上线前必须解决）

现状是 **SQLite 单文件 + 单进程**，`create_engine` 未配连接池、未开 WAL，
且**没有行级锁 / SELECT FOR UPDATE / 乐观锁版本号**。

这意味着：
- **单进程下安全**——所有写请求串行经过同一事务边界，状态机守卫足够；
- **一旦多进程/多副本部署，钱包与合约的并发写存在真实竞态**
  （两个进程同时读到 `status=funded` 再各自放款，状态机在应用层判断，DB 层无锁拦不住）。

**生产化改造路径（按优先级）**：

1. **换 PostgreSQL**（改一个环境变量即可，SQLAlchemy 层无需动业务代码）
   ```bash
   PLATFORM_DATABASE_URL=postgresql+psycopg://user:pass@host/db
   ```
2. **关键写路径加悲观锁**：`fund` / `release` / `withdraw` / `dispute_split`
   在读合约与钱包时用 `with_for_update()`：
   ```python
   contract = db.query(Contract).filter(...).with_for_update().first()
   acct = db.query(WalletAccount).filter(...).with_for_update().first()
   ```
3. **或加乐观锁版本号**：`Contract.version` 已有字段，
   UPDATE 时带 `WHERE version = :v` 并检查影响行数，冲突则 409 重试。
4. **连接池与超时**：`create_engine(url, pool_size=20, max_overflow=10, pool_pre_ping=True)`
5. **限流改 Redis**：`core/ratelimit.py` 现在是**进程内内存**，多副本下形同虚设。
6. **事件总线改 MQ**：`core/events.py` 是进程内同步派发，
   多副本下事件只在处理请求的那个进程里触发（如经验入库、后继子任务发布）。
7. **定时任务改专用调度器**：现在是可调用的 HTTP job 端点（已加令牌鉴权），
   生产用 K8s CronJob / APScheduler 单实例触发，避免多副本重复执行。

**容量参考**：单机 Postgres + 4 个 uvicorn worker，这套读写比下支撑
日均十万级任务量没问题；瓶颈会先出现在 AI 分解（外部 LLM 调用）和地理检索
（现在是全表扫 + Python 算距离，⚠️ 规模化需换 PostGIS 或 geohash 索引）。

## 三、安全性

### 3.1 已实现（每项都有测试）

**账号与认证**
- 密码 **PBKDF2-HMAC-SHA256，12 万次迭代 + 随机盐**（`core/security.py`）
- 自签 token 绑定会话 id，**会话可吊销**（改密/换绑/重置密码后全端下线）
- 三入口限流一致：注册 3/60s、短信登录 5/60s、**密码登录 5/60s**
- 新设备登录站内提醒；换绑手机需「新号验证码 + 旧密码」双验证

**授权**
- 资源级鉴权：任务/合约/会话/纠纷都校验「你是不是当事人」，非当事人 403
- 管理端 `require_admin`；**内部 cron 端点独立令牌** `X-Job-Token`（与用户身份正交）
- 越权测试集中在 `test_hardening.py`，覆盖跨用户读取报名/合约/会话/导出

**资金**
- 整数分记账、只增流水、三态账本（可用/托管/冻结）
- **四条对账硬不变量**：全局守恒 / 托管有据 / 冻结有据 / 平台佣金有据
- 提现风控：日限额、大额（≥¥1万）冻结进人审、**必须先绑实名一致的收款账户**
- 幂等指纹防吞单/串味；防重放守卫覆盖全部关键资金动作

**审计与存证**
- **管理员操作审计**（封禁/裁决/结算/提现审批全留痕，可按动作查询）
- **SHA256 存证哈希链**：合约关键动作入链，改一行必须重写整条后继链才不被发现
- 对账不平自动开差错工单 + 通知全体管理员

**内容与风控**
- 敏感词机审（任务/内容/评论）、举报队列、封禁影响面预览 + 对手方告知
- IM 站外引导识别（防跳单）、陌生人私聊条数上限、消息撤回保留审计副本
- 位置脱敏（精确地址仅成交双方可见）、30 天后清除打卡坐标

### 3.2 ⚠️ 上线前必须补

| 项 | 现状 | 要做什么 |
|---|---|---|
| **JWT 密钥** | compose 里写死 `change-me-in-production` | 换强随机值，走 secrets 管理 |
| **Job 令牌** | 默认 `dev-job-token-change-me` | 同上 |
| **HTTPS** | 无 | Nginx/网关加 TLS，强制 HSTS |
| **短信验证码** | 固定 `123456` | 接真实短信服务商 |
| **实名认证** | 模拟通过 | 接 eKYC（身份核验 + 人脸） |
| **支付** | 模拟充值提现 | 接持牌支付通道（微信/支付宝/银联） |
| **全局限流** | 仅认证接口，且进程内 | 网关层 IP 限流 + Redis 分布式限流 |
| **CORS** | 已配 middleware | 生产收紧到白名单域名 |
| **依赖扫描** | 无 | CI 加 `pip-audit` / `npm audit` |
| **日志脱敏** | 无统一处理 | 手机号/身份证/银行卡打码后再落盘 |

### 4.2 生产部署（推荐配置）

```yaml
# docker-compose.prod.yml 关键差异
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes: [pgdata:/var/lib/postgresql/data]

  server:
    environment:
      PLATFORM_DATABASE_URL: postgresql+psycopg://postgres:${DB_PASSWORD}@db/platform
      PLATFORM_JWT_SECRET: ${JWT_SECRET}          # 强随机
      PLATFORM_JOB_TOKEN: ${JOB_TOKEN}            # 强随机
      ANTHROPIC_API_KEY: ${ANTHROPIC_API_KEY}     # 启用真实 AI 分解
    command: uvicorn app.main:app --host 0.0.0.0 --workers 4
    deploy: { replicas: 2 }

  cron:                       # 单实例跑定时任务，避免多副本重复执行
    image: curlimages/curl
    command: >
      sh -c 'while true; do
        for j in tasks/jobs/auto-accept tasks/jobs/expire-tasks
                 tasks/jobs/settle-reviews contracts/jobs/expire-unsigned
                 disputes/jobs/escalate-overdue missions/jobs/tick-all; do
          curl -sX POST -H "X-Job-Token: $$JOB_TOKEN" http://server:8000/api/v1/$$j;
        done; sleep 3600; done'
```

## 五、社区、市场与营销运营

### 5.1 冷启动：先解决「鸡生蛋」

双边市场最大的坑是两边都空。**不要两边同时推**，按顺序来：

**第一步：把供给端做厚（先招工人，不招雇主）**
- 选 **1 个城市 × 1~2 个高频品类**（推荐：保洁 / 跑腿代买 / 搬家）。
  不要一上来铺全品类全城市——密度不够就没有履约体验。
- 目标：**单个商圈 50~100 个实名执行者**。低于这个密度，发单等不到人接，
  雇主第一次体验就崩了。
- 获取渠道：同城群、蓝领招聘平台、家政/跑腿公司谈整队入驻、地推。
- 钩子：**平台补贴前 N 单佣金**（现在 `fee_bps` 已支持按信用等级折扣，
  可直接给新人 0 佣金），加「保证金免缴」。

**第二步：需求端小范围做透**
- 平台方**自己当第一批雇主**发真实单（这不丢人，是标准做法），
  确保执行者有钱赚、留得住。
- 然后定向邀请：写字楼物业、小区业主群、小微商户。
- 关键指标：**任务被接单率 > 80%**、**平均接单时长 < 30 分钟**。
  达不到就继续加供给，不要扩张。

### 5.3 社区运营节奏

**日常**
- 每天看 `admin/funnels`：接单率掉了就补供给，验收纠纷多了就查品类标准。
- 纠纷 SLA 已有自动升级（7 天），但**人工仲裁必须 24h 内响应**——
  纠纷处理体验直接决定口碑，这是不能省的人力。
- 每周挑 1~2 个优质闭环案例，让执行者发到社区，平台给流量。

**社群（圈层）玩法**
- 按**技能**建圈：保洁师傅圈、设计师圈——沉淀专业交流，圈内成交有信任加成。
- 按**地域**建圈：某商圈/某小区——密度就是履约速度。
- 圈主给权益（优先派单、佣金折扣），让圈主自己拉人。

**内容与获客**
- 让老手写「XX 任务怎么做才不返工」的案例文 → 既是 SEO 也是新人培训。
- 把「AI 分解」做成传播点：用户输入一句「我要搬家」，
  平台自动拆成 3 个可执行子任务并报价——这是**很强的演示钩子**，
  适合做短视频/直播演示。

### 5.4 变现与定价

- 当前抽佣 **8%**（`PLATFORM_FEE_BPS` 可配），高信用执行者有折扣。
- 冷启动期建议：**前 3 个月 0 佣金**换密度，靠融资/自有资金补贴。
- 成熟后的收入结构：佣金 + 保证金沉淀 + 会员（优先派单/低费率）+
  企业版（批量发单、对公结算、发票）+ 增值（认证徽章、置顶曝光）。
- 平台收入已有实收口径与结算接口（`/admin/platform-finance`），
  财务对账不用另做系统。

### 5.5 风险与合规（别忽视）

- **资金合规**：托管资金属于用户备付金，**必须接持牌支付机构做账户隔离**，
  自己拿账户池收钱是红线。
- **劳务关系**：明确平台是信息中介、执行者是独立承揽人，
  合约模板要写清（现在 `contract/service.py` 的 terms 已含框架，需律师定稿）。
- **税务**：执行者收入需代扣代缴或提供完税凭证方案。
- **人身安全**：线下任务已有到场打卡、行程分享、紧急联系人（GEO-021/023/024），
  运营上还要有**保险**（意外险/责任险）和黑名单联动。
- **资质品类**：法律/医疗/电工等已有职业资质准入（ACC-022），
  运营必须严格审核证件，别为了 GMV 放水。

## 六、诚实的差距总结

**已经很扎实的**：交易闭环、资金安全与守恒、纠纷程序正义、账号安全、审计留痕。
这些有 258 个测试钉着，逻辑上经得起推敲。

**离真正上线还差的**（按紧迫度）：
1. Postgres + 行锁/乐观锁（多副本资金安全）—— **最关键**
2. 支付 / 短信 / eKYC 三个外部接入 —— 没有就没法真实收付款
3. HTTPS、密钥管理、Redis 限流 —— 基础运维安全
4. 保险、税务、劳务关系法律定稿 —— 合规前置
5. App 打包发版 + 推送 —— 移动端体验完整性

代码侧我可以继续把 1 补上（换 Postgres 配置 + 关键路径加锁 + 并发压测），
2~4 需要外部资源与专业意见，5 需要开发者账号。
