# 链上任务托管：实现、操作与上线边界

更新：2026-10-07。本版包含可编译、可部署的 `chain/contracts/TaskEscrow.sol`，真实 EVM 生命周期测试，Web 钱包操作页 `/chain`、App 钱包浏览器入口、部署/恢复脚本与只读对账工具。已经在本机测试链部署。**未部署公链，未完成独立安全审计，不宣称可直接承接真实资金。**

## 合作闭环

1. 发布方创建任务：指定执行方、仲裁人、合同原文摘要、业务编号摘要、每期金额与固定交付期限、入金期限、验收期、仲裁期和仲裁超时分配比例。1–32 期；各期时间递增。每次创建均有独立编号，业务编号仅用于关联，不证明该钱包的实名身份。
2. 执行方以自己的钱包调用 `accept(id, expectedTermsHash)`，确认包括链 ID、合约地址、双方身份、所有期限、代币和服务费在内的完整不可变条款。EOA、企业多签和可执行合约调用的钱包均可以作为主体；没有平台代签或 API token 代替钱包签名。
3. 发布方授权本次精确 ERC20 金额并调用 `fund`，必须在期限内一次足额托管。拒绝入金余额与约定不符的收费代币。原平台钱包、人民币账本和原合同状态**不因这笔链上交易改变**。不得为同一业务双重入金。
4. 执行方逐期 `deliver`，提交已共享文件的摘要。发布方验收 `approve` 后本期款项进入执行方待提现余额；验收逾期任何人可触发 `releaseAfterReview`。这是公开调用，**时间到了仍需有人提交交易并支付 gas**，不是后台定时器自动运行。
5. 双方可在交付后的验收期内 `dispute`。冻结本期的验收与逾期放款；约定仲裁人可在仲裁期内 `resolve`，在本期金额内划分执行方所得与发布方退款，并提交裁决文件摘要。仲裁超时任何人可按双方事先同意的比例 `resolveAfterTimeout`，避免仲裁人失联永久锁款。
6. 当前阶段未按时交付时，任何人可 `refundOverdue` 退回全部未结算金额；已经交付的阶段不能借此撤回。双方也可协商终止全部剩余阶段：一方 `proposeCancellation`，另一方使用准确版本及分配金额 `acceptCancellation`；提案替换或任何履约推进都会使旧提案失效。提案最多有效 7 天，页面默认为 24 小时。
7. 执行方可授权仅有交付权的机器地址，设定最长 90 天有效期（页面为 7 天），随时撤销。代理不能验收、发起争议、取消、入金或提取主体款项。自主机器也可作为直接钱包主体参与，但必须自行安全管理其钱包和 gas。
8. 结算产生三类待提取余额：执行方净所得、发布方退款、平台服务费。`withdraw` 只转给调用者自己。转账失败会整体回滚，保留余额。费率部署后不可变，最高 10%；费用只从执行方实际所得扣除，退款不收费。

时间使用链上区块时间，UI 展示用户本地时间。截止时刻本身仍允许交付/争议/裁决，超时操作要求严格晚于截止。争议不会自动顺延后续固定交付期限；需要变更时先协商终止，重新约定，不能单方改价或改期。交付前没有“已发生隐性劳动”的自动判定，需要双方协商终止分配，或提交符合合同约定的交付证据后进入争议流程。

## 资金与管理权限

- 普通不可增发重基、不收转账税、无恶意回调语义的 ERC20；不能承诺兼容任意代币。资产发行人的冻结/升级/偿付风险不由此合约消除。
- 非代理、不可升级。平台管理员只控制暂停新建及入金、两步移交管理员；不能改历史条款、指定新仲裁人、抽走余额或强制裁决。暂停期间交付、争议、超时退出、退款、结算和提现继续可用。
- 没有余额 sweep。误转代币会作为无法分配的 surplus 留在合约；不能把对账中的 surplus 认作收入。请只通过 `fund` 入金。
- 守恒：`token.balanceOf(escrow) >= totalEscrowed + totalCredits`；各任务 `remaining` 之和等于 `totalEscrowed`。普通路径无误转时取等号。
- 合同/交付/争议/裁决只记摘要，不上传个人信息、证件、合同原文。摘要不证明事实为真。原文、证据交换、保留期限、仲裁服务仍需业务安排。
- Web 在每次交易前核对网络、托管运行时代码哈希、代币、精度、费率、收款地址，拒绝错误部署。只读 RPC 与钱包网络必须一致。钱包账户变化时需要重新连接；交易身份最终由合约校验。页面确认深度来自部署配置，不等同所有链的最终性。

测试链重启会重置所有示例状态，重新生成 manifest；**不是生产持久化节点**。部署文件 `web/public/escrow-deployment.json` 已加入 gitignore，禁止把本机 RPC 配置复制至服务器页面。测试使用 Hardhat 公开测试账户，仅用于 DEMO；不能在真实网络使用。开发者可在仅本机测试链的专用钱包中导入 Hardhat 测试账户操作，不把其私钥提交进项目或用于真实资金。

App `EXPO_PUBLIC_CHAIN_WEB_URL` 设置为手机可访问的 HTTPS `/chain` 地址，可从钱包及合同证据页打开对应网页。钱包内置浏览器可执行签名；当前未集成原生 WalletConnect 会话，也未验证 APK/IPA 真机。机器客户端可直接使用生成的 ABI 加自己的 ethers Signer 调用同一地址；无平台密钥托管。

```js
// From chain/, with a previously configured wallet/smart-account signer.
import { Contract } from 'ethers';
import { compile } from './scripts/compile.mjs';
const escrow = new Contract(deployment.address, compile('TaskEscrow').abi, signer);
// Verify signer.provider network + runtime code hash against deployment first.
const job = await escrow.getJob(taskId);
// Assigned executor or valid delivery delegate only; digest is a shared evidence-file hash.
const tx = await escrow.deliver(taskId, deliveryDigest);
await tx.wait(deployment.confirmations);
```

## 真实网络部署与恢复

先确定网络、结算资产、仲裁安排、费用收款地址、企业多签管理员及确认策略。单代币实例不能在部署后更换资产。真实资产上线还需独立合约审计与业务适法评估。

`chain/scripts/deploy-escrow.mjs` 默认只输出不签名的部署计划。所需环境变量：

| 变量 | 含义 |
|---|---|
| `CHAIN_RPC_URL`, `CHAIN_ID` | 部署 RPC 与预期网络，严格匹配 |
| `CHAIN_OWNER` | 管理员，建议业务已建立的多签 |
| `ESCROW_TOKEN` | 经过审查的代币地址 |
| `ESCROW_FEE_RECIPIENT`, `ESCROW_FEE_BPS` | 固定手续费收款方及万分比 |
| `CHAIN_CONFIRMATIONS` | 链对应的确认深度，默认 12 |
| `CHAIN_KEY_FILE` | 部署者私钥文件，仓库外、0600；仅显式广播时读取 |
| `CHAIN_RECEIPT_FILE` | 新建的本地签名交易/回执文件，禁止覆盖历史部署 |
| `ESCROW_MANIFEST_FILE` | 待审核发布的前端部署文件输出路径 |
| `ESCROW_PUBLIC_RPC_URL` | 面向客户端的 RPC，不能含服务端秘密凭据 |
| `ESCROW_NETWORK_NAME` | 用户可读网络名称 |
| `ESCROW_TEST_ONLY` | 默认 1；仅正式批准的资产/环境设为 0 |

运行 `node scripts/deploy-escrow.mjs` 审阅；显式设置 `CHAIN_SEND=1` 才签名并广播。脚本在广播**之前**以独占创建方式保存已签名的完整交易与交易哈希；网络超时使用相同设置加 `--resume`，复用相同交易，不重新取 nonce 盲目部署。输出包含运行时代码哈希的 manifest；经确认后才复制到 Web 静态目录。私钥不得进入 Web、App、API 容器、公开日志或 manifest。

只读对账：`node scripts/audit-escrow.mjs /path/to/escrow-deployment.json`。可用 `CHAIN_RPC_URL` 覆盖为运维 RPC。它在已确认区块核对余额、所有任务剩余款与全局负债，前后比对区块哈希，发生重组则失败。该工具按任务顺序读取。另已实现 SQLite 持久化事件索引、确认深度、重组回滚、备份，以及默认 dry-run 的超时结算执行器；生产常驻服务、告警接收和运营签名账户尚未接入，详见 [商业化工程清单](COMMERCIAL-READINESS.md)。

## 企业档案：股权、协议、法律合同、财务信息

新增 `BusinessRecords.sol` 与 `/records` 页面。范围是四类资料的可验证版本历史和钱包确认，既可记录股东名册/转让协议，也可记录合作协议、法律合同、会计凭证/报表和后续更正。它不是股权交易所或自动工商登记系统。

- 一个组织有独立链上空间、控制账户、确认人名单与确认门槛。控制账户可由企业多签承担。普通钱包自行创建的空间**没有自动获得工商认证**。
- 每份档案用不含个人信息的业务编号关联版本。`append` 要求准确前版号，防止并发写入覆盖；类别不能在更新时调换；版本哈希包括网络、合约地址、组织、业务编号、前版哈希、原文承诺摘要、类型、声明种类和该版确认政策。
- 新版本以“待确认”开始。提交人与确认人分离，只有当版指定钱包能确认；新规则不会给旧版增添确认权。撤回自己的确认不删除历史签名事件，当前状态会反映撤回。达到约定确认数不等于法定股东会决议已成立，法定身份、授权及会议程序需有原文依据。
- 更正或撤销由新版本声明及原文说明表达，旧版永久保留。最新版可能仍待确认，用户必须同时查看版本与确认状态，不能把“最后提交”当作“最后生效”。
- 机器提交权限用四类位图授权，支持到期、撤销，最长 90 天，页面默认 7 天。只有财务提交权限的机器人不能写股权版本，也不会因此取得人工确认权。
- 控制权两步交接；控制账户可调整未来确认规则。这是明确的治理权限，生产环境应由企业已建立的多签政策控制；平台不存在全局管理员强行覆盖某组织记录的接口。

文件工具使用 WebCrypto AES-256-GCM 在客户端加密，以随机密钥和 IV 保护原文；32 字节随机盐参与 SHA-256 承诺，降低公开摘要被猜测原文的风险。链上只记录承诺。加密档案与恢复文件分别下载，恢复文件含密钥、盐和原始文件名，应独立保管。解密验证 GCM 认证标签及原文重新计算的链上承诺，错误密钥、修改密文、修改盐或不同链上承诺均拒绝。**当前为本机档案备份工具，不是已运行的企业加密云盘/密钥托管服务**；没有把原文静默上传到 RPC、服务器或公链。

本地示例空间 #1 有四类合成测试档案，股权档案还含一个待确认更正版；不代表任何真实公司。现有 demo 运行时可以 `cd chain && node scripts/seed-records.mjs` 部署此部分，不重置托管任务。新启动 `npm run demo` 同时部署两套合约。

部署脚本 `node scripts/deploy-records.mjs` 默认仅输出计划；显式广播沿用 `CHAIN_RPC_URL / CHAIN_ID / CHAIN_KEY_FILE / CHAIN_CONFIRMATIONS / CHAIN_RECEIPT_FILE / CHAIN_SEND`，另设 `RECORDS_MANIFEST_FILE / RECORDS_PUBLIC_RPC_URL / RECORDS_NETWORK_NAME / RECORDS_TEST_ONLY`。无构造参数、无全局管理员；每个组织独立建立自己的控制政策。失败恢复使用 `--resume` 和同一回执文件。审核后的 manifest 发布为 `business-records-deployment.json`；本机示例配置禁止同步至远程静态站。

法律边界的依据（中国大陆场景，具体交易仍应结合组织类型及所在地审核）：

- 最高法《人民法院在线诉讼规则》区分上链后完整性与上链前真实性；上链并不自动证明原始内容真实：[最高法说明](https://www.court.gov.cn/shenpan/xiangqing/309591.html)。
- 《公司法》第八十六、八十七条涉及股东名册及依法需要的变更登记、出资证明和章程变更；可把相关电子文件及办理回执存证，但不能仅以一次代币或哈希操作宣称手续已完成：[市场监管总局全文](https://www.samr.gov.cn/djzcj/zcfg/fl/art/2026/art_9b4263a169cf43c2aba950cfc9ac1af2.html)。
- 《电子签名法》规定可靠电子签名的条件及效力；普通钱包地址不能自动证明自然人/企业实名、签署授权及法定签章资格：[工信部门公布文本](https://ynca.miit.gov.cn/zwgk/zcwj/flfg/art/2022/art_a6ec461de9174d6b87ef092d15615652.html)。
