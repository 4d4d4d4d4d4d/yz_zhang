# 人机委托与协作治理联调

适用于私有测试部署；不包含真实支付、可靠电子签名或工商核验。任务市场、本地服务、社区及企业预算功能继续保留。

## Web / App 操作

1. 在开发者入口创建带 `tasks:write` 的 API Key。Key 明文只出现一次，应由使用者安全保存。
2. 展开该 Key 的机器授权，选择允许的操作、任务类目、单笔风险额度、累计风险额度和有效天数，阅读责任提示后提交。
3. Key 所属用户始终是责任人。只有已实名且接受当前平台协议的用户可以授权；授权不能原地扩权，必要时吊销旧 Key，创建新 Key 并重新授权。
4. 机器可以发布、报名、交付单次单名额任务。签约、付款、验收和提现不在这次授权范围内。
5. 开发者页可查看最近 100 条成功操作记录；失败请求返回错误，不会记录为已成功任务。

金额单位为整数分。累计额度是授权期间操作风险额度，不是余额；发布按预算加奖金计入，报名按报价、预算加奖金、保证金的最大值计入，交付按预算加奖金与保证金的最大值计入。报名、交付分别占用额度，不自动释放。每次新授权最长 90 天。

## 机器调用

服务器通过 SSH 隧道映射到本地 `127.0.0.1:18080` 后，API 前缀为 `/api/v1`。生产系统需配置正式 HTTPS 地址。

请求头：

```http
X-API-Key: <使用者自己的密钥>
Idempotency-Key: <该业务操作固定的唯一编号，1—80字符>
Content-Type: application/json
```

- `GET /api/v1/open/v1/tasks?marketplace=true`：列出公开招募任务，需 `tasks:read`。默认仅列出本人的发布／执行任务。
- `POST /api/v1/open/v1/tasks`：发布任务，需 `tasks:write` 及 publish 授权。
- `POST /api/v1/open/v1/tasks/{id}/applications`：报名，需 apply 授权。
- `POST /api/v1/open/v1/tasks/{id}/deliver`：交付，需 deliver 授权且责任人是该任务执行者。

发布示例：

```json
{"title":"制作协作页面原型","category":"软件开发","budget_cents":10000,"is_remote":true,"ip_assignment":"assign"}
```

报名示例：`{"message":"可以交付原型","bid_cents":10000}`。
交付示例：`{"note":"原型交付说明"}`。

重试使用同一幂等编号与同一参数。成功请求重试返回原结果；同一编号改变参数返回冲突。额度不足、超出类目、授权过期或 Key 被吊销时不能继续写入。任务自身的资格、合同和状态要求继续适用。

## 合作体与主体资料

加入合作体须有当前成员发出的有效邀请，邀请有效期七天。加入者自己确认风险揭示版本。

法律主体与权益记录位于合作体详情。登记名称、编号、责任成员、治理依据、文件名称及版本、认缴／实缴和权益说明单独保存，与贡献份额分离。每次提交新版本保留旧版本，所有版本均显示“尚未核验”。成员可提交记录不代表其有权代理公司；当前没有登记机关核验或法定代表人授权验证。

## 共同分配

1. 合作体成员发起金额及说明，系统保存当时成员名单和贡献份额快照；发起本身记为本人确认。
2. 全体当前成员查看提案并确认。任一成员可拒绝或撤回，终止该提案。
3. 全员确认后任一成员可执行；平台再次检查七天有效期、当前成员、贡献依据和真实可用余额。
4. 成员或贡献依据发生变化时，重新发起提案，不沿用旧确认。执行参数不能偏离提案。
5. 并发执行或网络重试返回原分配，避免重复转账。分配快照、确认人及执行关联写入存证事件。

旧 `POST /ventures/{id}/distributions` 必须同时提交 `proposal_id`、与提案完全一致的 `amount_cents` 和 `memo`，不能绕过确认。

这是项目资金控制；不是公司／合伙法定表决、税务处理或股权转让系统。哈希链位于平台数据库，不等于已部署链上智能合约或外部可信存证。

## 服务器验收脚本

`deploy/smoke-governance.py` 必须在 API 容器内运行，先检查 `PLATFORM_ENV=test` 和 PostgreSQL 地址。脚本创建带明确测试名称的任务、合作体、主体记录及模拟余额，检验机器额度和收益分配并发控制，结束时吊销测试 Key。不能对生产环境运行，不会输出 Token 或 Key 明文。
