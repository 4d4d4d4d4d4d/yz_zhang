## 1. 用户想要的平台

一个人与人之间的窗口。每个人拥有独立门面及虚拟身份，整合不同平台的文章、视频、小店、直播，让人了解其能力与价值。AI 支持跨专业问题，必要时组织专家；人、人机、机机通过可信约定协作；经验经授权积累为平台和 Agent 的能力。范围覆盖遛狗/外卖/社交、机器人/工业品的跨模块组织、长期经营以及复杂公司活动，兼容公司、合伙和股权等现有关系。UI 应极简、有代入感、有克制而高质量的动效。

## 3. 前后端实现和迁移

前端：新增发现页、公开空间、空间编辑器、合作入口；原广场保留在 `/opportunities`；导航聚焦四入口；登录支持安全站内返回地址；空间私聊打开真实会话；登录和新页面使用克制的窗口视觉。未伪造人物、成交量或作品。

后端：新增 spaces 模块与 `b0a120260004` 迁移。保存只针对当前用户；发布是显式操作；列表/详情应用同一隐私过滤；分页受限，搜索转义；无服务器外链请求；版本冲突 409；账号注销清除空间，个人数据导出包含空间。

原生 App：空间 UI 已于 V115 进入 App（浏览/编辑/发现/四入口/深链），V119 补上代扣明细与 PIPL 权利页。V120 给整单放款加了两步确认——RN 里没有 `confirm()`，所以第一下只把「剩余几期、共多少钱」摊在屏幕上、不发请求。移动 Web 的响应式实现仍不能写成原生 App 已完成；真机验收依旧缺失。

## 4. 验证记录与交付状态

本轮测试与部署结果见 [CHANGELOG-2026-10-07.md](CHANGELOG-2026-10-07.md)。测试数量以命令输出为依据。商业化检查 7/17 是技术配置检查，不是完成百分比。

V120 核对的一件事值得单记：台账里 `SC-013`「分期合约可被整单验收绕过」**一半是误判**——服务端只放剩余托管、并把未放的期一并标成 `released`，这条路是自洽的、是有意设计。缺的那一半在客户端：两端按钮上原来只有「验收通过（放款）」五个字，而发布方当初分期正是为了不一次付完。**判定一条欠账之前要先去读实现**，否则会去修一个没坏的地方，而真正缺的那一半仍然留着。
