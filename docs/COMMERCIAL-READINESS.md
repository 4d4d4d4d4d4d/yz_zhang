# 商业化差距与本轮工程交付

实查日期：2026-10-07。定位为 OPC 协作平台，保留人、人机、机机协作，以及公司/合伙组织、内容与本地服务场景。

## 目前处于哪一阶段

可以进行**邀请制、无真实资金的内部联调**。真实收费交易与公开商业运营还未达到放行条件，不是仅换域名、填密钥即可上线。

在运行中的服务器 API 环境执行只读检查：**17 项技术配置检查通过 7 项、未通过 10 项**。这只是必要配置检查，绝不是产品完成度或商用成熟度百分比。检查还没有覆盖真实供应商验收、业务适法审核、外部安全审计、容量证明、值班响应和 App 上架。

未通过：生产运行模式、支付、短信、实名、内容审核、第三方登录、资金存管、正式电子签约、外部存证、税务/开票方案。其中支付、短信、实名、内容审核的注册表里**没有正式适配实现**，电子签约只有传输适配器，尚未接成完整业务状态机。因此“剩下都只是账户和手续”的旧判断不准确。

## 本轮已补

| 工程 | 可验证结果 | 边界 |
|---|---|---|
| 持久化链上事件索引 | 按确认深度拉取、去重、重启续读、重组回滚、批次事务原子提交 | SQLite 是可重建派生索引；平台主业务仍使用 PostgreSQL。未把索引事件直接记成用户余额 |
| 索引备份/恢复 | SQLite 一致性快照，测试恢复后数据一致 | 仍需生产备份保留和异地恢复安排 |
| 超时操作扫描 | 从已确认区块计算允许的退出操作，输出未签名交易计划 | 不主动验收、签合同或裁决；区块时间决定是否到期 |
| 受控执行器 | 状态重验、模拟执行、gas 上限、单笔费用上限、一次一笔待处理交易 | 默认 dry-run。真实广播需要运营方签名账户和明确费用上限 |
| 交易恢复 | 广播前落盘完整签名交易，断网后重启复用同一交易哈希 | 专用 gas 账户不能和其他发交易进程混用；不自动加价替换卡住的交易 |
| 后台商用检查 | `/admin` 中读取服务器真实配置，展示缺实现/缺配置 | 仅管理员可见，不泄露密钥或连接串；永远不自动发出“商用获批”结论 |
| 运维接入文件 | 索引 systemd 模板、结构化健康日志、Prometheus 指标及告警规则 | 未配置值班接收人；模板不代表已在生产运行 |

## 剩余工作按上线门槛排列

| 优先级 | 工作 | 工程缺口 | 需要外部输入/资源 | 完成证据 |
|---|---|---|---|---|
| P0 | 确定首期收费边界 | 按首期能力关闭尚未完成的真实交易入口 | 首期用户地域、经营主体、收费对象与结算方式 | 经确认的试运营范围与服务协议 |
| P0 | 支付与资金存管 | 供应商正式实现、真实回调验签、退款/分账/提现/对账联调 | 已开通的商户或平台产品，具体 API 权限 | 小额真实闭环及账单核对，失败补偿通过 |
| P0 | 实名、短信、审核 | 选定供应商后的正式适配及故障处置 | 产品、签名/模板、企业账户、测试凭据 | 验证成功/失败/超时/重放及人工处理路径 |
| P0 | 企业与钱包身份关系 | 用户/组织授权、签署资格、钱包绑定撤销与恢复 | 组织认证材料、谁有何种代表权限 | 越权测试和真实企业签署验收 |
| P0 | 电子签约全流程 | 同意授权、冻结原文版本、发起/回调或轮询、失败重试、成品归档 | 选定供应商正式账户及签约资质 | 双方签署成品和供应商验证报告 |
| P0 | 企业私密文档共享 | 权限控制、加密对象存储、版本备份、密钥恢复及操作审计 | 企业文件保管/恢复政策、存储区域 | 越权/撤权测试和灾难恢复实操；当前本地下载工具不能替代 |
| P0（启用链上资产时） | 正式网络与资产 | 真实部署、源码核验、确认策略、索引与执行器接入、故障演练 | 网络、代币、管理员多签、gas 预算、独立审计 | 审计问题关闭及正式地址验收。测试币记录不算 |
| P0 | 上线基础设施 | HTTPS、机密管理、备份恢复、限流容量、故障告警和值班 | 域名、证书、容量预算、告警接收人 | 生产部署检查、恢复报告、目标并发下压测结果 |
| P0 | 业务与服务运营 | 税票/账单处理、争议与投诉时限、人工审核职责 | 财税/法律审核、客服与运营人员 | 真实案例演练与签字负责的流程 |
| P1 | 原生 App 钱包和上架 | 原生钱包会话、真机联调、推送、签名打包与商店检查 | 开发者账号、设备、钱包服务配置 | APK/IPA 真机验收和商店发布；当前只是钱包网页入口 |

这些任务相互关联。支付/签约等供应商尚未确定时，新增一个“通用 HTTP 接口”不能证明真实业务可用，也不应解除上线拦截。当前不提供凭空的上线日期；选定首期范围和供应商后，才能按正式 API、沙箱结果与验收排期给出可靠工期。

## 复现与运营命令

```sh
# API 环境中的只读检查，不输出连接串或密钥
cd server
python -m scripts.commercial_readiness

# Node 24，先编译合约。索引无需签名账户。
cd ../chain
npm run compile
node scripts/index-events.mjs /path/escrow-deployment.json /var/lib/opc-chain/escrow.sqlite TaskEscrow
node scripts/index-events.mjs /path/records-deployment.json /var/lib/opc-chain/records.sqlite BusinessRecords --watch
# 导出前先重新校对主链；默认最多 1000 条。大结果通过 AFTER_BLOCK/AFTER_LOG_INDEX/EVENT_LIMIT 按返回的 nextCursor 分段读取。
node scripts/index-events.mjs /path/escrow-deployment.json /var/lib/opc-chain/escrow.sqlite TaskEscrow --export
# 仅生成计划，不动资金或 gas
node scripts/plan-settlements.mjs /path/escrow-deployment.json
node scripts/run-settlements.mjs /path/escrow-deployment.json
```

执行器只有显式 `CHAIN_SEND=1` 才广播，另需 `CHAIN_KEY_FILE`、`KEEPER_JOURNAL`、`KEEPER_MAX_GWEI`、`KEEPER_MAX_TX_ETH`。每次调用最多处理/恢复一笔；优先处理 journal 的待确认记录。用 `KEEPER_FIRST_ID` 和 `KEEPER_SCAN_LIMIT` 分页扫描，不能把单次扫描的前 100 单当作全平台。默认不设置真实密钥、不启动付费广播。

服务模板在 `deploy/chain/`。Node 必须支持 `node:sqlite`（本项目验证版本 24）。先编译生成 artifacts，再部署同一版本的 ABI 与服务；事件索引不需要生产私钥。RPC 原始错误不进入日志。指标文件必须接入 Prometheus/node_exporter，告警路由必须由运营方指定；当前只是已提供可部署配置，尚无真实生产接收端验收。

文件名为 `.sqlite` 的 journal/index 含公开交易信息与待广播签名交易，应按运营资料限权保管。签名交易不是私钥，但可以被持有者广播。不要把 journal 上传前端或进入 Git。
